Differences from the owner build as the owner runs it
-----------------------------------------------------
- MAWS_E2E=1 on every launch (launchMaws sets it, the real-store case keeps it): custody is bypassed (configure sends
  binaryPath null and the host runs the installer's pin), Chromium uses a mock keychain, and the quit question is
  answered from MAWS_E2E_QUIT_ANSWER instead of the native dialog.
- No harness routes (MAWS_HARNESS=0; the packaged build has none); every observation went through the product's own UI
  and its X2 bridge.
- Unsigned, ad-hoc build: notifications fall back (dock bounce and toast) instead of native delivery.
- A scratch config home with `{}` user settings, the owner's login-shell environment otherwise (MAWS captures it), Sonnet
  sessions and Haiku subagents instead of the owner's default model, scratch repositories.
- The window is driven through Playwright: blur, focus and native menu items through Electron's API on MAWS's own window;
  the ⌘⇧J key, the Korean IME, ⌘-click, the Open panel and by-eye taste are the owner's.
- Approvals are answered by clicks on MAWS's cards; the §10.4 child's own tool calls needed none (auto mode).
