   keeps an "ended with an error" badge with the time. (Owner: yes.)
2. Opening a session replaces the current main tab, whatever the current tab shows; the explicit way to a new tab
   is the session's right-click menu "Open in new tab" (⌘-click and middle-click stay as shortcuts). Pins and
   unsaved work stay visibly, as 2.5 says. (Owner's words: "when opening a session, it currently opens in a new
   tab; instead replace the current tab; the user can right-click to open a certain session in a new tab". The
   rule is about the main tab, not about the sidebar.)
3. To-human: a choice click sends immediately as the next prompt through the queue. Free text is written inline
   on the question card itself (a Reply field in the card, opened by its Reply action), sent from there through
   the same path, after which focus returns to the composer; the composer is never used for the answer and its
   draft is untouched. Essential is read on explicit Mark read (architect's pick; not asked).
4. Sessions: an engine starts on the owner's first action that needs it (Send, a chip change, a fresh read);
   saved facts show instantly before that; a terminal-held session stays read-only with an explicit Take over.
5. Extensions Browse: the engine's configured sources only; sandbox toggles deferred to a separate decision.
   Resume scope: current project with All projects one click away. (Architect's picks, stated to the owner;
   reversible.)
6. Browser profile settings (answered 2026-10-08, after the sitting): clicking the profile pill in a Browser tab
   opens a floating popover anchored to the pill (profile name, signed-in state, switch profile, re-import;
   dismissed on click-away); nothing leaves the current page. Not a sidebar tab. Owner's choice among popover,
   sidebar tab and both. Belongs to the in-app browser ticket owned by the cua_repl session (3.E), not to E11's
   fix waves; E11 records it against owner-results rows D6 and N4b.10.
