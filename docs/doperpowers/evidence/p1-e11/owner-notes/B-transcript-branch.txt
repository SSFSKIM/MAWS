Exact current mechanism, verified by reading:

- src/engine-host/fs/chain-follower.ts:172-221 ignores duplicate UUIDs, retains a skeleton for each UUID-bearing record, and normalizes absent/non-string parentUuid to null. A progress record remains a skeleton but never becomes the leaf or emits an event; throughProgress at 526-534 follows its parent links.
- handleRecord at 274-296 extends when the effective parent equals the current leaf. Otherwise it first tries an announced rewind continuation, then a null-parent system/compact_boundary restart; everything else enters branch(). Thus a candidate branch is a parent/tip mismatch, NOT simply “two records have the same parent”. A new UUID-bearing null-parent record can be a new root. Anonymous records are handled separately at 224-242: file-history-snapshot, queue-operation, summary and ordinary last-prompt bookkeeping do not fork the chain. last-prompt matters for a rewind only with leafUuid and rewound:true (244-271).
- branch at 327-353 walks known parents backwards and joins the existing prefix at the first on-chain ancestor, stopping on a missing parent/cycle with a gap. removed is the old chain minus the new chain. It preserves an already-recovered response-group prefix, rather than reverting it to raw ancestry.
- Attachment-only removal is silent (354-356). Same-response interleaves are retained in file order (357-370): assistant message.id, result sourceToolAssistantUUID/parentUuid, matching agentId/isSidechain, and established delivery ownership identify the group (445-460). The incoming record AND every displaced record must belong to that group, or the specified eligible interleaved delivery. A human prompt or another response is not arbitrarily swallowed.
- Empty cuts, local-command-only cuts and synthetic no-response-only cuts are silent (372-381). This is semantic suppression at the producer, not cosmetic renderer hiding.
- W7 hold-back is different (382-389, 463-468). It requires a current foreign holder, an incoming record not attributed to MAWS, and a removed record attributed to MAWS. It keeps the old chain and emits HELD_NOTICE with key transcript_branch_held once per held episode/core. It does NOT emit a retraction for every tool. FsService wires holder count, pin and ownership at src/engine-host/fs/service.ts:429-431 and refolds when the foreign holder exits at 155-158.
- For a nonsilent cut, terminalRewind (471-486) recognizes the constrained old-turn-boundary prompt shape with at most one holder. An unanchored rewind may also explain the cut. Otherwise 396-408 emits boundary.retraction with reason transcript_branch and the removed UUIDs. Current code does not emit the generic writer notice there. A W7 refold can emit one reconciliation retraction and its separate exit notice at 782-795.
- src/renderer/src/transcript/model/reduce.ts:651-664 routes the boundary to affected turns, or the current/loose stream if no indexed message/hook owns the UUIDs. derive.ts:327 collects retracted UUIDs; 603-606 always adds a row for a received boundary. isPersistentRow at 115-126 and the folded projection at 742-775 keep boundaries visible while tools, thinking and ordinary notices can disappear into the work group. Hence B2's adjacent empty-looking dividers. There is no “deduplicate every six” or “hide invisible cuts” fix here; the producer must not emit false cuts.
- derive.ts:1312-1320 and copy.ts:278-286 now use neutral conversation-history copy, with the reason and UUIDs in technical detail. view/rows/requests.test.tsx:229-243 explicitly excludes the old visible wording.

Correction to a supplied anchor: X3 divider.cause is NOT transcript_branch. src/renderer/src/transcript/model/rows.ts:64 and schema.ts:76 allow only the optional value crash, added by E11 W-C to distinguish an engine crash from a user's stop. transcript_branch is the X1 boundary.retraction reason. These are separate row types and separate facts.

3 How Claude Code itself and the reference apps treat the chain

The engine file is a graph, not an array of alternating chat messages. A parent mismatch does not prove a second writer.

Charter docs/charter.md:138-148 binds C4 to the latest leaf's parent chain, rather than file order; C4's child is at 357 onward. X3 transcript derivation is C6, at 418 onward; C7 owns composer/requests.
