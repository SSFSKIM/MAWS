/Users/new/Developer/GitHub/MAWS/src/renderer/src/stores/layout-model.ts:249–291:

/Users/new/Developer/GitHub/MAWS/src/renderer/src/stores/layout.ts:243–264 supplies the destination project and the unstarted-session guard. Critical details:
- A New chat with no indexed SessionRecord is an unstarted session, not just an ordinary composer containing unsent text.
- When a default replace meets such an unpinned unstarted tab, the target session opens beside it immediately. The guard then decides whether to discard the old intent/tab.
- If discarded, the draft tab disappears without a reopen entry. If declined, both remain.
- If the draft starts while the guard is deciding, preserve its tabs and panel.
- A pre-hydration click replayed over an unstarted saved tab preserves that draft and asks nothing; both can remain.
- Already-open destination, explicit new-tab and explicit split bypass this replacement guard.

3.4 Editor convention, and why not to over-import it

The useful VS Code analogy is a preview editor: single selection opens a replaceable preview, another selection replaces it; double-click or editing makes it durable. This is a convention comparison, not a traced VS Code implementation in this research. In particular, “Command-click opens beside” is not a universal VS Code Explorer rule (modifier meanings depend on surface/keymap; Explorer also has multiselect). MAWS should document its own Command/middle-click-new-tab and explicit Open in split rather than assert a universal shortcut.

MAWS already implements replacement without a preview bit. Adding double-click-pins/edit-pins everywhere would be a new policy and persistent state vocabulary, not a necessary fix. Its existing explicit pin is enough if the automatic preservation exceptions become narrow and legible.

4. ROUGH FIX PLAN

4.1 F1 — fix the exceptions, not the already-landed default (M)

Recommended behavior:
1. Plain sidebar click/keyboard Enter and picker confirmation navigate in the focused destination-project pane. Existing destination anywhere activates once, never duplicates. Keep project sets and the maximum two-pane model.
2. An ordinary unpinned tab is replaceable regardless of kind when replacing it does not discard unsaved work. Remove the blanket non-session exemption. In particular, a clean file, diff, agent transcript, browser view, deliverable viewer, Settings or Diagnostics must not force a new tab merely because of its kind.
3. An explicit main-tab pin resists replacement. Make it a recognizable pin icon/control with a tooltip (“Keep this tab when switching sessions”), not only a tiny dot and context-menu action. Do not confuse it with sidebar favorites or right-panel pins.
4. Unsaved file buffers, pending saves and unstarted launches must never be silently disposed. Initially preserve them and mark why (“Unsaved changes — kept open” / “Starting — kept open”), rather than quietly growing the strip. Run the existing kind-specific lifecycle guard; browser/deliverable cleanup needs the same discipline. Do not equate replacing a view with terminating the session or destroying its resources.
5. For started sessions keep the already-session-scoped draft when navigating; no new feature needed and no text moves to another session. For an unstarted New chat, preserve the intent/draft under its own identity when navigating rather than treating navigation as destructive discard. Give it a recoverable Draft/New chat entry or reopen path before removing its visible tab; never hide the only way to retrieve it. This part is M rather than an S type-check edit because current discard and retention semantics are tab-coupled. If that recovery affordance is not included, retain the current guarded preservation rather than lose a draft.
6. Command-click/middle-click and Open in new tab remain explicit new-tab gestures; split remains explicit. Opening an already-open destination activates it even for these gestures, per the existing unique-tab contract. Add clear gesture/pin help to the keymap/help surface and relevant tooltips. No new arbitrary tab cap.

Why this recommendation: it directly removes the most frequent non-session surprise while retaining the workstation's deliberate multiple-session and file/tool views. Running/background work itself should not pin a tab; the engine is independent of the view and the sidebar/Overview carries supervision.

Implementation seams:
- /Users/new/Developer/GitHub/MAWS/src/renderer/src/stores/layout-model.ts: factor the pure replacement transition so it can replace an eligible active kind, preserve position/history, and retain the existing deduplication/project routing.
- /Users/new/Developer/GitHub/MAWS/src/renderer/src/stores/layout.ts: orchestrate an eligibility/lifecycle guard rather than make the pure model read editor state; recheck target identity after asynchronous decisions, keep hydration races safe.
- /Users/new/Developer/GitHub/MAWS/src/renderer/src/keymap/actions-runtime.ts: share per-kind protection with navigation but distinguish preserve/suspend from explicit destructive close; preserve focus ownership.
