## Verdict
Wave A (F-history-anchors, bb2fdde79, 610cd5e13, 1364039af, dc914a7b6): correct. Each fix closes its finding.
- **Keys:** the actor key (`who`) is unique per list in both `showEditors` and `elementEditors`.
- **Notice:** `pending.serial` comes from one counter for the whole window and only goes up, and each host shows at most one notice, so two notices never share a key. A notice that changes from starting to refused keeps its serial and does not remount.
- **Focus restore:** focus goes back to the opener only when focus is on body, on a detached element, or inside the menu. So an Escape (or a blur) from a field the owner moved to never takes focus away. A field that unmounts on Escape drops focus to body, and the page then gets it, which is better than before. The document editor binds no Escape key, so Escape from the page still closes the list.
- **Deck Escape:** the stage's Overlay calls stopPropagation on Escape whenever something is selected, so the window never saw that Escape, before or after the change. The only change is that an Escape a text box takes (its keymap returns true, which calls preventDefault) now ends the text edit and leaves the menu open. That is consistent with the routing.
- **Heading:** `headingFrom` reads the current preview after the await. It cannot bring back a closed preview, because `loaded` and the snapshot are cleared together. It keeps `view` and `carried` unchanged, so nothing re-binds.

Wave B (F-library-viewers-cutover, 1586d7eeb, d4d7c58e5, 380dfbf26, 284a6907d): correct apart from the P3 above.
- **Stale window:** during the re-read, the frame, Reveal, Open externally and Save a copy all act on the same revision. Only a followed-latest Export can differ (the P3).
- **Reload:** it still re-keys the read, so it reads from nothing and shows loading.
- **Superseded moves:** the `refused` callbacks only call `cancelVersionRequest`, which is a no-op once a later open has superseded the request. Back's callback is a no-op. No UI is left stuck.
- **Guard asks:** a move that supersedes another reuses the pending ask. Every waiting move is either landed or refused (when replaced, withdrawn, when the guard answers false, after dispose or while closing).
- **Guard asked twice:** this only happens after a withdraw: a new move made while the first ask is still pending asks again, and the first answer is ignored. That is fewer concurrent asks than before the change, where every move asked.
- **Ported pick cases:** they match the deleted `comment/pick.test.ts` case for case. The title-fallback case was dropped, and the reason given is sound.
- **Outside the routing:** neither wave changed behaviour beyond the departures the workers reported. One trivial note: comment-session.tsx now has `type Notice` and a component `function Notice` in the same file. That is legal, and lint's `no-redeclare` is off.
