### Root causes and fixes that differ from the triage

- **c14:** the cause was Tiptap's `chain().focus()`. When the page did not have the keyboard (the Insert menu used from the keyboard, Block style, another atom's field), it defers the page's focus to the next animation frame. That frame took the keyboard back from the field `editAtom` had just focused, so typing replaced the selected atom. The fix is in `Toolbar.tsx` only: the page is focused synchronously before every insert. The triage's `focusField` transaction meta in `atom.ts` was not needed.
- **c16:** the line split was c14's cause: the Return went to the page while the chip was selected. The c16 commit makes the date field itself hold the chip:
  - an empty or incomplete value no longer clears the date;
  - Enter commits what the field shows;
  - Escape puts back the chip's last date;
  - both keys are prevented and stopped at the field, and the caret goes back synchronously right after the chip.
  - The stop and the synchronous hand-back apply to every atom field, because the handler is shared.
- **c20:** there were two leak routes.
  - The drawing was made off the document, or before the page's design-system stylesheet arrived, and was never redrawn. The view now draws only once it is attached to the page, and redraws when the page's colours change. It listens for the same triggers as `page-ground.ts`.
  - Mermaid is one shared instance that the transcript also configures with the dark app's palette. The page's colours now ride in each diagram's own `%%{init}%%` directive, placed after any front matter. A directive the source writes itself still wins.
- **F18:**
  - Links take `color: inherit`, the underline thickens on hover, and `:focus-visible` draws a 2px focus ring.
  - `hlink` now comes from the text colour in `office.ts` and in the export's local table; a system that declares `hlink` keeps it.
  - As you asked, Word's Hyperlink style takes the theme part's `hlink` (new helper `themeSlot`), falling back to the text colour. Both cases are pinned in `docx.test.ts`.
  - PPTX links follow too, since PPTX takes its theme from `office.ts`.
  - **Judgement call:** the focus ring uses `var(--ds-color-accent, var(--accent))`. A bare app token would break `theme.css`'s token rule and would vanish in the HTML export. Say if you want `currentColor` instead.
  - **Not pre-approved:** I also edited `html.test.ts` and `source.test.ts`, the HTML export's tests. They proved an override reaches the export by reading the link's accent; they now read it from the highlight band. I counted them as "the tests for these files" because the export inlines `theme.css`.
  - `e2e:design-systems` now reads the accent from the highlight band through `accentBand`/`markedBand`. `accentBand` throws when the box-shadow names no colour.
