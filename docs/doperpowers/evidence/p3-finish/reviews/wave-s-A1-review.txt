- [P2] Draw the link focus ring in currentColor, not the system accent — /Users/new/Developer/GitHub/MAWS/.claude/worktrees/agent-af4cd2993bc56e015/src/artifacts/document/editor/theme.css:74-77
  Should-fix (F18). The ruling in triage row c11 says "no accent on hover or focus", and the MAWS law (defaults/maws/DESIGN.md:164) says "No accent on … a link". But `var(--ds-color-accent, var(--accent))` resolves to the governing system's accent, and the HTML export resolves `--ds-*` too. So a keyboard-focused link in a read-only page or an exported file gets a ring in the system's accent (terracotta for MAWS). The "app's focus ring" cannot be used literally:
  - the app has no focus-ring token; its rings are `outline: 2px solid var(--accent)`;
  - a bare `var(--accent)` fails theme.dom.test's token rule;
  - the export cannot resolve it, so the whole outline would drop.
  `outline: 2px solid currentColor` meets the token rule (no `var()`, no literal), survives the export, follows the link's text colour, and has the text's contrast rather than the accent's 3.7:1. The theme test 'takes no colour of its own in any state' (theme.dom.test.tsx:97) only checks properties matching `/color/` and `text-decoration`, so `outline` slips past it; it should cover `outline` too. The impact is limited to places where a link is a tab stop (read-only pages, the export), since links inside the editable contenteditable are not.

So the directive injected after the front matter now overrides an author's `config: { theme, themeVariables }`. Through `withPalette` it parses to base / rgb(250, 249, 246). Before this change the front matter won over the `initialize` palette. The code comment claims "a directive the source writes itself … wins", which holds for a `%%{init}%%` line but not for front-matter config, mermaid's documented non-deprecated route. Only diagrams that set theme config in front matter are affected: their colours are silently replaced and the render still works. The new test covers only a `title:` front matter. The stored source is unchanged; only the render string carries the directive. One possible fix is to skip the injection, or merge the palette under the front matter's `config`, when the front matter declares one.
