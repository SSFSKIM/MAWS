## Verdict

Answers to the brief's specific questions, beyond the findings above:
- F4, another window's card: each window's setup store docks only from its own calls. `applySetup` docks relay cards only, never trust cards, so no other window holds a card that this commit should have undocked. When a composer card carrying a message exists for an intent, main refuses the no-turn start and the notice falls back to Open session; nothing is lost.
- F4 e2e: it is plausible. The replay matches control requests by subtype, `workspace_trust_recorded: true` comes from the bootstrap recording whatever the directory, and the session's own launch attests again because the replay writes no `.claude.json`, which is what sessions.spec asserts. One weakness: `closeScene` checks `replay_mismatch` only for the seeded ids, so a mismatch in the started session's journal after ready would not fail the case.
- F7, mid-export changes: entering a preview change or compare mode during the export or the dialog still saves what was shown at the click. The save dialog is a sheet, so the tab cannot change underneath it. The dashboard delegates to DocumentTabState, so it inherits the same behaviour.
- Tests: apart from the vacuous stale-press case, they test behaviour rather than restating the edit. They cover the IPC sequence and options for each answer, a record's resume path, the editor's `[previewing, shown]` reports through version, compare and leaving history, the six disabled entries, and the silence after a cancelled save.
