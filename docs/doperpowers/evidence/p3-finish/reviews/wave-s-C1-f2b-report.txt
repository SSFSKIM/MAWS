## What the code does now
- **The plists:** read only on macOS; the default directory is null on any other platform, so there is no stat and no spawn there. Each path costs one stat. A plist that is not there is skipped with no conversion.
- **The conversion:** `plutilJson` runs `/usr/bin/plutil` with the engine's arguments, 5 s timeout and 2 MiB cap. It uses asynchronous `execFile` rather than the `execFileSync` the ruling named: the engine host's single event loop serves every session, and a synchronous spawn would stall all of them during each launch. The function was already async, and the arguments, no-shell rule and timeout are unchanged.
- **Failures:** a malformed plist, a failed conversion or a timeout keeps the 600 s floor.
- **Test isolation:** the managed-preferences directory and the converter are injectable (`HookSources`), so no test touches /Library.
- **The cache:** read as JSON with the signature unchecked; it can only lengthen the wait.
- **`enabledPlugins` precedence:** the managed sources come last, the engine's preferred one last of all.

**A fix beyond the ruling:** the plugins-directory line used to treat any non-empty value of the switch as on, so `CLAUDE_CODE_USE_COWORK_PLUGINS=0` sent it to `cowork_plugins` and missed the user's plugins. Both the user file and the plugins directory now follow the engine's on-words.

## What L35 still does not read
A hook from any of these still runs under the 600 s floor:
- a plugin's hooks module: it is code, with no declared timeout;
- built-in plugins, seed-directory plugins (`CLAUDE_CODE_PLUGIN_SEED_DIR`), and any plugin the engine finds outside `installed_plugins.json`;
- install records with a relative `installPath`;
- server-managed settings that changed after the engine last wrote its cache, because the engine fetches fresh ones at start.

The engine's other cowork trigger (Qgn at :655208) is set only by an embedding SDK host, which MAWS's CLI launch never is, so it does not apply.

The closing condition I proposed earlier still fits: the engine reports each hook's timeout on its `hook_started` event, which today carries only `hook_id`, `hook_name` and `hook_event` (:698758).
