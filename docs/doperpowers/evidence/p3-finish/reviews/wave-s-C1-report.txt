## F5: what changed
- **Ask Claude from a narrowed Space with a linked folder** creates the session in that folder's project and location through the existing `session.projects.addFolder` call (New chat's Open folder) rather than `session.projects.add`. With add, a folder inside a repository would become a sidebar project of its own; with addFolder it folds under the repository's project and the session still starts in the folder.
  - A Space without a linked folder starts in the focused project.
  - The prefill and the card's label read: Make a <kind> in the Space “<name>”: .
  - If addFolder fails (the folder is gone), the failure is toasted and no chat starts.
- **`artifact_create` takes an optional `space`.** It is a Space id or name, matched exactly and then case-insensitively. The same resolver serves A's create and B's document and dashboard create.
  - An unknown Space is refused as `notFound {space}`, and the message names the Spaces that exist. A name two Spaces share is refused as `invalid` with their ids.
  - The store's create receives `spaceId`, and the first answer carries the Space's default design system. `designSystemId` stays unset.
  - The answer carries `spaceId` and `spaceName`.
- **`artifact_list` entries** carry `spaceId` and `spaceName`.
- **Both tool descriptions** now mention the fields. No fixture or test pinned the old descriptions; the protocol-probe recordings predate them and were not touched.
- **Out of bounds, not touched:** no store, preload, IPC or persisted-format change.
