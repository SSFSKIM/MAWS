## Findings

- [P1] X35 "committed in the same frame" cannot hold: the hold is renderer-side and `committed` is a separate message — spec §4.2 rule 2, §6 X35; ledger §3 row 1
  The composition hold is the renderer provider buffering remote Y frames from `compositionstart` until `view.composing` is false (`src/artifacts/document/collab.ts:16-17`), editor-wide (tracker row 138). The host commits and answers the call at once; the ledger makes `artifact.provisional {state: 'committed'}` its own port message. So while the human composes anywhere, the renderer receives `committed`, withdraws the layer, and the real text is still held: the agent's words vanish until `compositionend`, the opposite of rule 2 and of §2 item 9's "replacing it in the same frame". Even without a hold, two port messages are two tasks, so a paint can land between them (a flash, or both texts). Row 138 sits in A2's Rows while §9 defers the block-scoped hold "beyond what A2's rule 4 needs"; the two cannot both stand. Fix: the renderer withdraws the layer only when the update carrying the call's identity is integrated (the `committed` event carries the commit's seq or the write's origin and the layer is held until that update applies; the hold buffers provisional frames with the Y frames), and the spec says which of row 138 and §9's deferral is true.

- [P1] The parity bench's rule is unresolvable at n = 3 and has no verdict band; the deck cells cannot be pinned to "the same effort" — spec §4.2 A1, §2 item 11, Decision Log 10
  The grounding the spec cites says the opposite of what the spec cut to: "run at least 5 repetitions per cell. Server-side first-byte p90 runs to 3 to 6 s, so fewer runs cannot separate a 2 s difference" (`research/p4-edit-speed-grounding.md` §4.6); §3 records first output at 5 to 22 s on a 21.6 s average edit, so "about 20 %" (about 4 s) is inside one run's noise at three repetitions. The rule names parity (within ~20 % with similar requests and tokens) and "Desktop clearly faster" and nothing between, which is the after-the-run argument a rule "stated before the run" exists to prevent. The deck cells (the sitting's 66 s, "never dropped", Decision Log 15.14) land on "the nearest kind Desktop offers": Code sessions load the owner's user scope (grounding §1.4) but have no deck kind unless gated; Cowork runs a scratch `CLAUDE_CONFIG_DIR` at effort `medium` with its own 47K system prompt, so "the same model and effort, the owner's usual setting" is false for exactly those cells. A cause the breakdown can name that is no lever (the relay's first-byte overhead, D-19; the user scope's 131 tools) has no routing. Fix: at least 5 repetitions with medians and the spread reported; one threshold (MAWS median > 1.2 × Desktop median on send-to-edit-landed = Desktop faster; else parity) with no middle band; a deck clause (judge only when Desktop offers Slides or Design in a Code session; otherwise report the components and judge MAWS-controlled time only); "cause outside the levers" routes to a row, not A3.

- [P2] X34 binds every `artifact_*` call to 1,000 ms, which the live specs' `artifact_export` calls will break — spec §4.2 guard, §6 X34; ledger §2
  `e2e/presentations-live.spec.ts:85,350`, `e2e/design-live.spec.ts` and `e2e/p1-live.spec.ts` drive `artifact_export` (PPTX and PDF through a hidden `BrowserWindow` in main, P3 §4.8). A real deck export over 1 s is likely (inference; no timing in the evidence tree), and the guard as written then fails those specs or forces one loose bound for the store tools too, which is "guards nothing" (§8). The heavy fixture is "published or edited once by the host's test writer", a path with no `mcp_message` frames, while the guard reads `tools/call` in to `control_response` out from the journal (`src/engine-host/journal.ts:2`): the fixture cannot be measured by the helper it is meant to ground. Fix: the guard names its tools (create, read, edit, publish, dataset, comments, reply, resolve, list, search), export and screenshot get a bound of their own or are excluded by name; the heavy fixture drives the tools over the wire (the scripted transport under `src/engine-host/conformance/`), not the test writer.

- [P2] T5 is MAWS's own invention against the owner's "adopt as is" and D-20, and was never put to the owner — spec §4.4, §2 item 3
  The owner's words (obs 5): "구글 슬라이드/캔바의 검증된 메커니즘을 그대로 Adopt하기". D-20: invent only what the notes ask for. The five questions put to the owner (`p4-design-notes.md` lines 32-34) asked only select-first versus caret-first. The draft binds "a double-click from any state edits the deepest text element or cell under the pointer, ignoring scope, with the word selected (T5; MAWS's own improvement, since no reference reaches grouped text in one gesture)"; Canva's double-click enters one level, and the draft's own §11 says no reference does this. A child meets §2 item 3 while the owner's intent (the proven mechanism, as is) is missed, and the one-gesture reach changes what a double-click on a group means for every grouped element. Fix: name T5 as a departure in the approval ask with Canva's level-entry as the default, or adopt level-entry and let the decks round decide.

- [P2] The launch profile's subtractive cases are not reachable additively, and dropping `user` from `--setting-sources` sheds the model and effort too — spec §4.2 profile, §2 item 9; ledger §8 X6
  §3 records that model and effort come from the owner's `~/.claude/settings.json` (Opus 5.5, `effortLevel: xhigh`) because MAWS passes neither; the engine's precedence is user < project < local < flag (`src/engine-host/session-start-hooks.ts:69`), so flag-level `enabledPlugins: false` per plugin and `outputStyle` ride `--settings`, but "hooks: none" has no per-source switch (only `disableAllHooks`), and the draft also names `--setting-sources` per session. A child that sheds the user scope to drop hooks silently changes the model, the effort, the permission settings and the gateway env, against Decision Log 8 ("no effort decision"). Nothing in §4.10 probes this. Fix: pin the mechanism (flag-level keys only; `disableAllHooks` for "none"; `--setting-sources` never loses `user`), add R-7 (a wire probe that the `init` record shows the same model, effort and the chosen plugins), and make that an A2 acceptance line.

- [P2] Wave 0 is infeasible under A-13, and the mini's one GUI is the hidden critical path — spec §7
  W1's four batches are in flight, which is the four-worker cap (P1 A-13, `2026-10-05-p1-extension.md:154`); wave 0 then names A1, A2's guard and document layer, B2's spike, LC-1 to LC-3 and B5 as dispatchable now. Separately, the bench's record run, the IME spike, every live check and every L round take the mini's GUI under the quiet flag (gate-offload Decision Log 78's procedure), during which no e2e gate runs for any worker; L is seven surfaces × two rounds × two or three assessors "using every corner", days of GUI time; the MacBook alternative takes the owner's own GUI. Fix: a slot order for wave 0 (which two start as W1 batches land) and a mini calendar rule (bench and L rounds in named windows between wave gates; cua-driven checks on the MacBook only with the owner's go).

- [P2] X36's placement seam crosses the portability boundary — ledger §4 row 3, spec §4.3
  The ledger places `placeCard(host, pinRect)` for the pin popover in `src/renderer/src/side/card/placement.ts` while the popover and `ThreadCard` live under `src/artifacts/` (`src/artifacts/slides/editor/comments/`), which the lint rule forbids from importing the renderer (`eslint.config.js:10-13`, P3 §4.10 binding). The geometry is already pure (`placement.ts:3`), so the fix is cheap: move the placement function under `src/artifacts/` (or hand it through `ArtifactHost`) and say so in X36 before B2 codes against it.

- [P2] X35 rule 1 ("changes no `layoutKey`") leaves B1's margin cards at stale anchors for the stream's duration — spec §4.2 rule 1, §4.3, §2 item 1
  Provisional text drawn at a block grows that block for seconds; the margin re-lays only on `layoutKey` (§4.3, by design for row 235), so every card below the target sits at the wrong y until the commit, then jumps, under the acceptance "typing above a passage moves its card the same frame". Both B1 and A2 are bound to these rules, so neither child can resolve it alone. Fix: state which it is: the layer renders out of flow (an overlay that reserves no height) or it triggers a rAF-coalesced relayout that B1's keystroke measurement includes.

- [P2] The live user test loop has no merge step, no host, and an account rule that stops short of the accounts the build reaches — spec §4.9, §6 X39, §8

(c) The build's sessions run on the owner's accounts through the gateway in auto mode (D-18, D-19) with a scratch config home, which has none of the owner's plugins, so the shell surface's launch-profile item cannot be assessed there. (d) A finding outside the round's surface (the transcript beside a document) has no routing. (e) The round's host is unnamed (see the mini finding). Fix: an architect triage per round (merge, dedup, pre-grade, a bounded owner sheet with the rest defaulting to rows); X39's outward-act rule extended to every account the build can reach (a Notion test page, a Drive test folder, break-it on MAWS only, no destructive acts in references); a cross-surface routing line; the host named per round.
