5. WORKTREES (C10 + C4 index)
Record (X1, src/shared/graph/session.ts:29-30): worktree: {path, branch|null} | null, and branch: string|null. There is NO
  managed/unmanaged flag on the record. "Managed" is derived elsewhere: path includes '/.claude/worktrees/' (R/sessions/ArchiveDialog.tsx:16),
  or WorktreeInfo.managed from git.
Membership (src/main/index/projects.ts:30-51): locate() matches /^(.+)\/\.claude\/worktrees\/([^/]+)/. For a match,
  projectDirectory is the main checkout and worktreePath is the worktree root; otherwise the directory IS the project directory and
  worktreePath is null.
  Discovery (sessions.ts:210-231): project_id = projectAt(location, create = hasMessages); worktree_path = location.worktreePath;
  worktree_branch = the transcript's gitBranch. This is rewritten on every summary.
  Launch (C10, src/main/sessions/setup.ts:151-178, 202-210): newWorktree and existingWorktree record {path, branch}; the project comes from
  resolveMembership(cwd) (sessions.ts:307; projects.ts:134-137), the same path rule.
  Consequence (by reading): managed worktree sessions land under their parent project with record.worktree set. A hand-made
  worktree elsewhere (a sibling dir, which the owner's /worktree skill makes) gets its own discovered project
  (projects.ts:140-145). A MAWS launch into such a checkout may start with worktree set, but discovery later overwrites
  worktree_path to null (sessions.ts:218). Unverified at runtime.
Project worktree list: git.worktree.list {repoRoot} → {repoRoot, commonDir, worktrees: WorktreeInfo[]}. Each WorktreeInfo is
  {repoRoot, path, branch|null (detached), head, isMain, locked, prunable, managed} (src/shared/ipc/schema/git.ts:106, 130;
  src/shared/sessions/worktree.ts:9-19). It is cacheable through useCommand (in QUERY_COMMANDS, R/ipc/query.ts:35). No store holds it; it is read on demand by
  the Worktrees… dialog (R/sessions/WorktreesDialog.tsx:29-37), the location chip (R/composer/frame/LocationChip.tsx:40) and
  useSetupIntent (R/sessions/useSetupIntent.ts:126). The dialog's row model already orders main first, then git order, and labels by
  basename(path) and branch or 'detached', listing sessions per checkout from main's occupancy (R/sessions/worktree-rows.ts:60-84).
Deriving "Main / Worktree 1 / Worktree 2" without new data:
  - Sessions by group: key = record.worktree?.path ?? MAIN within a project's records. This is pure, from the sessions store, for managed worktrees.
  - Labels: basename(worktree.path) (name) or worktree.branch (as worktree-rows.ts:73-74). A main-checkout session's branch is record.branch.
  - Empty worktrees and git order: one useCommand('git.worktree.list', {repoRoot: project.directory}). This is cheap under drill-in,
    since only the open project needs it.
  - Folding sibling (unmanaged) worktrees under their main project NEEDS a change: index membership by git commonDir
    (main-side, C4's locate/projectAt), or a renderer join that matches a project's directory against another project's
    git.worktree.list paths. The second option costs one git call per project, about 276 for the owner.
