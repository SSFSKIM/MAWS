1. MODEL AND EFFORT SELECTOR
Facts
- Component: epitaxy-cds-model-selector (W/c360a9e1c-CPGBhuJc.js:2) wraps the shared CDS selector (W/shared-9-CtVPc8gf.js:2,
  export S=Ny) with triggerVariant:"pill", config {shortcuts:true, thinkingStyle:"separate"}. Placement "composer" ->
  popup side:"top", align:"end"; placement "rail" -> side:"bottom", align:"start", popup width = anchor width.
- The model menu is a Menu.Root/Trigger/Popup layer anchored to the pill (sideOffset 4, collision padding), so it is not
  inside the editor DOM. Popup max-w-[min(26rem,var(--available-width))] (shared-9:2, ey).
- Trigger = ghost button labelled with the resolved model name. aria-label "Model: {name}". Tooltip and shortcut: "Open model
  menu" Cmd+Shift+I (W/shared-21-C9ZCBX9N.js:4). While loading: spinner + "Loading models…". "Default model" is only the
  EMPTY label, used when the catalog has 0 models (shared-9:2, Se=i??_e when B=models.length===0). The trigger never says "Default" for a real model.
- Menu rows (shared-9:2, ay): Item checkedRole radio, accent Check on the current model. Digits 1–9 shown as muted
  footnote trailing hints (data-number-key, aria-keyshortcuts). Each row carries its capability description, badges and a
  tooltip/disabled reason. Sections: "main" (headline models, top level), "overflow" under a "More models" submenu with
  "Search models"/"No matches", and "deprecated" (shown only if it is the current model) (shared-9:2, _y).
  CL 2.x: "three headline models at the top level, older models and context-size variants under More models, each model
  shows a capability description, unavailable models appear disabled". A supports_1m_context model gets a name suffix (gs.millionContextSuffix).
- Default pre-selection (c360a9e1c:2; W/cc43287c9-Dhm1ErF1.js): hostDefaultModel = settingsDefaultModel (Claude Code
  settings.json model) gets a neutral "Default" badge on its row; presetModelId gets a "Preset" badge.
  CL: "Your project's settings.json model is used by default for new sessions", "model-picker memory - the picker now
  remembers your last model choice", "reflect your organization's allowed default model".
- Effort is a SEPARATE trigger next to the model pill (thinkingStyle "separate" drops effort from the model label;
  data-cds="ModelSelectorEffort"), lazy chunk W/c8e04f916-Bey9kAvj.js:1 (EffortControl).
  - Trigger: ghost button showing the level name. aria "Effort: {name}". Shortcut "Open effort selector" Cmd+Shift+E.
  - Popover w-[220px], gap-lg. Header "Effort" (muted) + current level, with a "?" Help popover ("About effort", 220px).
    "Faster" … "Smarter" end labels above a stepped slider (min 0, max n-1, step 1, showStops).
  - Warning row for Max: "Claude thinks longer with Max effort and uses your limits faster than High." Badge "High usage".
  CL 1.10628: "Choose effort with a slider next to the model picker".
- Effort levels come from the catalog per model (thinking.effort_options), not a fixed list. Label set
  (W/c1c1ec7b9-DVuWiUSs.js): low "Low", medium "Medium", high "High", xhigh "Extra-high", max "Max"; "{effort} · Fast".
  An optional extra stop "Ultracode" (c360a9e1c:1) selects the highest effort plus dynamic workflows (CL).
- Mid-session change dialog: "Change effort?" / "This session is cached with effort set to {current}. Changing it to
  {next} means Claude re-reads the whole session on your next message, which uses more of your limit." (cc43287c9).
  Slash commands /model and /effort; fast mode toggle inside the picker.
MAWS should copy: a model pill anchored above-right of the composer in a portal menu (headline models + "More models"
submenu, a "Default" badge on the settings default, digit keys), plus a separate effort pill with a 220px stepped slider.
Labels come from the engine's catalog; the trigger always names the real model.

5. FINAL ANSWER VS THINKING VS TOOL GROUPS
Facts
- A turn is a flat item list (c1c1ec7b9:95): text, tool groups, thinking. Tool groups are one-line summaries
  ("ran …, edited …") with expandable ~40px rows (c1c1ec7b9:115). Text renders as prose at the same level.
- Thinking is hidden in the default "Normal" view. Transcript view menu offers Normal / Thinking / Verbose (CL 2.x
  default-view setting; Summary removed). In Thinking/Verbose, thinking appears as a "Thought process" step
  (c1c1ec7b9:83) or a left-rule block (border-l-2 border-alpha-2 pl-md, text-muted italic). In thinking view a one-line
  recap appears above each tool group (CL 1.2581).
- "Thought for {seconds}s" exists in Code only in the live turn-status line at the tail (TurnStatus, c1c1ec7b9:95).
  That line shows elapsed seconds, tokens and "# running tasks". While thinking it cycles "Thinking…" → "Still
  thinking…" → … It is NOT a collapsible transcript header. The chat/Cowork timeline has its own "Thought for" with
  "# steps / Hide steps" (W/shared-11-CETOUHfJ.js:37; W/shared-14-DNjmCwiw.js:7).
- The final answer is never inside a collapsible group. Only short narration followed by a tool call can fold into
  the neighbouring group (c1c1ec7b9:65). The closing text has no following tool, so it always renders as standalone prose after the last group.
MAWS should copy: tool runs as collapsible summary groups and the final answer as plain prose outside them. Thinking
stays hidden by default behind a Normal/Thinking/Verbose view switch. Elapsed "Thought for" lives in a live status line.

  tools and the default permission mode, persistSession false. The panel (W/cccc2cf0a-CVUXWHS7.js:5):
