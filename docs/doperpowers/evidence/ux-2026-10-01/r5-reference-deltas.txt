BOTTOM LINE
- No value MAWS adopted has been contradicted by anything that changed in the current builds. In Codex 26.928.40906 every
  measured number r1 gave is still in the code:
  - the 768px column with 16px inline padding, shared by transcript and composer, and the 896px breakout
  - 14px/1.625 prose, 12px code, 13px chrome, headings at 1.5/1.25/1.125/1
  - the user bubble: 70%, 22px radius, 10x16 padding, 5% tint, 20-line collapse, hover actions
  - the composer: 22px radius, 44px editor growing to 25dvh, same toolbar assembly
  - the 254px two-view model and effort menu, with "Default" as a list entry
  - the change receipt: 3 rows, "Show N more files", the 800ms hover diff up to 420px
  - 30px/13px sidebar rows, 5 projects and 5 threads, the same hover card
  - the question pager and its receipt, and the usage and status surfaces
  The installed 26.928.31416 agrees: its relevant chunks differ from 40906 only by import renames. The CHANGES file between
  the two touches only personalization and "dot" safety strings.
- Claude Desktop 2.16120.0 also keeps every value MAWS took:
  - the 768/960/1280 width setting
  - the 480px question card with its "{position} of {count}" pager, Skip, Next/Submit, and the "Not answered" receipt
  - the 240-512 x 384px slash popover
  - the permission labels and the refused-auto wording
  - the context ring popover
  - the /rewind picker
  - 30px sidebar rows
- What the owner will see differ, from upstream changes:
  1. Codex renamed Review to "Changes". The side-panel tab is "Changes" and the receipt's hover line and tooltip read "View
     changes". MAWS still says "Review changes" and calls its tool Review. [MAWS differs: wording only]
  2. Codex dropped the "Priority" sidebar sort. Last updated is the default, and a stored "priority" sort is migrated to it.
     MAWS's recency-sorted project list now matches.
  3. Claude Desktop removed the composer's 0.5rem overhang, so its composer is now exactly the column's width. That is MAWS's
     rule, so the two now agree.
  4. Claude Desktop's "Large" transcript text went from 16px to 15px with a 22px leading. MAWS does not copy that setting, so
     this has no effect.
- What re-checking found that is not drift: these mismatches existed against the old builds too.
  a. Composer shadow. In Codex the 40px-blur shadow r1 quoted applies only to windows under 40rem (640px). Every wider
     window gets "0 4px 80px 8px". MAWS's tokens.css:31 copied the 40px value. [MAWS differs]
  b. Question card. MAWS's single-select pick advances on its own. Claude Desktop never auto-advances (a click only selects;
     Next moves on), and r1 records that Codex enables Next only once the question is answered. This is MAWS's own rule.
  c. Model list. MAWS shows "Default" with a badge. Codex shows "Default" with the sub-text "Recommended set of models" and
     no badge.
  d. Refused-auto notice. MAWS says "Auto mode isn't available for this session. Using acceptEdits instead." Claude says
     "... Asking for permissions instead." or "Auto mode isn’t available for the selected model. Switched to {newMode}.",
     where {newMode} is a label such as "Accept edits". MAWS shows the mode id and a straight apostrophe.
- New and worth a probe: Claude Desktop renders engine-driven UI when the init frame advertises capabilities
  ["ui_surface_v1"] (Claude item 1 under NEW PATTERNS).
