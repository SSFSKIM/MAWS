# Whole-app review, 2026-10-02

Independent review of MAWS at master c6b07d9a, requested by the owner ("whole branch, whole app review" with astra-high reviewers). Method: the tree was split into five areas; for each, a scratch shared clone received a synthetic `base` commit holding the whole tree minus that area and a `review-head` commit holding the full tree, so the review-code panel (level `max`: finders and verifier on astra/high, the lens deriver skipped because the architect supplied the lenses) saw exactly one area as "the change" with the rest of the tree present for context and docs/charter.md named as the spec. Each panel ran one lens-free sweep, four or five lens reviewers and one binding verifier that re-inspected and in most cases independently reproduced every candidate. Raw results (the panel's `result` object) sit beside this file as `<area>.findings.json`. Only verifier-confirmed findings are listed; candidate counts per lane are in the coverage tables inside the JSON.

## Triage and rulings (architect)

- Partition into waves follows file ownership so workers run in parallel without touching the same files: F1 e2e harness (test-only code); F2 session, clear sequence, queue, ipc; F3 transport, process table, rpc, launcher; F4 normalizer fidelity (plus `shared/graph`); F5 the `fs/` readers; F6 transcript model; F7 transcript child sources; F8 tool surfaces (tools, terminal, request-card, panel); F9 git layer; F10 persisted stores and atomic writes; F11 composer drafts and submission (plus `sessions/setup-actions.ts`); F12 shell navigation, palette, keyboard and focus; F13 sessions (archive for project-less sessions, hidden-project reveal); F14 host loss and index; F15 setup intents, engine defaults, IPC router; F16 pty-host. Every fix carries a regression test built from the verifier's reproduction.
- Tech debt, not fixed now: renderer-only libraries in production dependencies (e2e-build scalpel-4#1): a packaging-size matter with no user-facing defect; needs a packaged build to verify.
- F2 item 1: Stop pauses or cancels a staged clear-and-implement sequence exactly as it pauses the queue; only Resume lets it continue (the worker records which of pause or cancel it chose and why).
- F5 item 1: one holder-backed ownership predicate in `holders.ts`, used by `service.ts` and `chain-follower.ts`. Pinned-engine records carry an entrypoint but no PID (fixture pass3/w7-collision-disk), so an `sdk-ts` record without a PID is own only when registry evidence maps that entrypoint and session uniquely to MAWS PIDs; with another SDK holder present, unknown-PID writes count as foreign; a record with a PID uses the exact predicate.
- F10 item 4: an Electron single-instance lock keyed by the already-set userData before any store opens; settings updates re-read and merge the disk state.
- F10 scope: the shared atomic-write helper also replaces the writers in `sessions/json-files.ts` and `attention/file-attention-store.ts`; F14 and F15 leave those two files alone.
- F13 (to dispatch): the tab strip's reveal action on a hidden project restores the project to the sidebar and reveals its row (tooltip "Show in sidebar"); the Other sessions group gets an "Archived sessions…" entry so a project-less archived session has an in-app recovery route.

- Live specs edited by F1 (c7-live, composer-live, code-tools-live) are verified by reading, typecheck and extracted unit tests only; there is no live engine in the workers' environment.
