## Decisions

- Follow the architect's received Decision Log 16 ruling: pass through `session.send`'s own `queued`, with `queueId` and no invented uuid. `sent`/`steered` carry the host's uuid; C12's already-existing released resume answers `started`. No IPC or queue ownership changes.
- Tolerate unknown keys only in the file reader: `StoredLaunchSpecSchema.strip()` and a stripping `StateFileSchema`. Keep shared `LaunchSpecSchema` strict for IPC and `saveLaunchSpec`; passthrough would cause an older build to write fields it does not understand.
- Preserve the standalone editor's explicit send/steer API with one extracted wire-dispatch primitive in the seam module. It makes no state decision. The composer's normal human path and all new outside-box callers use `sendHumanPrompt`; bash and memory modes remain in `editor/submit.ts`.
- The seam reads the mounted composer's event-fed queue; without an attached composer it subscribes before reading the existing `session.queue.list` snapshot. Detached cached queue state is not trusted. This preserves the between-write-and-turn busy predicate without requiring a mounted Composer.
- Delivered observation subscribes to the existing `session.eventBatch` before reading `session.events`, matching only the session's own `user.message` uuid. It returns the event and disposes its subscription on delivery, cancellation or read failure. The caller owns an optional AbortSignal; no arbitrary delivery deadline, new IPC or new persisted field.
- The generic Claude API skill's SDK guidance does not apply to this extraction: parent D-1 explicitly requires the unmodified pinned engine protocol. No SDK, engine or model change is made.

## Surprises

- The brief's assertion that both commands return `MessageUuidOutput` was not true: `session.steer` does, but `session.send` returns `{messageUuid: MessageUuid | null, disposition: 'sent' | 'queued', queueId}` (`src/shared/ipc/schema/session.ts:94-96`). A paused/non-empty idle queue has no uuid until submission. Reported to the architect; received Decision Log 16 adds `queued` and `queueId` to X22. The received parent pin remains `8814d733db1b3c50798b9d3ec766985b29e05420`. Correlating queued entries to later uuids is C/E1's work, not a new helper or host change here.
- G3 is deliberately limited to the two named object readers. Persisted queue/grant objects and nested strict launch objects (`resume`, `trust`, `retry`) still reject unknown keys. Extending those shapes would need the same read/write separation; unchanged here.
- The digest's `SessionDigestSchema` is strict (`src/shared/ipc/schema/session.ts:300`), but it is an IPC/read-model shape, not a host JSON file: `src/main/sessions/read-model.ts` folds it in memory, and `src/main/index/source.ts` seeds it from the index's transcript summary. No persisted digest-reader corruption path found.
- `profiles.json` is main-owned, not host-owned. `ImportedProfilesFileSchema` and `ImportedProfileSchema` are strict (`src/shared/browser/profiles.ts:26-51`); same-version unknown keys make `ImportedProfiles.open` move the file to `.broken-*` and start empty, which allows the boot sweep to remove unlisted partitions. A higher numeric version is already guarded: read-only, no rename/write/sweep (`src/main/browser/import/profiles.ts:38-53,112-124`). Do not add same-version fields without addressing the older reader; unchanged here.
- Deliverable records and their version rows are strict (`src/shared/maws/deliverable.ts:14-37`). A later unknown key makes host `FileDeliverableStore.get` answer null and shared `readRecords` omit the record; the file stays on disk (`src/engine-host/deliverables/store.ts`, `src/shared/maws/deliverable-files.ts`). Same forward-compatibility hazard, different recovery; unchanged here.
- The host's `models.json` cache also uses strict file/entry schemas (`src/engine-host/models-cache.ts:19-20,97-110`); unknown keys cause a warning and the built-in catalogue instead of the cached data, without moving the file. Unchanged here.
