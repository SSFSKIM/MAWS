## Decisions

1. 2026-10-09, `session.recentTurns` (confirmed by the architect, ledger §1 at 02510523): main-owned, `{appSessionId, limit 1..20}` → `{turns: {prompt: {text, at} | null, answer: {text, at} | null, toolCalls}[], earlier, source: 'transcript' | 'none'}`, oldest first; one read of the last 256 KiB of the engine's transcript at the index's `transcript_path` (else the path derived from the record), current chain only, classified by the host's pure `recordToEvents`; the same path for live, exited and terminal-only sessions; immediate (no host call); no launch, no `setVisible`, no unread or index change, no follow. Rejected: main's read model (digests, not events) and the host's `session.events` (a stream-less session starts a follow, a long-lived watcher per selection). The answer goes through master's owner-aware `previewLine` (`src/shared/owner/preview.ts`, E11 F2b 2.6), not a reimplementation of C's grammar (the architect's correction); C's module may replace it when C lands.
2. 2026-10-09, groups: Today, Yesterday, "Earlier this week", "Last week", then one group per local calendar week ("Week of Sep 14"; the year added outside the current one), weeks starting Monday. The brief's "Today, Yesterday, Earlier (then by week)" read as weekly groups after Yesterday. Claude Desktop 2.16120.0 groups the seven daily buckets by date and then by month (`c042dc97b-CRGVyvdk.js:3-91`); weeks are the brief's word. A row shows the clock time under Today and Yesterday, the weekday and clock under the rest of this week, the date under older weeks; the preview shows the relative age ("2 hours ago"); all from the one `lastActivity` time that orders the rows.
3. 2026-10-09, "archived and hidden sessions stay out unless asked": a fourth toggle, **Archived** (no chord: the CLI has no such toggle), brings in archived sessions and a hidden project's; such a row carries an "Archived" badge when archived.
4. 2026-10-09, scope: the project the chooser opened on, its main checkout (the CLI's default, kept); a session with no project opens on All projects (report F §4.2: "current project when context exists, All projects otherwise"), and All projects off then shows Other sessions. `/resume` leaves out the session it was typed in.
5. 2026-10-09, gestures: a click or the arrows select and preview, Enter or a double click opens in the current tab (`openSession`, F2b 2.5's replacement), ⌘Enter in a new tab (`openTab`); no separate Resume button (the old widget's C10 Resume): opening shows the transcript and the first Send continues the session once A lands. The list keeps the keyboard in the search field (a press on it does not take focus, Desktop's); a printable key typed elsewhere in the chooser goes to the search; an IME's composition keys are its own; Esc clears a non-empty search first (B's `data-escape-clears` rule), then closes.
6. 2026-10-09, the preview: the cached facts (title, folder, branch, project, last active, the digest's owner-aware last answer) at once; the recent turns (`PREVIEW_TURNS` 6) for the settled selection after 150 ms (Desktop settles 120 ms and a search's first row 300 ms), the opening selection at once; a stale answer dropped; 30 s cache (Desktop's `staleTime`); Desktop's copy for the states ("Loading preview…", "Couldn’t load the preview.", "No messages yet.", "Earlier messages not shown", "Nothing to preview."); the user prompt as a right-aligned bubble capped at 400 characters, the answer at 700, the tool calls as "N tool calls" (MAWS's divider wording). On a narrow window the preview stacks under the list rather than hiding (report F's "without squeezing both columns").
7. 2026-10-09, X19 on the branch: P2-B's hunks in `composer/WidgetDialog.tsx` and `composer/mentions/widgets.ts` taken byte for byte from B's head 439f8aae (the task review confirmed the blobs match); B's registration hunk in `widgets/index.ts` taken too, but its `LIBRARY` set holds only `'resume'` here, since shipping `'plugins'` would put today's 560 px PluginsWidget into the fixed 960 px box before B lands; the second of B and D to land unions that one line. `WidgetFrame`'s library hunk is not taken: the chooser draws its own head so both hosts look the same (the sidebar's has no session for `WidgetFrame`'s focus return).
8. 2026-10-09, the keyboard legend is a `div` (`data-legend`), not a `footer`: F2a 2.2's rule (no provenance foot; `widgets/index.test.tsx` and `e2e/widgets.spec.ts` assert no `footer`) is about provenance, and the legend is Desktop's keyboard help, which report F asks for in place of the old wire/C10 text.
