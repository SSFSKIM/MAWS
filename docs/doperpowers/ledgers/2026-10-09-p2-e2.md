## Decisions

1. **The dock's host is found by a per-tab registry, not by `placedIn.paneId`.** `tools/browser/comment/dock.ts`: the placed pane registers its card host (`useId`) for its tab while its placement mode is `owner`; the connect reads `dockOf(tabId)` at the pick. Rationale: the pick goes to the window whose pane holds the view (E4d Design §8), and only that pane registers; the Placement's `paneId` is minted inside the pane's effect (a fresh one per StrictMode replay), so hoisting it to name the host would change E4a's token lifecycle for no gain. The host stays mounted while the pane is `claiming` (a collapsed panel, a hidden main tab), so a draft survives a collapse; it unmounts when another pane takes the view (`elsewhere`), which closes the card by E1's host-unmount rule.
2. **`layout: 'docked'` is an in-flow strip (amends X21's "docked layout"; architect accepted 17:05).** E1 built docked as the overlay's bottom edge (`absolute`), which over a native view is hidden under the page. Docked now renders the host in flow as the last child of the pane's column (`[data-card-dock]`), measuring its parent column (the room it may take), and the card `relative` with an 8 px margin in a new style mode `strip` (`stripCard`: the column's width less 16 px, height at most half the column less 16, never over 320). The strip grows with the card, the page element (`[data-browser-pane]`, what the placement measures) shrinks by as much, and the native view's DOM-measured bounds follow it through E4a's ResizeObserver: no cover, nothing over the view. Half the column, so the page always keeps the other half and never falls under 1 px (which would release the view and leave the page hidden while the card is open). The anchored layout and its small-host fallback (`dockCard`, mode `docked`, absolute) are unchanged and E1's tests stay green.
3. **`CardTarget` gains `{kind: 'browser', pageUrl}`** (from a `browser-element` anchor's `pageUrl`); the browser host's `accepts` matches its tab's URL. ThreadView's "Show in deliverable" and the card's artifact-row action narrow to `kind: 'deliverable'`. No browser re-dock ("Show in browser") is built: proposed as a tracker row for P2-F (architect's ruling 3).
4. **The pick hands the window's own page the native focus** (`sendPicked` → `owner.webContents.focus()`). The click that picked leaves the native focus in the tab's page; the sheet's cover used to move it (`view.ts` `cover`), the card raises none, so the card's field would show focus while keystrokes went to the page. `owner` is `entry.placement.window`, the window holding the pane that placed the view, the same one the pick is sent to, so a pick never focuses another MAWS window (architect's ruling 4).
5. **A card's missing crop is a chrome line** (`commentCropTooLarge`, `commentCropFailed` notice kinds, E4d's own rule: with nothing over the page, words go in the tab's chrome, since a toast over a panel page would raise the cover); the sheet path keeps its toasts.
6. **Where the sheet stays.** A browser comment opens the sheet only when no pane of the receiving window holds the tab's view at the pick (`dockOf` null): main sends a pick only to the window whose pane placed the view, and that pane registers while `owner`, so the case needs the pane to stop owning between main's send and the renderer's receipt (a "Show here" in another window in the same instant). No product path reaches it in ordinary use; the sheet is the safe fallback rather than a card nobody draws. The code gutter, PR lines and the deliverable viewer's own placements are unchanged.

## Surprises

- E1's docked layout (`absolute`, the overlay's bottom edge) could not have served the browser pane: anything the renderer draws where the native view lies is under the page. The docked layout had to become an in-flow strip (Decision 2), which was E1's own design wording ("the card in flow at the host's bottom edge") rather than its build.
- The sheet's cover was also what moved the native focus out of the page after a pick (`view.ts` `cover`); with no cover the card's field showed focus while keystrokes went to the page, so the pick now focuses the window's own page in main (Decision 4).
- The browser pane's Placement mints its pane token inside its effect (a new one per StrictMode replay), so the card's host could not be named from `placedIn.paneId` without changing E4a's token lifecycle; a per-tab dock registry was simpler (Decision 1), and its first shape (one entry per tab) lost the surviving owner when a second pane claimed and left before its echo (task review round 1).
