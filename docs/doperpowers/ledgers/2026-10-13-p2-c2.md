## Surprises

1. The per-launch source's CHECK constraint (migration 8) made the brief's "the index gains a value" an X15 slot, which the brief had not allocated. It was raised as `[parent-impact]` before any code was written against it, and ruled.

2. **An async ask raises no attention item.** P1's E1 decided that an `mcp__maws__ask` with `blocking: false` raises no attention item (`e2e/maws-tools.spec.ts`, "no attention item for an async ask"), and the notifier notifies only actionable kinds. Under contract 5 (and under the owner's contract-4 style with the supplement) every question that can wait is such an ask, so P2-C's G6 for questions that wait (an `async_input` item, a notification, Needs you, the sidebar glyph) no longer fires on MAWS's own sessions; a blocking ask still raises a `question` item. Reported to the architect at checkpoint 2 as `[parent-impact]`; not changed here.

3. **The maws tool server does not tell a subagent's ask from the main conversation's.** It sees only the call's `claudecode/toolUseId` (`src/engine-host/tool-server/server.ts:25`); an ask's item carries `agentId: null` (`asks.ts`). A blocking ask from a subagent still returns its answer to that subagent's call, but an async one's answer goes as a `next` steer into the main conversation, which never asked it, and the subagent never hears it. A tracker row for the hand-back; not fixed here.
