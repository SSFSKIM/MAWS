## Decisions

1. **2026-10-14, `preview`.** `AskOptionSchema.preview?: string`, 1 to `ASK_PREVIEW_MAX` = 8000 characters of markdown: a 100-line snippet or a 40-line mockup fits, and 12 options stay far below the line cap. On a question with `multi: true` it is **refused**, not ignored: the issue is `questions.N.options.M.preview: preview is for single-select questions only`. An ignored preview would let the model believe the human had compared mockups they never saw, and refusing is how every other misplaced field is treated (`MODALITY_FIELDS`). The rule is in the field's zod `.describe()`, the one description in the input schema, because it is the one rule the model cannot read off a type.
2. **2026-10-14, `note`.** `AskAnswerSchema.note?: string`, 1 to `ASK_NOTE_MAX` = 2000 characters (as long as a question may be). It is allowed on every status, and `askAnswersProblem` never counts it as a value. It reaches the model in the blocking tool result as the AskResult's JSON does. In the async steer it is an indented `   note: "<JSON string>"` line under its answer (the indent a path uses) and also sits in the fenced block, so `parseAskSteer` reads it back. Neither field is named in `tools.ts`'s description or in `contract.ts`: the schema shows both, and the answer JSON names `note` itself.
3. **2026-10-14, a subagent's ask (Decision Log 35).** The routing rule: a `maws` call is a subagent's when its `claudecode/toolUseId` names a `mcp__maws__*` tool use the normaliser saw in an assistant frame whose `parent_tool_use_id` is set (`NormalizerState.subagentMawsUses`, `Normalizer.fromSubagent`). The host journals and normalises every row before acting on it (`session.ts` `processItem`: `record` then `client.observe`), so the live tool server reads the same state a rebuild would. The server passes it to each tool as `McpToolContext.fromSubagent` (deps `MawsToolServerDeps.fromSubagent`, `SessionMawsHost.fromSubagent`). `askTool` holds `(blocking ?? true) || fromSubagent` as the ask's `blocking`. Everything downstream follows from that one bit: no acknowledgement, the `question` item, the answer in the call's own result (`delivery: 'result'`), no steer, the sheet's "waiting" note. `maws.ask.opened.blocking` carries the same effective value (normaliser-controls). A call no frame named stays as before, so a future engine that reorders degrades to today's behaviour, never to a main ask held as a subagent's. The set is never pruned (a handful per launch).

4. **2026-10-14, the sheet (the worker's choices, kept).**
   - **Previews.** `@container` sits on the question's control, and at `@lg` (32rem, so a panel of about 550 px or more) the options and the pane sit side by side in columns `minmax(0,2fr) minmax(0,3fr)`. The default 380 px panel stacks them.
   - The pane renders the transcript's lazy `Markdown`, static, inside an absolutely positioned scroller. Its height never follows its content: `h-56` when stacked, the options' height (at least `min-h-56`) when side by side.
   - "Focused" is the last option focused or clicked. Before any, it is the selected option, else the first with a preview. Other moves nothing.
   - The pane is a `role="region"` labelled "Preview of <label>", carrying `data-ask-preview` and `data-preview-of`.
   - **Notes.** "Add note" is a quiet button at the left of the Decide for me / Skip row and opens a 2-row textarea (`maxLength` ASK_NOTE_MAX, labelled "Note on <question>", focused on open). Neither toggle touches it.
   - A note emptied and then blurred closes back to the button. `toAnswer` sends the note trimmed, only when something is written. `AnsweredSection` shows it under the answer (`data-ask-note`).
5. **2026-10-14, the e2e fixtures.** The two cases replay the recorded blocking and async ask fixtures, with the ask's arguments rewritten at test time (`askFixture`, `e2e/support/maws-tools.ts`). The rewrite touches exactly the `tools/call`, the `can_use_tool` and the assistant `tool_use`, each asserted to occur once. This is sound because the replay matches MAWS's writes by kind only. The recorded tool result and `input_json_delta` fragments stay the recording's, and no case reads them.
