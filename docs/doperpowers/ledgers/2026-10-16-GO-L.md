## Decisions

1. **Item 1, the transaction.** `node:sqlite`'s `DatabaseSync` has no transaction helper (its prototype: `open close prepare exec function location aggregate createSession applyChangeset enableLoadExtension loadExtension`), and the fixture is a raw Chrome History file, not the index; so the fixture writes `BEGIN IMMEDIATE` … `COMMIT` through `exec`, the form the index's `Db.transaction` and `openDb`'s migrations use on the same driver.
2. **Item 2, the ceiling and the test timeout.** A 10 s ceiling inside the node project's 5 s test timeout would never be the bound that fires, so the budget describe takes `{ timeout: 30_000 }` (the timing projects' value, a pattern several suites use per describe): each `io` wait is bounded at 10 s of real time, and a dead write fails at `io`'s assertion with the case's own message. The clock is `process.hrtime.bigint` captured at module load, so neither the cases' explicit fake set nor vitest's default one (Surprises 1) can freeze it. The two cases still take 6 to 20 ms.
3. **Item 3, where the clock lives.** On `HistoryApi` (optional `now?()`), not a new `DocumentEditor` prop: the rail names days against the clock of the history that stamped the versions, `MemoryHistory` already held that clock as an option (the case already passed `{ now: () => at.value }`), and the renderer's IPC implementation (`src/renderer/src/tools/document/history-api.ts`) omits it and keeps the wall clock. The rail reads it through its controller (`HistoryController.now`), so `HistoryRail`'s memo keeps a stable dependency (`controller`) instead of a function rebound every render. Additive and optional, so no wire or IPC name changes; the case's one line becomes a fixed local noon, which keeps a minute, a day and three days earlier on their own calendar days in any zone, an hour's DST shift included.
4. **Item 4, the comments.** vitest.config.ts keeps one line saying where the compile-time suites are checked now, so the block is not re-added. tsconfig.node.json's C8a comment said the include entries exist because "vitest's typecheck runs this project composite"; the project itself is composite (tsconfig.base.json), so `tsc -p` refuses an unlisted file too and the entries stay needed; the comment now says that.
5. **Item 6, the e2e lane under `pool`.** `GATE_RUNNER` is still the e2e lane's last fallback, except when it is `pool`, which leaves e2e on Linux (Decision Log 35: no Linux e2e on the pool until the seccomp profile). The `Class1a:` trailer moves class 1a alone: it neither moves the e2e lane nor adds `unit:darwin` and the e2e groups to the default set, which stay the e2e lane's doing. `pool=true` only when static, unit or probes is in the set, so an e2e-only run never makes a box. `Runner: pool` is refused with a pointer to `Class1a: pool`.
6. **Item 6, corepack's form.** CI-opt's tested form from the sandbox's maws-probe.yml, not a bare `corepack enable`: the shims go to `$RUNNER_TEMP/bin` (added to `GITHUB_PATH`), not beside Node in the box's shared tool cache, `COREPACK_ENABLE_DOWNLOAD_PROMPT=0` for the job, and `pnpm --version` once so a broken shim fails the setup step. It runs after `setup-node` (a pool container has no `node` before it). `setup-node`'s automatic `package-manager-cache` is npm-only, so `cache: ''` is all the pool needs there.
7. **Item 6, the plan job.** Its `runs-on` expression is unchanged (the `&runner` anchor dropped, nothing repeats it now). The ensure step follows the plan step and runs only on `steps.plan.outputs.pool == 'true'`; `pool` is a step output, not a job output, since nothing downstream reads it.

## Surprises

1. **vitest 5.0.2's default fake set fakes `process.hrtime`.** The brief's premise was that it leaves `hrtime` real. In the installed vitest, `useFakeTimers()` without `toFake` fakes every timer fake-timers knows except `nextTick` and `queueMicrotask` (`index.DGdajAO2.js` ~6830), and that list includes `hrtime` and `performance`. A scratch case confirmed it: under `vi.useFakeTimers()` `process.hrtime.bigint()` advanced 0 ns across a busy loop of half a second, while a reference taken at module load advanced 505 ms; under the export cases' explicit `toFake: ['setTimeout', 'clearTimeout', 'Date']` it is real. Hence the captured reference (Decisions 2).
2. The P5 heap-limit comment on `NODE_OPTIONS` in gate.yml named the vitest pass; it now says the pass is gone, and the 5,120 MB limit stays for tsc over the web project.
