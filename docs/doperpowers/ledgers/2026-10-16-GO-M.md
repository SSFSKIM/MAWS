## Decisions

1. **Item 1, the seam.** Decision Log 35 names it the `MAWS_E2E_PREBUILT` seam; it is `scripts/e2e-build.sh harness|plain`, driven by `MAWS_E2E_BUILD_CACHE` and `MAWS_E2E_BUILD_KEY` as the brief specifies, and no variable of the name `MAWS_E2E_PREBUILT` exists. A "skip the build, out/ is ready" switch would let a group run over the other variant's out/, and the harness groups skip their cases on a plain out/ (`HARNESS_BUILT`), which is a false green; the cache keys the variant, so it cannot.
2. **Item 1, `plain` is named.** The plain variant builds with `MAWS_HARNESS=0` rather than whatever the caller's environment holds, so a stored plain build is always plain; `electron.vite.config.ts` reads only `MAWS_HARNESS === '1'`, so `0` and unset build the same bundle. The one behaviour change without the cache: a developer who exports `MAWS_HARNESS=1` and runs a plain group (`e2e:library`, `e2e:c12`, …) now gets the plain build the group's script names, where the inline build silently made the harness one.
3. **Item 1, the key is the checked-out commit (`$GITHUB_SHA`).** The brief says "the commit under test"; the bundle's build stamp (`__MAWS_BUILD__.commit`, E11 §2.7) is `git rev-parse --short=8 HEAD`, and in a gate job HEAD is `ci-gate.sh`'s nonce commit on top of the tested sha, so keying on the tested sha would let one run restore a bundle stamped with another run's nonce. Keyed on `$GITHUB_SHA`, a restored out/ is byte-for-byte the build an inline `electron-vite build` made in the same run for the same variant; two fresh builds of one commit and variant differ only in the stamp's `builtAt` (the time the config was evaluated), so the restored bundle reports the first job's build time. Reruns of one run (`gh run rerun`) share the key; two `ci-gate.sh` runs of one tree do not.
4. **Item 1, integrity and pruning.** The store copies out/ into a staging directory beside the entry and renames it into place, with the sha256 digest of the built out/ (every file's hash, sorted by path); a restore recomputes it and, on a mismatch, discards the entry and builds. The newest four keys (by the key directory's mtime, touched on each restore) are kept. The cache lives at `~/Library/Caches/maws-e2e-build` on the runner, outside the work directory the checkout cleans, and only the e2e job's macOS step sets the variables.
5. **Item 1, what is not cached.** `e2e:default`'s `pnpm build` step (the bare set, `electron-vite build` plus desk-hub's, run verbatim as `verify` orders it, Decision Log 5) and `build:app` in the packaged job build as before; one plain build per gate remains when `default` is in the set.
6. **Item 3, voice's packaged case.** The case is selected by `MAWS_E2E_EXECUTABLE` (`e2e/voice.spec.ts:24`: under it the scripted cases' fixtures skip and the `packagedVoice` fixture runs). `pnpm e2e:voice` with that variable would still build the harness out/ first (40 s the packaged app never reads), so a new script `e2e:voice:packaged` runs the file against the packaged executable as `e2e:packaged` and `e2e:supervisor:packaged` do, with `--grep packaged:` so only that case runs, keeping the package scripts the one definition of what the workflow runs (§2). `verify` is unchanged; it never ran this case, since `pnpm e2e:voice` there has no executable.
7. **Item 3, the job's shape.** On `[self-hosted, macOS, ARM64]` whatever the e2e lane (as `unit:darwin`), only by `Gates: packaged`. The tools check asks `xcode-select -p` before `xcrun swiftc --version`, because without a developer directory `/usr/bin/xcrun`'s shim offers to install the tools in a dialog on the runner's desktop, which would then hold the runner's pre-job check; the job fails with an `::error::` line and installs nothing. `pnpm build:app` runs with `MAWS_SIGN_IDENTITY` empty (the script's unsigned branch), then `verify:fuses`, `e2e:packaged`, `e2e:supervisor:packaged` and `e2e:voice:packaged`, each run when the build succeeded whatever the check before it did, each with its own HTML report directory (`PLAYWRIGHT_HTML_OUTPUT_DIR`), since one Playwright run otherwise replaces the last one's report; the artifact `e2e-packaged` carries them on failure. Same env as the e2e jobs (`MAWS_E2E_QUIET=1`, `SHELL=/bin/zsh`).
