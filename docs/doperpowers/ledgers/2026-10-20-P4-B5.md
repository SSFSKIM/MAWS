## Decisions

- **The send is its own route D operation.** `connectors.directSend` has no grant, and the store's new delivery fence breaks only on the artifact's deletion. Re-using a page's grant was rejected: a pending one-time grant for `notion-create-pages` on an HTML artifact would let that page call the tool itself.
- **The final-write rule is kept at admission:** not cancelled, within the deadline, the artifact not deleted, the source still verified, the credential epoch not withdrawn, main still attached. After the write, the answer is kept as the receipt even if one of those then changes. Withholding it would hide a page that exists and invite a duplicate send.
- **The owner cannot cancel once the request may have gone out.** Closing the sheet then doesn't stop the send; its receipt, or a warning toast, still arrives.
- **Notion is found through a new `connectors.observe`** (one live session's mcp_status read, route E's) **plus `connectors.directLocate`.** A source qualifies when a report lists `notion-create-pages`, or when it is HTTP with its verified host at mcp.notion.com. Route D's cache only fills when something reads mcp_status, and a Notion server that needs sign-in reports no tools. Sources are ranked by connection state; an HTTP source with no sign-in saved is tried open first, never pushed into OAuth unprompted (the owner sheet's rule).
- **Readable pages need a dialect.** A new serializer writes Notion's enhanced Markdown from the document's own structure: tab indentation, XML tables, one-line quotes, callouts. It is wired in as X31's internal `dialect: 'notion'`, always written to its own file, and it never changes the agent tool's format list.
- **gws runs under the login shell's environment** that main already captures. MAWS opens the URL gws prints; gws doesn't open the browser itself. The upload runs from the export's own directory, because gws refuses paths outside its working directory.
- **An upload happens only from gws's own ready sign-in**, with two guards:
  - GOOGLE_APPLICATION_CREDENTIALS is pointed at a path that doesn't exist, so gws can't fall through to gcloud's application-default credentials (on this MacBook, the cli-owner service account, whose Drive the owner can't see).
  - GOOGLE_WORKSPACE_CLI_CREDENTIALS_FILE is removed from every gws run, because it outranks the sign-in and `auth status` never names its identity.
  - Neither guard puts a credential anywhere.
- **First sign-in requests Drive only** (`-s drive`). A sign-in that lacks Drive keeps its scopes and adds Drive.
- **gws setup and install run in a pinned Terminal tab** (the pattern Settings uses for engine update): `gws auth setup --login` needs gcloud and its own TUI wizard.
- **The session-route Send to was retired**, library included. Row 294 closes only when "the editor header and the library send straight", and keeping two Send paths would contradict the owner's ask.
- **Receipts live in main's memory only.** A durable record would need an index migration slot.
- 2026-10-20 (the architect, at the landing): the session route's retirement stands, and the final-write reading is confirmed (P4 Decision Log 42; P3 Decision Log 113).

## Surprises

- A refused consent never ends gws 0.22.5's login: yup-oauth2's listener answers the `?error=access_denied` callback with 400 "No `code` in URL" and keeps waiting. The owner's Cancel or the 5-minute deadline ends it.
- The two gws fall-throughs above (application-default credentials, and the credentials-file variable) are both invisible to `auth status`.
- The IPC command registry is at TypeScript's union limit in the e2e typed `invoke` helpers. Adding the `delivery.*` commands raised TS2590 in 8 e2e files. I changed their `page.evaluate` argument to an untyped one, a type-only change in shared e2e support (connector-scene, c7-replay, library-session, sessions, side, engine-replay, sessions-available, terminal-take-over), and made the delivery schema outputs single objects instead of unions.
- The Notion serializer's subagent read Notion's enhanced-Markdown spec through this session's Notion connector (a read). It also tried to create one private draft probe page there; auto mode denied it and nothing was sent. No other agent touched the owner's Notion, Drive or gws state.
