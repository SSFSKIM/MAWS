> **Where things stand.** A message the model sends the owner mid-turn goes through a message tool, because text written before a tool call comes back as an untagged thinking block. In a MAWS session that tool is MAWS's own, `mcp__maws__message`. The owner's output style, the doperpowers to-human plugin's, names `mcp__to-human__message`. While a session's to-human lane is on, the launch advertises MAWS_NATIVE_TO_HUMAN, and the plugin then does not register its tool. But an appended prompt can be missing or stale: a resumed session keeps the prompt it recorded until the launch decision turns the snapshot off, and a snapshot defers a new append to the next compaction.

## Decisions

- The command hook in `--settings`, not a host callback: only it reaches every start.
- Exec form (`args`) running `/usr/bin/printf`, so no shell and none of the owner's shell configuration runs.
- The group merges with any caller hooks, never doubles on a retried spec, and leaves with the lane.
- 2026-10-21 (the architect, at the landing): the P2's disposition accepted as a tracker row open to the owner's ruling (P4 Decision Log 50).

- The worktree-isolation guard refuses `cd /tmp && …` in a worktree agent (MAWS #92).
