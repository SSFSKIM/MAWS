## Decisions

- No sign-in from MAWS: the probe showed the login reused by name and URL.
- The engine's precedence stands: no `--strict-mcp-config`, and a `--mcp-config` entry shadows a same-named one.
- Every entry is validated before a launch passes it, since an invalid `--mcp-config` makes the engine exit; names the engine reserves or drops are refused.
- The trust bootstrap passes no servers: it serves no turn.

## Surprises

- MAWS's sessions resolve engine 2.1.306 (the realpath of `~/.local/bin/claude`), not the tested 2.1.296, since the owner's Settings name no binary.
- A `--mcp-config` server reads scope `dynamic`, so route D's attestation, which reads user and local scope, does not see it.
- The owner's plugins' SessionStart hooks ran during the probe's launch, as in any MAWS session.
