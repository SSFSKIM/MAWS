## Briefs (verbatim)

### UX2-L

> You are UX2-L, the layout shell, in MAWS's UX2 wave.
>
> **Your surface:** the window's chrome and header, the tab strip, the side panel and its surfaces, the main area's right side, document and deck tabs' toolbars, and the sidebar's footer. Build the layout the mockups show and the owner approved: D1, D2, D3, D4, D9, the proposal P1 and the "Settled by the owner" bullets about the layout, which include Claude Desktop's stacking for surfaces (a plain click on a second icon stacks it below the first, two at most; clicking an open icon closes it; tabs only within one tool), one chrome row, the narrow-window rule (700 to 1100 px the sidebar steps aside while a surface is open, below 700 a surface is a sheet), widths by content (Review, Files and Browser wide; Side chat, Background work, Subagents, Session info and the terminal narrow), the overflow menu and pinning, the cards (Environment, Context, Connectors, and Artifacts as the project-scoped Library with a project switcher, replacing the overview's Artifacts section and the panel's Artifacts tool), a document's own tools in its toolbar as floating cards with Fit measured on the width they leave, and the usage pill in the sidebar footer with its unit. Lens 7's findings (l7-shell-01 to -13) are the shell's evidence; say which of them your work closes.
>
> The other batch, UX2-K, owns the sidebar's top (its destinations), the Projects page and a new Customize tab. The sidebar rows, Needs you and the project filter are UX1's and stay as they are; your work changes the space around them, not them.
>
> This is the largest change to MAWS's shell since it was built, and other work will land on it. Keep the existing layout store's persistence and per-project tab sets working across the change (a person's saved layout upgrades, it does not reset), keep keyboard access to every surface, and keep MAWS's surfaces that have no Claude Desktop counterpart reachable.
>
> MAWS is a macOS Electron workstation that supervises Claude Code sessions, with artifacts (documents, decks, design systems, dashboards) beside them. The root spec is `docs/charter.md`; P4's composite spec is `docs/doperpowers/plans/2026-10-19-p4-smoothing.md` (the child P4-W, wave UX2; Decision Log 77), parent pin blob 58f6a17ef5b3c2a9db95e2265d4d32ba796f7400 at master 12238b23b. UX1, the wave before yours, just landed (Decision Log 76; its ledger `docs/doperpowers/ledgers/2026-10-23-P4-UX1.md`): the sidebar's rows, Needs you, the project filter, notifications, search and the transcript are new on master, so build on them rather than around them.
>
> **What UX2 is.** The owner is redesigning MAWS's layout after Claude Desktop's, for one reason in their words: the main area is the main thing, the UI should be clean and economical, and nothing should take space it does not earn. Their running direction is `docs/doperpowers/evidence/p4/ux-wave/ux-directions.md`: directions D1 to D9, the open questions and proposals, and the bullets headed "Settled by the owner", which are their rulings and are binding. The approved design is the mockup round in `/Users/new/Developer/MAWS-notes/ux-comparison-2026-10-23/layout-mockups/` (serve the folder with `python3 -m http.server` and open index.html; each screen has notes with the directions it answers, where it differs from Claude Desktop and why, and its measured sizes; the Overview screen holds every size and breakpoint with its source). The owner approved it with the answers recorded in the directions file; where a mockup shows an option the owner did not choose, the recorded answer wins. The owner's screenshots of Claude Desktop are in `MAWS-notes/ux-comparison-2026-10-23/owner-notes/`; the comparison's findings, per lens, are in `MAWS-notes/ux-comparison-2026-10-23/<lens>/findings.json` with screenshots, and lens 7 (l7-shell) is the shell's. Claude Desktop is evidence of what works, not a spec to copy: read its source for how it does a thing (`research/SOURCES.md` says where the tree is and how to cite it), then build what fits MAWS.
>
> **How the work goes.** Read the directions, the mockups and the code you will change before changing it. This is design-heavy work on a large surface: plan your own milestones and use subagent workers for bounded pieces if that serves you; one accountable branch. Test-first where the change has testable logic; a test that only restates the edit does not count. Where the mockups and rulings leave a detail open after you have read the code, choose what best serves the owner's taste and say what you chose in the hand-back; a choice the owner would notice in a way neither covers goes to the hand-back as a question instead of being built. Light theme first; components use tokens only.
>
> **Rules.**
> - `~/.claude` is read-only. Never write the owner's settings, never patch the engine, never touch the owner's running MAWS, its dist or its user data. No GUI automation: the architect runs a hands-on acceptance after the wave lands. To look at your work, render it headless (the repo's e2e harness screenshots, or a browser on a built renderer), never by driving the screen.
> - Start your branch off origin/master in your worktree and push it to origin. A fresh worktree has no node_modules: run `pnpm install --frozen-lockfile --prefer-offline` first.
> - Don't edit `docs/tech-debt-tracker.md`, the charter, the specs, the ledgers or the UX-wave evidence; the architect records your work from the hand-back. A change that needs a design or spec decision beyond the rulings goes to the hand-back as `[parent-impact]`.
> - Local heavy runs: one focused test file at most, through `/tmp/maws-review/with-slot.sh`; typecheck, lint, multi-file and full suites go to the pool. No e2e on the MacBook.
> - Gates run on GitHub Actions through `scripts/ci-gate.sh <worktree>`, which refuses a call naming no gates: class 1a is `--gates static,unit,probes --class1a pool`; Mac groups by name with `--runner macos --class1a pool`. Gate-offload §3.5 says how to read a red job. `e2e/layout-transfer.spec.ts:462` is red on master (run 40070801732); if your layout work makes it pass or changes its geometry, say so, otherwise it is not yours.
> - One other UX2 batch lands beside you on its own surface (named in your brief). If you must touch a file outside your surface, keep the change minimal and name it in the hand-back.
> - Review with a doperpowers:reviewer-medium agent over your range. Fix what is real and material; a real but tiny finding becomes a proposed residue row; a finding against design intent is dismissed with the reason. Stop when a round produces only those.
> - Commits end with the line `Sminos-Session: GUI AI agent workspace charter#37052769 (MAWS on macbook)` as a second -m paragraph.
>
> **Hand back:** the branch and its head; what you built against each direction and ruling, with commits; headless screenshots of the main states at 1280x820 and 1512x982 and of the narrow rules (paths); the choices you made where the design left detail open; questions for the owner; gate run ids and results; review findings and dispositions; proposed residue rows (Logged, Owner, Item, Evidence, Closes when; no '|' inside a cell); any `[parent-impact]`.

## Decisions

- Only Review, Files and Browser open wide; Artifacts was wrongly in the wide set and opens narrow. 420 px is the automatic narrow width, a stable value, so Expand cannot shrink the document; user widths persist.
- Arrange is always a menu, as the mockup has it; its front and back chords are not advertised, because the owner's tab chords take option-command brackets.
- Show in panel from the Library goes to the most recently active chat of the artifact's project and activates it; with none it refuses with a reason; unknown metadata shows Loading.
- A shared submenu guard on all nine SubTriggers keeps a submenu open while the pointer travels into it, wherever it flips; tests keep their single-jump pointer paths.
- The layout-transfer assertion becomes accounting plus expanded at least alone; the old strict bound moves to the debt row on Expand's gain.
- The browser-comment tests close a real completion toast before checking the page; the cover rule is unchanged.
- An integration's Mac groups are the whole matrix whenever shell, layout or sidebar code changes (P4 Decision Log 78).
