## Decisions

1. **The harness override goes; the setting decides.** `hostModeFromEnv` no longer maps MAWS_E2E or MAWS_HARNESS to `utility`: a test or harness launch takes `supervisor.shape` as the owner's app does (the daemon shape by default and by migration, a private `mawsd` on the scratch profile), and MAWS_HOST_MODE still wins. Rejected: MAWS_E2E forcing `daemon` (it would ignore a profile whose setting says embedded, so the shape switch could not be tested, and differ from the owner's app); every group run twice, once per shape (the design inheritance's rejection: about double the Mac minutes).
2. **A launch's cleanup ends every process naming its profile, a given profile's too.** After the app closes, `endProfileProcesses` kills what names `<profile>/` or works in it (killScratchProcesses: `mawsd`, its engine host and pty host, their engines), waits for the pty host's shells as for the app's, removes the daemon shape's socket fallbacks outside the profile, and a survivor fails the launch. Rejected: leaving a given profile's daemon to its caller. About forty specs relaunch over a given profile after a cleanup, written for utility hosts that ended with the app; they would reattach to the previous launch's `mawsd` carrying that launch's environment seams, and each would need its own sweep. A relaunch after `app.close()` alone (panel, shell) still reattaches, as the owner's app does.
3. **The separator in the match.** `<profile>/`, never the bare path, so one profile never ends another whose path it prefixes (`ud` and `ud2`; a unit test). Rejected: the bare path, as the supervisor suites' scratch roots use it (theirs are realpath'd mkdtemp roots, never prefixes).
4. **A worker's exit ends what its uncleaned launches left** (a test that failed or timed out before its cleanup, a spec with none): a synchronous SIGKILL of what names each such profile, on CI-opt's check that no `maws-e2e-` process outlives its job. Rejected: a global teardown sweeping every private `mawsd` under the tmpdir (it would reach a concurrent run on the same account); an e2e seam that idles `mawsd` out fast (a product change that departs from the owner's shape). A hard-killed worker (a job timeout) runs no hook; the job's own sweep is CI-opt's.
5. **The pins.** Kept where the mode is what the spec tests, each with its reason: `e2e:supervisor` and supervisor-scratch (the embedded sentinel, and the daemon suite by its script), supervisor-packaged, local-latency and daemon-idle (measured, per shape), cross-build (its scenes name each app's shape; O3-D re-scenes it), connector-cold-delivery (its stand-in attaches to the embedded supervisor's own socket once main is gone), p1-live-keep-quit (E11 S5's record of the embedded keep), and the artifacts-perf case, newly pinned to `utility` (its bounds assume a host that ends with its app, so each relaunch's first sync is cold, and that main restarts after a SIGKILL). Dropped: connector-scene's `detached` (the connector scenes test connectors; the daemon shape's engine host outlives the app as the supervisor does). Rejected: dropping every pin.
6. **The utility sentinel is `e2e:c7-utility`**: c7's specs (requests and composer over the engine replay) with MAWS_HOST_MODE=utility, on CLASS1_E2E and HOSTED_MAC_E2E, not MAC_VM_E2E (no guest evidence); CI-opt reviewed it. Rejected: transcript (its harness renders fixtures and barely reaches the hosts), terminal (the pty host alone).
7. **Acceptance 5's missing test** drives the real teardown (`leaveDaemonShape`) against live stand-ins of the owner's `mawsd` and pty host, their locks naming them with their start times, under every MAWS_HOST_MODE, harness, shape and packaging: both stay running and unsignalled. The existing test faked the teardown, so it showed the call was not made but not that the processes were untouched. Rejected: no new test.
8. **The quit banner on the daemon shape (a scoped exception to "no product code but the mode default", the architect's approval above).** Found by run 40723401776 at c12-quit.spec.ts:128: the wait counted only the session's work (terminals outlive the app there) while the banner counted the busy terminal too ("2 things", then a quit after one). `startWaiting` now publishes and stores the waited report with no busy terminal when terminals outlive; c12-quit reads the shape from `host.status.transport` and asserts each shape's behaviour. Rejected: a shape-aware spec asserting the wrong count or none.
9. **Acceptance 2's split (the architect's ruling above).** The three hosted after-sets cover the 35 hosted groups (c7-utility included); default, discover, connectors-oauth and browser-comment, which the hosted lane refuses, get one green mini run each on this tree, their before side cited from master's most recent green mini runs; c7-utility gets its own mini baseline for admission.

10. **The medium review's first round** (doperpowers:reviewer-medium on 94a69b5f4..d6e55db2c; 2 P2, both real and fixed by a fix-wave worker in 1d3c94577, each with a test that failed first): (1) a profile cleaned through another spelling of its path (`/var` against `/private/var`) missed a daemon started under the first, since the match is literal: both helpers now match every spelling (given, resolved, `/private` dropped on macOS), each ending in the separator; (2) the worker-exit sweep signalled a pid from its listing without its start time, so a recycled pid could be another process: it now revalidates each pid's start time before SIGKILL, as killScratchProcesses does. Logged rather than fixed: the cleanup's wait for shells lists the profile's processes in the given spelling only (a tracker row, sent to the architect, who writes the tracker). Rejected: matching through the profile's lock files alone (a host whose lock was already removed, or an engine, would be missed).

11. **The review converged.** The second round, narrowed to the fix wave's 1d3c94577, found nothing (verdict correct). Rounds: 2 findings, then 0.

12. **On the daemon shape a launch returns once the engine host is ready through `mawsd`** (e2e/support/launch.ts `untilDaemonHostReady`, the architect's acceptance above). After-set 2 (run 40766897996) ran on VMs about twice as slow as after-set 1's on the same tests (deliverables `:102` 59 s against 26 s; code 11.9 job-minutes against 5.3), and every red and flake was a launch's first default 5 s wait for seeded sessions indexed through the engine host's scan (`e2e/support/maws-tools.ts:224`, `c12-budget.spec.ts:65`, `transcript.spec.ts:1040`): the daemon shape starts its hosts cold (`mawsd`, then the engine host and pty host it serves) where the utility shape forked them, and on a slow VM that start passed 5 s. The wait is bounded at 30 s, never fails, and each launch prints it (`[e2e] daemon host ready: waited … ms after the window, … ms after the launch`), so a slower cold start shows in the job logs. Rejected: a longer timeout in each spec's first wait (the same failure in every spec written for the utility shape's start); a wait on every shape (the utility and embedded shapes need none). The tree changed, so the after-sets restart on the new head; sets 1 and 2 on b928f97f0 stay above as observations.

13. **The wait's review round** (doperpowers:reviewer-medium on 99a3b3714; 2 P2, both real, fixed by a fix-wave worker in 5d06f3e2a): (1) the 30 s bound was checked only after a `host.status` read settled, so a read left pending (a navigation's context, a stuck IPC) held the launch to the test's own timeout: the wait moved to `e2e/support/host-ready.ts`, which races each read and each poll against one bound, unit-tested (`test/support/host-ready.test.ts`, its never-settling read failing first against the old logic); (2) `smoke.spec.ts:34` times the window's regions from `launchedAt`, which the wait would have charged with the host's cold start: `launchMaws` takes `hostReady: false` and the fixture `mawsHostReady`, which smoke sets. Then 40c9d7082 unrefs the wait's timers, so the bound's timer, left running after an early return, never holds a worker open. Rejected: a per-read timeout in the page (the bound is the launch's, not a read's).

## Surprises and discoveries

- A cold private daemon delays the first index after a launch (decision 12); on slow hosted VMs past the specs' 5 s.
- Two harness races older than this branch surfaced on the daemon shape's timing (decision 14): `firstWindow` taken as the app's window, and a sidebar row located before its org key derives.
- browser-comment is not mini-only: off HOSTED_MAC_E2E it runs on the mini by default, but `Lane: hosted` takes it (the correction to acceptance 2's split).
- The quit banner on the daemon shape counted busy terminals the wait no longer waits for (decision 8). The owner's default shape since O2, so the owner has seen it.
- `quit-guard.test.ts`'s keep-by-mode case read the harness default (`MAWS_E2E` meaning `utility`); it now names `utility` through MAWS_HOST_MODE, as `e2e:c7-utility` does.
- This worktree's `node_modules` lacks packages other files import (`tweetnacl`, `@modelcontextprotocol/sdk`, `org-protocol`), so `src/main/lifecycle.test.ts`, the root-wiring tests and parts of the e2e typecheck cannot run here; class 1a runs them.
