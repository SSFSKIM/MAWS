## Purpose

After C11 the terminal's menu commands exist in MAWS as widgets over the transcript, each backed by the engine's own read or control and each honest about what it will not touch: type `/` and pick `model` to see the engine's catalogue with the gateway's models grouped and, on a GPT-routed model, the note that auto-mode reviews will run locally on Sonnet 5 and count against usage; pick `permissions` to see the effective mode from the init frame and every rule with its source file; `usage`, `context`, `config`, `plugins` (with reload), `mcp` (with reconnect), `sandbox`, `hooks`, `memory`, `skills`, `agents`, `status`, `compact`, `rename`, `resume`, `export` and `diff` do the same over their reads. A Settings tab at Codex density holds the engine binary and its pinned version, the gateway default with the relay-unreachable policy and the per-session Direct option, the keyboard map with chord capture, the theme and the notification policy, stored in MAWS's own folder and never in `~/.claude`. An Accounts tab shows ClaudeUsage's accounts in ClaudeUsage's own geometry with the routing account marked and the reason stated, and hands sign-in, reconnect and removal to ClaudeUsage. The status line's usage popover gains its routing footer (which account, through what, and the switch to Direct or back), and the switch restarts the session with a notice you can see. Session info in the right panel shows the engine version and binary, the model with its subagent model and overrides, the route and account, the effective mode with the auto-mode lane read from `get_status`, context, usage, cost, hooks and MCP. When ClaudeUsage's relay is down at first send, C10's docked card gets its handler ("Open ClaudeUsage, then start") and the settings policy that decides whether to ask, wait or run direct.

What C11 does not do: build the palette itself or the popover shell it opens in (C7's `SlashPalette` and `registerSlashWidget`), launch, resume or fork sessions (C10's `session.start` and `session.fork`; C11's Direct switch calls them), read the engine's store (C4), render the transcript (C6), host right-panel tabs (C8's X5 host; C11 declares one tool), read ClaudeUsage's files a second time (C7's reader in main is the one read, D-17), sign a user in or hold any credential (ClaudeUsage's, D-19), edit any file the engine owns (rules, settings, hooks, memory, `.mcp.json`, plugin state: every widget says so in its footer, D-12; the one control the engine itself persists on MAWS's request, the MCP toggle, says so too and names the file), or patch the engine (D-1).

## Terms

- **Widget**: the component C11 registers for one of the twenty names in C7's `WIDGET_COMMANDS` (`model, effort, fast, permissions, usage, config, plugins, mcp, sandbox, hooks, memory, skills, agents, status, compact, context, rename, resume, export, diff`), rendered by C7's palette over the transcript with props `{ appSessionId, args, close }`. **Widget frame**: C11's chrome inside that component: a head (title and the `/name`), a body, and a foot naming the read or control it used and what it will not edit (mockup 06 vignette 05, the pattern). **Engine-read widget**: a widget whose body is one structured read and nothing else (permissions, usage, context, config, plugins, mcp, sandbox, hooks, memory, skills, agents, status, diff, export). **Mutating widget**: one that also issues a control (model, effort, fast, compact, rename, resume, and the reload and reconnect actions inside plugins and mcp).
- **Catalogue**: C7's `session.catalog` snapshot for a session (commands, agents, skills, `terminalOnly`), the source of the skills and agents widgets. **Model catalogue**: the engine's `list_models` answer through C3's `session.listModels`, and C10's `engine.models` cache before any process.
- **Route**: a session's inference path, `gateway` (D-19's default: `ANTHROPIC_BASE_URL=http://127.0.0.1:8641` with the marker token and `ENABLE_TOOL_SEARCH=true`) or `direct` (the engine's own login, the flag-settings override that defeats the owner's `settings.json`). **Relay**: ClaudeUsage's loopback listener on port 8641 (`GET /api/hello` answers 200 with an empty body, any method; `RequestPipeline.swift:184–192`). **Relay health**: C3's `RelayHealth` from `engine.relayHealth`.
- **Account**: one row of ClaudeUsage's `accounts.json` as C7's `AccountUsage` carries it. **Routing account**: the relay's `drainTarget` from `pins.json`; **pinned account**: the account `pins.json` assigns to an engine session id (`pinsFor`); **manual target**: `drainTargetIsManual` is true. **Window**: a 5-hour (`session`), 7-day (`weekly_all`) or per-model weekly (`weekly_scoped#<Model>`) reading, C7's `UsageWindow`.
- **Lane**: which classifier reviews tool calls in auto mode: **server** (the verdict rides on the main request, free, `get_status`'s `Auto mode server: Enabled`) or **local** (the engine's own classifier requests on Sonnet 5 through the gateway, counted as usage; forced by a non-Anthropic main model, by a server fallback, or by fast mode). C3 carries it as `EngineSessionStatus.gateway.autoModeServer` and `localLane` (`{ observedInTurn: EventId, at } | null`: set when the unavailable-safeguard verdict or the classifier billing notice arrives, with `observedInTurn` the X1 `EventId` of the `turn.started` event that opened the turn (`${appSessionId}:${launchId}:${seq}:${i}`, C3's id for every event), cleared at the next `turn.started`; `EngineSessionStatus.turn.id` carries the same id for the comparison; Ask of C3).
- **Gateway model**: a catalogue entry whose `value` starts with `claude/` (C10's `isGatewayModel`); the relay's own catalogue, hard-coded in ClaudeUsage: the four bare aliases `astra`, `sol`, `luna`, `terra` are its Codex (GPT) models and the vendor-prefixed ids its OpenRouter models (`Codex/CodexModelCatalog.swift:3–21`, `OpenRouter/OpenRouterModelCatalog.swift:3–20`, `RequestPipeline.swift:1272–1305`). Every gateway model is served by a non-Anthropic provider and therefore takes the local lane in auto mode (§19).
- **Switch**: the per-session change of route, a stop and a resume of the same session with a visible notice, behind a confirm that names the session's background work (C10's `BackgroundWorkDisclosure`) and, when the current model is a gateway model and the target is Direct, requires a Direct-compatible model first. **Relay policy**: the setting that decides what a first send does when the relay is unreachable: `ask` (C10's card), `wait` (the card, emphasising ClaudeUsage, auto-starting when the relay answers) or `direct` (start direct at once, with a notice).
- **Hand-off**: activating ClaudeUsage for an action MAWS does not perform (add, reconnect, remove an account). ClaudeUsage registers no URL scheme, CLI or notification interface (`Resources/Info.plist:1–28`, no `CFBundleURLTypes`), so a hand-off is `open -b com.haegi.ClaudeUsage` plus an instruction naming the control in its panel, and the outcome is observed through the files it rewrites.
- **Accounts tab**, **Settings tab**: two singleton main-area tabs (mockup 06 vignettes 01 and 04, 760 px). **Session info tool**: the X5 panel tool C11 declares against C9's `panel/tool.ts` interface, which C8's host mounts.
