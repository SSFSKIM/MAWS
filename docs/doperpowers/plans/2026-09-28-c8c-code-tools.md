## Purpose

After C8c the code a session works in is one click away, and what it changed is readable without a terminal. Press "+" and choose Files: the panel shows the session's directories as a tree, one root per directory the session may read, and clicking a file opens it read-only in the main area, code highlighted with the line the owner was sent to scrolled into view, a markdown file rendered with a Source toggle, an image inline, a PDF as a row that opens it outside MAWS. Choose Review: the panel shows what changed under the scope that fits (Uncommitted on a dirty tree, This branch on a clean one, Staged when the index differs, Last turn when the transcript's change receipt sent you there), a file list with `+N −M` per file and viewed markers, the hunks unified or split, `Showing hunk 1 of 3` with previous and next, and `Open file ↗` on a hunk lands a viewer tab on the hunk's first changed line; a second Open further down the file moves that tab's line instead of opening another. The change receipt's "Review changes" opens Review on the turn's files; C11's `/diff` widget's "Open in Review" opens it too; a `diff` tab in the main area shows the same Review beside the transcript. Behind the viewer is one privileged read service in main, `files.*`, whose every read is confined to the session's own directories by an allowlist bound to the file actually opened, so a symlink planted in the tree cannot read the owner's keychain, and whose known limits are written down, one per operation, rather than hidden.

What C8c does not do: edit a file (P1, CodeMirror's editing and merge view on this viewer's base), stage, discard, commit or push (P1 source control), render PDF or HTML inside the app (P1, the sandboxed frame), invent a session-start scope (ruling 3), read `get_workspace_diff` for Review (R4 concerns only C11's hand-off, which passes a path), read a file from anywhere but main through `files.read` (K1, K4), or touch the host, the summary's sections or the sibling tools (C8a, C8b).

## Terms

- **`files.*`**: the X2 namespace this child adds (`src/shared/ipc/schema/files.ts`), owner main: `files.list`, `files.read`, `files.watch`, `files.unwatch`, `files.openExternal`, event `files.changed`. The **service** is the main-process module behind them (`src/main/files/`).
- **Allowlist**: for one session, the realpaths of `record.directory`, each of `record.additionalDirectories` and `record.worktree.path` (C5's X1 `SessionRecord`), read in main from the **read model** (`SessionReadModel.record(appSessionId)`, `src/main/sessions/read-model.ts`), which C4's `IndexSessionSource` fills in launch mode `index` and the stub source fills in mode `scenario`. A **root** is one allowlist entry. A path is **under** a root when its realpath equals the root or begins with the root followed by a path separator (a segment boundary; `/repo2` is not under `/repo`).
- **Open-first boundary** (K1): the service opens the path before it trusts it, `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` (`O_DIRECTORY` too for a directory), `fstat`s the descriptor, then confirms the opened object by taking `realpath(path)` again, requiring it under a root, `stat`-ing it and comparing `(dev, ino)` with the descriptor's, and only then judges its type. What cannot be served from the descriptor (a listing's entries, a watch) is re-confirmed the same way after its last path-based step, and a watch again before every batch it forwards. **The recorded limits**, one per operation (Interfaces, *Residual limits*): `read` has none by race, since an ancestor swapped to an outside symlink before the open is refused at the post-open confirmation whether it stands or was restored (an in-root realpath's object cannot be the outside descriptor's), and a hard link inside a root is accepted by design; `list` and `watch` keep swap-and-restore windows around the path-based steps Node cannot bind to a descriptor (Node has no `openat` chain or `fdopendir`, macOS no `O_RESOLVE_BENEATH`). **The boundary points**: a test-only hook, `hooks.at(point, path)`, the service awaits at named points (`before-open`, `after-open`, `after-readdir`, `after-watch-install`, `before-batch`), so a test can perform a substitution at each deterministically.
- **Scope** (Review): which set of changes is shown, `uncommitted` (working tree against `HEAD`), `branch` (This branch, the three-dot diff against the main worktree's branch), `turn` (Last turn, the change receipt's files), `staged` (the index against `HEAD`). The spec's *Review (C8c)* table binds their sources and defaults.
- **Patch file**: one file's part of C4's multi-file unified patch after `splitPatch`: its paths, its change kind and its hunks as strings beginning `@@`, the shape `@git-diff-view/react` takes.
- **Viewer**: the component registered into C5's `fileTab` slot (`src/renderer/src/app/slots.ts`), rendering `{ tab: { path, line, appSessionId } }` read-only. **Kind**: what the viewer decides to draw for a file, `code`, `markdown`, `image`, `external` or `head` (a bounded first chunk of a file past the cap).
- **`openFile`**: C8c's exported function that opens a file tab through C5's `openTab({ kind: 'file', path, line, appSessionId })` (K4); the only way any surface opens a file.
- **Receipt hand-off**: C6's `TranscriptActions.reviewChanges(turnId, path?)`, wired by C8c to open Review on the `turn` scope (K3).
- **Harness**: C8a's `#panel` page (`src/renderer/src/harness/panel/PanelHarness.tsx`) over fake sessions; C8c adds a delimited block to it, and loads its receipt fixture through C8a's `loadTranscript(id, fixture, { releaseTo })`, which attaches the `HarnessSession`'s source (keyed `harness:<n>`) under the fake session's id as well; the block renders over that source re-keyed to the fake session's id (Interfaces, *Harness API*). **Stub mode**: the product app launched with `MAWS_SESSION_SOURCE=stub:<scenario.json>` (C5's stub source), where a scenario's session record can name a scratch repository as its `directory`, so `files.*` and `git.*` run for real against it.

### `files.*` (`src/shared/ipc/schema/files.ts`, owner main)

```ts
export const FilesEntrySchema = z.strictObject({
  name: z.string(), path: z.string(),                       // path: absolute, under the confirmed directory's realpath
  kind: z.enum(['file', 'dir', 'symlink', 'other']),        // from lstat; 'other' (additive): sockets, fifos, devices — listed, never opened
  size: z.number().int(), mtimeMs: z.number(),
  target: z.string().nullable(),                            // additive: readlink for a symlink, else null; shown, never followed
});
export const commands = {
  'files.list': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string().optional() }),
                  output: z.strictObject({ root: z.string().nullable(), path: z.string(), entries: z.array(FilesEntrySchema), truncated: z.boolean() }), owner: 'main' },
                  // no path: the roots as 'dir' entries in record order (directory, additionalDirectories…, worktree when it differs), root null, path ''.
                  // with path: root is the allowlist root that contains it, path the confirmed realpath; truncated (additive) past FILES_LIST_MAX_ENTRIES
  'files.read': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string(), offset: z.number().int().min(0).optional(), length: z.number().int().min(1).max(FILES_READ_MAX_LENGTH).optional() }),
```

### The open-first boundary (`src/main/files/service.ts`)

`createFilesService({ records: (appSessionId) => SessionRecord | null, hooks?: { at?(point: BoundaryPoint, path: string): Promise<void> } })` with `type BoundaryPoint = 'before-open' | 'after-open' | 'after-readdir' | 'after-watch-install' | 'before-batch'`. `records` is `model.record` in the product; `hooks` exists for the boundary tests and is undefined in `register.ts`; every point is awaited at most once per step, with the path as given (`before-batch` with the watched realpath). `OPEN_FLAGS = O_RDONLY | O_NOFOLLOW | O_NONBLOCK` (`| O_DIRECTORY` for a directory). The steps, in order, for `read` (regular file) and `list` (directory); `watch` follows `list` through step 5b and continues below:

Why step 3 opens the path as given and not `real0`: opening the realpath would itself follow whatever the ancestors are at that instant and hide the substitution step 5 is there to catch; opening the given path lets the kernel refuse a final-component symlink (`O_NOFOLLOW` answers `ELOOP` on macOS, measured, Surprises) and step 5 catch an ancestor that pointed outside at the open, whether the substitution stands or was restored before step 5: a restored tree's realpath names an in-root object whose `(dev, ino)` cannot equal the outside descriptor's (tested: swap at `before-open`, restore at `after-open`), so `read` has no race window. The one way an in-root realpath names the same object as an outside path is a hard link, regular files only (macOS has no directory hard links and no bind mounts); it needs no race and the object is then itself in the tree, accepted by design. Why `O_NONBLOCK`: `open(O_RDONLY)` on a FIFO with no writer, or on a device that waits on open, blocks the libuv threadpool thread; the router awaits the handler with no timeout (`src/main/ipc/router.ts:100-121` on master; `70-82` when written), so four such requests would freeze every `fs` call in main; with `O_NONBLOCK` the open returns at once and step 5b rejects the type (a regular file's reads are never `EAGAIN`, so `handle.read` is unaffected). Why `list` confirms again after its last metadata read and not after `readdir` alone: Node has no `fdopendir` (`readdir('/dev/fd/<fd>')` answers `ENOTDIR` on macOS, measured), so `readdir`, every `lstat` and every `readlink` are by path; an ancestor swapped after `readdir` but before the `lstat`s would make those reads answer outside metadata, so the confirmation that guards the answer must follow the last of them, and the collected entries stay private until it passes. Roots are realpaths because `/tmp` is `/private/tmp` on macOS and a record's `worktree.path` may be either form; `realpath` is the native one (`fs.promises.realpath`) for both the roots and the requested path, since it canonicalises case on APFS (measured: `/tmp/RP-CASE-TEST/sub` → `/private/tmp/rp-case-test/Sub`) and the JS `fs.realpathSync` does not, and this machine's own records spell the repository `/Users/new/developer/github/MAWS` beside the canonical case.

`openExternal`: step 1 only, then `shell.openPath(real0)` as the very next statement; `''` → `{ opened: true, message: null }`, anything else → `{ opened: false, message }`; nothing is read back. Under `MAWS_E2E=1` with `MAWS_E2E_OPEN_LOG` set to a file path, the service appends `real0` and a newline to that file instead of calling `shell.openPath` (the e2e's seam; precedent C5's `MAWS_E2E_QUIT_ANSWER` in `lifecycle/quit-guard.ts`), and answers `{ opened: true, message: null }`.

`watch`: steps 1 to 5b as `list` (`O_DIRECTORY`), then, with the descriptor still open, `watcher = fs.watch(real, { persistent: false })`; `await hooks?.at?.('after-watch-install', path)`; **confirm again** (`realpath(path)` afresh under a root, `stat`, `(dev, ino)` equal to the descriptor's), on a mismatch `watcher.close()` and the refusal; then step 7 closes the descriptor and the entry `{ real, identity: { dev, ino }, watcher, holders: Set<AppSessionId>, pending }` is keyed by `real` (a second holder joins the existing entry after its own steps 1 to 5b succeed and its step-5 `(dev, ino)` equals the entry's `identity`; when it differs, the stale entry is invalidated as a failed batch confirmation would (watcher closed, entry removed, one `invalidated` per existing holder) and the second holder's watch installs anew). `fs.watch` takes a path, not the descriptor (libuv's darwin backend is FSEvents, by path), which is why the install is followed by a confirmation and every batch by another. A `rename` or `change` with a filename is coalesced per `(real, filename)` over a 250 ms trailing debounce into one batch; when the batch fires: `await hooks?.at?.('before-batch', real)`; `stat(real)` and compare `(dev, ino)` with `identity`; on a mismatch (or a failed `stat`) the batch is dropped unforwarded, the watcher closed, the entry removed, and each holder receives one `files.changed { appSessionId, path: real, kind: 'invalidated' }`; on a match each filename is `lstat`ed and emitted once per holder as `files.changed { appSessionId, path: join(real, filename), kind }` with `kind` `removed` when `lstat` fails, `created` when `birthtimeMs` is within the last 2 s, else `changed`; an event without a filename emits `{ path: real, kind: 'changed' }` after the same confirmation. `unwatch` removes the holder and closes the watcher at zero. A window's watches are released when it reloads or closes, as C4's git handlers release theirs (settled by the refresh pass 2026-09-29, superseding the 2026-09-28 reading that C4 offered no reload moment and C8c needed its own `did-start-navigation` hook in `src/main/index.ts`): since debt wave 1B every main handler receives `{ sender }` as its second argument (`src/main/ipc/router.ts:21-25, 100`), and `registerGitHandlers` follows each sender once and releases what it holds on `destroyed` and `did-navigate` (`src/main/git/register.ts:11-27`); `registerFilesHandlers` does the same, a holder being `(sender.id, appSessionId)`, events still emitted once per holder session, and the C8c block in `src/main/index.ts` passes no reload hook.

**Residual limits, per operation** (the recorded limits of K1): `read`: none by race, since step 5 refuses an ancestor swapped to an outside symlink before the open whether the swap stands or was restored (the positive test below); hard links accepted by design (an in-root hard link is the file itself in the tree; it needs no race). `list`: a window between the first path-based read of step 6 (`readdir`) and the final confirmation, in which a swap-and-restore lets outside names and metadata (never contents) into the answer. `watch`: a swap-and-restore between the install and its confirmation attaches the watcher to the outside directory until the first batch's confirmation catches the swap if it stands, or forwards the outside directory's filenames (never contents) if it was restored in time; and a swap between a batch's confirmation and its per-filename `lstat` classifies `kind` from outside metadata for that batch. `openExternal` has only the path check (the residual race the spec names). The `list` and `watch` windows are swap-and-restores completing between two path-based steps; none has a deterministic point and none is tested. Everything else a substitution can do is caught at a confirmation and tested below.

### The boundary tests (`src/main/files/service.test.ts`, vitest node, a temp tree per test)

Negatives, each answering the refusal message and reading nothing: a symlink inside a root pointing to a file outside; `..` segments that leave the root; a root that is itself a symlink (the allowlist holds its realpath, a path through the link resolves under it and is served, a path escaping through it is refused); a path that is a prefix but not a child (`/repo2` under `/repo`); a relative path; a session with no record; a session whose every root is missing on disk; a missing name under an in-root symlink to an outside directory (`<root>/out/nope`, `out` → an outside directory): the refusal, not `not found`, while a missing in-root name answers `not found` (the leak rule by the deepest existing ancestor's realpath); and, ruled 2026-09-29 (O1), three more: the `..` probe `/X/probe/../../<root>/nope` answers the refusal whether `/X/probe` exists or not, an in-root `<root>/src/../README.md` answers the refusal though it names an in-root file, and a dangling in-root link (`<root>/link` → a missing outside path) answers the refusal, not `not found`. **Pre-open, at `before-open`** (suite `files service boundary`): after the pre-check passed, replace the final component with a symlink pointing outside (refused by `ELOOP`), replace an ancestor with a symlink pointing outside (refused at step 5), replace the file's parent with a symlink to an outside directory holding a directory of the file's name (the refusal, not `not a regular file`: no type is named before step 5), replace the file by a directory (`read` answers `not a regular file` at step 5b) and the directory by a file (`list` refused at step 3, `ENOTDIR`); and one permitted case, stated so the executor does not chase it: an in-root replacement at `before-open` (`rename` of another in-root regular file onto the path) *succeeds* and serves the replacement's bytes, because the object opened is confirmed as itself and lies inside the roots; containment, not the path's history, is what K1 guards. **Swap and restore, at `before-open` then `after-open`** (same suite): replace an ancestor with a symlink pointing outside at `before-open` and restore it at `after-open`: the open followed the symlink, step 5's fresh realpath is back under the root, and the `(dev, ino)` mismatch refuses; no outside byte is served (this is why `read` has no race window). **Post-open, at `after-open`** (same suite): replace the target with a different regular file inside the root (`rename` onto the path) after the open, so step 5's `stat(real)` names the replacement while the descriptor holds the original: the `(dev, ino)` mismatch refuses, and the test proves the identity check, not only the containment; the same for `list` with an in-root sibling directory renamed onto an empty target (`rename` onto a non-empty directory fails). **FIFO** (same suite; `mkfifo` through `child_process.execFileSync`): a pre-existing FIFO under a root answers `not a regular file` within 1 s (`vi.waitFor` bound); a regular file replaced by a FIFO at `before-open` answers the same within 1 s; a healthy `read` of a sibling file completes immediately afterwards (the threadpool was not consumed). **Late confirmation** (suite `files service late confirmation`): `list` at `after-readdir`: replace an ancestor with a symlink to an outside directory that holds a file of the same name as an inside entry but a different size: the final confirmation refuses and the answer carries no entry (the outside size is asserted absent). `watch` at `after-watch-install`: the same substitution: the post-install confirmation refuses, the watcher is closed (spy on the `FSWatcher`'s `close`), and a write into the outside directory emits nothing. `watch` at `before-batch`, with a healthy watch and two holders: the same substitution: the batch is not forwarded (no `files.changed` names a filename), the watcher is closed, the entry is gone, and each holder receives exactly one `files.changed { path: real, kind: 'invalidated' }`; a `watch` call re-issued while the substitution stands is refused at step 1, and after the tree is restored succeeds and delivers the next change. Positives (suite `files service listing and reading`): reads at `offset`/`length` with `truncated` and `length`, a utf8 chunk ending on a character boundary (a 3-byte character straddling the requested end: `length` is short by the partial bytes and the next chunk begins with the whole character), a CRLF file whose first chunk would end on the `\r` (the chunk withholds it, `length` is one short, the next chunk begins `\r\n`), one encoding per file (a text file with a NUL at 1.5 MiB: chunk 1 and chunk 2 both `utf8`, the sniff reading bytes `0..BINARY_SNIFF_BYTES` for chunk 2), an entry deleted at `after-readdir` (the listing answers without it and no message names it), base64 for a PNG and for a NUL-bearing file, utf8 for text, `mime` by extension, a listing with directories first, a symlink entry with its `target` and `kind: 'symlink'`, a FIFO entry as `kind: 'other'`, the roots listing in record order deduplicated by realpath, `truncated` past the cap. **Negative controls**: the ancestor substitution at `before-open` run against a test-local `checkThenOpen(path)` that performs step 1 and then `readFile(real0)` (the shape K1 corrects, `artifacts.ts:18-34`) reads the outside file's bytes; the `after-readdir` substitution run against a test-local `checkThenList(path)` (step 1, then `readdir(real0)` and `lstat` per entry, no final confirmation) reports the outside file's size. The controls prove each substitution reproduces its race, so the service's refusal in the same scenario is evidence and not an accident of the point. The residual `list` and `watch` windows above are not tested: a swap-and-restore inside a window between two path-based steps has no deterministic point; `read`'s swap-and-restore is tested above.

### Viewer kinds and caps (`viewer/kinds.ts`)

| Kind | When | Renders |
|---|---|---|
| `markdown` | extension `.md`, `.mdx`, `.markdown` and `bytes ≤ MARKDOWN_RENDER_CAP` | C6's `Markdown` (`live: false`) with a `Source` toggle to `code` |
| `image` | mime `image/*` (png, jpg, jpeg, gif, webp, bmp, ico, avif, svg) and `bytes ≤ IMAGE_CAP` | `<img src={dataUrl(mime, encoding, content)}>` fit to width, natural size on click; `dataUrl` branches on `files.read.encoding`: `base64` → `data:<mime>;base64,<content>`; `utf8` (svg, the service's text rule) → `data:<mime>;base64,<base64 of new TextEncoder().encode(content)>`, so non-ASCII text survives; svg also offers `Source`, which shows the utf8 text |

| `head` | text with `bytes > CODE_CAP` | `code` over the first chunk with `Showing the first <head> of <size>`, `Load more` (up to `CODE_CAP`), `Open externally` |
| `code` | everything else (any text, markdown past its cap, svg source) | CodeMirror 6 read-only; a file larger than the first chunk is completed by continuation reads before it is presented as complete (below) |

`CODE_CAP = 4 MiB`, `MARKDOWN_RENDER_CAP = 1 MiB`, `IMAGE_CAP = 8 MiB` (one `files.read` call), `BINARY_SNIFF_BYTES = 8192`. The viewer's first call is `files.read { path, length: FILES_READ_DEFAULT_LENGTH }` and the kind is decided on its answer. **Continuation**: for `code` (and `markdown`, whose cap fits one chunk) with `truncated: true` and `bytes ≤ CODE_CAP`, the viewer paints the first chunk at once under the notice `Loading <loaded> of <size>` and issues `files.read { path, offset: offset + length, length: FILES_READ_DEFAULT_LENGTH }` until `truncated` is false, appending each chunk to the same `EditorState` (the concatenation is exact because every chunk of one file answers the file's one `encoding`, decided by the service from the file's first `BINARY_SNIFF_BYTES`, and a `utf8` chunk never ends inside a character or between the `\r` and `\n` of a CRLF, which CodeMirror would otherwise count as two line breaks); the notice is removed at completion and only then does the harness's `viewer().notice` read `null`; a re-read caused by `files.changed` runs the same sequence. `head` (`bytes > CODE_CAP`) keeps its first chunk and `Load more`. **Line jump**: `tab.line` is 1-based; the jump is `EditorView.scrollIntoView(line.from, { y: 'center' })` with the line decorated for two seconds, applied against the loaded state: when the line is not yet loaded the jump is retried after each chunk and lands when it exists, and a line beyond the complete document scrolls to the end and flashes nothing; a `line` change on the same tab (C5's `openTab` refresh) jumps again. Images whose `bytes` exceed the first chunk are re-read in one call of `length: bytes`. SVG in an `<img>` is inert (no script runs in an image document) and `data:` is in `img-src` (`src/main/csp.ts`).
