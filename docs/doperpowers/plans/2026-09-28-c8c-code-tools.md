## Purpose

After C8c the code a session works in is one click away, and what it changed is readable without a terminal. Press "+" and choose Files: the panel shows the session's directories as a tree, one root per directory the session may read, and clicking a file opens it read-only in the main area, code highlighted with the line the owner was sent to scrolled into view, a markdown file rendered with a Source toggle, an image inline, a PDF as a row that opens it outside MAWS. Choose Review: the panel shows what changed under the scope that fits (Uncommitted on a dirty tree, This branch on a clean one, Staged when the index differs, Last turn when the transcript's change receipt sent you there), a file list with `+N −M` per file and viewed markers, the hunks unified or split, `Showing hunk 1 of 3` with previous and next, and `Open file ↗` on a hunk lands a viewer tab on the hunk's first changed line; a second Open further down the file moves that tab's line instead of opening another. The change receipt's "Review changes" opens Review on the turn's files; C11's `/diff` widget's "Open in Review" opens it too; a `diff` tab in the main area shows the same Review beside the transcript. Behind the viewer is one privileged read service in main, `files.*`, whose every read is confined to the session's own directories by an allowlist bound to the file actually opened, so a symlink planted in the tree cannot read the owner's keychain, and whose known limits are written down, one per operation, rather than hidden.

What C8c does not do: edit a file (P1, CodeMirror's editing and merge view on this viewer's base), stage, discard, commit or push (P1 source control), render PDF or HTML inside the app (P1, the sandboxed frame), invent a session-start scope (ruling 3), read `get_workspace_diff` for Review (R4 concerns only C11's hand-off, which passes a path), read a file from anywhere but main through `files.read` (K1, K4), or touch the host, the summary's sections or the sibling tools (C8a, C8b).

## Terms

- **`files.*`**: the X2 namespace this child adds (`src/shared/ipc/schema/files.ts`), owner main: `files.list`, `files.read`, `files.watch`, `files.unwatch`, `files.openExternal`, event `files.changed`. The **service** is the main-process module behind them (`src/main/files/`).
- **Allowlist**: for one session, the realpaths of `record.directory`, each of `record.additionalDirectories` and `record.worktree.path` (C5's X1 `SessionRecord`), read in main from the **read model** (`SessionReadModel.record(appSessionId)`, `src/main/sessions/read-model.ts`), which C4's `IndexSessionSource` fills in launch mode `index` and the stub source fills in mode `scenario`. A **root** is one allowlist entry. A path is **under** a root when its realpath equals the root or begins with the root followed by a path separator (a segment boundary; `/repo2` is not under `/repo`).
- **Open-first boundary** (K1): the service opens the path before it trusts it, `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` (`O_DIRECTORY` too for a directory), `fstat`s the descriptor and checks its type, then confirms the opened object by taking `realpath(path)` again, requiring it under a root, `stat`-ing it and comparing `(dev, ino)` with the descriptor's. What cannot be served from the descriptor (a listing's entries, a watch) is re-confirmed the same way after its last path-based step, and a watch again before every batch it forwards. **The recorded limits**, one per operation (Interfaces, *Residual limits*): the common one is an ancestor directory replaced by a symlink pointing outside and restored between the pre-check and the open (Node has no `openat` chain, macOS no `O_RESOLVE_BENEATH`); `list` and `watch` each add a window of the same class around their path-based steps. **The boundary points**: a test-only hook, `hooks.at(point, path)`, the service awaits at named points (`before-open`, `after-open`, `after-readdir`, `after-watch-install`, `before-batch`), so a test can perform a substitution at each deterministically.
- **Scope** (Review): which set of changes is shown, `uncommitted` (working tree against `HEAD`), `branch` (This branch, the three-dot diff against the main worktree's branch), `turn` (Last turn, the change receipt's files), `staged` (the index against `HEAD`). The spec's *Review (C8c)* table binds their sources and defaults.
- **Patch file**: one file's part of C4's multi-file unified patch after `splitPatch`: its paths, its change kind and its hunks as strings beginning `@@`, the shape `@git-diff-view/react` takes.
- **Viewer**: the component registered into C5's `fileTab` slot (`src/renderer/src/app/slots.ts`), rendering `{ tab: { path, line, appSessionId } }` read-only. **Kind**: what the viewer decides to draw for a file, `code`, `markdown`, `image`, `external` or `head` (a bounded first chunk of a file past the cap).
- **`openFile`**: C8c's exported function that opens a file tab through C5's `openTab({ kind: 'file', path, line, appSessionId })` (K4); the only way any surface opens a file.
- **Receipt hand-off**: C6's `TranscriptActions.reviewChanges(turnId, path?)`, wired by C8c to open Review on the `turn` scope (K3).
- **Harness**: C8a's `#panel` page (`src/renderer/src/harness/panel/PanelHarness.tsx`) over fake sessions; C8c adds a delimited block to it, and loads its receipt fixture through C8a's `loadTranscript(id, fixture, { releaseTo })`, whose source is keyed to the fake session. **Stub mode**: the product app launched with `MAWS_SESSION_SOURCE=stub:<scenario.json>` (C5's stub source), where a scenario's session record can name a scratch repository as its `directory`, so `files.*` and `git.*` run for real against it.

### `files.*` (`src/shared/ipc/schema/files.ts`, owner main)

K1's names and shapes, completed with the fields execution needs (marked *additive*):

```ts
export const FilesEntrySchema = z.strictObject({
  name: z.string(), path: z.string(),                       // path: absolute, under the confirmed directory's realpath
  kind: z.enum(['file', 'dir', 'symlink', 'other']),        // from lstat; 'other' (additive): sockets, fifos, devices — listed, never opened
  size: z.number().int(), mtimeMs: z.number(),
  target: z.string().nullable(),                            // additive: readlink for a symlink, else null; shown, never followed
});
export const commands = {
  'files.list': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string().optional() }),
                  output: z.strictObject({ root: z.string().nullable(), path: z.string(), entries: z.array(FilesEntrySchema), truncated: z.boolean() }), owner: 'main' },
                  // no path: the roots as 'dir' entries in record order (directory, additionalDirectories…, worktree when it differs), root null, path ''.
                  // with path: root is the allowlist root that contains it, path the confirmed realpath; truncated (additive) past FILES_LIST_MAX_ENTRIES
  'files.read': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string(), offset: z.number().int().min(0).optional(), length: z.number().int().min(1).max(FILES_READ_MAX_LENGTH).optional() }),
                  output: z.strictObject({ encoding: z.enum(['utf8', 'base64']), content: z.string(), bytes: z.number().int(), offset: z.number().int(), length: z.number().int(), truncated: z.boolean(), mime: z.string() }), owner: 'main' },
                  // length (input) defaults to FILES_READ_DEFAULT_LENGTH; base64 when the head sniffs binary or the mime is not text; length (output, additive) is the byte count
                  // this chunk covers, so the next chunk's offset is offset + length: a utf8 chunk ends on a character boundary (up to three trailing bytes of an
                  // incomplete sequence are withheld for the next chunk), so it may be shorter than asked; truncated when offset + length < bytes
  'files.watch':   { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string() }), output: z.void(), owner: 'main' },   // a directory; ref-counted per confirmed realpath; re-confirmed after install and before each batch
  'files.unwatch': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string() }), output: z.void(), owner: 'main' },
  'files.openExternal': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string() }),
                  output: z.strictObject({ opened: z.boolean(), message: z.string().nullable() }), owner: 'main' },   // message (additive): shell.openPath's error text
} as const satisfies Record<`files.${string}`, CommandSpec<z.ZodType, z.ZodType>>;
export const events = { 'files.changed': z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string(), kind: z.enum(['created', 'changed', 'removed', 'invalidated']) }) } as const;
// invalidated (additive): the watched directory (path is its confirmed realpath) failed a re-confirmation and its watch was dropped; the holder re-lists and re-watches, which runs the boundary again

export const FILES_READ_DEFAULT_LENGTH = 1024 * 1024;       // C4's SPILL_DEFAULT_LENGTH; the viewer's first chunk
export const FILES_READ_MAX_LENGTH = 8 * 1024 * 1024;       // one call's ceiling; the image cap is one call
export const FILES_LIST_MAX_ENTRIES = 5000;
```

Refusals are thrown from the handler and reach the renderer as `IpcError { code: 'internal', message }` (C1's router). Exact messages: `path outside the session's directories` (every containment failure, including a final-component symlink, a post-open mismatch and a session with no resolvable root), `unknown app session: <id>`, `not found: <path>` (only when the lexical path would lie under a root, so the command says nothing about what exists elsewhere, C4's rule in `artifacts.ts`), `not a regular file: <path>` and `not a directory: <path>` (the type check, reached only inside a root; a FIFO, socket or device is `not a regular file`, and its open never blocks because of `O_NONBLOCK`), `path must be absolute`.

### The open-first boundary (`src/main/files/service.ts`)

`createFilesService({ records: (appSessionId) => SessionRecord | null, hooks?: { at?(point: BoundaryPoint, path: string): Promise<void> } })` with `type BoundaryPoint = 'before-open' | 'after-open' | 'after-readdir' | 'after-watch-install' | 'before-batch'`. `records` is `model.record` in the product; `hooks` exists for the boundary tests and is undefined in `register.ts`; every point is awaited at most once per step, with the path as given (`before-batch` with the watched realpath). `OPEN_FLAGS = O_RDONLY | O_NOFOLLOW | O_NONBLOCK` (`| O_DIRECTORY` for a directory). The steps, in order, for `read` (regular file) and `list` (directory); `watch` follows `list` through step 5 and continues below:

| Step | `read` | `list` | On failure |
|---|---|---|---|
| 1 pre-check | `isAbsolute(path)`; `roots = rootsOf(record)` (each entry's `realpath`, entries that do not resolve dropped); `real0 = realpath(path)`; `real0` under a root | same | `path must be absolute`; `unknown app session`; `not found` or the refusal (the leak rule); the refusal |
| 2 point | `await hooks?.at?.('before-open', path)` | same | — (test-only) |
| 3 open | `open(path, OPEN_FLAGS)` on the path as given | `open(path, OPEN_FLAGS \| O_DIRECTORY)` | `ELOOP` (final component became a symlink), `ENOTDIR`, `EISDIR`, `ENOENT` → the refusal (`ENOENT` → `not found` under the leak rule) |
| 4 type | `fstat`; `isFile()` | `fstat`; `isDirectory()` | `not a regular file` / `not a directory`; close |
| 4b point | `await hooks?.at?.('after-open', path)` | same | — (test-only) |
| 5 confirm | `real = realpath(path)` afresh; `real` under a root; `st = stat(real)`; `st.dev === fstat.dev && st.ino === fstat.ino` | same | the refusal; close |
| 6 serve | `handle.read` loop at `offset` for `min(length, size - offset)` bytes; sniff the first `BINARY_SNIFF_BYTES` (a NUL byte → binary); `mime = mimeOf(name)`; `encoding` `base64` when binary or `mime` is not `text/*`, `application/json`, `application/xml`, `application/javascript`, `application/x-sh`, `image/svg+xml`; for `utf8`, drop up to three trailing bytes of an incomplete sequence (unless the chunk ends the file) so `length` is what the chunk covers | `names = readdir(real)`; `await hooks?.at?.('after-readdir', path)`; each entry `lstat`ed at `join(real, name)`, `target` by `readlink` for symlinks, into a private array; **then confirm again**: `realpath(path)` afresh under a root, `stat` it, `(dev, ino)` equal to the descriptor's; only then sort (directories first, then files by `localeCompare`), cut at `FILES_LIST_MAX_ENTRIES` with `truncated: true`, and answer | `list`: a mismatch at the final confirmation → the refusal; nothing collected is answered (names and metadata alike) |
| 7 close | always, in `finally` | same | — |

Why step 3 opens the path as given and not `real0`: opening the realpath would itself follow whatever the ancestors are at that instant and hide the substitution step 5 is there to catch; opening the given path lets the kernel refuse a final-component symlink (`O_NOFOLLOW` answers `ELOOP` on macOS, measured, Surprises) and step 5 catch an ancestor that now points outside. Why `O_NONBLOCK`: `open(O_RDONLY)` on a FIFO with no writer, or on a device that waits on open, blocks the libuv threadpool thread; the router awaits the handler with no timeout (`src/main/ipc/router.ts:74-85`), so four such requests would freeze every `fs` call in main; with `O_NONBLOCK` the open returns at once and step 4 rejects the type (a regular file's reads are never `EAGAIN`, so `handle.read` is unaffected). Why `list` confirms again after its last metadata read and not after `readdir` alone: Node has no `fdopendir` (`readdir('/dev/fd/<fd>')` answers `ENOTDIR` on macOS, measured), so `readdir`, every `lstat` and every `readlink` are by path; an ancestor swapped after `readdir` but before the `lstat`s would make those reads answer outside metadata, so the confirmation that guards the answer must follow the last of them, and the collected entries stay private until it passes. Roots are realpaths because `/tmp` is `/private/tmp` on macOS and a record's `worktree.path` may be either form.

`openExternal`: step 1 only, then `shell.openPath(real0)` as the very next statement; `''` → `{ opened: true, message: null }`, anything else → `{ opened: false, message }`; nothing is read back. Under `MAWS_E2E=1` with `MAWS_E2E_OPEN_LOG` set to a file path, the service appends `real0` and a newline to that file instead of calling `shell.openPath` (the e2e's seam; precedent C5's `MAWS_E2E_QUIT_ANSWER` in `lifecycle/quit-guard.ts`), and answers `{ opened: true, message: null }`.

`watch`: steps 1 to 5 as `list` (`O_DIRECTORY`), then, with the descriptor still open, `watcher = fs.watch(real, { persistent: false })`; `await hooks?.at?.('after-watch-install', path)`; **confirm again** (`realpath(path)` afresh under a root, `stat`, `(dev, ino)` equal to the descriptor's), on a mismatch `watcher.close()` and the refusal; then step 7 closes the descriptor and the entry `{ real, identity: { dev, ino }, watcher, holders: Set<AppSessionId>, pending }` is keyed by `real` (a second holder joins the existing entry after its own steps 1 to 5 succeed). `fs.watch` takes a path, not the descriptor (libuv's darwin backend is FSEvents, by path), which is why the install is followed by a confirmation and every batch by another. A `rename` or `change` with a filename is coalesced per `(real, filename)` over a 250 ms trailing debounce into one batch; when the batch fires: `await hooks?.at?.('before-batch', real)`; `stat(real)` and compare `(dev, ino)` with `identity`; on a mismatch (or a failed `stat`) the batch is dropped unforwarded, the watcher closed, the entry removed, and each holder receives one `files.changed { appSessionId, path: real, kind: 'invalidated' }`; on a match each filename is `lstat`ed and emitted once per holder as `files.changed { appSessionId, path: join(real, filename), kind }` with `kind` `removed` when `lstat` fails, `created` when `birthtimeMs` is within the last 2 s, else `changed`; an event without a filename emits `{ path: real, kind: 'changed' }` after the same confirmation. `unwatch` removes the holder and closes the watcher at zero. All watches are dropped when the renderer reloads: `registerFilesHandlers` takes `onRendererReload(listener)` from the C8c block in `src/main/index.ts`, wired to the app window's `webContents` `did-start-navigation` **[refresh]** in the way C4's git watcher handles a reload, if it does; otherwise this hook is C8c's alone.

**Residual limits, per operation** (the recorded limits of K1, each a swap-and-restore that completes inside one window; none has a deterministic point, none is tested, all are the same class): `read`: an ancestor replaced by a symlink pointing outside and restored between step 1 and step 3, so the open follows it and step 5 sees the restored tree; the bytes served are then the outside file's. `list`: the `read` window, and a second one between the first path-based read of step 6 (`readdir`) and the final confirmation, in which a swap-and-restore lets outside names and metadata (never contents) into the answer. `watch`: the `read` window at install; a swap-and-restore between the install and its confirmation attaches the watcher to the outside directory until the first batch's confirmation catches the swap if it stands, or forwards the outside directory's filenames (never contents) if it was restored in time; and a swap between a batch's confirmation and its per-filename `lstat` classifies `kind` from outside metadata for that batch. `openExternal` has only the path check (the residual race the spec names). Everything else a substitution can do is caught at a confirmation and tested below.

### The boundary tests (`src/main/files/service.test.ts`, vitest node, a temp tree per test)

Negatives, each answering the refusal message and reading nothing: a symlink inside a root pointing to a file outside; `..` segments that leave the root; a root that is itself a symlink (the allowlist holds its realpath, a path through the link resolves under it and is served, a path escaping through it is refused); a path that is a prefix but not a child (`/repo2` under `/repo`); a relative path; a session with no record; a session whose every root is missing on disk. **Pre-open, at `before-open`** (suite `files service boundary`): after the pre-check passed, replace the final component with a symlink pointing outside (refused by `ELOOP`), replace an ancestor with a symlink pointing outside (refused at step 5), replace the file by a directory (`read` refused by the type check) and the directory by a file (`list` refused); and one permitted case, stated so the executor does not chase it: an in-root replacement at `before-open` (`rename` of another in-root regular file onto the path) *succeeds* and serves the replacement's bytes, because the object opened is confirmed as itself and lies inside the roots; containment, not the path's history, is what K1 guards. **Post-open, at `after-open`** (same suite): replace the target with a different regular file inside the root (`rename` onto the path) after the open, so step 5's `stat(real)` names the replacement while the descriptor holds the original: the `(dev, ino)` mismatch refuses, and the test proves the identity check, not only the containment; the same for `list` with an in-root sibling directory renamed onto an empty target (`rename` onto a non-empty directory fails). **FIFO** (same suite; `mkfifo` through `child_process.execFileSync`): a pre-existing FIFO under a root answers `not a regular file` within 1 s (`vi.waitFor` bound); a regular file replaced by a FIFO at `before-open` answers the same within 1 s; a healthy `read` of a sibling file completes immediately afterwards (the threadpool was not consumed). **Late confirmation** (suite `files service late confirmation`): `list` at `after-readdir`: replace an ancestor with a symlink to an outside directory that holds a file of the same name as an inside entry but a different size: the final confirmation refuses and the answer carries no entry (the outside size is asserted absent). `watch` at `after-watch-install`: the same substitution: the post-install confirmation refuses, the watcher is closed (spy on the `FSWatcher`'s `close`), and a write into the outside directory emits nothing. `watch` at `before-batch`, with a healthy watch and two holders: the same substitution: the batch is not forwarded (no `files.changed` names a filename), the watcher is closed, the entry is gone, and each holder receives exactly one `files.changed { path: real, kind: 'invalidated' }`; a `watch` call re-issued while the substitution stands is refused at step 5, and after the tree is restored succeeds and delivers the next change. Positives: reads at `offset`/`length` with `truncated` and `length`, a utf8 chunk ending on a character boundary (a 3-byte character straddling the requested end: `length` is short by the partial bytes and the next chunk begins with the whole character), base64 for a PNG and for a NUL-bearing file, utf8 for text, `mime` by extension, a listing with directories first, a symlink entry with its `target` and `kind: 'symlink'`, a FIFO entry as `kind: 'other'`, the roots listing in record order deduplicated by realpath, `truncated` past the cap. **Negative controls**: the ancestor substitution at `before-open` run against a test-local `checkThenOpen(path)` that performs step 1 and then `readFile(real0)` (the shape K1 corrects, `artifacts.ts:18-34`) reads the outside file's bytes; the `after-readdir` substitution run against a test-local `checkThenList(path)` (step 1, then `readdir(real0)` and `lstat` per entry, no final confirmation) reports the outside file's size. The controls prove each substitution reproduces its race, so the service's refusal in the same scenario is evidence and not an accident of the point. The residual limits above are not tested: a swap-and-restore inside a window has no deterministic point.

## Residue decisions (C8c, 2026-09-28)

Ready to paste into the charter's C8 section under "**Residue decisions (C8c, 2026-09-28):** what the composite spec left to the child, settled here; the execution document `docs/doperpowers/plans/2026-09-28-c8c-code-tools.md` carries the interfaces, milestones and gates. - *`files.*` surface and boundary*: five commands and one event, owner main, defined in `src/shared/ipc/schema/files.ts` (the `files` namespace added to C1's `NAMESPACES` and registry): `files.list { appSessionId, path? } → { root, path, entries[{ name, path, kind: file | dir | symlink | other, size, mtimeMs, target }], truncated }` (no `path`: the roots), `files.read { appSessionId, path, offset?, length? ≤ 8 MiB } → { encoding: utf8 | base64, content, bytes, offset, length, truncated, mime }` (1 MiB default chunk; base64 when the first 8 KiB holds a NUL or the mime is not text; a utf8 chunk ends on a character boundary and `length` is the bytes it covers, so `offset + length` is the next chunk), `files.watch`/`files.unwatch { appSessionId, path }` (ref-counted per confirmed directory, 250 ms debounce), `files.openExternal { appSessionId, path } → { opened, message }`, event `files.changed { appSessionId, path, kind: created | changed | removed | invalidated }` (`invalidated`: the watched directory failed a re-confirmation and its watch was dropped; the holder re-lists and re-watches). The allowlist is the realpaths of `directory`, `additionalDirectories` and `worktree.path` read from main's `SessionReadModel.record` (C4's index in launch mode `index`, the stub in `scenario`); containment is at a segment boundary; `read`, `list` and `watch` open first (`O_RDONLY | O_NOFOLLOW | O_NONBLOCK`, `O_DIRECTORY` for directories; `O_NONBLOCK` so a FIFO or a device cannot hold a threadpool thread, the type check rejecting it), `fstat` and type-check, then confirm a fresh post-open realpath under a root and `(dev, ino)` against the descriptor; `read` serves from the descriptor; `list`, which Node cannot serve from a descriptor, reads names and per-entry metadata by the confirmed realpath into a private array and confirms again after the last of those reads, answering nothing on a mismatch; `watch`, whose `fs.watch` is by path, confirms again after the watcher is installed and before every batch it forwards, dropping the watch with an `invalidated` event on a mismatch; every refusal answers `internal` with `path outside the session's directories`, a non-existent path `not found` only when it would lie inside; the recorded limits are swap-and-restore windows, one per operation (`read`: between the pre-check and the open; `list`: also between its first path-based read and its final confirmation, names and metadata only; `watch`: also between the install and its confirmation and between a batch's confirmation and its per-name `lstat`, filenames and kinds only); `openExternal` is path-checked immediately before `shell.openPath` with no descriptor guarantee. ## Surprises & Discoveries

- Observation: Node cannot list a directory from a descriptor on macOS, so `files.list` cannot "serve entries from the descriptor" literally; the listing is bracketed by two `(dev, ino)` confirmations instead.
  Evidence: Node 22.23.2 on macOS 26.6.2, `fs.openSync(dir, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` then `fs.readdirSync('/dev/fd/' + fd)` → `ENOTDIR`, `fs.opendirSync('/dev/fd/' + fd)` → `ENOTDIR`; `fstat` on the descriptor answers `isDirectory: true` with `dev`/`ino`. Resolution: step 6 of the boundary for `list` (Interfaces): names and per-entry metadata read by path into a private array, the final confirmation after the last of those reads, nothing answered on a mismatch; recorded as a refinement of K1's "serve from the descriptor" and reported to the architect. The same holds for `watch`: `fs.watch` takes a path, so the install and every batch are followed by a confirmation.
- Observation: `O_NOFOLLOW` refuses a final-component symlink and `O_DIRECTORY` refuses a non-directory, exactly as K1 relies on; a read through a symlinked *ancestor* with `O_NOFOLLOW` succeeds, which is why the post-open realpath confirmation is load-bearing and not belt-and-braces.
  Evidence: same probe: `open(root/link.txt, O_RDONLY|O_NOFOLLOW)` → `ELOOP`; `open(root/dirlink, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` → `ENOTDIR`; `open(root/sub/a.txt, O_RDONLY|O_DIRECTORY)` → `ENOTDIR`; `open(root/dirlink/s.txt, O_RDONLY|O_NOFOLLOW)` then `readFileSync(fd)` → `secret` (the outside file's content). `realpathSync('/tmp/…')` → `/private/tmp/…`, so roots must be realpaths too.
- Observation: main already has one session-record accessor that works in both launch modes, so the allowlist resolver needs no second path for the stub source.
