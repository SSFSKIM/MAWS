## Purpose

After C8c the code a session works in is one click away, and what it changed is readable without a terminal. Press "+" and choose Files: the panel shows the session's directories as a tree, one root per directory the session may read, and clicking a file opens it read-only in the main area, code highlighted with the line the owner was sent to scrolled into view, a markdown file rendered with a Source toggle, an image inline, a PDF as a row that opens it outside MAWS. Choose Review: the panel shows what changed under the scope that fits (Uncommitted on a dirty tree, This branch on a clean one, Staged when the index differs, Last turn when the transcript's change receipt sent you there), a file list with `+N −M` per file and viewed markers, the hunks unified or split, `Showing hunk 1 of 3` with previous and next, and `Open file ↗` on a hunk lands a viewer tab on the hunk's first changed line; a second Open further down the file moves that tab's line instead of opening another. The change receipt's "Review changes" opens Review on the turn's files; C11's `/diff` widget's "Open in Review" opens it too; a `diff` tab in the main area shows the same Review beside the transcript. Behind the viewer is one privileged read service in main, `files.*`, whose every read is confined to the session's own directories by an allowlist bound to the file actually opened, so a symlink planted in the tree cannot read the owner's keychain, and whose one known limit is written down rather than hidden.

What C8c does not do: edit a file (P1, CodeMirror's editing and merge view on this viewer's base), stage, discard, commit or push (P1 source control), render PDF or HTML inside the app (P1, the sandboxed frame), invent a session-start scope (ruling 3), read `get_workspace_diff` for Review (R4 concerns only C11's hand-off, which passes a path), read a file from anywhere but main through `files.read` (K1, K4), or touch the host, the summary's sections or the sibling tools (C8a, C8b).

## Terms

- **`files.*`**: the X2 namespace this child adds (`src/shared/ipc/schema/files.ts`), owner main: `files.list`, `files.read`, `files.watch`, `files.unwatch`, `files.openExternal`, event `files.changed`. The **service** is the main-process module behind them (`src/main/files/`).
- **Allowlist**: for one session, the realpaths of `record.directory`, each of `record.additionalDirectories` and `record.worktree.path` (C5's X1 `SessionRecord`), read in main from the **read model** (`SessionReadModel.record(appSessionId)`, `src/main/sessions/read-model.ts`), which C4's `IndexSessionSource` fills in launch mode `index` and the stub source fills in mode `scenario`. A **root** is one allowlist entry. A path is **under** a root when its realpath equals the root or begins with the root followed by a path separator (a segment boundary; `/repo2` is not under `/repo`).
- **Open-first boundary** (K1): the service opens the path before it trusts it, `O_RDONLY | O_NOFOLLOW` (`O_DIRECTORY` too for a listing), `fstat`s the descriptor and checks its type, then confirms the opened object by taking `realpath(path)` again, requiring it under a root, `stat`-ing it and comparing `(dev, ino)` with the descriptor's. **The recorded limit**: an ancestor directory replaced by a symlink pointing outside and restored between the pre-check and the open is not caught (Node has no `openat` chain, macOS no `O_RESOLVE_BENEATH`). **The hook**: a test-only function the service awaits between its pre-check and its open, so a test can perform that substitution deterministically.
- **Scope** (Review): which set of changes is shown, `uncommitted` (working tree against `HEAD`), `branch` (This branch, the three-dot diff against the main worktree's branch), `turn` (Last turn, the change receipt's files), `staged` (the index against `HEAD`). The spec's *Review (C8c)* table binds their sources and defaults.
- **Patch file**: one file's part of C4's multi-file unified patch after `splitPatch`: its paths, its change kind and its hunks as strings beginning `@@`, the shape `@git-diff-view/react` takes.
- **Viewer**: the component registered into C5's `fileTab` slot (`src/renderer/src/app/slots.ts`), rendering `{ tab: { path, line, appSessionId } }` read-only. **Kind**: what the viewer decides to draw for a file, `code`, `markdown`, `image`, `external` or `head` (a bounded first chunk of a file past the cap).
- **`openFile`**: C8c's exported function that opens a file tab through C5's `openTab({ kind: 'file', path, line, appSessionId })` (K4); the only way any surface opens a file.
- **Receipt hand-off**: C6's `TranscriptActions.reviewChanges(turnId, path?)`, wired by C8c to open Review on the `turn` scope (K3).
- **Harness**: C8a's `#panel` page (`src/renderer/src/harness/panel/PanelHarness.tsx`) over fake sessions; C8c adds a delimited block to it. **Stub mode**: the product app launched with `MAWS_SESSION_SOURCE=stub:<scenario.json>` (C5's stub source), where a scenario's session record can name a scratch repository as its `directory`, so `files.*` and `git.*` run for real against it.

### `files.*` (`src/shared/ipc/schema/files.ts`, owner main)

K1's names and shapes, completed with the fields execution needs (marked *additive*):

```ts
export const FilesEntrySchema = z.strictObject({
  name: z.string(), path: z.string(),                       // path: absolute, under the confirmed directory's realpath
  kind: z.enum(['file', 'dir', 'symlink', 'other']),        // from lstat; 'other' (additive): sockets, fifos, devices — listed, never opened
  size: z.number().int(), mtimeMs: z.number(),
  target: z.string().nullable(),                            // additive: readlink for a symlink, else null; shown, never followed
});
export const commands = {
  'files.list': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string().optional() }),
                  output: z.strictObject({ root: z.string().nullable(), path: z.string(), entries: z.array(FilesEntrySchema), truncated: z.boolean() }), owner: 'main' },
                  // no path: the roots as 'dir' entries in record order (directory, additionalDirectories…, worktree when it differs), root null, path ''.
                  // with path: root is the allowlist root that contains it, path the confirmed realpath; truncated (additive) past FILES_LIST_MAX_ENTRIES
  'files.read': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string(), offset: z.number().int().min(0).optional(), length: z.number().int().min(1).max(FILES_READ_MAX_LENGTH).optional() }),
                  output: z.strictObject({ encoding: z.enum(['utf8', 'base64']), content: z.string(), bytes: z.number().int(), offset: z.number().int(), truncated: z.boolean(), mime: z.string() }), owner: 'main' },
                  // length defaults to FILES_READ_DEFAULT_LENGTH; base64 when the head sniffs binary or the mime is not text; truncated when offset + returned < bytes
  'files.watch':   { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string() }), output: z.void(), owner: 'main' },   // a directory; ref-counted per confirmed realpath
  'files.unwatch': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string() }), output: z.void(), owner: 'main' },
  'files.openExternal': { input: z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string() }),
                  output: z.strictObject({ opened: z.boolean(), message: z.string().nullable() }), owner: 'main' },   // message (additive): shell.openPath's error text
} as const satisfies Record<`files.${string}`, CommandSpec<z.ZodType, z.ZodType>>;
export const events = { 'files.changed': z.strictObject({ appSessionId: AppSessionIdSchema, path: z.string(), kind: z.enum(['created', 'changed', 'removed']) }) } as const;

export const FILES_READ_DEFAULT_LENGTH = 1024 * 1024;       // C4's SPILL_DEFAULT_LENGTH; the viewer's first chunk
export const FILES_READ_MAX_LENGTH = 8 * 1024 * 1024;       // one call's ceiling; the image cap is one call
export const FILES_LIST_MAX_ENTRIES = 5000;
```

Refusals are thrown from the handler and reach the renderer as `IpcError { code: 'internal', message }` (C1's router). Exact messages: `path outside the session's directories` (every containment failure, including a final-component symlink, a post-open mismatch and a session with no resolvable root), `unknown app session: <id>`, `not found: <path>` (only when the lexical path would lie under a root, so the command says nothing about what exists elsewhere, C4's rule in `artifacts.ts`), `not a regular file: <path>` and `not a directory: <path>` (the type check, reached only inside a root), `path must be absolute`.

### The open-first boundary (`src/main/files/service.ts`)

`createFilesService({ records: (appSessionId) => SessionRecord | null, hooks?: { beforeOpen?(path: string): Promise<void> } })`. `records` is `model.record` in the product; `hooks` exists for the boundary tests and is undefined in `register.ts`. The steps, in order, for `read` (regular file) and `list` (directory):

| Step | `read` | `list` | On failure |
|---|---|---|---|
| 1 pre-check | `isAbsolute(path)`; `roots = rootsOf(record)` (each entry's `realpath`, entries that do not resolve dropped); `real0 = realpath(path)`; `real0` under a root | same | `path must be absolute`; `unknown app session`; `not found` or the refusal (the leak rule); the refusal |
| 2 hook | `await hooks?.beforeOpen?.(path)` | same | — (test-only) |
| 3 open | `open(path, O_RDONLY \| O_NOFOLLOW)` on the path as given | `open(path, O_RDONLY \| O_NOFOLLOW \| O_DIRECTORY)` | `ELOOP` (final component became a symlink), `ENOTDIR`, `EISDIR`, `ENOENT` → the refusal (`ENOENT` → `not found` under the leak rule) |
| 4 type | `fstat`; `isFile()` | `fstat`; `isDirectory()` | `not a regular file` / `not a directory`; close |
| 5 confirm | `real = realpath(path)` afresh; `real` under a root; `st = stat(real)`; `st.dev === fstat.dev && st.ino === fstat.ino` | same | the refusal; close |
| 6 serve | `handle.read` loop at `offset` for `min(length, size - offset)` bytes; sniff the first `BINARY_SNIFF_BYTES` (a NUL byte → binary); `mime = mimeOf(name)`; `encoding` `base64` when binary or `mime` is not `text/*`, `application/json`, `application/xml`, `application/javascript`, `application/x-sh`, `image/svg+xml` | `readdir(real, { withFileTypes: true })`, then `stat(real)` again and compare `(dev, ino)` with the descriptor; entries `lstat`ed at `join(real, name)`, `target` by `readlink` for symlinks, sorted directories first then files by `localeCompare`, cut at `FILES_LIST_MAX_ENTRIES` with `truncated: true` | a mismatch after `readdir` → the refusal (the listing is discarded) |
| 7 close | always, in `finally` | same | — |

Why step 3 opens the path as given and not `real0`: opening the realpath would itself follow whatever the ancestors are at that instant and hide the substitution step 5 is there to catch; opening the given path lets the kernel refuse a final-component symlink (`O_NOFOLLOW` answers `ELOOP` on macOS, measured, Surprises) and step 5 catch an ancestor that now points outside. Why `list` re-stats after `readdir`: Node has no `fdopendir`; `readdir('/dev/fd/<fd>')` answers `ENOTDIR` on macOS (measured), so the listing is by the confirmed realpath and bracketed by two identity checks, which narrows the window to the same class as the recorded limit. Roots are realpaths because `/tmp` is `/private/tmp` on macOS and a record's `worktree.path` may be either form.

`openExternal`: step 1 only, then `shell.openPath(real0)` as the very next statement; `''` → `{ opened: true, message: null }`, anything else → `{ opened: false, message }`; nothing is read back. Under `MAWS_E2E=1` with `MAWS_E2E_OPEN_LOG` set to a file path, the service appends `real0` and a newline to that file instead of calling `shell.openPath` (the e2e's seam; precedent C5's `MAWS_E2E_QUIT_ANSWER` in `lifecycle/quit-guard.ts`), and answers `{ opened: true, message: null }`.

`watch`: steps 1, 3 (`O_DIRECTORY`), 4, 5, then close, then `fs.watch(real, { persistent: false })` keyed by `real` with a `Set<AppSessionId>` of holders; `unwatch` removes the holder and closes the watcher at zero; a `rename` or `change` with a filename is coalesced per `(real, filename)` over a 250 ms trailing debounce and emitted once per holder as `files.changed { appSessionId, path: join(real, filename), kind }` with `kind` `removed` when `lstat` fails, `created` when `birthtimeMs` is within the last 2 s, else `changed`; an event without a filename emits `{ path: real, kind: 'changed' }`. All watches are dropped when the renderer reloads: `registerFilesHandlers` takes `onRendererReload(listener)` from the C8c block in `src/main/index.ts`, wired to the app window's `webContents` `did-start-navigation` **[refresh]** in the way C4's git watcher handles a reload, if it does; otherwise this hook is C8c's alone.

## Surprises & Discoveries

- Observation: Node cannot list a directory from a descriptor on macOS, so `files.list` cannot "serve entries from the descriptor" literally; the listing is bracketed by two `(dev, ino)` confirmations instead.
  Evidence: Node 22.23.2 on macOS 26.6.2, `fs.openSync(dir, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` then `fs.readdirSync('/dev/fd/' + fd)` → `ENOTDIR`, `fs.opendirSync('/dev/fd/' + fd)` → `ENOTDIR`; `fstat` on the descriptor answers `isDirectory: true` with `dev`/`ino`. Resolution: step 6 of the boundary for `list` (Interfaces), recorded as a refinement of K1's "serve from the descriptor" and reported to the architect.
- Observation: `O_NOFOLLOW` refuses a final-component symlink and `O_DIRECTORY` refuses a non-directory, exactly as K1 relies on; a read through a symlinked *ancestor* with `O_NOFOLLOW` succeeds, which is why the post-open realpath confirmation is load-bearing and not belt-and-braces.
  Evidence: same probe: `open(root/link.txt, O_RDONLY|O_NOFOLLOW)` → `ELOOP`; `open(root/dirlink, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` → `ENOTDIR`; `open(root/sub/a.txt, O_RDONLY|O_DIRECTORY)` → `ENOTDIR`; `open(root/dirlink/s.txt, O_RDONLY|O_NOFOLLOW)` then `readFileSync(fd)` → `secret` (the outside file's content). `realpathSync('/tmp/…')` → `/private/tmp/…`, so roots must be realpaths too.
- Observation: main already has one session-record accessor that works in both launch modes, so the allowlist resolver needs no second path for the stub source.
