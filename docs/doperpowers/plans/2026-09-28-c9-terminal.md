## Purpose

After C9, the owner opens a session's right panel, adds a Terminal tab, and gets a real login shell in that session's worktree: the prompt shows the worktree path, `claude` and `codex` run in it with their full-screen interfaces drawn correctly (box drawing, Korean and emoji text, IME composition, links that open in the browser), output from `cat` of a large file never freezes the app, and the shell keeps running, with its scrollback, while the owner switches to the Review tab, to another session, or reloads the renderer. Pinning the tab carries that shell across sessions; when the shell belongs to a different worktree than the session now shown, the tab says so and offers a new terminal instead of pretending it moved. If the terminal service crashes, the tab says "Terminal lost" and offers a new one once the service is back. A `claude --bg` job attaches by opening a terminal with a typed command (C10 wires the affordance; C9 provides the call). None of this exists before C9: C1 left a PTY host that spawns one `/bin/sh`, echoes, and knows nothing of rendering, flow control, environment, or lifecycle.

The first milestone is the spike the charter demands (§7.2, C9 G1): both renderer candidates behind one adapter under the real Claude Code and Codex terminal interfaces, with a recorded verdict. Research at authoring (Surprises & Discoveries) makes the expected verdict xterm.js 6 with the WebGL addon; the spike exists to observe it, not to assume it.

## Terms

- **PTY** (pseudo-terminal): the kernel object a shell talks to as if it were a terminal. node-pty (`src/pty-host/`) creates one per terminal; the app writes keystrokes to it and reads the bytes the shell and its programs print.
- **PTY host**: the utility process `src/pty-host/index.ts` from C1 (charter §4.1). It owns every pty; the renderer only ever sees `pty.*` commands and events.
- **Renderer adapter**: the interface `TerminalRenderer` in `src/renderer/src/terminal/renderer.ts` that hides which terminal-emulator library draws the terminal. Two implementations exist during the spike (`xterm.ts`, `ghostty.ts`); the product ships one.
- **xterm.js**: the terminal-emulator library `@xterm/xterm` (a TypeScript VT parser plus a DOM renderer, with a WebGL renderer as an addon). **ghostty-web**: the `ghostty-web` package, Ghostty's terminal core compiled to WebAssembly with a Canvas 2D renderer written in TypeScript.
- **WebGL context**: the GPU drawing handle a `<canvas>` gets from `getContext('webgl2')`. Chromium keeps at most 16 live per renderer process and evicts the oldest beyond that; a lost context fires `webglcontextlost`.
- **Alternate screen**: the second screen buffer full-screen programs switch to (mode 1049) so that leaving them restores the shell's screen and scrollback.
- **Synchronized output**: DEC private mode 2026; a program brackets a frame in `CSI ? 2026 h` … `CSI ? 2026 l` so the terminal draws it in one go instead of tearing.
- **Grapheme cluster**: what a reader sees as one character (a Hangul syllable, an emoji with skin tone and ZWJ joins). Terminals must allocate the same number of cells for it as the program assumed, or box drawing drifts.
- **Flow control**: keeping a fast producer (a program printing) from outrunning a slow consumer (the renderer parsing). Here: the host counts bytes it emitted minus bytes the renderer acknowledged, and pauses the pty (`pty.pause()`, which stops reading so the kernel buffer fills and the program blocks on `write`) above a high watermark, resuming below a low one.
- **Offset**: the byte position of a chunk in a pty's output stream since spawn. Every `pty.data` event carries the offset of its first byte; acknowledgements name an offset; attach replies name the offset at which live events resume.
- **Ring buffer**: the last N bytes of a pty's output kept in the host so a renderer that reconnects (after a reload) can be shown what it missed.
- **Terminal handle**: the renderer-side object (`src/renderer/src/terminal/registry.ts`) that owns one renderer instance, its container `<div>`, and the identity of its pty; it outlives the React tree that shows it, which is how a terminal keeps its state across tab switches.
- **Panel tool**: what X5 calls a right-panel tab type. C8 owns the host; C9 declares the Terminal tool against the interface assumed in Interfaces (`src/renderer/src/panel/tool.ts`).
- **Harness**: a second renderer page, `src/renderer/harness.html`, loaded instead of the app when `MAWS_HARNESS=1`. `#probe` is the spike and performance page (both adapters, workloads, metrics); `#panel` is a fake panel host that mounts the Terminal tool with two fake sessions.
- **TUI**: a full-screen terminal user interface; here the interfaces of `claude` (Ink-based) and `codex` (ratatui-based).
- **XTVERSION**: the query `CSI > 0 q` a program sends to learn the terminal's name and version. Claude Code 2.1.283 sends it and only asks about synchronized output if it is answered (Surprises & Discoveries).
- **Kitty keyboard protocol**: an opt-in key encoding (`CSI > flags u`) that disambiguates modifiers; both TUIs request it and fall back to legacy encoding when the terminal does not answer.

## Residue decisions (C9, 2026-09-28)

What the design left to the child, settled here, formatted for the charter's C9 section. Grades: binding where the design binds the outcome or where siblings depend on the shape; advisory where a later child may overturn with a dated line in the charter. Milestones below point at a decision by its italic title.

- *Renderer*: xterm.js `@xterm/xterm` 6.0.0 with `@xterm/addon-webgl` 0.19.0 is the expected primary, with xterm.js's own DOM renderer as the fallback and ghostty-web discarded; the spike (M1) observes and records this rather than assuming it. Evidence at authoring: `ghostty-web`'s last stable release is 0.4.0 (2025-12-09) with prereleases ending 2026-06-28 and no push since 2026-07-02; on 0.4.0 Korean IME is broken (coder/ghostty-web #119, open; the owner types Korean), `getHyperlinkUri()` always returns null (#137), a WebAssembly heap-corruption fix (commit bec9e16) is unreleased, synchronized output is never honoured by its renderer, the Kitty keyboard encoder is not wired, the WASM ships as a `data:` URI that a strict CSP blocks (#188), and its `write` callback fires on the next animation frame with no backpressure design; those are four charter list items failed on paper (IME, hyperlinks, synchronized output, sustained output) before any measurement. xterm.js 6.0.0 (2025-12-22) supports mode 2026, OSC 8 through `linkHandler`, grapheme clustering through `@xterm/addon-unicode-graphemes` 0.4.0, IME, and `write(data, callback)` flow control. Ghostty's core is measurably faster (libghostty-vt versus xterm.js, 2 to 7× on throughput per xtermjs/xterm.js #5686), which is why the adapter keeps a `RendererKind` seam and the probe page stays: a maintained libghostty package (ghostty-org's signed `ghostty-vt.wasm` has no renderer or npm package yet) re-runs the same spike without touching the tool. Kitty keyboard protocol is deferred: it exists only in xterm.js 6.1 betas, which also drop single-character IME commits under it (#6112); both TUIs fall back to legacy keys. Alternative rejected: shipping ghostty-web `0.4.0-next.20` (what Coder's Mux pins) for its speed; it carries the same IME and design gaps and no release process. Advisory (§4.7), with the spike's switch rule binding (G1).
- *WebGL policy*: a terminal holds a WebGL context only while visible (mounted and its tab selected); hiding disposes the WebGL addon, showing reloads it, so contexts in flight equal visible terminals (one, two under a split) against Chromium's cap of 16 per renderer process; a budget of 8 concurrent WebGL terminals is enforced in the registry, the rest draw with the DOM renderer. On `webglcontextlost` the addon waits three seconds for a restore, then fires `onContextLoss`; the adapter disposes it, continues on the DOM renderer, and retries WebGL on the next show. The same path covers sleep and resume and is exercised deterministically through the `WEBGL_lose_context` extension in the end-to-end test. Alternative rejected: raising `--max-active-webgl-contexts`, which moves the cliff instead of removing it. Advisory.
- *Scrollback and memory*: 10,000 lines per terminal, a constant `SCROLLBACK_LINES` in `src/renderer/src/terminal/constants.ts`, no settings surface in P0 (C11 may lift it into settings). Bound: xterm.js stores 12 bytes per cell, so a 10,000-line buffer costs 12 × cols × 10,000 bytes at most, 6 MB at the panel's 50 columns and 24 MB at 200; the host additionally keeps a 256 KiB ring buffer per pty for reattachment. Alternative rejected: xterm.js's 1,000 default, too short for `pnpm test` output. Advisory.
- *PTY stream and flow control*: output crosses X2 as binary (`Uint8Array`) chunks, one `pty.data` event per node-pty read (observed ≤ 64 KiB), each stamped with its stream `offset`; keystrokes stay strings (`pty.write`). Backpressure is credit by offset: the renderer acknowledges the offset it has parsed (`pty.ack`), coalesced to one ack per 32 KiB or 16 ms; the host pauses the pty when emitted-minus-acknowledged bytes reach 256 KiB and resumes at 64 KiB (within xterm.js's flow-control guide, which caps the high mark at 500 KB and drops data past a 50 MB buffer if nobody pauses the producer). A hidden terminal acknowledges at most 1 MiB/s so a runaway `cat` in a background tab blocks its producer instead of starving the UI thread. `pty.attach` returns the ring buffer and the offset at which live events continue; the renderer drops any event below that offset, which makes reconnection after a renderer reload exact. Binary because both candidate renderers take bytes, the renderer's decoder then sees exactly what the program wrote, and the host can split on byte counts without caring about character boundaries. Alternative rejected: strings with host-side decoding, which is what C1 shipped and works, but forces two decoders and per-chunk string copies on the hot path. Binding on the X2 shape (siblings validate these entries), advisory on the numbers.
- *Terminal environment*: the shell is the user's login shell (`$SHELL`, else `/bin/zsh`) started with `-l`, so PATH and exports come from the owner's own dotfiles exactly as in Terminal.app; the seed environment is the base (the PTY host's `process.env` until C3 lands X6's captured login-shell environment, swapped at one function, `baseEnvironment()` in `src/pty-host/env.ts`) minus the parent-session exclusions of §4.1, plus `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=MAWS`, `TERM_PROGRAM_VERSION=<app version>`, `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1` (Claude Code 2.1.283 enables synchronized output only if XTVERSION is answered, which xterm.js 6.0.0 does not, or if this variable or a `TERM_PROGRAM` allowlist says so), and `LC_CTYPE=UTF-8` when no `LANG`, `LC_ALL` or `LC_CTYPE` is present (a Dock-launched app has none; this makes the tty UTF-8 without choosing a language). No gateway variables, no `CLAUDE_CODE_FORK_SUBAGENT`: a terminal is the owner's shell, not an engine launch. Alternative rejected: reusing X6's engine allowlist verbatim, which would route a hand-started `claude` through app-chosen settings instead of the owner's shell. Binding on the exclusions and the no-injection rule (D-12 interop), advisory on the additions.
- *Unicode width*: the terminal must allocate cells the way the program computed them. xterm.js runs with `@xterm/addon-unicode-graphemes` active so ZWJ emoji sequences and Hangul are one cluster of two cells, matching Ink's `string-width` and ratatui's `unicode-width`; the spike verifies with a cursor-position report (`CSI 6 n`) after printing fixture strings and compares the reported column with the expected width. Advisory on mechanism; the CJK-and-emoji item is binding (G1).
- *Search*: not in P0. Nothing in §5.6 asks for it, neither TUI needs it, and Codex's own terminal ships Clipboard, Fit and WebLinks only; `@xterm/addon-search` drops in later behind an adapter method. Advisory.
- *Splits*: no split inside a Terminal tab. The panel is 380 px wide; a second terminal is a second Terminal tab (`multiInstance: true`, titled "Terminal 2"), which also gives "multiple ptys per session" without layout state. A terminal in the main area or a bottom dock is P1 (§3). Advisory.
- *Persistence*: a terminal's renderer instance and container `<div>` live in the terminal registry, not in React state; the tool's render mounts the existing container and detaches it on unmount, so switching tabs, closing the panel or switching sessions under a pinned tab never re-creates the emulator or loses scrollback, and a running process is untouched. A pinned Terminal tab keeps its shells: it does not move to the new session's cwd; when the shell's spawn cwd differs from the shown session's directory (or its worktree path), the tool shows the worktree warning with "New terminal here". After a renderer reload the registry re-adopts live ptys from `pty.list` by `(appSessionId, label)` and `pty.attach` replays the ring buffer; after an app restart there are none (hosts die with the app, D-16). Binding on "pinned keeps its shells and warns" (§5.6, D-10), advisory on mechanism.
- *Keyboard*: with a terminal focused, every key without ⌘ goes to the pty (Esc, ⇧Tab, Tab, ⌃C, ⌃D, ⌃L, ⌃R, arrows, ⌥-chords with `macOptionIsMeta: true`), except ⌃Tab and ⌃⇧Tab, which stay the app's tab cycle; every ⌘ chord goes to the app, except ⌘C (copy selection; nothing when there is none), ⌘V (paste), ⌘A (select all), which the terminal handles. ⌘K remains the command palette (§5.8): clearing a terminal is ⌃L or the tab's context menu. This is the focused-pane rule of §5.7 applied to a terminal: the app's Enter/Esc/⇧Tab meanings belong to the composer and request card, which are not focused. Implemented as one key filter installed through the adapter. `macOptionClickForcesSelection: true` so ⌥-drag selects while a TUI tracks the mouse. Kitty keyboard protocol off (see *Renderer*). Binding on the rule, advisory on the chord list.
- *Copy, paste and links*: ⌘C copies the selection as plain text; ⌘V pastes, bracketed when the program asked for it; the tab's context menu offers Copy, Paste, Select all, Clear. OSC 8 links and detected URLs open on ⌘-click through `pty.openLink` (owner main, `shell.openExternal` after a scheme check: `http`, `https`, `mailto`; anything else is logged and ignored). `file:` links and bare paths that should open a viewer tab are P1 (they need C8's Files tool). OSC 52 clipboard writes from programs are not honoured. Advisory.
- *Fonts and palette*: 21 new X7 token names, added to `mockups/tokens.css`, `tokens-light.css` and `src/renderer/src/styles/tokens.css`: `--term-bg` (light: `var(--bg-raised)`), `--term-fg` (`var(--fg)`), `--term-cursor`, `--term-cursor-fg`, `--term-selection`, and `--term-ansi-<name>` and `--term-ansi-bright-<name>` for `black red green yellow blue magenta cyan white`. Values are advisory (light: a VS Code-light-derived readable set on a white ground; dark: the same family on `#1a1a1a`). The adapter reads them with `getComputedStyle(document.documentElement)` and rebuilds the theme on every `settings.changed`, so the terminal recolours with the app and no component holds a colour literal. Font: `--font-mono` and `--text-code`, line height 1.2. Names binding once C1 accepts them into X7 (overlap flagged), values advisory.
- *Lifecycle and close*: a terminal is `starting`, `running`, `exited` (with code and signal) or `lost` (the host crashed or restarted: main's supervisor emits `pty.exit` with null code and null signal for every pty it knew, C1 M4). `exited` and `lost` keep the dead screen visible and show a bar: "Process exited (code N)" or "Terminal lost, the terminal service restarted", with "New terminal" (enabled once `pty.hostState` is `ready`, same cwd) and "Close". Closing a `running` terminal asks `pty.foreground`; when a program other than the shell is in the foreground the tool shows an inline bar "A command is running: `<name>`. Close anyway?" with "Close" and "Keep" (no dialog dependency), otherwise closes at once; closing kills the pty with SIGHUP. The tab title follows the program's OSC 0/2 title, falling back to the foreground process name. Binding on the behaviours G2 names, advisory on copy.
- *Terminal tool and X5*: the tool is `src/renderer/src/tools/terminal/index.ts` exporting `terminalTool: PanelTool<TerminalTabState>` and `openTerminal({ appSessionId, cwd, command? })` for C10's attach affordance (the command is written to the shell followed by a newline; the tty buffers it until the shell reads). The X5 interface it assumes is written in `src/renderer/src/panel/tool.ts` (Interfaces) and holds four things C8's host must honour or C9 adapts at that file: state is created once per tab and kept across visibility changes, panel close and session switches under a pin; the render context carries the shown session's record (for the worktree comparison); `beforeClose` can veto a close; `multiInstance` allows a second Terminal tab. Until C8 lands, the harness's `#panel` page is the host. Advisory (X5 is C8's).
- *Testing and harness*: vitest node project for `src/pty-host/**` against real node-pty (flood, pause and resume, ring buffer, attach offsets, environment, initial command, foreground detection) and for `src/shared/ipc/schema/pty.test.ts`; vitest happy-dom project for `src/renderer/src/terminal/**` with a `FakeRenderer` implementing `TerminalRenderer` (ack coalescing, offset dedupe, visibility throttle, WebGL budget, key filter, theme assembly from an injected token reader); Playwright `e2e/terminal.spec.ts` launching the built app with `MAWS_HARNESS=1` against the real renderer, the real host and real shells; the `#probe` page doubles as the performance harness with its measurements written as JSON by `spikes/terminal-probe/run.mjs`. Advisory.
- *Dependencies*: `@xterm/xterm` 6.0.0, `@xterm/addon-webgl` 0.19.0, `@xterm/addon-fit` 0.11.0, `@xterm/addon-web-links` 0.12.0, `@xterm/addon-unicode-graphemes` 0.4.0, all exact (the 6.1 line is beta-only through 2026-08-30 and the addons' internals track the core's minor); `ghostty-web` 0.4.0-next.20 as a devDependency during M1 only, removed on discard. Advisory.

## Interfaces and Dependencies

### X2 — `pty.*` (`src/shared/ipc/schema/pty.ts`)

C1's five commands and two events are replaced by the set below (C1 M4: "C9 owns the `pty.*` entries from here on"). `AppSessionIdSchema` is the X1 brand schema from `@shared/graph/ids`. Owners: `pty-host` unless stated. Validators never transform (C1's rule); `z.instanceof(Uint8Array)` checks the realm-local class the structured clone produces at each hop (MessagePort into main, `webContents.send` into the preload, the context bridge into the page), which M2's tests and the smoke prove end to end.

```ts
export const PtyIdSchema = z.string().brand<'PtyId'>();
export const PtyExitSchema = z.strictObject({ exitCode: z.number().int().nullable(), signal: z.number().int().nullable() });
export const PtySpawnInputSchema = z.strictObject({
  appSessionId: AppSessionIdSchema,      // which session the terminal belongs to; a label, the host never reads session state
  label: z.string().min(1),              // the tool's tab-instance id; (appSessionId, label) is unique among live ptys and is how a reloaded renderer re-adopts
  cwd: z.string().min(1),
  cols: z.number().int().positive(), rows: z.number().int().positive(),
  shell: z.string().optional(),          // absolute path; default the login shell (Residue *Terminal environment*); the probe passes a TUI binary here
  args: z.array(z.string()).optional(),  // default ['-l']; the probe passes the TUI's arguments
  command: z.string().optional(),        // written to the pty followed by '\n' right after spawn (C10's attach path)
});
export const PtyInfoSchema = z.strictObject({
  ptyId: PtyIdSchema, appSessionId: AppSessionIdSchema, label: z.string(), pid: z.number().int(), cwd: z.string(),
  shell: z.string(), cols: z.number().int(), rows: z.number().int(), spawnedAt: z.string(),
  alive: z.boolean(), paused: z.boolean(), exit: PtyExitSchema.nullable(),
  offset: z.number().int().nonnegative(),   // total bytes emitted so far
```

### PTY host internals (`src/pty-host/`)

`table.ts` holds `PtyEntry { info: PtyInfo; pty: IPty; ring: RingBuffer(256 KiB); acked: number; flow: 'flowing' | 'paused'; initialCommand?: string }`. All state changes happen on the host's single thread in the order messages arrive, which is the linearization; the transition table is the contract M2's tests pin:

| State | Event | Guard | Action | Next |
|---|---|---|---|---|
| flowing | data(n) | `total + n − acked ≥ HIGH` (256 KiB) | append ring; emit `pty.data{offset: total}`; `total += n`; `pty.pause()` | paused |
| flowing | data(n) | otherwise | append ring; emit; `total += n` | flowing |
| paused | data(n) | (node-pty may deliver chunks already read) | append ring; emit; `total += n` | paused |
| paused | ack(o) | `total − max(acked, o) ≤ LOW` (64 KiB) | `acked = max(acked, o)`; `pty.resume()` | flowing |
| paused | ack(o) | otherwise | `acked = max(acked, o)` | paused |
| flowing | ack(o) | | `acked = max(acked, o)` | flowing |
| any | attach | | `acked = total`; resume if paused; reply `{ info, replay: ring.bytes(), nextOffset: total }` | flowing |
| any | resize(c, r) | alive | `pty.resize`; update info | same |
| any | write(s) | alive | `pty.write(s)` | same |
| any | exit(code, sig) | | `info.alive = false; info.exit = …`; emit `pty.exit` | dead |
| dead | kill | | remove entry | — |
| dead | (1 h since exit) | | remove entry | — |

An ack with an offset above `total` is clamped and logged (a renderer bug, not a crash). `pty.write` and `pty.resize` on a dead pty answer `{ ok: false, error: { code: 'internal', message: 'pty exited' } }`; on an unknown id, C1's `unknown pty`. Node-pty is spawned with `encoding: null` (raw `Buffer`s, forwarded as `Uint8Array` views without copying), `handleFlowControl: false` (the host pauses the pty itself; the in-band XOFF/XON matching is for programs, not for us), `name: 'xterm-256color'`. `initialCommand` is written immediately after spawn (the tty line discipline buffers it until the shell reads; M2's test proves it with zsh and bash).

`env.ts`: `baseEnvironment(): NodeJS.ProcessEnv` returns `process.env` today and X6's captured login-shell environment once C3 exposes it (the one-line swap; overlap flagged); `terminalEnvironment(base, { appVersion }): Record<string, string>` applies Residue *Terminal environment*: the exclusion list `PARENT_SESSION_VARIABLES` (exported, tested), the additions, the locale rule; it never adds `ANTHROPIC_*`, `ENABLE_TOOL_SEARCH` or `CLAUDE_CODE_FORK_SUBAGENT`.

`foreground.ts`: `foregroundOf(entry): { process: string | null; busy: boolean }` reads node-pty's `pty.process` (the foreground process name on macOS); `busy` is `process !== basename(entry.info.shell)` and `process !== null`.

### Terminal registry and store (`src/renderer/src/terminal/registry.ts`, `src/renderer/src/stores/terminals.ts`)

```ts
export type TerminalId = string & z.$brand<'TerminalId'>;     // renderer-assigned; survives "New terminal" (a new pty under the same tab)
export type TerminalStatus = 'starting' | 'running' | 'exited' | 'lost';
export interface TerminalInfo {
  id: TerminalId; appSessionId: AppSessionId; label: string; cwd: string;
  ptyId: PtyId | null; pid: number | null; status: TerminalStatus; exit: { exitCode: number | null; signal: number | null } | null;
  title: string | null; acceleration: Acceleration; visible: boolean;
}
export interface TerminalHandle { readonly info: TerminalInfo; readonly renderer: TerminalRenderer; readonly container: HTMLElement }
export class TerminalRegistry {
  open(init: { appSessionId: AppSessionId; label: string; cwd: string; command?: string }): TerminalId;   // creates the handle; spawns on first mount (needs a measured size)
  adopt(): Promise<void>;                     // pty.list → for each live pty, a handle with pty.attach replay (called once at renderer start)
  get(id: TerminalId): TerminalHandle | undefined;
  mount(id: TerminalId, parent: HTMLElement): void;   // appends the container, setVisible(true), fit, resize, focus if requested
  unmount(id: TerminalId): void;              // detaches the container, setVisible(false)
  respawn(id: TerminalId): Promise<void>;     // exited or lost → new pty, same cwd and label; the old screen is cleared
  close(id: TerminalId): Promise<void>;       // pty.kill then dispose
  foreground(id: TerminalId): Promise<{ process: string | null; busy: boolean }>;
  subscribe(cb: (infos: TerminalInfo[]) => void): () => void;   // feeds the Zustand store
}
export const terminals: TerminalRegistry;     // one per page; subscribes to pty.data, pty.exit, pty.hostState and settings.changed once
```

The registry is the only subscriber of `pty.data`; it dispatches by `ptyId`, drops events whose `offset` is below the handle's `nextOffset`, calls `renderer.write(data, () => ackUpTo(offset + data.byteLength))`, and coalesces acks (Residue *PTY stream and flow control*); hidden handles ack on a 250 ms tick, capped at 256 KiB per tick. `settings.changed` rebuilds the theme through `theme.ts` and pushes it to every handle. `pty.hostState` transitions to `crashed` or `restarting` mark every live handle `lost` (the supervisor's `pty.exit` events arrive too; both paths converge). The Zustand store holds `TerminalInfo[]` only; handles are never in React state.

### M2 — PTY host

At the end of M2 the host speaks the `pty.*` set of Interfaces: output arrives as `Uint8Array` with offsets, a flooding program is paused at the high watermark and resumed on acks, a reconnecting renderer gets the ring buffer and the resume offset, shells start as login shells with the terminal environment, a spawn can carry a typed command, `pty.list` and `pty.foreground` answer, and C1's echo smoke still passes with the diagnostics strip decoding bytes. Touches: `src/shared/ipc/schema/pty.ts` and its test, `src/pty-host/{index,table,flow,env,foreground}.ts` and tests, `src/main/ipc/router.ts` (`pty.openLink`), `src/renderer/src/app/Diagnostics.tsx` (decode), `e2e/smoke.spec.ts` (only if it inspects the payload), `src/renderer/src/harness/Probe.tsx` (ack path).

Exposes: the `pty.*` registries, `PtyTable`, the flow transition table as tests, `terminalEnvironment`, `PARENT_SESSION_VARIABLES`. Consumes: C1's host runtime and supervisor, node-pty.

Decisions local to M2: the flow state machine is the transition table in Interfaces, implemented in `flow.ts` as a pure reducer over `{ total, acked, state }` so the watermark logic is tested without a pty; each node-pty chunk is copied into an exact-size `Uint8Array` before it is emitted (a view over one of Node's pooled `Buffer`s would carry the whole pool through structured clone), which is the host's one copy per chunk besides the ring buffer; the ring buffer is a fixed 256 KiB `Uint8Array` with a write cursor and `bytes()` returning the ordered tail; `pty.attach` on a dead pty returns the ring with `info.alive: false` (the reloaded renderer shows the dead screen and the exit bar); `pty.kill` on a live pty sends SIGHUP and the entry is removed when `onExit` fires, not before; dead entries expire after one hour on a timer that is `unref`'d; `pty.openLink` in main checks `new URL(url).protocol` against `http:`, `https:`, `mailto:` and calls `shell.openExternal`, answering `{ opened: false }` otherwise. `baseEnvironment()` is the single seam C3 replaces (overlap flagged); `appVersion` for `TERM_PROGRAM_VERSION` is the package version imported from `package.json` at bundle time, so the supervisor's fork call stays C1's.

Does not touch: the renderer adapter beyond the probe's ack wiring, the registry, the tool, tokens.

## Surprises & Discoveries

- Observation: ghostty-web is not a viable primary as of authoring, on paper, before the spike runs: last stable 0.4.0 (2025-12-09), prereleases to `0.4.0-next.20` (2026-06-28), no push since 2026-07-02, 62 open issues; on 0.4.0 Korean IME fails (#119), OSC 8 `getHyperlinkUri()` returns null (#137), a WASM heap-corruption fix (bec9e16) is unreleased, synchronized output is never honoured by its renderer, the Kitty encoder is unwired, WASM ships as a `data:` URI that a strict CSP blocks (#188), and `write`'s callback fires on the next frame with no backpressure.
  Evidence: research pass 2026-09-28 against npm metadata, the repository and the 0.4.0 tarball (`ghostty-vt.wasm` 423 KB, `ghostty-web.js` 682 KB with the WASM inlined); issue numbers as cited. The spike still runs it, because G1 binds and the observed failure is the record.
- Observation: xterm.js 6.0.0 (2025-12-22) supports mode 2026 (#5453, one-second safety timeout) and OSC 8, but answers XTVERSION and offers the Kitty keyboard protocol only in the 6.1 betas (through `6.1.0-beta.304`, 2026-08-30), where Kitty mode drops single-character IME commits (#6112). Claude Code 2.1.283 sends XTVERSION, `CSI ? u`, and queries mode 2026 only if XTVERSION was answered, otherwise falling back to a `TERM_PROGRAM` allowlist or `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1`; Codex wraps every frame in crossterm's synchronized update and pushes Kitty flags (`CODEX_TUI_DISABLE_KEYBOARD_ENHANCEMENT` turns them off).
  Evidence: `~/claude-code-bundle/2.1.283/cli.pretty.js` around the terminal-capability probes; openai/codex `tui.rs` and `keyboard_modes.rs` at rust-v0.158.0; xtermjs/xterm.js #5453, #5600, #6112. Consequence: Residue *Terminal environment* sets the force variable; Kitty is deferred.
- Observation: Chromium keeps at most 16 live WebGL contexts per renderer process and evicts the oldest; two other Electron terminal apps hit it (blank panes). Electron can raise it with `--max-active-webgl-contexts`.
  Evidence: `kMaxActiveWebGLContexts` in Chromium; agent-orchestrator #5662; abundio PR #171 (caps live contexts at 12). Consequence: Residue *WebGL policy*.
- Observation: a CSP with `script-src` that lacks `'wasm-unsafe-eval'` (and `'unsafe-eval'`) blocks WebAssembly from loading at all; C1's production CSP is `script-src 'self'`.
  Evidence: MDN, CSP `script-src`, "Unsafe WebAssembly execution" (read 2026-09-28). Consequence: the harness-only CSP sources in M1; a ghostty promotion would amend C1's *Window security defaults* residue.
- Observation: xterm.js's flow-control guide caps the recommended high watermark at 500 KB and warns that past a ~50 MB internal buffer, data is dropped; its buffer costs 12 bytes per cell.
  Evidence: xtermjs.org/docs/guides/flowcontrol; `BufferLine.ts` cell size. Consequence: the 256/64 KiB watermarks and the 168 MB flood in acceptance item 8, which would lose data without host-side pausing.
- Observation: node-pty 1.1.0 exposes `pause()`/`resume()` for host-driven flow control and `process` for the foreground process name; `handleFlowControl` is an in-band XOFF/XON matcher meant for programs, not hosts.
  Evidence: `typings/node-pty.d.ts` at v1.1.0. Consequence: the host pauses the pty itself.
- Observation: reported edge cases in xterm.js hosts for the two TUIs: Codex's inline-mode scroll-region inserts leave gaps (openai/codex #27644, including an Electron embed); Claude Code's SGR mouse sequences can leak into the composer (anthropics/claude-code #66289).
  Evidence: the issues as cited. Consequence: spike items 12 and 13.
