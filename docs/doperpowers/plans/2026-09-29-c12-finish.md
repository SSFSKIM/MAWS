## Purpose

C12 makes P0 a daily driver and hands the owner a sitting that can close it. After C12:

- **Many sessions stay cheap.** MAWS keeps every session live that memory allows. When the sum of the engine process trees passes a budget (25% of physical memory by default, 8 GB on the owner's 32 GB Mac), it releases the least recently used idle session that holds nothing the owner could lose. A released session reads idle in the sidebar and on the Overview with a quiet "released" mark, raises no notification and no Needs-you item, and Session info says when and why. Typing in it and pressing Send resumes it through C10's resume path, with its queue and session grants intact, in about a second. When the budget is exceeded and every live session holds work, nothing is stopped: one app-wide banner says so and offers each session's stop behind C10's disclosure of what would end.
- **The engine cannot vanish under MAWS.** The installer keeps five versions and the pin (2.1.283) is already the third oldest (grounding §0 item 4). MAWS copies the pinned binary into its own `userData` at pin time and launches from the copy, with a checksum recorded; a missing copy is a clear refusal that names the fix.
- **Quitting never ends work silently.** The quit question counts sessions mid-turn, sessions running background tasks or workflows, and terminals running a command, and offers "Quit when idle". The same question, worded "Restart to update" and "Restart when idle", is ready for the updater that P1 brings.
- **An owner-only build exists.** `pnpm build:owner` produces `dist/mac-arm64/MAWS.app` from source, development-signed when the owner names an identity, unsigned otherwise. Signing, notarization and the updater are written below as deferred P1 milestones with their preconditions.
- **The residue is swept.** A "Worktrees…" dialog on the project menu is the lasting entry point to every worktree of a repository. The launch environment mirrors the owner's terminal after a probe. The session title no longer follows the latest prompt. The last stale "Arrives with" reasons are gone.
- **The sitting is ready.** Agents pre-run every §10 item they can under a scratch config home through Playwright over the built app and commit an evidence pack. The owner gets a numbered script for the items only the real home or human hands can observe, and the architect gets a recomposition checklist against §10.

What C12 does not do: the prewarmed spare (P1, D2); a user-facing spend cap (D3); signing, notarization, DMG, ZIP, the updater or a feed (P1, D7); re-pinning the engine (after P0, D6); the keyboard map editor (C11's); the debt-wave-4 rows that are not listed under "Tracker rows" below (the architect's wave, a precondition of M4); split-pane polish beyond what the owner names after the sitting (D11); the owner's sitting itself, C8's and the charter's recomposition, the scale review and §20 (the architect's closing act, §12 C12's Cut line).

## Terms

- **Tree**: an engine process and every descendant, measured as the sum of their resident set sizes by C3's sampler (one `ps -axo pid=,ppid=,rss=` every 10 s, `src/engine-host/process-table.ts:14,31-61`), reported as `EngineSessionStatus.memory.treeRssKiB`. Shared pages are counted once per process, so the sum overstates what the machine loses; the grounding measured one idle owner-settings tree at 418,688 KiB alone and three together at about 270 MB each (grounding §1.2). The budget uses the sum as measured, which errs toward releasing early.
- **Budget**: the limit on the sum of the trees of every live engine process MAWS owns. Default: 25% of physical memory (`os.totalmem()`), 8 GiB on the owner's Mac; a setting overrides it.
- **Hard reason**: something a process holds that an exit would lose or interrupt: an open turn (any origin), background tasks or workflows, a pending request (a broker item, or a clear-and-implement plan kept for retry), queued messages (paused or not), a held peer message, and a connected MCP server whose name is in the stateful list. Session grants are not a hard reason, because the snapshot re-applies on resume.
- **Stateful server**: an MCP server name the owner lists in Settings › Engine because the server keeps state that dies with its process (the owner's ptc kernel is the likely one; unverified whether it does). Names are matched exactly as `system/init.mcp_servers[].name` reports them (for example `plugin:ptc:ptc`).
- **Candidate**: a live process in state `ready` with no hard reason and a memory sample. **Release**: MAWS ending a candidate's process through C3's termination ladder with the new exit reason `budget`, least recently used first, one per evaluation. **Released session**: one whose last exit was a release and which has not launched since. **Last used**: the latest of the launch, a turn's end, and any command the human sent to the session (send, steer, answer, interrupt, `!`, `#`, a mode, model or effort change); viewing a session is not use.
- **Over budget with no candidate**: the sum exceeds the budget on two consecutive samples and no candidate exists. The only response is the banner.
- **Custody copy**: `<userData>/engine/<version>/claude`, a copy of the installer's `<source>/<version>` where `<source>` is `dirname(ENGINE_BIN)`, `/Users/new/.local/share/claude/versions` (C3's `src/engine-host/launch.ts:11`), beside a `manifest.json` recording version, SHA-256, size, source path and copy time. **Pin time**: the first start at which the pinned version has no custody copy, and every re-pin. **Re-pin**: moving `settings.engine.pinnedVersion` to another engine version after the re-probe §15 requires; documented here, not run (D6).
- **Busy work** (D8): a session mid-turn or still launching, a session with running background tasks or workflows, and a terminal whose shell has a foreground command (C9's `pty.foreground` answering `busy: true`).
- **Pre-run**: the agents' run of §10 under a scratch `CLAUDE_CONFIG_DIR` through Playwright over the built app (M4). **Evidence pack**: what the pre-run commits under `docs/doperpowers/evidence/c12/`. **Owner's script**: the numbered steps only the owner can run, on the real config home or by hand. **Recomposition checklist**: the table the architect completes from the evidence pack and the owner's results.
- **Scratch home**: a throwaway `CLAUDE_CONFIG_DIR` made by C3's `scratchConfigHome()` (`test/live/support/live.ts:92`) and checked by `assertConfigHomeSafe` before anything spawns; with it, a throwaway `MAWS_USER_DATA` and scratch repositories under `/private/tmp`.

## Interfaces and Dependencies

### The policy (`src/engine-host/budget.ts`, new)

```ts
export const DEFAULT_BUDGET_FRACTION = 0.25;
export const EXITED_RING = 500;          // events an exited stream keeps in memory; older ranges rebuild from the journal
export const EXITED_ROWS_MAX = 24;       // exited rows the host keeps; the oldest exit goes first
export type HardReason = 'turn' | 'background_tasks' | 'pending_request' | 'queued_messages' | 'held_peer_message' | 'stateful_mcp';
export interface BudgetPolicy { limitKiB: number; statefulMcpServers: readonly string[] }
export function hardReasons(s: EngineSessionStatus, stateful: ReadonlySet<string>): HardReason[];
export interface BudgetVerdict {
  totalKiB: number; limitKiB: number; over: boolean; unmeasured: number; // live rows with no sample yet (counted as 0)
  release: AppSessionId | null;                                          // at most one per evaluation
  blocked: { appSessionId: AppSessionId; reasons: HardReason[] }[];      // live rows that are not candidates, with why
  candidates: number;
}
export function evaluate(rows: readonly EngineSessionStatus[], policy: BudgetPolicy, stateful: ReadonlySet<string>): BudgetVerdict;
```

Rules, each pinned by a unit test: the sum covers every row whose process is not `exited`; `hardReasons` maps `turn !== null` → `turn`, `backgroundTasks.length > 0` → `background_tasks` (ambient tasks included unless C3's definition of `ambient` shows they are not the owner's work; the executor records which), `pendingRequests > 0 || pendingPlan !== null` → `pending_request`, `queue.length > 0` → `queued_messages`, `heldPeerMessages.length > 0` → `held_peer_message`, a `connected` server whose name is in the set → `stateful_mcp`; grants and non-stateful servers never appear; a candidate is `process === 'ready'` with no reason and `memory.treeRssKiB !== null`; `release` is the candidate with the oldest `lastUsedAt` (ties by `appSessionId`) and is non-null only when `over`; the function is pure and never reads the clock. The exited-history caps (`EXITED_RING`, `EXITED_ROWS_MAX`) belong to the same policy: the table applies them at the same evaluation, and a release trims the released session's ring at its exit like any other.

### Engine custody (`src/main/engine/custody.ts`, new)

```ts
export interface CustodyManifest { version: string; sha256: string; size: number; source: string; copiedAt: string }
export type Custody =
  | { state: 'ok'; path: string; manifest: CustodyManifest }
  | { state: 'missing' | 'mismatch' | 'version'; path: string; message: string };
export function custodyPath(userData: string, version: string): string;   // <userData>/engine/<version>/claude
export async function ensureCustody(o: { userData: string; version: string; sourceDir: string }): Promise<Custody>;
```

At pin time `ensureCustody` copies `<sourceDir>/<version>` to a temporary name beside the target with `fs.copyFile(…, COPYFILE_FICLONE)` (an APFS clone when both paths are on one volume, a full copy otherwise), sets mode 0755, runs `--version` on the copy by absolute path, computes SHA-256, writes `manifest.json`, then renames into place. At every start it re-hashes the copy and compares with the manifest (the cost is measured and recorded; if over one second, the size and mtime are compared at start and the hash in the background before the first launch). Answers: `missing` when neither the copy nor the source exists, `mismatch` when the hash differs, `version` when `--version` disagrees; each message names the version, the custody path and the fix (`Re-pin in Settings › Engine`). Main's configure sends `binaryPath: settings.engine.binaryPath ?? custody.path` to C11's `engine.configure`, so a refusal surfaces through C3's existing `binary_missing` or `binary_version` launch refusal with the custody path in its message; a path the owner chose in Settings is used as chosen, without custody. C11's re-pin confirm runs `ensureCustody` for the new version before writing `pinnedVersion`. Tests and the live supports keep `ENGINE_BIN` as the installer path they read; the source directory is overridable only in development builds (`MAWS_ENGINE_SOURCE_DIR`, refused when `app.isPackaged`) so acceptance can delete a scratch source.
