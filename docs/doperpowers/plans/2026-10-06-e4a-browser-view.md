## Purpose

After E4a the owner opens web pages inside MAWS. A session has its own browser tabs (P-21): the right panel's Browser tool shows the shown session's tabs with Codex's chrome (tabs, back, forward, reload, an address bar that searches history as it is typed, a zoom banner, find in page, a context menu, Open in external browser), and any tab can also open as a main tab for room. The page itself is a real Chromium renderer, a `WebContentsView` main owns and lays exactly over the pane the renderer measures, hidden and replaced by a frozen picture whenever a sheet, the palette, a menu or a dialog would draw over it, and back within a frame when the layer closes. A page that fails to load shows Codex's error page for its state; `file:` and the app's own schemes are refused; a page's permission requests are denied with a banner; a download the owner starts goes through a save dialog; pages open in their own persistent partition, never the app's session, and the chrome says which profile is browsing. Visited pages feed a MAWS-owned history table that the address bar suggests from. Tabs survive a relaunch as suspended `{url, title}` entries that load only when asked. The agent asks for a page with `show_pane 'browser' {target}` and the tab opens in the panel. Underneath, E4a lays the seams the other three children build on: the `BrowserTab` model with its `control` field and the "You have the page · Hand back" slot, one `TabDebugger` per tab for E4c's tools, E4b's CHIPS import and E4d's crop, and the main-side input attribution hooks A-33 measured.

To see it: open a session, add Browser from the panel's "+", type `wikipedia.org` and press Enter; the page loads in the panel; ⌘K opens the palette over it and the page freezes into a picture until Esc; drag the panel's edge and the page follows; close MAWS and relaunch: the tab is listed, unloaded, offering its last URL.

## Terms

- **Tab**: one `BrowserTab` (`src/shared/browser/tab.ts`, new): MAWS's record of a browser page, owned by main, belonging to one session (`appSessionId`, P-21), identified by `tabId` (`b_` plus 12 hex characters). **Loaded**: the tab has a `WebContentsView`. **Suspended**: it has none, only `{url, title, favicon}`; every tab is suspended at relaunch and past the loaded-tab cap.
- **View**: the tab's `WebContentsView` (Electron 44.4.5, `electron.d.ts:18947`), created in the tab's **partition** session (`persist:maws-browser` by default; `persist:maws-chrome-<profileDir>` for an imported profile, E4b), never the default session.
- **Pane**: the DOM element in MAWS's renderer where a tab's page is shown: the body of the Browser panel tool (X5) or of a `browser` main tab (X14). **Placement**: the pane's rect, reported to main through `browser.view.place`; a tab is placed in at most one pane at a time. **Cover**: the state in which main hides every placed view of a window because a layer draws over the renderer (`browser.view.cover`); the **placeholder** is the picture of the page the renderer shows meanwhile.
- **Chrome**: the renderer-drawn controls around the pane: the tab strip, the navigation row (back, forward, reload or stop, the address bar, the partition pill, the control slot, the overflow menu), the zoom banner, the find bar, the notice banners.
- **Layer**: anything the renderer draws that can overlap a pane: a modal sheet or dialog (Radix `Dialog`, `AlertDialog`; the palette; the slash-widget dialog), a non-modal popper (Radix `DropdownMenu`, `ContextMenu`, `Popover`, `HoverCard`), the floating Overview, and the chrome's own address suggestions.
- **Load error**: a main-frame `did-fail-load` (`errorCode` not `-3`), classified into Codex's six states: `dns`, `offline`, `refused`, `timeout`, `certificate`, `generic`.
- **History row**: one `(partition, url)` in the index table `browser_history` (migration 5), with `visit_count`, `typed_count`, `last_visit_ms`, `title`, `source`.
- **Control**: the tab's `control: 'idle' | 'agent' | 'human'` with `controlSince`; E4a defines the field, the `handBack` command, the `changed` event and the chrome slot; E4c supplies every transition but `handBack`'s.
- **`TabDebugger`**: the one `webContents.debugger` attachment per tab (`src/main/browser/debugger.ts`, new), Playwright-agnostic, shared by E4c's bridge, E4b's CHIPS import and E4d's crop; it owns the in-flight `Input.*` command table the attribution reads.
- **Attribution**: main's reading of each input to the view as the human's or the agent's (A-33): keys through `before-input-event` and the from-debugger bit, mouse buttons through `before-mouse-event` matched against in-flight `Input.dispatchMouseEvent` commands, wheels through the bit.
- **Engine host**, **main**, **renderer**, **X1 event**, **replay**, **scratch profile**, **harness**: as E1's and E2's documents define them. E4a touches the engine host nowhere.

## Design (the residue §3 D and E4's cut leave open, with reasons)

### 1. Ownership and data flow

Main owns every tab: the `BrowserTab` records, the views, the partitions, the history writes, the persistence file and the per-tab `TabDebugger`. The renderer owns the chrome and the pane, holds a mirror of the tabs (`useBrowser` store, `src/renderer/src/tools/browser/store.ts`) fed by `browser.tabs.list` once and `browser.tabs.changed` after, and tells main two things it alone knows: where a pane is (`browser.view.place`) and when a layer covers the window (`browser.view.cover`). Every page string the renderer shows (title, URL, host, favicon) comes from main as data and is rendered as text or a `data:` image, never as markup. The engine host is untouched; E4c reaches these tabs through main later. Nothing in main waits on the renderer: a placement that never arrives leaves the view unattached, a cover that never lifts leaves it hidden, and both are visible in `browser.tabs.changed` (`placedIn`, `covered`) so the e2e and E4c can see them.

### 2. The tab model and store (G1, G4; the `BrowserTab` contract)

`BrowserTabSchema` (`src/shared/browser/tab.ts`, strict), the ledger's fields first and E4a's additive ones after:

```ts
BrowserTab = {
  tabId: string (/^b_[0-9a-f]{12}$/), appSessionId: AppSessionId, partition: string,
  url: string, title: string, favicon: string | null,            // favicon: a data: URL main built (Design §7), never the page's URL
  loading: boolean, canGoBack: boolean, canGoForward: boolean, zoom: number,   // zoom: Chromium's factor, 1 = 100%
  control: 'idle' | 'agent' | 'human', controlSince: string,     // ISO; E4c moves it, E4a only to 'idle' through handBack
  suspended: boolean,
  // E4a additive
  loadError: { url: string, host: string, kind: 'dns' | 'offline' | 'refused' | 'timeout' | 'certificate' | 'generic', code: number, description: string } | null,
  crashed: { reason: string } | null,                            // render-process-gone's reason until the next committed navigation
  failed: { message: string } | null,                            // the view could not be created (Design §15); Retry clears it
  unresponsive: boolean,
  blockedPopups: number,                                         // window.open calls denied by the gate since the last navigation (Design §14)
  find: { active: number, matches: number } | null,              // the open find bar's last result
  denied: { host: string, permission: string }[],                // this document's denied permission requests (cleared on navigation; at most 8)
  download: { name: string, state: 'progressing' | 'done' | 'cancelled' | 'failed', received: number, total: number, path: string | null } | null,
  memoryKiB: number | null,                                      // the renderer process's working set from the last sample; null while suspended or unsampled
  placedIn: { paneId: string, surface: 'panel' | 'main' } | null,  // the owning pane's token (Design §3); a pane compares its own
  covered: boolean,                                              // main hid the view for a layer
  createdAt: string, lastShownAt: string,
}
```

The store (`src/main/browser/tabs.ts`): `Map<tabId, TabEntry>` where `TabEntry = { tab: BrowserTab; view: WebContentsView | null; debugger: TabDebugger | null; placement: Placement | null; … }`, plus `selected: Map<appSessionId, tabId | null>` (what the panel tool shows for a session; also what E4c's `browser_tabs select` moves). Changes go through one `update(tabId, patch)` that bumps a per-session dirty flag and emits `browser.tabs.changed { appSessionId, tabs, selected }` for that session on the next macrotask (coalesced: a page load produces a dozen changes in a frame). The whole list per session is sent rather than a patch because a session has few tabs and the renderer's reducer is then trivial.

**Opening.** `browser.tabs.open { appSessionId, url, select, reuse?, requestId? }`: `url` is validated (Design §14) or `null` (a new empty tab); a loaded view is created only when the tab is placed or `url` is given; `select` makes it the session's selected tab; `reuse: 'url'` selects an existing tab of the session at the same normalised URL instead of opening one (Decision Log 7); a repeated `requestId` within 10 s answers the tab the first call made (two windows handling one `maws.pane.show`). Page-driven opens (`window.open`, `target="_blank"`) arrive through `adoptChild` instead (Design §14). **Closing.** `browser.tabs.close { tabId }` destroys the view (`webContents.close()`), detaches the debugger, drops the entry, and selects the neighbour (the next tab, else the previous) for the session. A session whose record is deleted closes its tabs: the browser service subscribes to `SessionStore.onChange` (`src/main/index/sessions.ts:504`) and acts on `cause === 'removed'` (`ChangeCause`, `:28`; every deletion path reports it, `bindRow`'s included); at boot, tabs whose session the index does not know are dropped from the file. Archiving changes nothing (the tabs stay, suspended or not).

**Persistence (G4).** `<userData>/browser/tabs.json`: `{ version: 1, tabs: [{ tabId, appSessionId, partition, url, title, favicon, zoom, createdAt, lastShownAt }], selected: { [appSessionId]: tabId | null } }`, written through `atomicWriteFile` (`src/main/files/atomic-write.ts:14`) at most once per 300 ms while dirty and synchronously at `will-quit` (`atomicWriteFileSync`, `:33`). At boot every entry is restored **suspended** (`suspended: true`, no view, `loading: false`, `control: 'idle'`, `loadError: null`); `url` and `title` are what the pane's empty state suggests (X14). A suspended tab loads when the human presses its "Open <url>" button or types an address, or when E4c navigates it. The ledger's X14 rule holds for a `browser` main tab on a disk-only session too (Design §13): nothing differs between a session MAWS launched and one found on disk.

**The loaded-tab cap (Design §12).** `BROWSER_LOADED_TABS_MAX = 12` loaded tabs across the app, and `BROWSER_TABS_MEMORY_MAX_MIB = 2048` as a soft cap on the sampled sum of loaded tabs' working sets. Opening or resuming a tab past the count, or a memory sample past the soft cap, suspends the least recently shown loaded tab that is **eligible**: not placed, not loading, not downloading, `control === 'idle'`; the suspension is a `webContents.close()` with `{url, title, favicon, zoom}` kept, and the chrome shows `BROWSER_COPY.tabsCap(n)` through the `browser.notice` event (Interfaces) once per suspension. When no tab is eligible (twelve fresh tabs all loading), `browser.tabs.open` opens the new tab **suspended** (its URL kept as the suggestion) and a page-driven `window.open` is denied and counted (Design §14); nothing is ever force-closed. The reason for 12 and not Codex's 32 (`main-BvBtZhys.js:117250`): E0b measured 114 to 137 MB of working set per renderer on a toy page (`findings.txt:157`; real sites run several times that, which is why the memory cap exists beside the count), so twelve loaded tabs stay under a quarter of the 8 GB default engine budget on the owner's Mac (charter §4.4), while a sitting rarely has more than a handful of pages open at once; both constants are one line to change.

### 3. The view manager and the placement and cover protocol (G3)

`src/main/browser/view.ts`. A tab's view is created lazily: `new WebContentsView({ webPreferences: { partition, preload: <out/preload/browser.js>, sandbox: true, contextIsolation: true, nodeIntegration: false, webSecurity: true, backgroundThrottling: true } })` (pass two's construction, `pass2/main.mjs:121`), its `webContents` wired (Design §4 to §11), and added to a window's `contentView` only when a pane places it.

**Placement has one owner.** `browser.view.place { tabId, paneId, surface, rect: { x, y, width, height } | null, claim: boolean }` comes from a pane; `paneId` is a token minted per mount (`crypto.randomUUID()`), and main keeps per tab `owner: { paneId, windowId, surface } | null`. A report with `claim: true` makes its pane the owner (sent on mount, on "Show here", and whenever a mounted pane sees `placedIn === null` for its tab); a report from a pane that is not the owner is ignored, `null` included, so a pane that lost the view can neither move it nor hide it. Main reads the window from the sender (`BrowserWindow.fromWebContents(context.sender)`), rounds the rect to integers, and: with a rect, attaches the view to that window if it is not there (`removeChildView` from any other window first; a view lives in one `contentView` at a time), `setBounds(rect)`, `setVisible(!covered && shown)`; with `null` from the owner, hides the view and clears the owner (the view stays attached to its last window, hidden, so a reselection is one `setVisible`). `placedIn` carries `{ paneId, surface }`, so a pane compares its own token and never needs its window id: a pane whose token is not `placedIn.paneId` stops reporting, drops its observers' effect, and draws `BROWSER_COPY.shownElsewhere` with a "Show here" button that claims again; when the owner unmounts (the panel's selected tab changes, `ToolBody.tsx:3`: only the selected body is mounted) and `placedIn` turns null, the other mounted pane claims on its own, so a main tab takes the page back as soon as the panel moves on. Two panes claiming in the same frame settle on the last claim, deterministically. The rect is in CSS px of the window's content area, which under `hiddenInset` equals the window's bounds and maps 1:1 onto `setBounds` (E4-0, `findings-pass2.txt:181-185`); the renderer rounds before sending and sizes the pane on integer px (a sub-pixel seam otherwise, `:185-186`). A rect with `width < 1` or `height < 1` (a collapsed panel keeps its column at 0 and stays mounted, `Shell.tsx:2`; a maximized panel hides the main area, `:24`) is sent as `null`.

**The window's own renderer reloading or crashing** (⌘R is the View menu's `reload` role, `src/main/menu.ts:125`, and a browser user presses ⌘R with focus in the address field): on the app window's main-frame `did-start-navigation` that is not same-document, and on its `render-process-gone`, main clears that window's cover state and every owner whose `windowId` is that window, and hides those views; the fresh renderer's panes claim again on mount. Without this, a cover never lifts and stale views draw over the reloading UI.

`shown` is false while the tab has a `loadError` or `crashed` (the renderer draws the error page in the pane instead) and while it is suspended. `setBorderRadius` is not used (the pane's corners are square in both surfaces).

**The renderer's half** (`src/renderer/src/tools/browser/Pane.tsx`): a `ResizeObserver` on the pane element reports its own size changes within the frame (the probe's route: 3.2 ms median from a window resize to the applied bounds, `findings-pass2.txt:188-191`); a subscription to the layout store (`useLayout.subscribe`) reports on the next animation frame after any `regions` or `main` change, which is how position-only moves (the sidebar collapsing, a split moving, the panel resizing from its other edge) reach main, since a `ResizeObserver` does not fire for them; `window.resize` reports too. During the Resizer's drag the store changes on every pointer move, so the rAF report runs once per frame as the probe's drag did (60 of 60 frames within one frame, `:192-193`). On unmount the pane sends `rect: null`. Nothing is interpolated or throttled beyond one report per frame; main applies at once (`:267-270`).

**Cover.** The renderer sends `browser.view.cover { covered: true }` when the first layer that can overlap a pane opens and `{ covered: false }` when the last closes; main, for every view placed in the sender's window: if the view's `webContents.isFocused()`, calls `win.webContents.focus()` first (the native first responder would otherwise stay in the hidden page and take the sheet's typing and its Esc); hides the view (`setVisible(false)`, 0.27 ms, `:206`); then takes `capturePage()`, which works while hidden (5 ms, `:207`; hiding first keeps the sheet from painting over a still-visible page during the capture), resizes the image to 1× (`nativeImage.resize` at the view's CSS size; a DPR-2 capture of a main-tab pane would exceed the bound), encodes it as JPEG at quality 80 and emits `browser.view.covered { tabId, placeholder: 'data:image/jpeg;base64,…' | null }` (null past 400 KiB or on a throw); the pane draws the placeholder as an `<img>` filling the pane under the layer (the sheet's `bg-bg/60` overlay then dims the page as Codex's does rather than a blank), and drops it when `browser.tabs.changed` shows `covered: false`. A capture that fails (a page that has never painted throws "Current display surface not available", `:200-201`) yields `placeholder: null` and the pane shows its `bg-bg` background. Cover is per window: a sheet in one window hides nothing in another; the cover carries no tab ids because the renderer knows the layer and main knows the placed views (Decision Log 20).

**Which layers cover** (Decision Log 2): the renderer's `cover.ts` watches `document.body`'s direct children with one `MutationObserver` (`childList: true`, no subtree) and classifies each child `el` **in this order**, because Radix portals render with `asChild` (`react-portal`'s `createPortal(…, document.body)`), so the body child *is* the dialog element or the popper wrapper, and a Popover's content carries `role="dialog"` inside a popper wrapper (`@radix-ui/react-popover/dist/index.mjs:245`, `react-popper/dist/index.mjs:200`): (1) `el.matches('[data-radix-popper-content-wrapper]')`: a popper (every `Popover`, `DropdownMenu`, `ContextMenu`, `HoverCard`, `Tooltip`); it covers when, measured after two animation frames (floating-ui positions asynchronously) and re-measured on its own resize, its rect intersects a placed pane's rect, except a wrapper containing `[role="tooltip"]`, which never covers (small, transient, and the chrome's own controls use native `title` tooltips, which macOS draws above every view); (2) else `el.matches('[role="dialog"], [role="alertdialog"]') || el.querySelector(…)`: modal, covers while mounted (every `Sheet`, the palette, the widget dialog, `InlineEdit`'s confirm, the resume picker; Grounding "Layers"); (3) else any other body child but `#root` and `[data-radix-focus-guard]`: the intersection rule (the composer's `@` and `/` popups, which `@tiptap/suggestion` mounts into `body` without any Radix marker, `node_modules/@tiptap/suggestion/dist/index.js:343-375`, `composer/mentions/popup.tsx`). The floating Overview (`overviewOpen`, `overview/OverviewPanel.tsx:59-67`) covers while open. The chrome's own address suggestions (Design §4) are a layer too and cover while shown (so the list draws over the frozen page as an omnibox popup does). **Toasts** are not body children: the viewport is `absolute right-3 bottom-3 z-40` inside the shell (`app/ToastHost.tsx:49`), which is exactly where a panel browser's pane sits, so `cover.ts` observes the viewport's `li` children with a second observer and applies the intersection rule to each; E4a's own notices therefore never go through toasts (they would freeze their own page) and are chrome notices (Design §4, `browser.notice`). A covered view is a hidden page (no `requestAnimationFrame`); E4c's actionability waits say so in their row (A-33). `cover.test.ts` mounts the real Radix `Dialog`, `Popover`, `DropdownMenu` and `Tooltip` in happy-dom rather than hand-made wrappers, so the classifier is pinned against the library's DOM.

**Visibility and focus emulation (M0; Decision Log 1).** `src/main/browser/visibility.ts` exports `FOCUS_EMULATION: 'off' | 'on'`, set by M0's verdict and overridable by `MAWS_BROWSER_FOCUS_EMULATION=0|1`. With `on`, the `TabDebugger` attaches at view creation (never detached on idle) and sends `Emulation.setFocusEmulationEnabled { enabled: true }` after each `did-navigate` and `render-process-gone` recovery, and `{ enabled: false }` while the tab is covered, unplaced, or its window is hidden or minimized (else a hidden page keeps painting, `findings-pass2.txt:262-263`); `document.hasFocus()` then reads true in the page whatever the window's state, a cost A-33 accepts. With `off`, nothing attaches until E4c's bridge needs it.

### 5. The error pages (G2)

Main classifies each main-frame `did-fail-load` whose `errorCode` is not `-3` (`ERR_ABORTED`: a navigation replaced by another, never an error to show) with `classifyLoadError(code, description)` (`src/shared/browser/errors.ts`, pure, Codex's table `main-BvBtZhys.js:90639-90671`): `ERR_NAME_NOT_RESOLVED`, `DNS_PROBE_POSSIBLE` → `dns`; `ERR_INTERNET_DISCONNECTED` → `offline`; `ERR_CONNECTION_REFUSED` → `refused`; `ERR_CONNECTION_TIMED_OUT`, `ERR_TIMED_OUT` → `timeout`; `ERR_CERT_*` → `certificate`; everything else → `generic`. `certificate-error` is never overridden (`callback(false)`; the load then fails with its `ERR_CERT_*`, and the page offers no "proceed anyway" in P1). The tab records `loadError { url: validatedURL, host: hostOf(url), kind, code, description }`, keeps `url` as the failed URL in the address field (Codex's `pendingUrl`, `:116281`), re-reads `canGoBack`/`canGoForward`, clears `loading`, and main hides the view (Design §3 `shown`).

**The lifecycle** (Decision Log 23): `loadError` and `crashed` are cleared at the next main-frame `did-navigate` (a committed, non-error navigation: Electron emits `did-navigate` only from the non-error branch of `DidFinishNavigation`, and `did-fail-load` for a committed error page, so the error page's own commit never clears the flag) and at any navigation command (`browser.tabs.navigate`, a typed address, E4c's navigate), which sets `loading` and un-hides the view as soon as the new page commits. Back or Forward away from an error entry commits the neighbour and clears; Back into an error entry re-runs the failed load and fails again, setting it anew. `tabs.test.ts` pins the sequences start → fail → back → navigate, commit → fail (a late main-frame failure after content, which this child treats like any other: error page and hidden view, recorded in Surprises if a real site produces it), and fail → fail (two refused hosts in a row). Tab state never comes from `loadURL`'s promise (it rejects on every `did-fail-load`, superseded navigations included, `electron.d.ts:18461-18466`): every `loadURL` is `void`ed and the events are the only source.

The renderer draws the page in the pane (Decision Log 3; Codex loads HTML into its view, `:90440-90627`; MAWS draws DOM so the page is themed by tokens, written through `copy.ts`, and reachable by the e2e as the chrome is): the heading `BROWSER_COPY.loadError.heading` ("This site can't be reached"), the summary per kind with the host (`dns`: "{host}'s server IP address could not be found"; `offline`: "{host} could not be loaded because the computer is offline"; `refused`: "{host} refused to connect"; `timeout`: "{host} took too long to respond"; `certificate`: "{host}'s certificate could not be verified"; `generic`: "{host} could not be loaded"), then `BROWSER_COPY.loadError.try` ("Try:") over the list ["Checking the connection", "Checking the proxy, firewall, and DNS configuration"] for every kind but `certificate` (which gets no list), a details disclosure with the four header-and-body pairs Codex ships (Internet connection, DNS settings, "Allow MAWS to access the network in your firewall or security settings" with `appName` MAWS, proxy server), the error code line in `text-fg-faint font-mono` (`ERR_CONNECTION_REFUSED`, or `ERR_FAILED (<code>)` when the description is empty, Codex's `bH`), and a **Reload** button (`browser.tabs.navigate { to: 'reload' }`, which main turns into `loadURL(loadError.url)` since the committed entry is Chromium's error page). The crash page uses the same frame with `BROWSER_COPY.crashed(reason)`.

**Refused addresses** (G2's second half): `resolveAddress` and main's `validateBrowserUrl` (Design §14) refuse `file:`, `maws-deliverable:`, `chrome:`, `devtools:`, `javascript:`, `data:`, `blob:`, `about:` (but `about:blank`, main's own empty document) and every other scheme but `http:` and `https:`; the field shows the refused-scheme banner and keeps the text; main's `will-navigate` refuses the same for a page's own top-level navigations and `will-frame-navigate` for its subframes (Design §14).

### 6. History and suggestions (migration 5)

`src/main/index/browser-history.ts` (`BrowserHistoryStore`, in `Index` beside `sideThreads`) over migration 5:

```sql
CREATE TABLE browser_history (partition TEXT NOT NULL, url TEXT NOT NULL, title TEXT, visit_count INTEGER NOT NULL DEFAULT 0,
  typed_count INTEGER NOT NULL DEFAULT 0, last_visit_ms INTEGER NOT NULL, source TEXT NOT NULL CHECK (source IN ('maws','imported')),
  PRIMARY KEY (partition, url));
CREATE INDEX browser_history_recent ON browser_history(partition, last_visit_ms DESC);
```

Writes: on a main-frame `did-navigate` or `did-navigate-in-page` to an http(s) URL that is not an error page, `visit(partition, url, { typed, at })` upserts the row (`visit_count + 1`, `typed_count + 1` when the navigation came from the address field, `last_visit_ms = at`, `source: 'maws'` on insert; an imported row visited again keeps `source: 'imported'`); `page-title-updated` sets `title` for the tab's current URL. `about:blank`, refused schemes and error pages never reach it. Reads: `suggest(partition, query, limit = 8)` answers rows whose `url` or `title` contains the query case-insensitively, ordered by `typed_count DESC, visit_count DESC, last_visit_ms DESC`, as `{ url, title }`; an empty query answers the eight most recent. E4b's import inserts `source: 'imported'` rows and "Remove imported profile" deletes a partition's rows; retention and a history view are deferred (Deferred). The agent never reads this table in P1 (E0b, `findings.txt:232-233`).

### 7. Favicons and titles

`page-favicon-updated` hands URLs; main fetches them in order until one answers (`session.fetch` on the tab's partition, `electron.d.ts:13232`, so the request carries the partition's cookies as the page's own would; a 5 s deadline each; an `image/*` content type or a sniffed image signature; at most 64 KiB), **sniffs the bytes** (PNG, JPEG, GIF, WebP, ICO by signature; SVG by a `<svg` root after a UTF-8 decode of the first kilobyte) and stores `favicon` as `data:image/<png|jpeg|gif|webp|x-icon|svg+xml>;base64,…` of the **original bytes** (`csp.ts:15` admits `data:` images; the chrome's `<img>` decodes ICO and renders SVG in image context, where no script runs) with a per-(partition, host) cache of 200 entries; anything else yields null. The bytes are never re-encoded through `nativeImage.createFromBuffer`, which reads PNG and JPEG only and returned an empty image for a valid ICO and an SVG on Electron 44.4.5 (the review's experiment), the two formats most `/favicon.ico` sites serve (Decision Log 13). `page-title-updated` sets `title`; an empty title reads as the host in the chrome (Codex's `sji`, `app-shared…js:386228-386250`).

### 8. Downloads and permissions (A-31)

**Downloads.** On the partition session's `will-download`: the tab is found by `webContents.id`; if its `control === 'agent'`, `item.cancel()` and emit `browser.download.refused { tabId, url, filename }` (E4c's tool error reads it; the chrome shows `BROWSER_COPY.downloadRefusedAgent` for 4 s); otherwise `item.setSaveDialogOptions({ defaultPath: join(app.getPath('downloads'), item.getFilename()) })` so Electron shows the native save dialog (above every view), and the tab's `download` follows `updated` and `done` (`progressing` with bytes; `done` with `getSavePath()`; `cancelled`; `interrupted` → `failed`). One download is tracked per tab at a time (a second replaces the line); the file goes where the dialog said and nowhere else. Downloads the app's own pages or E2's frames start are E2's filter's business and never reach this partition.

**Permissions.** On the partition: `setPermissionRequestHandler((wc, permission, callback, details) => { deny; record })` denies every request and appends `{ host, permission }` to the tab's `denied` (deduplicated, at most 8, cleared on the next main-frame navigation), with one carve-out: `clipboard-sanitized-write` is granted when the tab saw **human** input within the last 2 s (the attribution seam, Design §11) and `control !== 'agent'`, since Chrome grants it on user activation without any prompt and a site's Copy button would otherwise fail on every page (Decision Log 12, a precision of A-31 flagged for the architect); `clipboard-read` stays denied. `setPermissionCheckHandler(() => false)` (with the same clipboard carve-out), `setDevicePermissionHandler(() => false)`, `setDisplayMediaRequestHandler((req, cb) => cb({}))` (no capture); a page's fullscreen request is refused through the `fullscreen` permission (so `enter-html-full-screen` never fires); `login` (HTTP authentication) is cancelled (`callback()` with no credentials: the page shows the server's 401; a dialog is deferred). **`select-client-certificate`** on each view's webContents: `event.preventDefault(); callback()` with no certificate, since Electron's default hands the site the first certificate in the owner's keychain or raises a signing prompt (`electron.d.ts:803-809`, `:17613`; nothing in `src/main` handles it today); pinned by a unit test. **`will-prevent-unload`**: `event.preventDefault()`, so a page's `beforeunload` never blocks a close or a navigation the human or the agent asked for (no dialog in P1; Decision Log 26). The banner's copy names the permission as Electron names it (`notifications`, `geolocation`, `media`, …) through a small readable map in `copy.ts` (`permissionName`), falling back to the raw name. The context menu's Copy and ⌘C are native and unaffected.

### 9. The partition layout (the partition and file contract)

`src/main/browser/partition.ts`: `partitionFor(settings.browser.profile, profiles)` answers `'persist:maws-browser'` for `null` and `persist:maws-chrome-<profileDir>` for a `profileDir` that `profiles.json` lists; an unknown `profileDir` falls back to the default with one chrome notice (`browser.notice { kind: 'profileMissing', name }`) and the setting left as it is for E4b's picker to repair. The profile is read at tab creation (`settings.state().settings.browser`, `src/main/settings/index.ts:12-14`); a change applies to tabs opened afterwards and the Settings section says so. Each partition is prepared once (`preparePartition(ses)`): the user agent set to Chromium's without the `Electron/<v>` and `maws/<v>` product tokens (Decision Log 8), the permission handlers (Design §8), the `will-download` handler, and a `webRequest.onBeforeRequest({ urls: ['<all_urls>'] })` filter cancelling `file:` and `maws-deliverable:` requests (defence in depth; the default session's CSP override never applies here, `findings-pass2.txt:183-185`). Spellcheck and `FromPartitionOptions.cache` stay Electron's defaults.

Files under `<userData>/browser/`: `tabs.json` (Design §2); `profiles.json` (E4b writes `{ version: 1, profiles: [{ profileDir, name, partition, importedAt }] }`; E4a reads it when present and answers `browser.profiles.list`); `crops/` (E4d); `import/<uuid>/` (E4b, deleted after use); `<partition>/extensions/<id>/` (E4b). Electron keeps a `persist:` partition's own storage under `<userData>/Partitions/<name>/`, which E4b's "Remove imported profile" clears through `ses.clearStorageData()` and the directory's removal.

### 10. The `TabDebugger` helper (the shared attachment)

`src/main/browser/debugger.ts`, one per `TabEntry`, Playwright-agnostic: `attach()` (idempotent; `webContents.debugger.attach('1.3')`, then `Page.getFrameTree` once for `mainFrameId`, which Chromium keeps across cross-site swaps, `findings-pass2.txt:306-310`), `detach()`, `attached`, **`send(method, params?, sessionId?)` as the only sending path** (the raw `webContents.debugger` is never exposed; E4c's bridge, E4b's import and E4d's crop all call `send`, so every `Input.*` command, the tools' and MAWS's own, enters the **in-flight table** before the send and leaves it on reply or error, carrying `{ id, type, sentAt }` with `type` read from `params.type`; `findings-pass2.txt:143-144`'s "MAWS's own Input.* use must go through the same hook" is enforced by construction), `on(method, listener)` for events (Chromium's `sessionId` passed through, the root session as `''`), `onCommand(observer)` (an observer of `send`'s send and reply phases, the probe's `onCommand` shape, for E4c's logging and rows; it enters nothing itself), `inFlight(kind: 'mousePressed' | 'mouseReleased')` and `consume(kind)` for the attribution, and the `detach` event forwarded. ### 11. The control-state field and the attribution seams (A-33)

`control` and `controlSince` live on the tab; `browser.control.handBack { tabId }` sets `control: 'idle'` (from any state), stamps `controlSince`, and emits `browser.control.changed { tabId, control, controlSince }` (E4c's wait reads it). `src/main/browser/input.ts` (`attachInputSeams(entry)`) subscribes the view's `before-input-event`, `before-mouse-event` and `input-event` and classifies each into `entry.input.emit({ kind: 'key' | 'mouse' | 'wheel', source: 'human' | 'agent' })` by A-33's rules (`findings-pass2.txt:150-170`), as this **decision table** (`classify(hook, event, inFlight)`, a pure function; every row not listed emits nothing):

| hook | event | bit 23 in raw `_modifiers` | in-flight match | emits |
|---|---|---|---|---|
| `before-input-event` | `keyDown` | (absent on this hook) | — | `key` / `human` (CDP keys never raise this hook; `keyUp` and `char` are not counted again) |
| `input-event` | `keyDown`, `rawKeyDown` | set | — | `key` / `agent` (top frame only) |
| `input-event` | `keyDown`, `rawKeyDown`, `keyUp`, `char` | clear | — | nothing (the human's key was already counted on the first hook; counting here would double it) |
| `input-event` | `mouseWheel` | set | — | `wheel` / `agent` |
| `input-event` | `mouseWheel` | clear | — | `wheel` / `human` (the only hook that sees a human wheel) |
| `input-event` | `mouseDown`, `mouseUp`, `mouseMove`, `gestureScroll*` | any | — | nothing (mouse buttons are attributed on the next hook; moves and derived gestures are not events of record) |
| `before-mouse-event` | `mouseDown` | (absent) | an unconsumed `mousePressed` in flight | `mouse` / `agent`, and the entry is consumed |
| `before-mouse-event` | `mouseDown` | (absent) | none | `mouse` / `human` |
| `before-mouse-event` | `mouseUp` | (absent) | an unconsumed `mouseReleased` in flight | `mouse` / `agent`, consumed |
| `before-mouse-event` | `mouseUp` | (absent) | none | `mouse` / `human` |
| `before-mouse-event` | `mouseMove`, `mouseWheel`, others | — | — | nothing |

`entry.input.lastHumanAt` records the time of the last `human` emission (the clipboard carve-out, Design §8, and E4c's hand-back timer read it). The consumer of the emissions is E4c (`control` transitions, the hand-back timer); E4a's own consumers are the clipboard carve-out and the `window.open` gate (Design §14). Unit tests run the table on the probe's recorded shapes (`results/pass2/input.json`, `input2.json`). The bit is undocumented and slated for removal upstream: `input.test.ts` pins `_modifiers` against Electron's version string so an upgrade that drops it fails loudly (E4c carries the fallbacks A-33 names). The preload (`src/preload/browser.ts`, built as a second preload entry, Interfaces) exposes nothing to the page and sends nothing in E4a; E4c's cursor and E4d's hover UI extend it, and main accepts its messages only from a `webContents.id` in the tab map.

### 12. Memory: the sample and the cap

Each loaded tab is a renderer process outside the engine host's budget (the budget sums engine process trees, `src/engine-host/budget.ts:67-83`; a browser renderer is the app's own, and releasing an engine session for browser memory would be wrong). Main samples `app.getAppMetrics()` every 15 s while any tab is loaded, matches `pid` to `webContents.getOSProcessId()` and writes `memoryKiB` (`memory.workingSetSize`, already KiB); the renderer's Session info gains the row **Browser tabs** under Memory budget ("3 loaded · 412 MB · outside the engine budget", `BROWSER_COPY.sessionInfo(loaded, mib)`; none: "No tabs loaded"), read from the `useBrowser` store, so the tab count and its weight are reported beside C12's figures without changing the host's policy (Decision Log 5). The cap is Design §2's 12 loaded tabs.

### 13. Persistence, restore and replay parity (G4, X14)

Covered in Design §2: every tab restores suspended; the pane's empty state suggests the last URL; nothing auto-loads. A `browser` main tab (`{ appSessionId, browserTabId }`) whose `browserTabId` is unknown after a relaunch (closed meanwhile, or the file was lost) shows the session's Browser tool state as a main tab would: the empty state with the tab strip of what exists, headed `BROWSER_COPY.tabGone` ("That tab was closed"), and the toolbar title "Browser". A disk-only session (one MAWS found and never launched) has tabs like any other, since tabs are main's, keyed by `appSessionId`; replaying a transcript opens no tab (nothing in the engine host or the X1 stream names tabs in E4a). `layout.json` keeps the main tabs; `tabs.json` keeps the browser tabs; the two are reconciled at the pane, never at boot.

### 14. Security

- **Every URL is validated in main** (`validateBrowserUrl(input): { ok: true, url: string } | { ok: false, scheme: string }`, `src/shared/browser/url.ts`, pure, used by `browser.tabs.open`, `browser.tabs.navigate`, the `window.open` handler and `will-navigate`): `new URL()` must parse; the protocol must be `http:` or `https:`; `about:blank` is admitted only from main itself (the empty tab), never from a command; the renderer's `resolveAddress(text, searchUrl)` applies the same rule before offering "Go to", and a bare host (`wikipedia.org`, `localhost:3000`, an IPv4 or `[::1]`) is prefixed `https://` (`http://` for `localhost` and loopback addresses), anything with a space or no dot becomes a search through `searchUrl` with `%s` replaced by the encoded text. No renderer string reaches a view unchecked: a command carrying an invalid URL is refused as `invalid_input` by the schema (a `z.string().url()` plus the protocol refinement) before the handler runs.
- **The view's own navigations**: `will-navigate` prevents a top-level navigation to a non-http(s) URL (a `mailto:` is handed to `openExternalUrl`, which admits it, Decision Log 27; any other scheme is refused and the chrome shows `refusedScheme`), and under `MAWS_E2E=1` with `MAWS_E2E_OPEN_LOG` set appends `browser-blocked-navigation <url>` to the seam log (E2's pattern, `deliverables/policies.ts:161-166`, its own append); `will-frame-navigate` prevents a subframe's to `file:`, `maws-deliverable:`, `chrome:`, `devtools:`; the partition's `webRequest` cancels `file:` and `maws-deliverable:` requests. The default session's CSP override never reaches the partition, so pages keep their own CSP (E4-0).
- **`window.open` and new-window links are gated and adopted** (Interfaces "`window.open`"; Decision Log 24): `setWindowOpenHandler` validates `details.url` (`about:blank` admitted here alone, for the open-then-navigate pattern) and honours the open only when the tab saw attributed input (human or agent) within the last 5 s and fewer than 3 opens happened in that window, else answers `{ action: 'deny' }` and increments the tab's `blockedPopups` (`HandlerDetails` carries no user-gesture flag, `electron.d.ts:22103-22110`, and Electron ships no popup blocker, so a page could otherwise loop `window.open` into unbounded tabs, or under `linkTarget: 'external'` into the system browser). An honoured open with `linkTarget: 'external'` is denied and handed to `openExternalUrl`; with `in-app` it is **adopted**: `{ action: 'allow', outlivesOpener: true, createWindow: (options) => tabs.adoptChild(appSessionId, options).webContents }` for the dispositions `foreground-tab`, `background-tab` and `new-window`, so `window.opener` works (OAuth sign-in popups post back to it; Codex adopts the same way, `main-BvBtZhys.js:115690-115787`), and `deny` for `other`. `adoptChild` builds the `WebContentsView` with MAWS's own `webPreferences` (the opener's partition, the browser preload, sandbox, `contextIsolation`, `nodeIntegration: false`), ignoring the opener's requested ones, wires it like any tab, and selects it unless the disposition is `background-tab` (⌘-click). When the cap has no eligible victim, the open is denied and counted. `did-create-window` fires for adopted children and is where the entry's view is finalised.
- **The preload** is sandboxed with `contextIsolation`, exposes no `contextBridge` API in E4a, and main's `ipcMain` listeners for `browser:preload:*` channels (reserved, unused in E4a) accept only a sender whose `webContents.id` is a loaded tab's; a view can never invoke `browser.*` (the router's `isAppSender`, `router.ts:129-138`).
- **The chrome's CSP** is the app's (`csp.ts`); page strings render as text nodes; favicons and placeholders are `data:` images main built from decoded bytes; the suggestions list renders `url` and `title` as text.
- **Permissions deny-all; downloads human-only; DevTools** opens detached on the human's Inspect alone (never from a command E4c could call).
- **The remote-debugging port** is never enabled; `webContents.debugger` is the only CDP path (A-19).
- **Storage**: `persist:` partitions keep cookies and storage under `userData`, isolated from the app's session and from each other.

### 15. Failure semantics

- **A crashed tab renderer** (`render-process-gone`): `crashed: { reason }`, `loading: false`, the view hidden, the crash page with Reload (`loadURL(tab.url)` revives the renderer); the `TabDebugger` detaches and, under focus emulation, re-attaches on the next successful load; E4c re-attaches its bridge on its next action (`findings-pass2.txt:310-311`). `unresponsive` sets the flag and the banner; `responsive` clears it.
- **A partition that fails to open** (`session.fromPartition` throws, or the imported profile's directory is gone): the tab opens on the default partition and the chrome shows `BROWSER_COPY.partitionFallback(name)` through `browser.notice`; the setting is untouched.
- **A view whose window is gone**: on an app window's `close`, main `removeChildView`s every browser view attached to it and clears their placements (`placedIn: null`); the tabs and their pages live on, unattached, until a pane in another window places them or the app quits (`will-quit`: `tabs.json` flushed, every view closed).
- **A view that cannot be created** (`new WebContentsView` throws, or `loadURL` is refused synchronously): the tab's `failed: { message }` is set and the pane shows `BROWSER_COPY.viewFailed(message)` with Retry (which clears `failed` and tries again); nothing else is affected. A load that fails asynchronously is never `failed`: it is a `loadError` from `did-fail-load` (Design §5), and `loadURL`'s rejected promise is ignored.
- **The app window's renderer reloads or crashes**: Design §3's reset (cover cleared, that window's owners cleared, its views hidden; the panes claim again on mount).
- **The history store unavailable** (`Index.readOnly`): visits are dropped and suggestions answer `[]`; the address bar still navigates.
- **A placement from a window main does not know** (a closed window's late message): ignored.
- **`tabs.json` unreadable**: moved aside as `tabs.json.broken-<epoch>` and started empty, logged once, and `browser.notice { kind: 'tabsFileBroken' }` shown in the first Browser tool opened.
- **A capture that throws** (never painted, or the view destroyed meanwhile): `placeholder: null`.

## Decision Log

1. **The on-screen check first, focus emulation behind a flag.** M0 runs `visibility2.mjs` and `visibility5.mjs` with the owner present (A-33); the verdict sets `FOCUS_EMULATION`'s default. Unverified (the owner absent), the default is `off`: Chromium shows a `WebContentsView`'s contents when its widget is visible and the window is not occluded, Electron's `BrowserWindow` force-show exists for its own historical reason, and Claude Desktop hosts its whole UI in a child `WebContentsView` with no emulation (`findings-pass2.txt:240-246`); a hidden page on an unlocked display would be visible to the owner at first use (no animation, timers at one tick a second) and the flag (`MAWS_BROWSER_FOCUS_EMULATION=1`) turns the remedy on without a build. *Outcome* (2026-10-06, M0): the three readings were true (no lock key, display on, `UserIsActive` 1), both checks ran on screen and the child view read **visible** (rAF firing, 11 and 16 frames presented, nothing attached, no focus steal); `FOCUS_EMULATION` defaults to `'off'`; no Electron issue is drafted (`spikes/browser-probe/findings-pass2-onscreen.txt`).
2. **Cover layers are found in the DOM, not enumerated by store.** One `MutationObserver` on `body`'s direct children classifies each child in order: a popper wrapper first (intersection rule; a tooltip never), then a dialog or alertdialog (modal), then any other child but `#root` and the focus guards (intersection rule); a second observer on the toast viewport's `li` children applies the intersection rule; plus `overviewOpen` and the chrome's own suggestions. The order matters because a Radix Popover's content carries `role="dialog"` inside its popper wrapper (`react-popover/dist/index.mjs:245`), so a dialog-first rule would freeze the page under every composer chip popover; and because Radix portals render `asChild`, the body child *is* the marked element, so the rule matches the child itself before looking inside. Alternative: a hook in every sheet, dialog, menu and popover (fifteen files today, and every later child's), which the next sibling would forget; the observer costs nothing while no portal mounts and `cover.test.ts` pins it against the real Radix components. Chrome buttons use native `title` tooltips because macOS draws them above every view. (Revised after the document review, which found the Popover role and the tiptap popup.)
3. **The error page is renderer-drawn, the view hidden.** Codex loads an HTML error page into its view (`main-BvBtZhys.js:90440-90627`); MAWS draws the same content as DOM in the pane with tokens, copy through `copy.ts`, both themes, and Playwright-visible for the e2e; the view stays hidden while `loadError` or `crashed` is set and Reload loads the failed URL again (Codex's own retry, `:90618-90620`).
4. **The placeholder is a JPEG of the page taken before hiding.** 5 ms per cover (E4-0), quality 80, bounded at 400 KiB, sent as a `data:` URL the app's CSP already admits; a sheet's translucent overlay then dims the page as Codex's does. A blank pane behind a 60 % overlay flashes; a PNG at DPR 2 is 300 KB and more.
5. **Browser memory is reported beside the budget, not inside it.** C12's budget sums engine process trees and releases engine sessions (`src/engine-host/budget.ts:67-91`); a browser renderer is the app's own process, so feeding it into `totalKiB` would release an idle session to make room for a web page. E4a samples tab memory in main and shows "Browser tabs: N loaded · M MB · outside the engine budget" under Session info's Memory budget row, and caps loaded tabs at 12 (Design §2) as its own policy. The architect may read "reported into C12's budget report" as the host's field instead; then `BudgetState` gains an additive `browserKiB` the host receives from main through a new host command, a one-task change, and the Session info row reads it from there. Flagged in the hand-back, not `[parent-impact]`.
6. **Twelve loaded tabs and a 2 GiB soft cap, LRU suspension, placed tabs protected, never a forced close.** Codex's count is 32 with ranks and protections (`:117250`, `:117292-117330`); MAWS's sitting is smaller, and E0b's per-renderer figure (114 to 137 MB on a toy page) understates real sites by several times, so a sampled memory cap sits beside the count. The victim is the least recently shown loaded tab that is unplaced, idle, not loading and not downloading; a tab under `control: 'agent'` is never suspended under the agent (E4c's actions would fail mid-flight). With no eligible victim, a commanded open opens suspended and a page-driven open is denied and counted; nothing in flight is ever closed by the cap.
7. **`show_pane 'browser' {target}` reuses a tab at the same URL, else opens one, and main makes it idempotent.** A model that calls twice for the same page should not open two tabs; the comparison is main's, on the normalised URL string after the tab's own last navigation (a redirected tab no longer matches, and a second call then opens a new one, which is acceptable), and a repeated `requestId` within 10 s answers the first call's tab, so two windows handling one `maws.pane.show` (`connect.ts:65-73`) reach one tab. The session is passed explicitly (`appSessionId` in the params, as E2 does at `connect.ts:99`), because `addTool` re-targets a single-instance tool's existing tab, a pinned one included (`host.ts:290-304`), and the tab must land in the agent's session (P-21). No target opens the tool on the session's selected tab or the empty state. A refused target answers `TOOL_ERRORS.navigationRefused(target)` from the renderer's `connect.ts` before main is asked.
8. **The partition's user agent drops the `Electron/<v>` and `maws/<v>` tokens.** Sites serve degraded or blocked pages to unknown products (and some refuse `Electron`); the agent and the owner should see the page a Chrome user sees. The Chromium version and platform stay truthful. Codex's choice was not read; this is MAWS's own.
9. **No new keymap action.** ⌘L stays `composer.focus` (`actions.ts:49`); inside the page, main's `before-input-event` turns ⌘L into `focusAddress` only because the chord never reaches the renderer there; ⌘R, ⌘[, ⌘], ⌘F, ⌘=, ⌘- and Esc are handled the same way; ⌘0 stays Overview (a menu accelerator). Bindable `browser.*` actions are deferred (Deferred).
10. **The search engine default is Google** (`https://www.google.com/search?q=%s`), the Chrome default the imported profile will have; editable in Settings › Browser. *Owner may prefer DuckDuckGo or another.*
11. **`linkTarget` governs new-window links only.** `in-app` (default) adopts `target="_blank"` and `window.open` as a new tab in the same session, with `window.opener` intact; `external` hands them to the system browser through `openExternalUrl`. Same-window navigations never leave MAWS whatever the setting. The ledger named the field without its meaning; this is the reading.
12. **Deny-all, with `clipboard-sanitized-write` granted on recent human input.** Every permission request is denied with the banner (A-31), except a sanitized clipboard write within 2 s of attributed human input on that tab while the agent does not hold it: Chrome grants that write on user activation with no prompt at all, so denying it would break every site's Copy button (GitHub, documentation sites), which is stricter than A-31's "deny what would prompt" and not what the owner sees in Chrome; the agent never gets it (its clicks are attributed, and the owner's clipboard is not the model's to write). `clipboard-read` stays denied. The context menu's Copy and ⌘C are native and unaffected. **A precision of A-31 for the architect to confirm**; one line (`permissions.ts`) returns it to strict deny-all.
13. **Favicons are fetched by main and handed over as their own bytes.** The app's CSP (`img-src 'self' data: blob:`) refuses an `https:` favicon in the chrome, and widening it for arbitrary hosts is wrong; main fetches on the tab's partition (so the request looks like the page's own), sniffs the format, bounds the size, and hands a `data:` URL of the original bytes: ICO and SVG, which most sites serve, decode in the chrome's `<img>` (SVG in image context runs no script), whereas `nativeImage.createFromBuffer` reads PNG and JPEG only and emptied both in the review's experiment on 44.4.5. No page bytes are interpreted by the chrome as markup.
14. **History writes count in-page navigations as visits.** Single-page sites change the URL without a load; Chrome records those as visits too; `typed` is set only for the address field's own navigation.
15. **`-3` (`ERR_ABORTED`) is never an error.** A navigation replaced by another, a Stop, or a download fires `did-fail-load` with `-3`; showing an error page for it would flash on every quick second navigation.
16. **Tabs persist as a JSON file, not an index table.** The set is small, written whole on change, read once at boot, and E4b's "Remove imported profile" removes a partition's entries from it in one pass; a table would add a migration for no query.
17. **The panel tool's tab strip also appears in a main tab.** A main tab shows one tab; its strip lists the session's tabs so another is one click away (it opens as its own main tab), which keeps the chrome one component with one state.
18. **Downloads under the e2e skip the dialog.** `MAWS_E2E_SAVE_PATH` (under `MAWS_E2E=1` only) sets `item.setSavePath` so case 7 can assert the done line and the file; production always shows the dialog.
19. **`TabDebugger.send` is the only CDP path, and it owns the in-flight table.** Every `Input.*` command, the tools' and MAWS's own, enters the table before the send and leaves it on reply or error (A-33: "a command that errors or yields none can absorb one same-type human event, which the TabDebugger closes by releasing a window when its reply is an error"); the raw `webContents.debugger` is never exposed, so E4c's bridge cannot bypass the table by construction (`findings-pass2.txt:143-144`); `onCommand` is an observer of `send` and enters nothing.
20. **`browser.view.cover` is per window and carries no tab ids.** The renderer knows which layer opened, not which tabs are under it; main knows which views are placed in that window. A sheet in one window therefore never freezes another window's page.
21. **A `browser` main tab whose tab is gone shows the session's browser as a main tab**, headed "That tab was closed" (X14's rule: a kind that cannot restore its content restores to its tool's empty state); closing that main tab is the person's.
22. **Placement has one owner, claimed by token.** Two mounted panes for one tab (the panel tool and a main tab after Open in tab; two windows) would otherwise flip the view between them on every resize, since both keep their observers, and a non-owner's unmount `null` would hide the owner's live view; `paneId` plus `claim` makes ownership explicit, lets a pane recognise itself without knowing its window id, and lets the other mounted pane take the view back when the owner unmounts. (From the document review.)
23. **The load-error lifecycle: set on a main-frame `did-fail-load` that is not `-3`, cleared on the next `did-navigate` or navigation command.** Electron emits `did-navigate` only for a committed non-error navigation and `did-fail-load` for a committed error page, so the error page's own commit never clears the flag and Back to a good entry does. `loadURL`'s promise is never read: it rejects on every failure, superseded navigations included, and an executor awaiting it would turn DNS errors into "the view could not be created".
24. **`window.open` is gated on recent input and adopted, not re-opened.** Electron has no popup blocker and `HandlerDetails` carries no gesture flag, so a page could loop `window.open` into unbounded tabs or system-browser launches; the gate is attributed input (human or agent) within 5 s and three opens per 5 s, with the rest denied and counted in the chrome. Honoured opens are adopted through `createWindow` with `outlivesOpener` so `window.opener` works (OAuth sign-in popups post back to it; Codex does the same, `main-BvBtZhys.js:115690-115787`), with MAWS's own `webPreferences` on the child. (From the document review.)
25. **The app renderer's reload or crash resets its window's browser state.** ⌘R is the View menu's `reload` role and a browser user presses it with focus in the address field; without a reset the cover never lifts and stale views draw over the new page. The reset is per window; the fresh panes claim again on mount.
26. **A page's `beforeunload` never blocks.** `will-prevent-unload` is prevented: a close or a navigation the human or the agent asked for happens; Chrome's "Leave site?" dialog is deferred with the other per-site prompts. A page with unsaved form state can be lost; the owner's browser is for the session's work, not long-form editing, and the agent's navigations must not hang on a dialog nobody sees.
27. **`mailto:` links leave the app; every other non-http(s) scheme is refused with the banner.** `openExternalUrl` already admits `mailto:` (`open-external.ts:6`); app links (`zoommtg:`, `vscode:`, `slack:`) would launch arbitrary applications from a page and get an "Open in <app>?" confirm in a later child.
28. **E4a's notices are chrome notices, never app toasts.** The toast viewport sits inside the shell at the window's bottom-right (`ToastHost.tsx:49`), under a panel browser's view, so a browser action's toast would both hide behind the page and, under the cover rule, freeze it; the chrome shows its own transient line instead, and app toasts that overlap a pane cover it through the intersection rule for their few seconds.
