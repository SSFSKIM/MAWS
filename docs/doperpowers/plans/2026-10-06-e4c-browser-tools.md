## Purpose

After E4c the agent can use the browser the owner already has. In any session MAWS launches, the model sees six more tools: `mcp__maws__browser_tabs`, `browser_navigate`, `browser_snapshot`, `browser_act`, `browser_eval`, `browser_screenshot`. It opens a page in a tab of its own session, reads the page as an accessibility snapshot whose lines carry refs, fills a field or clicks a button by ref or by a CSS locator, reads a value with an expression, and takes a screenshot that comes back to it as an image and to the owner as a deliverable. Every call is one compact row in the transcript naming the tab, the target and the time it took; the owner sees the acting tab come forward in the Browser tool with the agent's cursor moving in the page. When the owner clicks into a page the agent is using, the agent's next action stops and the chrome says "You have the page · Hand back"; three seconds after the owner's last input, or at the button, the action resumes. A session resumed in the terminal has none of this and nothing breaks.

To see it: open a session with the Browser tool, send "Open https://example.com in the MAWS browser, snapshot it, and tell me the heading", watch the tab open and the row appear; then send "Click the More information link"; while the agent's click is pending, click the page yourself: the chrome shows "You have the page", the row says it is waiting, and three seconds after you stop the click lands.

## Terms

- **Tab**, **view**, **pane**, **placement**, **cover**, **chrome**, **control**, **`TabDebugger`**, **attribution**: as E4a's Terms define them. A tab is **shown** when its view is placed in a pane of a visible, uncovered window (E4a Design §3's `shown` with `covered` false and the window not hidden or minimized); otherwise it is **hidden**, which to the page means `document.visibilityState === 'hidden'` and no `requestAnimationFrame` (E4-0 (2)).
- **Browser tool** (lowercase "tool" when it means the MCP tool): one of the six `browser_*` tools on the `maws` server. **The Browser tool** (capital) is E4a's X5 panel tool.
- **Driver**: E4c's per-tab object in main (`src/main/browser/agent/driver.ts`) holding the CDP bridge, the Playwright `Browser`, `BrowserContext` and `Page` for one tab, created on the first browser tool call that targets the tab and closed on idle, tab close or crash.
- **Bridge** (the CDP bridge): E0b's `cdp/bridge.mjs` lifted into main (`src/main/browser/agent/bridge.ts`): a loopback WebSocket endpoint that answers the browser-level CDP methods Playwright needs and forwards page-session commands through `TabDebugger.send`, under E0b's allowlist plus an Origin check. **Host bridge**: the host↔main request and answer pair (`maws.browser.request`, `maws.browser.answer`), E1's `HostBridge` pattern with a pausable deadline.
- **Ref**: Playwright's `aria-ref` id (`e12`, `f2e7`: an optional frame ordinal and an element number) printed as `[ref=…]` on a snapshot line; valid for one document and until the next snapshot of that frame (E0b S2d). **Target**: what `browser_act` and `browser_screenshot` aim at: a ref, or a locator `{ css, role?, name? }` (the shape E4d's anchors carry, X10).
- **Action**: a browser tool call that acts on a page: `browser_navigate`, `browser_act`, `browser_eval`, and `browser_tabs {action: 'close'}` on a tab the human holds. A **load** is a page fetch the agent starts on a tab nobody holds: `browser_tabs open`, and `select` or `reload` on a suspended tab; a load marks the tab `control: 'agent'` before its first network event (so E4a's download handler refuses for the agent, A-31) and has a vacuous pause point. A **read** is `browser_snapshot`, `browser_screenshot`, `browser_tabs` otherwise; reads never touch `control` and never move the session's selected tab. The **pause point**: the moment before an action dispatches its first page-changing CDP command, after its input-free readiness wait, where the driver checks the abort signal and `control`.
- **Hand-back**: the transition out of `control: 'human'`, by the chrome's button (E4a's `browser.control.handBack`) or by `BROWSER_HANDBACK_IDLE_MS` (3,000 ms) without human input (A-31).
- **Stand-in**: the live test's substitute for main: it answers `maws.browser.request` events with canned answers the real app generated earlier (Design §13).
- **Engine host**, **main**, **renderer**, **X1 event**, **meta row**, **replay**, **fixture**, **conformance suite**, **scratch home**: as E1's document defines them.

## Design (the residue §3 D and E4's cut leave open, with reasons)

### 1. Ownership and data flow

The **host** owns the six tool definitions, parses arguments, asks main through the host bridge, formats the MCP result (JSON text first; the image block before the JSON for a screenshot; the snapshot's YAML as a second text block), writes the `screenshot` record, and answers the engine. **Main** owns everything that touches a page: the per-tab driver (bridge, Playwright, page), the six handlers, the control state machine, the cursor channel, the parking of unplaced tabs, the screenshot file. **The renderer** draws the `browser_action` row from the transcript's events (live and from disk), its waiting line from a transient IPC event, the acting-tab chip and the Browser tool's following of the agent; the **preload** draws the cursor from main's messages and reports nothing in this child. The normaliser emits `maws.browser.action` from the host's `control_response` row, so the row's facts (tab, target, URL, ms, deliverable, error) come from the journal and a rebuild reproduces them; the live waiting state is not an X1 event (it would re-deliver on every reload; E1's residue 3 for the pane bridge).

One call's path: `tools/call browser_act` → `server.ts` `call` → `browser.ts`'s definition parses with `BrowserActInputSchema` (a refusal answers `invalidArguments` at once) → `BrowserBridge.request({ requestId, toolUseId, tool, args }, ctx.signal)` → `EngineSession` emits `browserRequest` → `ipc.ts`'s `wire` emits `maws.browser.request` → main's `startBrowserAgent` (`hosts.onEvent('maws.browser.request', …)`) → the session's tab is found (P-21) → the driver runs the action (Design §5 to §7) reporting `maws.browser.waiting` while it waits on the human or a cover → main `dispatch('engine-host', 'maws.browser.answer', { appSessionId, requestId, result })` → the host's bridge settles → the tool formats the result → `control_response` → the normaliser emits `maws.browser.action` → the row.

Descriptions (exact; the fallback sentence first, A-18; each ends with a `Returns` sentence):

- `browser_tabs` (title "Browser tabs"): *List, open, close or select this session's tabs in the MAWS browser; without this tool, ask the user to open the page and describe what you need from it. "list" returns the session's tabs with their ids, URLs, titles and who controls each; "open" takes a url (http or https) and opens it in a new tab that stays open until you close it; "close" and "select" take a tabId. Tabs the user opened are listed too; the user sees the tab you act on. Returns the tab list and, for open, the new tab's id.*
- `browser_navigate` (title "Browser navigate"): *Navigate a MAWS browser tab to a URL, or go back, forward or reload; without this tool, ask the user to open the page. url is an http or https URL or one of "back", "forward", "reload" (reload also loads a tab the user left unloaded). Waits for the page to load (up to 30 s). A page that starts a download is refused: the user downloads files, you do not. Returns the tab's URL and title after the load.*
- `browser_snapshot` (title "Browser snapshot"): *Read a MAWS browser tab as an accessibility snapshot with element refs; without this tool, ask the user to describe the page or paste its text. Each interactive or named element has a ref like e12 that browser_act and browser_screenshot accept as a target. Refs are valid for the current document and until your next snapshot of it: after a navigation or a later snapshot, take a new snapshot before acting. The snapshot is cut at maxChars (default 24000, at most 64000) on a line boundary with a trailer saying how much was omitted and an outline of the page's landmarks and their refs, so you can call again with root set to a ref or a landmark role (banner, navigation, main, contentinfo, search, complementary, region, form) for one subtree; a rooted snapshot invalidates refs outside that subtree until the next whole-page snapshot. Returns the snapshot as text after a JSON header with the tab's URL, title and the cut.*
- `browser_act` (title "Browser act"): *Act on an element in a MAWS browser tab: click, fill, select, check, press, hover or scroll; without this tool, ask the user to do it and tell you the result. target is a ref from browser_snapshot (e.g. "e12") or a locator {css, role?, name?} such as a comment anchor carries. fill types value into a field (replacing its content); select picks the option whose label or value is value; check sets a checkbox to value ("true" or "false", default true); press sends a key or chord (e.g. "Enter", "Control+a") to the element; scroll scrolls the element into view and then by value pixels when given (negative scrolls up). The action waits for the element to be visible and enabled (up to 10 s). If the user is using the page, the action waits until they stop or hand it back, and the result says so. A ref that no longer resolves is an error naming it: take a new snapshot. Returns the tab's URL and title after the action and whether it navigated.*
- `browser_eval` (title "Browser eval"): *Evaluate a JavaScript expression in a MAWS browser tab's page and return its value; without this tool, use browser_snapshot or ask the user. Use it to read page state (text, attributes, computed values, JSON the page holds); it runs in the page with the page's permissions, so prefer browser_act for changes. A promise is awaited; the value is returned as JSON (cut at 16000 characters). If the user is using the page, the evaluation waits until they stop. Returns the value and the tab's URL and title.*
- `browser_screenshot` (title "Browser screenshot"): *Take a screenshot of a MAWS browser tab and receive it as an image; without this tool, use browser_snapshot. target (a ref or a locator) screenshots one element; fullPage captures the whole scrollable page; neither captures the viewport. The picture is also saved as a deliverable the user can open from the transcript. Pictures are kept under 3.5 MB (JPEG when a PNG would exceed it). Returns the image and a JSON record with the deliverable id, size and format.*

- `interrupted(tool)` → `<tool>: cancelled, the turn was interrupted` (internal: never written, the engine abandoned the call; the row reads it)

### 3. The host: `BrowserBridge` and the six definitions

`src/engine-host/tool-server/browser-bridge.ts`: `BrowserBridge` has `HostBridge`'s outcomes (`answered | timeout | withdrawn | ended`) and three additions E1's class lacks: **a pausable deadline** (`waiting(requestId, reason: 'human' | 'cover' | null)`: a non-null reason clears the deadline timer and records the reason; `null` re-arms the full `BROWSER_ANSWER_MS`; so the deadline is 30 s of main's own work, unbounded while the human holds the page or a cover holds the action, with the abort signal as the exit); **a cancel notification** (on the signal's abort **and on its own timeout** the bridge emits `browserCancel { appSessionId, requestId }` so main aborts the request's controller, stops waiting, drops it from the tab's queue if still queued, and the row turns cancelled; the host writes nothing for an aborted call, `server.ts:182`, and writes `browserTimeout` for a timed-out one); and **the app's presence** (`connected: () => boolean` and `onClientGone(cb)`: E10's host knows whether a client holds the socket, and under the utility-process host of today `connected` is `() => true` and `onClientGone` never fires; a request with no app answers `appNotOpen` at once, and when the client goes away every pending browser request, paused ones included, settles `appNotOpen`, so a detached host never holds an engine turn on a main that no longer exists; X13). `EngineSession` gains `browser: BrowserBridge`, `Listeners.browserRequest` and `.browserCancel`, `answerBrowser(requestId, result)`, `browserWaiting(requestId, reason)`; `ipc.ts`'s `wire` relays `browserRequest → emit('maws.browser.request', …)` and `browserCancel → emit('maws.browser.cancel', …)`; `handleMaws('maws.browser.answer', …)` and `('maws.browser.waiting', …)`; `MAWS_DEADLINE_SHAPES` gains both as `'immediate'`; `processExited` settles pending browser requests `ended` beside the panes and captures (`session.ts:1133-1136`).

`src/engine-host/tool-server/browser.ts`: `browserTools(deps: { bridge: BrowserBridge; deliverables: DeliverableWriter; userData: string; readFile })` returns the six `McpToolDefinition`s through `defineMawsTool`. Each `call` parses (the host and the normaliser parse with the same schema, so they agree on admission), builds the request `{ requestId: ctx.requestId, toolUseId: ctx.toolUseId, tool, args }` (for `browser_screenshot` plus `deliverableId: randomUUID()` and `path: screenshotPath(userData, appSessionId, deliverableId, 'png')`, the host naming the file so both sides know it; main may answer `.jpg` beside it after the fallback and the answer carries the path written), awaits the bridge, and maps: `answered` with `ok: false` → `toolError(answer.error)` (main's texts are the `BROWSER_TOOL_ERRORS` above, formatted in main from the same module); `timeout` → `browserTimeout`; `withdrawn`/`ended` → internal texts never written; `answered` with `ok: true` → the result validated against the tool's result schema (a mismatch is `actionFailed(tool, 'answer', '', 'malformed answer from MAWS')`, pinned by a test) and formatted: `browser_snapshot` `[toolText(json), { type: 'text', text: answer.text }]`; `browser_screenshot` reads the file at `answer.image.path` (`readFile`), writes the record through `deliverables.exclusive(appSessionId, () => deliverables.write({ id: deliverableId, appSessionId, kind: 'screenshot', path, title: answer.result.title || hostOf(url), sourceUrl: url, versions: [{ path, at, toolUseId }], toolUseId, createdAt }))` (X12; `sourceUrl` additive), then `[{ type: 'image', data: base64, mimeType }, ...toolText(result).content]`; the others `toolText(result)`. The browser tools never read `ctx.cwd`.

### 4. Main: the per-tab driver over `TabDebugger.send` (the bridge, Playwright, the idle rule)

`src/main/browser/agent/` (new, under E4a's `src/main/browser/`): `index.ts` (`startBrowserAgent({ tabs, hosts, emit, env, userData }) → { stop }`, wired from E4a's `startBrowser` or from `src/main/index.ts`'s E4c block after E4a's; subscribes `hosts.onEvent('maws.browser.request')` and `('maws.browser.cancel')`; answers through `hosts.dispatch('engine-host', 'maws.browser.answer', …)` and reports through `('maws.browser.waiting', …)`; one request at a time **per tab** (a per-tab promise chain: the engine does not run two actions on one tab concurrently, but two sessions' tabs run in parallel); the e2e seam under `MAWS_E2E=1` (Interfaces)), `bridge.ts`, `driver.ts`, `handlers.ts` (the six), `locate.ts`, `snapshot.ts`, `screenshot.ts`, `control.ts`, `cursor.ts`, `visible.ts`, `progress.ts`, `errors.ts` (formats `BROWSER_TOOL_ERRORS` into `{ ok: false, error }` answers).

**The bridge** (`bridge.ts`, E0b's `cdp/bridge.mjs` lifted to TypeScript with these changes and no others): every `dbg.sendCommand(method, params, sessionId)` becomes `debugger.send(method, params, sessionId)` and the single `dbg.on('message', …)` becomes `debugger.onAny(listener)`, a catch-all event subscription E4a's per-method `on(method, listener)` does not offer, added in an E4c block of E4a's `debugger.ts` (Playwright needs every event of every domain; the raw debugger is never touched; the in-flight `Input.*` table fills itself inside `send`, E4a Decision 19; the probe's `onCommand` hook is E4a's `onCommand` observer, which `cursor.ts`, the idle clock and the latency log read); `Page.getFrameTree` once for the target id (the real main-frame id, stable across process swaps, E4-0 (3)); the allowlist unchanged (`SESSION_TARGET_ALLOW`, the four refused domains, `knownSessions` fed by auto-attach events, unknown sessions refused with `unknown session`, `Target.getTargets` on a page session refused as `not available through the MAWS debugger bridge`, the browser-level `Target.createTarget`/`closeTarget`/`attachToBrowserTarget`/`exposeDevToolsProtocol` refused); **the Origin check** added: an upgrade carrying any `Origin` header is refused with 403 (a Node WebSocket client sends none; a page's would), beside the token-path check (404) and a limit of **one** open socket per bridge (a second upgrade while one is open is refused with 409); bound to `127.0.0.1` on an ephemeral port; `Browser.getVersion` answers Chromium's product string; `Browser.setDownloadBehavior` and the `Storage.*` browser-level calls answer empty as the probe did (Playwright sends them at attach; nothing is granted). **Waiting children while no socket is open**: Playwright's attach leaves `Target.setAutoAttach { waitForDebuggerOnStart: true }` set on the debugger session, so after the socket closes a new cross-site iframe or worker would arrive `attachedToTarget { waitingForDebugger: true }` with nobody to resume it and freeze for the human (E4-0 (4) measured the pause; Playwright resumes it when connected); the bridge therefore answers every `attachedToTarget` with `waitingForDebugger: true` that arrives while it has no socket by sending `Runtime.runIfWaitingForDebugger` on that session, and the driver's idle close sends `Target.setAutoAttach { autoAttach: false, waitForDebuggerOnStart: false, flatten: true }` before it keeps an attachment (both pinned by `driver.test.ts` and `bridge.test.ts`). `close()` terminates the socket, closes the server, and detaches the debugger **only when told to** (`close({ detach })`), since under focus emulation `on` the attachment is E4a's to keep. `bridge.test.ts` is G3 (Acceptance).

**The driver** (`driver.ts`): `Driver.for(entry)` creates on demand: `debugger.attach()` (idempotent), `startBridge(entry.debugger, …)`, `chromium.connectOverCDP(bridge.wsUrl, { timeout: 10_000 })`, `browser.contexts()[0].pages()[0]` (the bridge announces one page; `newPage` fails by design). The `Page` is kept across navigations and process swaps (E4-0 (3)); after a renderer crash (E4a's `render-process-gone` detaches the debugger; the bridge broadcasts `Target.detachedFromTarget`; Playwright's page closes) the driver is dropped and the next action creates a fresh one after E4a's Reload revived the renderer. Default timeouts: `page.setDefaultTimeout(BROWSER_ACTION_TIMEOUT_MS)`, `setDefaultNavigationTimeout(BROWSER_ANSWER_MS)`. **Every request has an `AbortController` in main** (`index.ts`), aborted by `maws.browser.cancel` (the host's abort or timeout) and by the tab's close; its `signal` is passed to every Playwright call (`{ signal }`), checked at the pause point and again right before dispatch, and a request still in the tab's queue when cancelled is dropped unrun. **Idle**: a driver with no command observed through `onCommand` for `BROWSER_BRIDGE_IDLE_MS` (5 min) while `control !== 'agent'` closes: Playwright's connection and the WebSocket always (after the auto-attach reset above); the debugger `detach()` only when `FOCUS_EMULATION === 'off'` (M0's verdict; with `on` E4a keeps the attachment for the page's visibility and "detaching after idle" falls, A-33). The idle clock counts every command `onCommand` observes, E4b's CHIPS import and E4d's crop included, so a detach never pulls the attachment out from under a sibling's use (E4a Design §10: every `send` passes `onCommand`). The cost of staying is +22 MB per attached renderer (E0b); the reason for five minutes rather than E0b's "while the agent holds the tab" is that a closed connection loses Playwright's ref table, so a model thinking for a minute between calls would meet stale refs for nothing. A tab's close (`webContents.close()`) and the session's exit close its driver at once. `playwright-core` is `require`d lazily on the first driver (114 ms from the asar, E4-0 (6)), never at startup.

**`require('playwright-core')` and `ws`** (A-33 item 6): both in `package.json` `dependencies` (exact versions), externalised by electron-vite's default and packed into the asar by electron-builder with no `asarUnpack`; nothing else in the build changes. `electron.vite.config.ts` gains no `external` entry (the dependency route needs none; the bundled-`ws` route would need `bufferutil` and `utf-8-validate` externalised and is not taken, Decision Log 8). The packaged proof is M4's.

### 5. Snapshots and refs (A-33 item 5)

`snapshot.ts` (main) takes the snapshot: `root` absent → `page.ariaSnapshot({ mode: 'ai' })`; a ref → `page.locator('aria-ref=' + root)`, checked with `count()` (0 → `rootNotFound`), then `locator.ariaSnapshot({ mode: 'ai' })`; a landmark role → `page.getByRole(role)`, `rootMatches = count()`, 0 → `rootNotFound`, else `.first().ariaSnapshot(…)` (one root only, because Playwright keeps one ref table per frame and the latest snapshot replaces it, so several rooted snapshots in one call would invalidate each other's refs, E0b S2d; the header says `rootMatches` and the description tells the model to pick a specific landmark by its ref). The raw text goes through the pure `cutSnapshot(text, { maxChars })` in `src/shared/browser/snapshot.ts`: if `text.length <= maxChars` it is returned whole with `truncated: false`; else the **outline** is built first: every line, **at any depth**, whose role is in `LANDMARK_ROLES` or is a `heading` of level 1 or 2, with its `[ref=…]` when it has one and its depth kept as indentation (landmarks sit deep in real pages: GitHub's `banner` at depth 2 and its `navigation "Global"` at depth 5, `results/pass2/snapshot-github-front.txt:5, 16`; Wikipedia's `main` at depth 2, `snapshot-wikipedia-main.txt:113`), at most `BROWSER_SNAPSHOT_OUTLINE_MAX_LINES`, with depth-0 and depth-1 ref-bearing lines filling any remaining room, prefixed `# outline (refs for root):`; then the body is cut at the last line boundary that keeps `outline + body + trailer` within `maxChars` (never inside a node line), then the **trailer** `… <n> more lines (<m> refs) omitted; call again with root: <ref> for a subtree or raise maxChars (max 64000)` with `m` counted by `/\[ref=[^\]]+\]/g` over the dropped lines. The result's JSON header carries `chars`, `lines`, `refs` of the whole, `truncated`, `omitted`. `snapshot.test.ts` runs the cut over E4-0's three saved real snapshots (`results/pass2/snapshot-*.txt`): GitHub at 24,000 keeps about 47 % of its refs and the outline names `banner`, `navigation "Global"`, `main` and `contentinfo` with their refs; Wikipedia at 64,000 is still cut and its outline names `main`; Hacker News, which has no landmarks, gets an outline of its depth-0 and depth-1 lines; a 448-character page is returned whole; a cut never splits a line; the trailer's counts equal the dropped lines' counts; the output never exceeds `maxChars`. The engine caps an MCP result at 25,000 tokens and spills a larger one to a file with a pointer (SPEC 31 §12.5); it counts at four characters per token (its 100,000-character generic cap equals the token cap), so the 64,000 ceiling sits at about 16,000 and the spill path is unreachable by construction, which the ceiling test pins in characters. Refs are `(f\d+)?e\d+`; the frame prefix appears once a second document exists (E0b) and OOPIF subtrees carry their own ordinal (E4-0 (4)), so `browser_act` by ref reaches into iframes with no frame argument.

### 6. Actions, targets, actionability and the pause point

`locate.ts`: a ref → `page.locator('aria-ref=' + ref)`; `count()` at once: a Playwright error naming an invalid frame (`Invalid frame in aria-ref selector`, E0b S2d) → `staleRef(…, 'previous-document')`; 0 → `staleRef(…, 'missing')`. A locator `{ css, role?, name? }` → `let loc = page.locator('css=' + css)` (the prefix keeps Playwright from reading `>>` or `text=` inside a CSS string); with `role`, `loc = loc.and(page.getByRole(role, name ? { name, exact: true } : {}))`; `count()` after waiting up to `BROWSER_LOCATE_MS` for at least one match (`loc.first().waitFor({ state: 'attached', timeout, signal })` in a try); 0 with `role` and `name` → a fallback `page.getByRole(role, { name, exact: true })` when it has exactly one match (the element moved; E4d's anchor still names it), else `targetNotFound`; several → `.first()` and `matches: n` in the result. The result's `target` echoes what resolved.

`handlers.ts` runs an action in four steps; every Playwright call takes the request's `{ signal }` and the per-tab `browser.download.refused` listener of this paragraph's last sentence is armed before step 1 and disarmed after the answer. (1) **The acting tab, for actions only**: `tabs.select(appSessionId, tabId)` unless the session's selected tab is in the human's hands (`control === 'human'`, or its `lastHumanAt` within `BROWSER_HANDBACK_IDLE_MS`: moving the panel away from a page the owner is typing in would send their keys to a hidden page), and `emit('browser.agent.acting', { appSessionId, tabId })` (the renderer opens the Browser tool once if the session has none open, Design §10). **No `control` change here**; reads skip this step entirely. (2) **Resolve and wait, without input**: `locate`, then a readiness wait that dispatches nothing: `loc.waitFor({ state: 'visible', timeout: BROWSER_ACTION_TIMEOUT_MS, signal })`, then `isEnabled()` (and `isEditable()` for `fill`, `select`, `press`) polled every 100 ms until true or the deadline (`actionTimeout`); `scroll` needs only `attached`. (Playwright's `trial` option is not used: it still sends the press and release and only swallows the DOM events, Grounding.) **The cover**: while `entry.tab.covered` is true the wait is suspended, not counted against the deadline, `progress.ts` reports `waiting: 'cover'` to the host (the deadline pauses) and the renderer (the row says a sheet covers the page), and the wait resumes on `browser.tabs.changed` with `covered: false`; a hidden page's `requestAnimationFrame` is paused even under focus emulation (`visibility4.json:66-69`), so nothing can make the action proceed under a sheet and A-33 item 2's "off for covered" stands (Design §9). (3) **The pause point**: `signal.aborted` → answer nothing (the host already withdrew or timed out; the row reads cancelled); then if `control === 'human'`, or `now - lastHumanAt < BROWSER_HANDBACK_IDLE_MS` (the person clicked within the last 3 s with no agent holding the tab, so `control` was left `idle`, Design §8), `control.ts` enters `human` if not there (the chrome's slot and button appear; the timer is armed from `lastHumanAt`), `progress.ts` reports `waiting: 'human'`, and the handler awaits `whenReleased(entry, signal)` (resolves when `browser.control.changed` leaves `human`: the hand-back button or the 3 s idle timer; rejects on the signal's abort → the internal `humanHasPage`, nothing written); `waitedMs` counts from here to the release; then `signal.aborted` is checked again, and `control.ts`'s `markActing(entry)` sets `control: 'agent'`. (4) **Dispatch**: `cursor.ts` moves the cursor to the target's box centre (Design §9), then the real action with a short timeout (`{ timeout: 5_000, signal }`; the action runs its own actionability checks, which now pass at once): `click` → `loc.click()`; `fill` → `loc.fill(value)` (Playwright's `Input.insertText`, which raises no input event, E4-0; nothing to attribute); `select` → `loc.selectOption(value)` (a string matches an option's value or label); `check` → `loc.setChecked(value !== 'false')`; `press` → `loc.press(value)` (CDP keys carry the from-debugger bit, attributed agent); `hover` → `loc.hover()`; `scroll` → `scrollIntoViewIfNeeded`, then `loc.hover()` and `page.mouse.wheel(0, Number(value))` when `value` is given. A thrown Playwright error → `actionFailed` with its first line; an abort during the dispatch → nothing written. After the action the handler waits briefly for a navigation it may have started (`page.waitForLoadState('load', { timeout: 2_000, signal })` in a try; `navigated` is whether `page.url()` changed), reads `url` and `title`, and answers with `ms` and the waits. **What cancellation can and cannot stop**: a request is abortable until its first page-changing CDP command leaves (queued, connecting, waiting, paused, about to dispatch); an in-flight CDP command is never cancelled (a `mousePressed` without its `mouseReleased` would leave the page with a stuck button) and the Playwright action is left to finish with its answer discarded. The human's input during the dispatch itself is attributed by E4a's table and takes `control` for the **next** action, which is the only arbitration P1 has (§3 D). **Downloads** (A-31): E4a's `will-download` refuses a download while `control === 'agent'` and emits `browser.download.refused`; loads mark the tab `agent` before their first network event (below) so an agent-opened download URL is refused rather than offered to the human in a save dialog; and every handler, actions and loads alike, listens for the tab's `browser.download.refused` from its start until its answer (the 2 s navigation grace included) and turns one into `downloadRefused`, so a `browser_act` click on a download link or a `browser_eval` that triggers one answers the error, not success.

`browser_navigate`: `url` → the pause point, then E4a's `navigation.navigate(entry, { url, typed: false })` (so E4a's load-error lifecycle, history write, `will-navigate` gate and the `loadError` state all apply as for a human's navigation) and `waitForSettled(entry, signal)`: resolves at once on a main-frame `did-navigate-in-page` (a hash or `pushState` navigation toggles no loading state), and after a main-frame `did-navigate` as soon as `!webContents.isLoading()` (checked right after the commit and on each `did-stop-loading`); rejects on `loadError` set (`navigationFailed` with E4a's `kind` and `code`), on `crashed` (`tabCrashed`), on a `browser.download.refused` for this tab (`downloadRefused`, A-31; a download aborts the navigation with `-3`, which E4a ignores, so without this listener the wait would run to the deadline), on the signal's abort (nothing written), or at the deadline (`browserTimeout`'s main-side twin, 28 s, so main answers before the host's 30). `back`/`forward` → E4a's `navigate(entry, 'back' | 'forward')` with the same wait (no history entry → `actionFailed(tool, 'back', '', 'no page to go back to')`); `reload` → `'reload'`, or on a **suspended** tab the load path below, which is how the agent loads a tab the owner left unloaded (E4a Design §2). `navigate.test.ts` pins the same-document case, the download case and the crash case over a fake webContents emitter.

**Loads** (`browser_tabs open`; `select` and `reload` on a suspended tab): E4a's `tabs.open({ appSessionId, url, select: true })` or `navigate(entry, { url: entry.tab.url })` returns synchronously after `loadURL` is voided and before any network event, and `control.ts`'s `markActing(entry)` runs in that same tick, so `control` is `agent` when `will-download` could fire and E4a refuses the download for the agent; then `waitForSettled`. A load's pause point is vacuous (a new or suspended tab has no holder). A cap-forced suspended open answers `loaded: false` and the description's "stays open" holds.

`browser_tabs`: `list` → the session's tabs as `BrowserTabSummary` (suspended tabs with `loaded: false`); `open` → the load above; `close` → the pause point when that tab is `control: 'human'` (or `lastHumanAt` within 3 s), then `tabs.close(tabId)`; `select` → `tabs.select`, and the load above when the tab is suspended, so a following snapshot works. Every `tabId` is checked against `entry.tab.appSessionId === appSessionId` first (P-21).

`browser_eval`: a read in the sense that it does not dispatch input, an action in the sense that it can change the page: it passes the pause point (Design §8's table), then `page.evaluate(expression)` with a string (Playwright evaluates a string as an expression and awaits a promise); the value is JSON-serialised (`undefined` → `null`; a non-serialisable value → `String(value)`), cut at `BROWSER_EVAL_MAX_CHARS` with `truncated: true`; a thrown error → `evalFailed(message)`. The expression runs through the tab's page session only (the bridge admits no other session; the handler holds no other page), so it can never reach MAWS's own renderer by construction.

`browser_snapshot` and `browser_screenshot` are reads: no pause point, no `control` change, no selection change (reading does not disturb the human, seeing what the human sees is the point of a shared surface, and moving the panel for a read would hide the page the owner is using; Decision Log 5 and 6). A read on an unplaced tab works through Design §9's parking.

### 7. Screenshots and the `screenshot` record (X12, A-34)

`screenshot.ts`: every capture passes `style: 'maws-agent-cursor{display:none!important}'` so the agent's own cursor and target outline (Design §9) never appear in the picture the model or the owner sees, and a screenshot sends no cursor message of its own. `target` → `locate`, then `loc.screenshot({ type: 'png', scale: 'css', style, timeout, signal })`; `fullPage` → `page.screenshot({ fullPage: true, type: 'png', scale: 'css', style, signal })`; else `page.screenshot({ type: 'png', scale: 'css', style, signal })`. `scale: 'css'` keeps the pixel size at CSS px (a Retina capture would quadruple the bytes for nothing the model needs). The bytes are checked against `BROWSER_SCREENSHOT_MAX_BYTES`: over it, the capture is retaken as `{ type: 'jpeg', quality: 80 }` (the fallback A-34 names; the extension becomes `.jpg` and the answer says `mimeType: 'image/jpeg'`); still over → `screenshotTooLarge`. **The path is derived, not received**: main computes `screenshotPath(userData, appSessionId, request.deliverableId, ext)` itself and the host accepts an answer whose `image.path` is one of the two paths it would compute for that id (the `.png` or the `.jpg`), so under E10's separate host process neither side writes where the other told it to. The file is written with E4a's `atomicWriteFile` (the directory created), the answer carries `{ path, width, height, bytes, mimeType }` (width and height from the PNG's IHDR or the JPEG's SOF, a 20-line reader in `screenshot.ts`); the host writes the record (Design §3). The viewer opens it as E2 opens an image record (`openDeliverable` → the Deliverables tool → the image inline; the executor verifies `kind: 'screenshot'` draws and adds the icon and group E2 already declares; `tools/deliverables/model.ts:31`, `icons.tsx:55`). **Under a cover** Chromium's `Page.captureScreenshot` presents no frame (the page's `requestAnimationFrame` is paused, `visibility4.json:66-69`): a viewport screenshot (no `target`, no `fullPage`) is taken through Electron's `webContents.capturePage()` instead, which E4-0 measured at 5 ms while hidden (`findings-pass2.txt:207`; the cursor is hidden first by a `hide` message, 50 ms grace); a `target` or `fullPage` capture waits for the cover to lift as an action does (`waiting: 'cover'`). On an unplaced tab the capture goes through Design §9's parking.

### 8. The takeover: the control state machine (A-31, A-33)

`control.ts` owns every transition of `entry.tab.control` but `handBack`'s (E4a's). Inputs: E4a's `entry.input.emit` events (`{ kind, source }`), E4a's `browser.control.changed` from `handBack`, the handlers' action start and end, two timers. Rules, as a table (`control.test.ts` pins every row with fake timers):

| from | event | to | side effects |
|---|---|---|---|
| `idle`, no request pending or queued for the tab | `human` input (key, mouse, wheel) | `idle` | `lastHumanAt` stamped (E4a's seam does this); nothing else: a person browsing a page no agent holds sees no "You have the page" and no button |
| `idle` with a request pending or queued, or `agent` | `human` input | `human` | `controlSince` stamped; the hand-back timer armed for `lastHumanAt + BROWSER_HANDBACK_IDLE_MS`, re-armed on every further human input; `browser.control.changed` emitted; an agent's in-flight CDP command completes; the pending action waits at its pause point |
| `idle` | an action reaches its pause point within `BROWSER_HANDBACK_IDLE_MS` of `lastHumanAt` | `human` | as the row above (the person was using the page a moment ago; the agent waits the rest of the 3 s, with the slot and the button shown) |
| `human` | the hand-back timer fires (3 s without human input, A-31) | `idle` | emitted; waiting actions resume |
| `human` | `browser.control.handBack` (E4a sets `idle` and emits) | `idle` | the timer cleared; waiting actions resume |
| `idle` | an action passes its pause point, or a load starts | `agent` | `controlSince` stamped; the agent-idle timer cleared; `setBackgroundThrottling(false)` on the view (Design §9) |
| `agent` | an action ends | `agent` | the agent-idle timer armed for `BROWSER_AGENT_IDLE_MS` (10 s), so a model thinking between two calls does not flicker the chrome |
| `agent` | the agent-idle timer fires | `idle` | emitted; throttling restored |
| any | `agent` input (CDP, attributed by E4a's table) | unchanged | nothing: the agent's own input never takes the page |
| `human` or `agent` | the tab is closed or its session exits | — | the timers cleared; `whenReleased` rejects for pending actions (they answer `tabClosed`); the request's controller aborted |

`whenReleased(entry, signal)` resolves when `control` leaves `human` and rejects on `signal.aborted` (the host's `maws.browser.cancel` from `control_cancel_request`, `notifications/cancelled`, the host's timeout or the session's exit: the action answers nothing and the row reads "Cancelled, the turn was interrupted" from its missing result; `humanHasPage` is the text the host would have written and is kept as the error name the ledger reserves). `waitedMs` is the time from the pause point's entry into the wait to the release. While `human`, E4a's control slot shows "You have the page" with **Hand back**; the row's waiting line says the same (Design §10). The 3 s rule is A-31's; `human` means "the person's use of the page conflicts with the agent's", which is why a click on a page no agent holds and no request awaits leaves `idle` (finding of the document review) while a click within 3 s before an action makes the action wait out the rest. A tab under `control: 'agent'` is never suspended by E4a's cap (E4a Decision 6) and E4a's clipboard carve-out and download handler read `control` as this child sets it.

The in-flight race E4-0 measured (a human press inside an agent press's window leaves exactly one unmatched press, which is the human's) means the takeover fires on the first human click even during a click; the "pause point" rule means the agent never dispatches into a page the human holds, and the abort checks mean a cancelled request never dispatches at all. What P1 does not do: hold `human` while the pointer is merely over the page, arbitrate typing against the agent's `fill`, or warn the agent that the page changed under it (Deferred).

### 9. The agent's cursor and the visibility hold

**The cursor** (`cursor.ts`, `src/preload/browser.ts`'s channel `browser:cursor`): main observes the tab's `TabDebugger.onCommand` for `Input.dispatchMouseEvent` sends (`params.type` `mouseMoved`, `mousePressed`, `mouseReleased`, with `x`, `y` in CSS px of the page, which is what Playwright sends and what the preload's `position: fixed` needs; at zoom the command carries CSS px, E4-0) and sends `view.webContents.send('browser:cursor', { kind: 'move' | 'press' | 'release' | 'target' | 'hide', x, y, box? })`: `move` on every `mouseMoved` and before each action from the target's `boundingBox()` centre (so `fill` and `press`, which move no mouse, still show where the agent is), `press`/`release` on the button events, `target` with the box when an action resolves its element, `hide` when `control` leaves `agent`. **Hidden pages: the cover waits, the unplaced tab is parked** (`visible.ts`). A page whose view is hidden has no `requestAnimationFrame`, so Playwright's actionability stability check (two consecutive frames, `coreBundle.js:19837`) and `Page.captureScreenshot` stall (E4-0 (2)). Two cases differ in what can be done. **Covered** (a sheet, the palette, a dialog over a placed view): `visibility4.json:66-69` measured that under `setVisible(false)` the page's `requestAnimationFrame` stays paused even with focus emulation on, and A-33 item 2 binds emulation off for covered tabs, so nothing makes an action proceed under a sheet: the action waits, as Design §6 step 2 says, reports `waiting: 'cover'`, and resumes when the cover lifts; `unpark` runs when a pane claims the tab (E4a's `place` with a rect supersedes the parking; its owner table is untouched because parking is not a placement) or when `control` returns to `idle` with nothing pending. If no variant passes, the agent's reads and acts on an unplaced tab answer `actionFailed(tool, action, target, 'the tab is not shown; open the Browser tool for this session')`, the row says so, and the open condition is a `[parent-impact]` item in the hand-back (the multi-session scene would need the owner's view). `control.ts` also calls `view.webContents.setBackgroundThrottling(false)` while `control === 'agent'` and restores `true` at `idle` (E4-0: an un-hide path for rAF and timers on a visible-but-throttled page, lost on navigation; Codex does the same, `main…:116249-116262`); it is a tune-up for the parked and placed cases, never a substitute for them. With `FOCUS_EMULATION === 'on'` E4a already keeps emulation on for shown tabs and off for covered and unplaced ones; this child changes none of E4a's emulation calls (the parked view is shown in E4a's sense once attached and visible, so E4a's own rule turns emulation on for it).

### 11. Failure semantics

- **A tab closed mid-action** (the human's ×, `browser_tabs close` from another call, the session's deletion): E4a closes the view and detaches; the driver's page closes; the Playwright call rejects; the handler answers `tabClosed`; `control.ts` clears timers; pending `whenReleased` waits reject with the same.
- **A navigation that fails**: E4a's `loadError` → `navigationFailed(url, kind, code)`; the tab shows E4a's error page; refs are gone (a new document) and the description says to snapshot again.
- **A renderer crash mid-action**: `render-process-gone` → `tabCrashed`; the driver is dropped; E4a's crash page offers Reload; the agent's `browser_navigate reload` revives it and the next call builds a fresh driver (re-attach about 24 ms warm, E4-0 (3)).
- **A snapshot over the ceiling**: never an error; the cut applies; `maxChars` above 64,000 is refused by the schema (`invalidArguments`).
- **A stale ref**: `staleRef` with the reason (previous document or missing), naming the ref (E4's cut: "a stale-ref error naming the ref").
- **The app not open** (E10's detached host with no client): `appNotOpen` at once; nothing waits.
- **The human holding the page past the turn's end**: the engine's turn cannot end while a tool call is pending, so the action waits unbounded while `human` (the deadline is paused) until the hand-back or the person interrupts the turn, which aborts the wait (`control_cancel_request` → `maws.browser.cancel`); the row then reads "Cancelled, the turn was interrupted" and `control` returns to `idle` on the 3 s rule as ever. When no action is pending the state simply decays to `idle` after 3 s.
- **An interrupted turn's `notifications/cancelled`** (or `control_cancel_request`, or the session's exit): the server aborts the call's signal (`server.ts:99-104, 127-143`); the bridge emits `browserCancel`; main stops the wait and lets an in-flight CDP command complete, discarding the answer (the host writes nothing for an aborted call); the row reads cancelled; a dispatched action that completed anyway is visible in the page (the engine abandoned the result, which is the engine's rule for every tool).
- **Main does not answer** (a hang the per-action deadlines did not catch): the host's `browserTimeout` after 30 s of non-waiting time; a later answer is `not_pending`.
- **The host's `dispatch` deadline** (`REQUEST_TIMEOUT_MS` 10 s on main→host commands): answers are small (the screenshot travels as a path, never as bytes) and immediate.
- **The bridge's socket refused or dropped**: the driver creation fails → `actionFailed(tool, action, target, 'MAWS could not attach to the tab: <message>')`; the next call retries from scratch.
- **E4a's cap suspends a tab the agent will come back to**: a tab under `agent` is never a victim; after `BROWSER_AGENT_IDLE_MS` it can be; the agent's next call on a suspended tab answers `tabNotLoaded` for reads and acts, and `reload`/`select` resume it.

### 12. Security

- **Every URL is validated in main** by E4a's `validateBrowserUrl` (the schema refuses a non-http(s) URL before the host asks; main refuses again at the handler, `navigationRefused`), and a navigation goes through E4a's `navigate`, so `will-navigate`, the partition's `webRequest` filter and the download handler apply to the agent exactly as to the human.
- **`browser_eval`'s expression reaches only the tab's page**: the handler holds the tab's `Page` (one page per bridge, the real main-frame id as the target), the bridge admits only sessions it announced or Chromium announced on that page session, and MAWS's own renderer is never a target the bridge can name (`Target.getTargets`, `attachToTarget` to another target, `Target.createTarget` refused; G3). The expression runs with the page's origin and the imported profile's cookies: the agent is the owner on every site by design (A-31's partition pill says so to the human) and the permission mode gates the call (A-31).
- **The bridge's boundary**: the allowlist of E0b (no `Browser.*`, `Storage.*`, `SystemInfo.*`, `Tethering.*` on a session; `Target.*` limited to auto-attach's three with `getTargetInfo` on the own target only), unknown sessions refused, loopback only, an ephemeral port, a 128-bit token path handed to the driver alone, no `/json/version`, the Origin header refused, one socket, closed with the driver. The raw debugger is never exposed (E4a). The remote-debugging port never ships (A-19).
- **Input attribution** is main's and the preload's cursor channel is one-way into the page; the page learns nothing it could not see.
- **Screenshots** are written under `userData` by main at a host-named path; the record is the host's; the viewer reads it under E2's admission for delivered paths.
- **The agent's tabs are the session's** (P-21): a `tabId` of another session is `tabNotFound`, and `browser_tabs list` never names another session's tabs.
- **Permissions**: the three acting tools prompt under `default` through C3's broker as any MCP tool (A-25); nothing in this child answers a permission.

## Decision Log

1. **The idle rule follows M0's verdict, and an idle close resets auto-attach.** With `FOCUS_EMULATION === 'on'` the `TabDebugger` attachment is E4a's to keep for the page's visibility, so the driver's idle close ends Playwright's connection and the socket and never detaches (A-33: "detaching after idle falls"); with `'off'` it detaches too, reclaiming the +22 MB. Either way the close first sends `Target.setAutoAttach { autoAttach: false, waitForDebuggerOnStart: false }` and the bridge resumes any waiting child while it has no socket, because Playwright's attach-time `waitForDebuggerOnStart: true` would otherwise freeze every new cross-site iframe and worker for the human once Playwright is gone (from the document review). The idle clock counts every command the `TabDebugger` sees, so E4b's and E4d's uses hold it. *Outcome* (M0, 2026-10-07): the verdict is `FOCUS_EMULATION_DEFAULT === 'off'` (`src/main/browser/visibility.ts:18`, E4a M0's on-screen reading), so the idle close also detaches (Decision Log 34 (a)). The name landed as `FOCUS_EMULATION_DEFAULT` plus `focusEmulationMode(env)` (`visibility.ts:20-23`; `MAWS_BROWSER_FOCUS_EMULATION=1` turns it on without a build), computed once in `startBrowser` (`index.ts:84`) and not exposed on `Browser`: the driver reads the effective mode with `focusEmulationMode(env)` over the same `env` `startBrowser` received (or the `index.ts` E4c block hands it over), never the default constant, and detaches only when that mode is `'off'`.
2. **playwright-core over a loopback WebSocket bridge, not an in-process transport or raw CDP.** `connectOverCDP` accepts only a ws or http endpoint (`types.d.ts:17346`) and playwright-core exposes no transport injection; E0b's bridge is proven (717 commands, the boundary verified by a raw client) and A-19 names it. A raw-CDP driver without Playwright (snapshots, refs, actionability re-implemented) would be E4c's own thousands of lines for what Playwright does. The socket's exposure is bounded: loopback, ephemeral port, token path, Origin refused, one client, closed with the driver; nothing but MAWS's main process ever learns the URL.
3. **The pause point is before dispatch, after an input-free readiness wait; a request is abortable until its first page-changing command leaves; an in-flight command is never cancelled.** The readiness wait is `waitFor({ state: 'visible' })` plus `isEnabled`/`isEditable` polling, never Playwright's `trial`, which still sends the press and release and only swallows the DOM events (`coreBundle.js:20283`; the first draft got this wrong and the document review caught it). The abort signal is checked at the pause point and again before dispatch and is passed to every Playwright call, so `control_cancel_request` aborts the wait and the action as the parent says; a half-sent click (`mousePressed` without `mouseReleased`) would leave the page with a stuck button, so once the first CDP command has left, the action finishes and its answer is discarded. A human click during the dispatch itself is attributed by E4a's table and takes `control` for the next action, which is all the arbitration §3 D asks of P1.
4. **`control` returns from `agent` to `idle` after 10 s without an action, from `human` to `idle` after 3 s without input (A-31), and `human` is entered only when the person's input conflicts with the agent.** Ten seconds covers a model's thinking between two calls without flickering the chrome and E4a's cap eligibility; three seconds is the owner's ruling. A click on a page no agent holds and no request awaits stays `idle` (the first draft flipped every click to "You have the page" with a Hand back button for a page the agent never held; the document review called it meaningless, and it is), while a click within 3 s before an action makes the action wait out the rest with the slot and the button shown; `lastHumanAt` is E4a's and is stamped either way.
5. **Reads never wait for the human, never touch `control`, never move the selection; actions do all three.** `browser_snapshot`, `browser_screenshot` and `browser_tabs` (but `close` on a held tab) proceed while `control === 'human'`: reading does not disturb the person, and the agent seeing what the person is doing is the point of a shared surface. `browser_eval` waits: it can change the page. Loads (`open`, a resume) mark `agent` before their first network event so E4a refuses an agent's download (A-31), but have no holder to wait for.
6. **An action selects its tab and opens the Browser tool once, and never moves the selection away from a tab the person is using.** §3 D says the human sees the acting tab; E1's `connectAsks` opens the sheet the same way. The selection does not move while the selected tab is `human` or saw human input within 3 s (the panel would otherwise hide the page the person is typing in and send their keys to a hidden page: from the document review), and reads never move it. A person who moves to another panel tab is not pulled back on later actions. Nothing switches the main view (the architect's ask ruling).
7. **The cover waits; the unplaced tab is parked by measurement.** Under a sheet the page's `requestAnimationFrame` stays paused even with focus emulation on (`visibility4.json:66-69`), so no hold can make an action proceed and A-33's "off for covered" costs nothing: actions and non-viewport screenshots wait for the cover to lift and say so; a viewport screenshot uses `capturePage`, which works hidden. A never-placed view (the agent's second tab; any tab of a session the owner is not viewing) is 1 × 1 and unattached, a case E4-0 never measured, so Task 0.3 measures three ways to give it a working viewport (sized unattached; attached off the window's content area and visible, the stock-Electron analogue of Codex's painted off-screen webview) and the first that passes click and screenshot becomes `park`; if none does, the multi-session scene needs the owner's view and the hand-back says so. The first draft's "visibility hold" (re-asserting emulation during actions) is withdrawn: it contradicted the measurement and A-33. `setBackgroundThrottling(false)` while `agent` stays as a tune-up. *Outcome* (M0 Task 0.3, 2026-10-07; `spikes/browser-probe/findings-e4c-unplaced.txt`, `results/e4c/unplaced.json`): **the parking variant is (b)**: `park` takes the view out of any window (a released tab's view still sits hidden in its last window, so `park` detaches it as E4a's `ViewManager.detach` does) and gives it `setBounds({ x: 0, y: 0, width: 1280, height: 800 })` and `setVisible(true)` while unattached; measured 1280 × 800, `visible`, rAF 121 Hz, snapshot with refs, click in 24 ms, screenshot 1280 × 800 CSS px. (e), a hidden host window per parked view, passes identically and is the fallback if a later reading needs an owner window. (a) as E4a creates a view (no bounds: 0 × 0, not 1 px), (c) attached off the content area and (d) give a 0 × 0 viewport (snapshot yes, click timeout, screenshot refused), so the off-content route does not exist in stock Electron. - **M2 Task 2.4, a parked page's visibility is Playwright's, not the view's** (`findings-e4c-released.txt`): with no CDP client attached, a view out of any window reads `hidden` with no rAF whether or not `setVisible(true)` was called; once Playwright is connected (its attach-time `Emulation.setFocusEmulationEnabled`) it reads visible at 121 Hz either way.
