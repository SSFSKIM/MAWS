## Purpose

After E4c the agent can use the browser the owner already has. In any session MAWS launches, the model sees six more tools: `mcp__maws__browser_tabs`, `browser_navigate`, `browser_snapshot`, `browser_act`, `browser_eval`, `browser_screenshot`. It opens a page in a tab of its own session, reads the page as an accessibility snapshot whose lines carry refs, fills a field or clicks a button by ref or by a CSS locator, reads a value with an expression, and takes a screenshot that comes back to it as an image and to the owner as a deliverable. Every call is one compact row in the transcript naming the tab, the target and the time it took; the owner sees the acting tab come forward in the Browser tool with the agent's cursor moving in the page. When the owner clicks into a page the agent is using, the agent's next action stops and the chrome says "You have the page · Hand back"; three seconds after the owner's last input, or at the button, the action resumes. A session resumed in the terminal has none of this and nothing breaks.

To see it: open a session with the Browser tool, send "Open https://example.com in the MAWS browser, snapshot it, and tell me the heading", watch the tab open and the row appear; then send "Click the More information link"; while the agent's click is pending, click the page yourself: the chrome shows "You have the page", the row says it is waiting, and three seconds after you stop the click lands.

## Terms

- **Tab**, **view**, **pane**, **placement**, **cover**, **chrome**, **control**, **`TabDebugger`**, **attribution**: as E4a's Terms define them. A tab is **shown** when its view is placed in a pane of a visible, uncovered window (E4a Design §3's `shown` with `covered` false and the window not hidden or minimized); otherwise it is **hidden**, which to the page means `document.visibilityState === 'hidden'` and no `requestAnimationFrame` (E4-0 (2)).
- **Browser tool** (lowercase "tool" when it means the MCP tool): one of the six `browser_*` tools on the `maws` server. **The Browser tool** (capital) is E4a's X5 panel tool.
- **Driver**: E4c's per-tab object in main (`src/main/browser/agent/driver.ts`) holding the CDP bridge, the Playwright `Browser`, `BrowserContext` and `Page` for one tab, created on the first browser tool call that targets the tab and closed on idle, tab close or crash.
- **Bridge** (the CDP bridge): E0b's `cdp/bridge.mjs` lifted into main (`src/main/browser/agent/bridge.ts`): a loopback WebSocket endpoint that answers the browser-level CDP methods Playwright needs and forwards page-session commands through `TabDebugger.send`, under E0b's allowlist plus an Origin check. **Host bridge**: the host↔main request and answer pair (`maws.browser.request`, `maws.browser.answer`), E1's `HostBridge` pattern with a pausable deadline.
- **Ref**: Playwright's `aria-ref` id (`e12`, `f2e7`: an optional frame ordinal and an element number) printed as `[ref=…]` on a snapshot line; valid for one document and until the next snapshot of that frame (E0b S2d). **Target**: what `browser_act` and `browser_screenshot` aim at: a ref, or a locator `{ css, role?, name? }` (the shape E4d's anchors carry, X10).
- **Action**: a browser tool call that acts on a page: `browser_navigate`, `browser_act`, `browser_eval`, and `browser_tabs {action: 'close'}` on a tab the human holds. A **read** is `browser_snapshot`, `browser_screenshot`, `browser_tabs` otherwise. The **pause point**: the moment before an action dispatches its first page-changing CDP command, after its actionability wait, where the driver checks `control`.
- **Hand-back**: the transition out of `control: 'human'`, by the chrome's button (E4a's `browser.control.handBack`) or by `BROWSER_HANDBACK_IDLE_MS` (3,000 ms) without human input (A-31).
- **Stand-in**: the live test's substitute for main: it answers `maws.browser.request` events with canned answers the real app generated earlier (Design §13).
- **Engine host**, **main**, **renderer**, **X1 event**, **meta row**, **replay**, **fixture**, **conformance suite**, **scratch home**: as E1's document defines them.

## Design (the residue §3 D and E4's cut leave open, with reasons)

### 1. Ownership and data flow

The **host** owns the six tool definitions, parses arguments, asks main through the host bridge, formats the MCP result (JSON text first; the image block before the JSON for a screenshot; the snapshot's YAML as a second text block), writes the `screenshot` record, and answers the engine. **Main** owns everything that touches a page: the per-tab driver (bridge, Playwright, page), the six handlers, the control state machine, the cursor channel, the visibility hold, the screenshot file. **The renderer** draws the `browser_action` row from the transcript's events (live and from disk), its waiting line from a transient IPC event, the acting-tab chip and the Browser tool's following of the agent; the **preload** draws the cursor from main's messages and reports nothing in this child. The normaliser emits `maws.browser.action` from the host's `control_response` row, so the row's facts (tab, target, URL, ms, deliverable, error) come from the journal and a rebuild reproduces them; the live waiting state is not an X1 event (it would re-deliver on every reload; E1's residue 3 for the pane bridge).

One call's path: `tools/call browser_act` → `server.ts` `call` → `browser.ts`'s definition parses with `BrowserActInputSchema` (a refusal answers `invalidArguments` at once) → `BrowserBridge.request({ requestId, toolUseId, tool, args }, ctx.signal)` → `EngineSession` emits `browserRequest` → `ipc.ts`'s `wire` emits `maws.browser.request` → main's `startBrowserAgent` (`hosts.onEvent('maws.browser.request', …)`) → the session's tab is found (P-21) → the driver runs the action (Design §5 to §7) reporting `maws.browser.waiting` while it waits on the human or a cover → main `dispatch('engine-host', 'maws.browser.answer', { appSessionId, requestId, result })` → the host's bridge settles → the tool formats the result → `control_response` → the normaliser emits `maws.browser.action` → the row.

Descriptions (exact; the fallback sentence first, A-18; each ends with a `Returns` sentence):

- `browser_tabs` (title "Browser tabs"): *List, open, close or select this session's tabs in the MAWS browser; without this tool, ask the user to open the page and describe what you need from it. "list" returns the session's tabs with their ids, URLs, titles and who controls each; "open" takes a url (http or https) and opens it in a new tab that stays open until you close it; "close" and "select" take a tabId. Tabs the user opened are listed too; the user sees the tab you act on. Returns the tab list and, for open, the new tab's id.*
- `browser_navigate` (title "Browser navigate"): *Navigate a MAWS browser tab to a URL, or go back, forward or reload; without this tool, ask the user to open the page. url is an http or https URL or one of "back", "forward", "reload" (reload also loads a tab the user left unloaded). Waits for the page to load (up to 30 s). A page that starts a download is refused: the user downloads files, you do not. Returns the tab's URL and title after the load.*
- `browser_snapshot` (title "Browser snapshot"): *Read a MAWS browser tab as an accessibility snapshot with element refs; without this tool, ask the user to describe the page or paste its text. Each interactive or named element has a ref like e12 that browser_act and browser_screenshot accept as a target. Refs are valid for the current document and until your next snapshot of it: after a navigation or a later snapshot, take a new snapshot before acting. The snapshot is cut at maxChars (default 24000, at most 64000) on a line boundary with a trailer saying how much was omitted and an outline of the page's landmarks and their refs, so you can call again with root set to a ref or a landmark role (banner, navigation, main, contentinfo, search, complementary, region, form) for one subtree; a rooted snapshot invalidates refs outside that subtree until the next whole-page snapshot. Returns the snapshot as text after a JSON header with the tab's URL, title and the cut.*
- `browser_act` (title "Browser act"): *Act on an element in a MAWS browser tab: click, fill, select, check, press, hover or scroll; without this tool, ask the user to do it and tell you the result. target is a ref from browser_snapshot (e.g. "e12") or a locator {css, role?, name?} such as a comment anchor carries. fill types value into a field (replacing its content); select picks the option whose label or value is value; check sets a checkbox to value ("true" or "false", default true); press sends a key or chord (e.g. "Enter", "Control+a") to the element; scroll scrolls the element into view and then by value pixels when given (negative scrolls up). The action waits for the element to be visible and enabled (up to 10 s). If the user is using the page, the action waits until they stop or hand it back, and the result says so. A ref that no longer resolves is an error naming it: take a new snapshot. Returns the tab's URL and title after the action and whether it navigated.*
- `browser_eval` (title "Browser eval"): *Evaluate a JavaScript expression in a MAWS browser tab's page and return its value; without this tool, use browser_snapshot or ask the user. Use it to read page state (text, attributes, computed values, JSON the page holds); it runs in the page with the page's permissions, so prefer browser_act for changes. A promise is awaited; the value is returned as JSON (cut at 16000 characters). If the user is using the page, the evaluation waits until they stop. Returns the value and the tab's URL and title.*
- `browser_screenshot` (title "Browser screenshot"): *Take a screenshot of a MAWS browser tab and receive it as an image; without this tool, use browser_snapshot. target (a ref or a locator) screenshots one element; fullPage captures the whole scrollable page; neither captures the viewport. The picture is also saved as a deliverable the user can open from the transcript. Pictures are kept under 3.5 MB (JPEG when a PNG would exceed it). Returns the image and a JSON record with the deliverable id, size and format.*

### 3. The host: `BrowserBridge` and the six definitions

`src/engine-host/tool-server/browser-bridge.ts`: `BrowserBridge` has `HostBridge`'s outcomes (`answered | timeout | withdrawn | ended`) and two additions E1's class lacks: **a pausable deadline** (`waiting(requestId, reason: 'human' | 'cover' | null)`: a non-null reason clears the deadline timer and records the reason; `null` re-arms the full `BROWSER_ANSWER_MS`; so the deadline is 30 s of main's own work, unbounded while the human holds the page or a cover holds the action, with the abort signal as the exit) and **a cancel notification** (on the signal's abort the bridge emits `browserCancel { appSessionId, requestId }` so main stops waiting and the row turns cancelled; the host writes nothing for the call, `server.ts:182`). `appNotOpen` fast-fail: the bridge is constructed with `connected: () => boolean` (E10's host knows whether a client holds the socket; under the utility-process host of today it is `() => true`); a request with no app answers `appNotOpen` at once (X13). `EngineSession` gains `browser: BrowserBridge`, `Listeners.browserRequest` and `.browserCancel`, `answerBrowser(requestId, result)`, `browserWaiting(requestId, reason)`; `ipc.ts`'s `wire` relays `browserRequest → emit('maws.browser.request', …)` and `browserCancel → emit('maws.browser.cancel', …)`; `handleMaws('maws.browser.answer', …)` and `('maws.browser.waiting', …)`; `MAWS_DEADLINE_SHAPES` gains both as `'immediate'`; `processExited` settles pending browser requests `ended` beside the panes and captures (`session.ts:1133-1136`).

`src/engine-host/tool-server/browser.ts`: `browserTools(deps: { bridge: BrowserBridge; deliverables: DeliverableWriter; userData: string; readFile })` returns the six `McpToolDefinition`s through `defineMawsTool`. Each `call` parses (the host and the normaliser parse with the same schema, so they agree on admission), builds the request `{ requestId: ctx.requestId, toolUseId: ctx.toolUseId, tool, args }` (for `browser_screenshot` plus `deliverableId: randomUUID()` and `path: screenshotPath(userData, appSessionId, deliverableId, 'png')`, the host naming the file so both sides know it; main may answer `.jpg` beside it after the fallback and the answer carries the path written), awaits the bridge, and maps: `answered` with `ok: false` → `toolError(answer.error)` (main's texts are the `BROWSER_TOOL_ERRORS` above, formatted in main from the same module); `timeout` → `browserTimeout`; `withdrawn`/`ended` → internal texts never written; `answered` with `ok: true` → the result validated against the tool's result schema (a mismatch is `actionFailed(tool, 'answer', '', 'malformed answer from MAWS')`, pinned by a test) and formatted: `browser_snapshot` `[toolText(json), { type: 'text', text: answer.text }]`; `browser_screenshot` reads the file at `answer.image.path` (`readFile`), writes the record through `deliverables.exclusive(appSessionId, () => deliverables.write({ id: deliverableId, appSessionId, kind: 'screenshot', path, title: answer.result.title || hostOf(url), sourceUrl: url, versions: [{ path, at, toolUseId }], toolUseId, createdAt }))` (X12; `sourceUrl` additive), then `[{ type: 'image', data: base64, mimeType }, ...toolText(result).content]`; the others `toolText(result)`. The browser tools never read `ctx.cwd`.

### 4. Main: the per-tab driver over `TabDebugger.send` (the bridge, Playwright, the idle rule)

`src/main/browser/agent/` (new, under E4a's `src/main/browser/`): `index.ts` (`startBrowserAgent({ tabs, hosts, emit, env, userData }) → { stop }`, wired from E4a's `startBrowser` or from `src/main/index.ts`'s E4c block after E4a's; subscribes `hosts.onEvent('maws.browser.request')` and `('maws.browser.cancel')`; answers through `hosts.dispatch('engine-host', 'maws.browser.answer', …)` and reports through `('maws.browser.waiting', …)`; one request at a time **per tab** (a per-tab promise chain: the engine does not run two actions on one tab concurrently, but two sessions' tabs run in parallel); the e2e seam under `MAWS_E2E=1` (Interfaces)), `bridge.ts`, `driver.ts`, `handlers.ts` (the six), `locate.ts`, `snapshot.ts`, `screenshot.ts`, `control.ts`, `cursor.ts`, `visible.ts`, `progress.ts`, `errors.ts` (formats `BROWSER_TOOL_ERRORS` into `{ ok: false, error }` answers).

**The bridge** (`bridge.ts`, E0b's `cdp/bridge.mjs` lifted to TypeScript with these changes and no others): every `dbg.sendCommand(method, params, sessionId)` becomes `debugger.send(method, params, sessionId)` and every `dbg.on('message', …)` becomes `debugger.on(…)` (the raw debugger is never touched; the in-flight `Input.*` table fills itself inside `send`, E4a Decision 19; the probe's `onCommand` hook is E4a's `onCommand` observer, which `cursor.ts` and the latency log read); `Page.getFrameTree` once for the target id (the real main-frame id, stable across process swaps, E4-0 (3)); the allowlist unchanged (`SESSION_TARGET_ALLOW`, the four refused domains, `knownSessions` fed by auto-attach events, unknown sessions refused with `unknown session`, `Target.getTargets` on a page session refused as `not available through the MAWS debugger bridge`, the browser-level `Target.createTarget`/`closeTarget`/`attachToBrowserTarget`/`exposeDevToolsProtocol` refused); **the Origin check** added: an upgrade carrying any `Origin` header is refused with 403 (a Node WebSocket client sends none; a page's would), beside the token-path check (404) and a limit of **one** open socket per bridge (a second upgrade while one is open is refused with 409); bound to `127.0.0.1` on an ephemeral port; `Browser.getVersion` answers Chromium's product string; `Browser.setDownloadBehavior` and the `Storage.*` browser-level calls answer empty as the probe did (Playwright sends them at attach; nothing is granted). `close()` terminates the socket, closes the server, and detaches the debugger **only when told to** (`close({ detach })`), since under focus emulation `on` the attachment is E4a's to keep. `bridge.test.ts` is G3 (Acceptance).

**The driver** (`driver.ts`): `Driver.for(entry)` creates on demand: `debugger.attach()` (idempotent), `startBridge(entry.debugger, …)`, `chromium.connectOverCDP(bridge.wsUrl, { timeout: 10_000 })`, `browser.contexts()[0].pages()[0]` (the bridge announces one page; `newPage` fails by design). The `Page` is kept across navigations and process swaps (E4-0 (3)); after a renderer crash (E4a's `render-process-gone` detaches the debugger; the bridge broadcasts `Target.detachedFromTarget`; Playwright's page closes) the driver is dropped and the next action creates a fresh one after E4a's Reload revived the renderer. Default timeouts: `page.setDefaultTimeout(BROWSER_ACTION_TIMEOUT_MS)`, `setDefaultNavigationTimeout(BROWSER_ANSWER_MS)`. **Idle**: a driver with no request for `BROWSER_BRIDGE_IDLE_MS` (5 min) while `control !== 'agent'` closes: Playwright's connection and the WebSocket always; the debugger `detach()` only when `FOCUS_EMULATION === 'off'` (M0's verdict; with `on` E4a keeps the attachment for the page's visibility and "detaching after idle" falls, A-33). The cost of staying is +22 MB per attached renderer (E0b); the reason for five minutes rather than E0b's "while the agent holds the tab" is that a closed connection loses Playwright's ref table, so a model thinking for a minute between calls would meet stale refs for nothing. A tab's close (`webContents.close()`) and the session's exit close its driver at once. `playwright-core` is `require`d lazily on the first driver (114 ms from the asar, E4-0 (6)), never at startup.

**`require('playwright-core')` and `ws`** (A-33 item 6): both in `package.json` `dependencies` (exact versions), externalised by electron-vite's default and packed into the asar by electron-builder with no `asarUnpack`; nothing else in the build changes. `electron.vite.config.ts` gains no `external` entry (the dependency route needs none; the bundled-`ws` route would need `bufferutil` and `utf-8-validate` externalised and is not taken, Decision Log 8). The packaged proof is M4's.

### 5. Snapshots and refs (A-33 item 5)

`snapshot.ts` (main) takes the snapshot: `root` absent → `page.ariaSnapshot({ mode: 'ai' })`; a ref → `page.locator('aria-ref=' + root)`, checked with `count()` (0 → `rootNotFound`), then `locator.ariaSnapshot({ mode: 'ai' })`; a landmark role → `page.getByRole(role)`, `rootMatches = count()`, 0 → `rootNotFound`, else `.first().ariaSnapshot(…)` (one root only, because Playwright keeps one ref table per frame and the latest snapshot replaces it, so several rooted snapshots in one call would invalidate each other's refs, E0b S2d; the header says `rootMatches` and the description tells the model to pick a specific landmark by its ref). The raw text goes through the pure `cutSnapshot(text, { maxChars })` in `src/shared/browser/snapshot.ts`: if `text.length <= maxChars` it is returned whole with `truncated: false`; else the **outline** is built first (every line at indentation depth 0 or 1 whose role is a landmark or that carries a `[ref=…]`, at most `BROWSER_SNAPSHOT_OUTLINE_MAX_LINES`, prefixed `# outline (refs for root):`), then the body is cut at the last line boundary that keeps `outline + body + trailer` within `maxChars` (never inside a node line), then the **trailer** `… <n> more lines (<m> refs) omitted; call again with root: <ref> for a subtree or raise maxChars (max 64000)` with `m` counted by `/\[ref=[^\]]+\]/g` over the dropped lines. The result's JSON header carries `chars`, `lines`, `refs` of the whole, `truncated`, `omitted`. `snapshot.test.ts` runs the cut over E4-0's three saved real snapshots (`results/pass2/snapshot-*.txt`): GitHub at 24,000 keeps about 47 % of its refs and the outline lists its landmarks with refs; Wikipedia at 64,000 is still cut; a 448-character page is returned whole; a cut never splits a line; the trailer's counts equal the dropped lines' counts. Refs are `(f\d+)?e\d+`; the frame prefix appears once a second document exists (E0b) and OOPIF subtrees carry their own ordinal (E4-0 (4)), so `browser_act` by ref reaches into iframes with no frame argument.

### 6. Actions, targets, actionability and the pause point

`locate.ts`: a ref → `page.locator('aria-ref=' + ref)`; `count()` at once: a Playwright error naming an invalid frame (`Invalid frame in aria-ref selector`, E0b S2d) → `staleRef(…, 'previous-document')`; 0 → `staleRef(…, 'missing')`. A locator `{ css, role?, name? }` → `let loc = page.locator(css)`; with `role`, `loc = loc.and(page.getByRole(role, name ? { name, exact: true } : {}))`; `count()` after waiting up to `BROWSER_LOCATE_MS` for at least one match (`loc.first().waitFor({ state: 'attached', timeout })` in a try); 0 with `role` and `name` → a fallback `page.getByRole(role, { name, exact: true })` when it has exactly one match (the element moved; E4d's anchor still names it), else `targetNotFound`; several → `.first()` and `matches: n` in the result. The result's `target` echoes what resolved.

`handlers.ts` runs an action in four steps. (1) **Select the tab for the human**: `tabs.select(appSessionId, tabId)` (the panel's Browser tool shows the acting tab, §3 D "the human sees the acting tab") and `emit('browser.agent.acting', { appSessionId, tabId })` (the renderer opens the Browser tool once if the session has none open, Design §10); `control.ts` sets `control: 'agent'` (Design §8). (2) **Resolve and wait**: `locate`, then the actionability trial `loc.click({ trial: true, timeout: BROWSER_ACTION_TIMEOUT_MS })` for `click`, `fill`, `select`, `press` (a disabled or hidden element fails the trial as it would the action; `trial` performs the checks and dispatches nothing, so no `Input.*` command enters the attribution table), `loc.check({ trial: true })` for `check`, `loc.hover({ trial: true })` for `hover`, `loc.scrollIntoViewIfNeeded()` for `scroll`; a timeout → `actionTimeout`. While this wait runs, `visible.ts` holds the page awake (Design §9) and `progress.ts` reports `waiting: 'cover'` to the host and the renderer when the wait passes 2 s with `entry.tab.covered` true (A-33 item 2: the row says a sheet covers the page). (3) **The pause point**: if `control === 'human'`, report `waiting: 'human'`, and await `control.ts`'s `whenReleased(entry, signal)` (resolves when `browser.control.changed` leaves `'human'`: the hand-back button or the 3 s idle timer; rejects on the signal's abort → `humanHasPage`); then set `control: 'agent'` again. (4) **Dispatch**: `cursor.ts` moves the cursor to the target's box centre (Design §9), then the real action with a short timeout (`5_000`): `click` → `loc.click()`; `fill` → `loc.fill(value)` (Playwright's `Input.insertText`, which raises no input event, E4-0; nothing to attribute); `select` → `loc.selectOption({ label: value })`, falling back to `{ value }`; `check` → `loc.setChecked(value !== 'false')`; `press` → `loc.press(value)` (CDP keys carry the from-debugger bit, attributed agent); `hover` → `loc.hover()`; `scroll` → `scrollIntoViewIfNeeded`, then `loc.hover()` and `page.mouse.wheel(0, Number(value))` when `value` is given. A thrown Playwright error → `actionFailed` with its first line. After the action the handler waits briefly for a navigation it may have started (`page.waitForLoadState('load', { timeout: 2_000 })` in a try; `navigated` is whether `page.url()` changed), reads `url` and `title`, and answers with `ms` and the waits. **An in-flight CDP command is never cancelled** (a `mousePressed` without its `mouseReleased` would leave the page with a stuck button); the human's input during the dispatch itself is attributed by E4a's table and takes `control` for the **next** action, which is the only arbitration P1 has (§3 D).

`browser_navigate`: `url` → E4a's `navigation.navigate(entry, { url, typed: false })` (so E4a's load-error lifecycle, history write, `will-navigate` gate and the `loadError` state all apply as for a human's navigation) and `waitForSettled(entry)`: resolves on the first `did-stop-loading` after a main-frame `did-navigate` or `did-navigate-in-page`, rejects on `loadError` set (`navigationFailed` with E4a's `kind` and `code`), on `crashed` (`tabCrashed`), on a `browser.download.refused` for this tab during the wait (`downloadRefused`, A-31; a download aborts the navigation with `-3`, which E4a ignores, so without this listener the wait would run to the deadline), or at the deadline (`browserTimeout`'s main-side twin, 28 s, so main answers before the host's 30). `back`/`forward` → E4a's `navigate(entry, 'back' | 'forward')` with the same wait (no history entry → `actionFailed(tool, 'back', '', 'no page to go back to')`); `reload` → `'reload'`, or on a **suspended** tab E4a's resume path (`navigate(entry, { url: entry.tab.url })`), which is how the agent loads a tab the owner left unloaded (E4a Design §2). `browser_navigate` is an action: it passes the pause point before it navigates.

`browser_tabs`: `list` → the session's tabs as `BrowserTabSummary` (suspended tabs with `loaded: false`); `open` → E4a's `tabs.open({ appSessionId, url, select: true })` then `waitForSettled` (a cap-forced suspended open answers `loaded: false` and the description's "stays open" holds); `close` → the pause point when that tab is `control: 'human'`, then `tabs.close(tabId)`; `select` → `tabs.select`, resuming a suspended tab as `reload` does, so a following snapshot works. Every `tabId` is checked against `entry.tab.appSessionId === appSessionId` first (P-21).

`browser_eval`: a read in the sense that it does not dispatch input, an action in the sense that it can change the page: it passes the pause point (Design §8's table), then `page.evaluate(expression)` with a string (Playwright evaluates a string as an expression and awaits a promise); the value is JSON-serialised (`undefined` → `null`; a non-serialisable value → `String(value)`), cut at `BROWSER_EVAL_MAX_CHARS` with `truncated: true`; a thrown error → `evalFailed(message)`. The expression runs through the tab's page session only (the bridge admits no other session; the handler holds no other page), so it can never reach MAWS's own renderer by construction.

`browser_snapshot` and `browser_screenshot` are reads: no pause point, no `control` change (reading does not disturb the human, and seeing what the human sees is the point of a shared surface; Decision Log 5). They do set the acting tab (step 1) so the human sees what the agent looks at.

### 7. Screenshots and the `screenshot` record (X12, A-34)

`screenshot.ts`: `target` → `locate`, then `loc.screenshot({ type: 'png', scale: 'css', timeout })`; `fullPage` → `page.screenshot({ fullPage: true, type: 'png', scale: 'css' })`; else `page.screenshot({ type: 'png', scale: 'css' })`. `scale: 'css'` keeps the pixel size at CSS px (a Retina capture would quadruple the bytes for nothing the model needs). The bytes are checked against `BROWSER_SCREENSHOT_MAX_BYTES`: over it, the capture is retaken as `{ type: 'jpeg', quality: 80 }` (the fallback A-34 names; the path's extension becomes `.jpg` and the answer says `mimeType: 'image/jpeg'`); still over → `screenshotTooLarge`. The file is written with E4a's `atomicWriteFile` at the host-named path (the directory created), the answer carries `{ path, width, height, bytes, mimeType }` (width and height from the PNG's IHDR or the JPEG's SOF, a 20-line reader in `screenshot.ts`); the host writes the record (Design §3). The viewer opens it as E2 opens an image record (`openDeliverable` → the Deliverables tool → the image inline; the executor verifies `kind: 'screenshot'` draws and adds the icon and group E2 already declares; `tools/deliverables/model.ts:31`, `icons.tsx:55`). A screenshot under a cover or on a hidden tab would hang in Chromium's `Page.captureScreenshot` (a background page presents no frame); the visibility hold (Design §9) wraps the capture as it wraps actions.

### 8. The takeover: the control state machine (A-31, A-33)

`control.ts` owns every transition of `entry.tab.control` but `handBack`'s (E4a's). Inputs: E4a's `entry.input.emit` events (`{ kind, source }`), E4a's `browser.control.changed` from `handBack`, the handlers' action start and end, two timers. Rules, as a table (`control.test.ts` pins every row with fake timers):

| from | event | to | side effects |
|---|---|---|---|
| any | `human` input (key, mouse, wheel) | `human` | `controlSince` stamped if it changed; the hand-back timer armed for `lastHumanAt + BROWSER_HANDBACK_IDLE_MS`, re-armed on every further human input; `browser.control.changed` emitted on the change; a pending agent action's wait begins (`whenReleased`) |
| `human` | the hand-back timer fires (3 s without human input, A-31) | `idle` | emitted; waiting actions resume |
| `human` | `browser.control.handBack` (E4a sets `idle` and emits) | `idle` | the timer cleared; waiting actions resume |
| `idle` or `agent` | an action starts (after the pause point) | `agent` | `controlSince` stamped on the change; the agent-idle timer cleared; `setBackgroundThrottling(false)` on the view (Design §9) |
| `agent` | an action ends | `agent` | the agent-idle timer armed for `BROWSER_AGENT_IDLE_MS` (10 s), so a model thinking between two calls does not flicker the chrome |
| `agent` | the agent-idle timer fires | `idle` | emitted; throttling restored |
| `agent` | `human` input | `human` | as the first row (the agent's in-flight CDP command completes; the next action waits) |
| any | `agent` input (CDP, attributed by E4a's table) | unchanged | nothing: the agent's own input never takes the page |
| `human` | the tab is closed or its session exits | — | the timer cleared; `whenReleased` rejects for pending actions (they answer `tabClosed`) |

`whenReleased(entry, signal)` resolves when `control` leaves `human` and rejects on `signal.aborted` (the host's `maws.browser.cancel` from `control_cancel_request`, `notifications/cancelled` or the session's exit: the action answers nothing and the row reads "Cancelled, the turn was interrupted" from its missing result; `humanHasPage` is the text the host would have written and is kept as the error name the ledger reserves). While `human`, E4a's control slot shows "You have the page" with **Hand back**; the row's waiting line says the same (Design §10). The 3 s rule is A-31's and holds whether or not an action is pending: `human` is "the person is using the page", not "the agent is blocked", so a person reading without input returns the tab to `idle` after 3 s and takes it back with their next click. A tab under `control: 'agent'` is never suspended by E4a's cap (E4a Decision 6) and E4a's clipboard carve-out and download handler read `control` as this child sets it.

The in-flight race E4-0 measured (a human press inside an agent press's window leaves exactly one unmatched press, which is the human's) means the takeover fires on the first human click even during a click; the "pause point" rule means the agent never dispatches into a page the human holds. What P1 does not do: hold `human` while the pointer is merely over the page, arbitrate typing against the agent's `fill`, or warn the agent that the page changed under it (Deferred).

### 9. The agent's cursor and the visibility hold

**The cursor** (`cursor.ts`, `src/preload/browser.ts`'s channel `browser:cursor`): main observes the tab's `TabDebugger.onCommand` for `Input.dispatchMouseEvent` sends (`params.type` `mouseMoved`, `mousePressed`, `mouseReleased`, with `x`, `y` in CSS px of the page, which is what Playwright sends and what the preload's `position: fixed` needs; at zoom the command carries CSS px, E4-0) and sends `view.webContents.send('browser:cursor', { kind: 'move' | 'press' | 'release' | 'target' | 'hide', x, y, box? })`: `move` on every `mouseMoved` and before each action from the target's `boundingBox()` centre (so `fill` and `press`, which move no mouse, still show where the agent is), `press`/`release` on the button events, `target` with the box when an action resolves its element, `hide` when `control` leaves `agent`. The preload (sandboxed, `contextIsolation`, `ipcRenderer.on` only; it exposes nothing and sends nothing in this child) keeps one `<maws-agent-cursor>` host element appended to `document.documentElement` with a closed shadow root (re-appended on `DOMContentLoaded` and whenever a message finds it detached): a 20 px arrow pointer (SVG, white fill, near-black stroke, a 6 px soft glow in one fixed accent blue, `#2f6feb` as E2's picker overlay uses in `bridge-script.ts`: the page is not MAWS's renderer and has no tokens; the colours are a system cursor's and theme-neutral), `pointer-events: none`, `z-index: 2147483647`, moved with a 160 ms ease (Codex's spring is the reference; a transition is enough here), a 24 px ripple on `press`, a 2 px accent outline of `box` fading over 800 ms on `target`, fading out 1.5 s after the last message or at `hide`. The page can see and remove the element (the DOM is shared; only the JS worlds are isolated) and gains nothing by it; it cannot read the channel. `src/preload/bundle.test.ts`'s constraint holds: the cursor code lives in `src/preload/browser-cursor.ts`, imported by `browser.ts` alone, so Rollup inlines it. No arrival handshake in P1 (Decision Log 10). The chip of a tab under `control: 'agent'` shows a small accent dot (`bg-accent`) before its title (E4c block in E4a's `TabStrip.tsx`), the acting tab.

**The visibility hold** (`visible.ts`): a page that is hidden (unplaced, covered, in a hidden or minimized window) has no `requestAnimationFrame`, so Playwright's actionability stability check (two consecutive frames) and `Page.captureScreenshot` stall (E4-0 (2); A-33 item 2). Playwright's own attach sends `Emulation.setFocusEmulationEnabled { enabled: true }` (`coreBundle.js:37638`), which is the measured un-hide path and keeps the page awake while the driver is connected; E4a, under `FOCUS_EMULATION === 'on'`, sends `{ enabled: false }` for covered, unplaced and hidden-window tabs (its Design §3), which would put the agent's tab back to sleep. So `hold(entry)` (called around every wait, dispatch and capture; reference-counted) sends `Emulation.setFocusEmulationEnabled { enabled: true }` through `debugger.send` when the tab is not shown and releases by restoring E4a's rule (`visibility.ts`'s own evaluation for that tab) when the count returns to 0; with `'off'` the release sends nothing (Playwright's attach-time state stands, and the idle close detaches). `control.ts` also calls `view.webContents.setBackgroundThrottling(false)` while `control === 'agent'` and restores `true` at `idle` (E4-0: a second un-hide path for rAF and timers, lost on navigation, so the hold's emulation is the one that counts; Codex does both, `main…:116249-116262`). The cover report stays: when an action's wait passes 2 s while `covered`, the row says "waiting · a sheet covers the page" (A-33), which is true information even when the hold keeps the action moving (the person has a sheet open over the page the agent is working in).

### 11. Failure semantics

- **A tab closed mid-action** (the human's ×, `browser_tabs close` from another call, the session's deletion): E4a closes the view and detaches; the driver's page closes; the Playwright call rejects; the handler answers `tabClosed`; `control.ts` clears timers; pending `whenReleased` waits reject with the same.
- **A navigation that fails**: E4a's `loadError` → `navigationFailed(url, kind, code)`; the tab shows E4a's error page; refs are gone (a new document) and the description says to snapshot again.
- **A renderer crash mid-action**: `render-process-gone` → `tabCrashed`; the driver is dropped; E4a's crash page offers Reload; the agent's `browser_navigate reload` revives it and the next call builds a fresh driver (re-attach about 24 ms warm, E4-0 (3)).
- **A snapshot over the ceiling**: never an error; the cut applies; `maxChars` above 64,000 is refused by the schema (`invalidArguments`).
- **A stale ref**: `staleRef` with the reason (previous document or missing), naming the ref (E4's cut: "a stale-ref error naming the ref").
- **The app not open** (E10's detached host with no client): `appNotOpen` at once; nothing waits.
- **The human holding the page past the turn's end**: the engine's turn cannot end while a tool call is pending, so the action waits unbounded while `human` (the deadline is paused) until the hand-back or the person interrupts the turn, which aborts the wait (`control_cancel_request` → `maws.browser.cancel`); the row then reads "Cancelled, the turn was interrupted" and `control` returns to `idle` on the 3 s rule as ever. When no action is pending the state simply decays to `idle` after 3 s.
- **An interrupted turn's `notifications/cancelled`** (or `control_cancel_request`, or the session's exit): the server aborts the call's signal (`server.ts:99-104, 127-143`); the bridge emits `browserCancel`; main stops the wait and lets an in-flight CDP command complete, discarding the answer (the host writes nothing for an aborted call); the row reads cancelled; a dispatched action that completed anyway is visible in the page (the engine abandoned the result, which is the engine's rule for every tool).
- **Main does not answer** (a hang the per-action deadlines did not catch): the host's `browserTimeout` after 30 s of non-waiting time; a later answer is `not_pending`.
- **The host's `dispatch` deadline** (`REQUEST_TIMEOUT_MS` 10 s on main→host commands): answers are small (the screenshot travels as a path, never as bytes) and immediate.
- **The bridge's socket refused or dropped**: the driver creation fails → `actionFailed(tool, action, target, 'MAWS could not attach to the tab: <message>')`; the next call retries from scratch.
- **E4a's cap suspends a tab the agent will come back to**: a tab under `agent` is never a victim; after `BROWSER_AGENT_IDLE_MS` it can be; the agent's next call on a suspended tab answers `tabNotLoaded` for reads and acts, and `reload`/`select` resume it.

### 12. Security

- **Every URL is validated in main** by E4a's `validateBrowserUrl` (the schema refuses a non-http(s) URL before the host asks; main refuses again at the handler, `navigationRefused`), and a navigation goes through E4a's `navigate`, so `will-navigate`, the partition's `webRequest` filter and the download handler apply to the agent exactly as to the human.
- **`browser_eval`'s expression reaches only the tab's page**: the handler holds the tab's `Page` (one page per bridge, the real main-frame id as the target), the bridge admits only sessions it announced or Chromium announced on that page session, and MAWS's own renderer is never a target the bridge can name (`Target.getTargets`, `attachToTarget` to another target, `Target.createTarget` refused; G3). The expression runs with the page's origin and the imported profile's cookies: the agent is the owner on every site by design (A-31's partition pill says so to the human) and the permission mode gates the call (A-31).
- **The bridge's boundary**: the allowlist of E0b (no `Browser.*`, `Storage.*`, `SystemInfo.*`, `Tethering.*` on a session; `Target.*` limited to auto-attach's three with `getTargetInfo` on the own target only), unknown sessions refused, loopback only, an ephemeral port, a 128-bit token path handed to the driver alone, no `/json/version`, the Origin header refused, one socket, closed with the driver. The raw debugger is never exposed (E4a). The remote-debugging port never ships (A-19).
- **Input attribution** is main's and the preload's cursor channel is one-way into the page; the page learns nothing it could not see.
- **Screenshots** are written under `userData` by main at a host-named path; the record is the host's; the viewer reads it under E2's admission for delivered paths.
- **The agent's tabs are the session's** (P-21): a `tabId` of another session is `tabNotFound`, and `browser_tabs list` never names another session's tabs.
- **Permissions**: the three acting tools prompt under `default` through C3's broker as any MCP tool (A-25); nothing in this child answers a permission.

## Decision Log

1. **The idle rule follows M0's verdict.** With `FOCUS_EMULATION === 'on'` the `TabDebugger` attachment is E4a's to keep for the page's visibility, so the driver's idle close ends Playwright's connection and the socket and never detaches (A-33: "detaching after idle falls"); with `'off'` it detaches too, reclaiming the +22 MB. *Outcome*: written by M0.
2. **playwright-core over a loopback WebSocket bridge, not an in-process transport or raw CDP.** `connectOverCDP` accepts only a ws or http endpoint (`types.d.ts:17346`) and playwright-core exposes no transport injection; E0b's bridge is proven (717 commands, the boundary verified by a raw client) and A-19 names it. A raw-CDP driver without Playwright (snapshots, refs, actionability re-implemented) would be E4c's own thousands of lines for what Playwright does. The socket's exposure is bounded: loopback, ephemeral port, token path, Origin refused, one client, closed with the driver; nothing but MAWS's main process ever learns the URL.
3. **The pause point is before dispatch, after the actionability trial; an in-flight command is never cancelled.** Playwright actions cannot be aborted mid-way and a half-sent click (`mousePressed` without `mouseReleased`) would leave the page with a stuck button; `click({ trial: true })` runs the actionability checks and dispatches nothing, so the control check happens after the wait and before the first page-changing command. A human click during the dispatch itself is attributed by E4a's table and takes `control` for the next action, which is all the arbitration §3 D asks of P1.
4. **`control` returns from `agent` to `idle` after 10 s without an action, from `human` to `idle` after 3 s without input (A-31), and `human` holds whether or not an action is pending.** Ten seconds covers a model's thinking between two calls without flickering the chrome and E4a's cap eligibility; three seconds is the owner's ruling; a person reading a page without touching it gives the tab back and takes it with their next click, which is the no-hold rule of A-31 read literally.
5. **Reads never wait for the human; actions do.** `browser_snapshot`, `browser_screenshot` and `browser_tabs` (but `close` on a held tab) proceed while `control === 'human'`: reading does not disturb the person, and the agent seeing what the person is doing is the point of a shared surface. `browser_eval` waits: it can change the page. The reads still select the acting tab so the person sees what the agent looks at.
6. **An agent call selects its tab and opens the Browser tool once.** §3 D says the human sees the acting tab; E1's `connectAsks` opens the sheet the same way. A person who moves to another panel tab is not pulled back on later actions: only `tabs.select` moves, which the open Browser tool reflects. Nothing switches the main view (the architect's ask ruling).
7. **The visibility hold.** A hidden page (unplaced, covered, hidden window) stalls actionability and screenshots; Playwright's attach already sends `Emulation.setFocusEmulationEnabled { enabled: true }` (the un-hide path E4-0 measured and the reason pass one never saw the hidden state), and under `on` E4a turns it off for exactly those tabs. `hold()` re-asserts it for an action's duration and releases to E4a's rule; `setBackgroundThrottling(false)` while `agent` is the second measured path (Codex does both). The cover is still reported after 2 s because it is true information for the person, and A-33 names the report.
8. **`ws` as a production dependency, not bundled.** Bundling `ws` into main requires externalising `bufferutil` and `utf-8-validate` or its first frame throws (E4-0 (6)); the dependency route is one line in `package.json` and the same path `playwright-core` takes. Node's built-in `WebSocket` is a client only.
9. **Six discrete tools, not a REPL.** Codex exposes one `js` tool with a typed browser API read at runtime; X9's binding cut is six tools with JSON schemas the owner's skills can target by name (`mcp__maws__browser_*`), gated per tool by the permission mode (`browser_eval` apart from `browser_snapshot`), each a row of its own.
10. **No cursor arrival handshake in P1.** Codex waits up to 1.5 s for its cursor to arrive before clicking; MAWS sends `move` before the trial and the real click lands after it, which is usually longer than the 160 ms transition; a handshake would add a preload→main report for a cosmetic gain. Deferred.
11. **Results carry `ms` and the waits; `maws.browser.action` is mapped from the response row.** The normaliser's inbound table has no timestamp and E1's `McpCall` is not E4c's to widen; main measures and the result says; the model reading a small `ms` field is harmless (E0b: "a browser_act row can show its own latency without hiding anything"). No meta row: the journal says it once and the disk path derives the same row from the call.
12. **The snapshot's JSON header is a first text block and the YAML a second; the screenshot's image goes first.** A JSON object with the YAML escaped inside would cost tokens and read worse; the engine keeps whole text blocks while they fit (SPEC 31 §12.5) and the normaliser and `derive` read the first JSON object (A-34). The image-then-JSON order is E2's live-proven shape; the live recording proves the two-block snapshot reaches the model (the reply names the reference).
13. **No automatic re-snapshot after an action.** Playwright's MCP does; at 24,000 characters by default it would cost about 6,000 tokens per click. The result says `navigated` and the tool descriptions say when to snapshot again.
14. **`root` as a landmark role roots on the first match.** Playwright keeps one ref table per frame replaced by the latest snapshot (E0b S2d), so several rooted snapshots in one call would invalidate each other's refs; the header's `rootMatches` and the description point the model to a specific landmark's ref from a whole-page snapshot.
15. **`browser_tabs open` requires `url`; `select` and `reload` resume a suspended tab; reads and acts on a suspended tab answer `tabNotLoaded`.** An empty tab is useless to a model; a suspended tab is E4a's restored state and loading it on a read would mask the cap; the two commands that mean "bring it" load it.
16. **A locator's fallback.** `{ css, role, name }` resolves by css narrowed by role and name; when the css fails and role plus name match exactly one element, that element is used (E4d's anchor still names what the person pointed at after a re-render); several matches use the first and say so. E0b's round trip was 4/4 on css alone; the fallback is for drift.
17. **Main writes the screenshot file at the host-named path; the host writes the record.** The record is the writer's (X13) and the bytes are main's; a path over IPC keeps a 3.5 MiB image off the supervisor's socket and inside the 10 s dispatch deadline; an orphan file from a crash between the two writes is harmless.
18. **The fixed port 17391 and deterministic tab ids under `MAWS_E2E=1`.** The replay feeds recorded arguments to the real app; a URL's port and a tab's id are in them. A fixed loopback port and a per-process sequence make the recording replayable; both are e2e-only (production ids stay random).
19. **The stand-in answers from snapshots the real app generated.** The refs in the recorded `browser_act` arguments must resolve against the real page in the replay; Playwright's numbering is deterministic for one page under one connection sequence, so the generator case produces the fixtures the stand-in uses and the e2e's first case asserts the equality before replaying.
20. **The cursor's colours are fixed.** The preload runs in the page, which has no MAWS tokens; a system cursor's white and near-black with E2's picker blue (`bridge-script.ts`) is theme-neutral; `tokens-guard` scans the renderer only.
21. **The OOPIF item is verified for the mouse by the e2e and for keys by reading.** A CDP click into an OOPIF raises `before-mouse-event` in the frame's coordinates and no `input-event` (E4-0), so the e2e's own Playwright click into the frame (outside the `TabDebugger`'s table) is attributed human by E4a's rule and triggers the takeover; a human key into an OOPIF has no e2e route (E4-0: the stand-in cannot be routed into an OOPIF; a CDP key carries the agent's bit), so it is E11's live sitting item.
