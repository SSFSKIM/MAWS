## Purpose

After E4d the owner can point at something on a web page in MAWS and talk to the agent about it. The browser chrome gains a **Comment** toggle (and the page's context menu a **Comment** entry). With it on, the pointer becomes a picker: the element under it is outlined and labelled (`button “Save”`), a click picks it, a drag picks an area and the smallest element that holds it, Esc leaves. The pick opens E3's comment sheet with the element named in its title, its CSS selector shown, and a cropped screenshot of exactly that element attached (removable with one click, A-31). Sending opens a side thread by default: the agent receives the comment, the element's selector, role, name and accessibility path, the page URL and the picture, and can act on that very element in the same tab with E4c's `browser_act {target: {css}}`; "Send to main" steers the running conversation instead. The page learns nothing: the click never reaches it, no message is posted to it, no page string is ever rendered as markup in MAWS, and nothing but geometry and names cross from the preload to main, where every field is checked before it becomes an anchor. The transcript draws the comment with a chip naming the element and the crop, live and from disk alike, and the chip opens the page in the session's browser.

To see it: open a session, add Browser from the panel's "+", load a page, press the Comment button in the chrome (or right-click an element and choose Comment); hover: the element is outlined with its name; click: the sheet opens, "Comment on button “Save”", with the screenshot chip; type "Make this primary" and press Enter; the Side pane opens on a thread whose first prompt carries the chip and the picture, and the agent clicks that button through its browser tools.

## Terms

- **Comment mode** (per tab, main-owned): the state in which the tab's preload outlines the hovered element and the next click or drag is a **pick**. **Armed**: on. One pick disarms (one pick per Comment, E2's rule). **Hover UI**: the preload's outline, its badge and the crosshair cursor, drawn in the page's DOM as E2's `maws-pick-overlay` is, A-33's "hover UI".
- **Pick report**: the preload's one message to main: the picked element's **description** (`css`, `role`, `name`, `a11y`, `tag`), its viewport **rect**, the scroll offset, the viewport size, the pick's mode (`click` or `area`) and the arm epoch. Geometry and names only; main validates every field.
- **Description** (`src/shared/browser/describe.ts`, the naming side A-37 gives this child): `css` a selector unique in the document (E0b's `cssPath`: the nearest ancestor-or-self with a unique id through `CSS.escape`, then `tag:nth-of-type(k)` steps), `role` the element's ARIA role (explicit, else implicit by E0b's table as extended here) or null, `name` its accessible name (E0b's `accessibleName`), `a11y` the role-and-name path from the outermost role-bearing ancestor, `tag` the local name.
- **Locator** (E4c's `BrowserLocatorSchema`, `src/shared/browser/locator.ts`): `{ css, role?, name? }`, what `browser_act` and `browser_screenshot` resolve. An anchor carries a locator's three fields flat (X10's `css`, `role`, `name`), with `locator` the css again (X10's one-string field, as the ledger reads).
- **Box**: the anchor's `box {x, y, width, height}`: integers, CSS px of the page's document (the viewport rect plus the scroll offset at the pick); for an area pick the marquee itself.
- **Crop**: main's screenshot of the pick's rect, `webContents.capturePage(rect)` on the tab's view, written under `<userData>/browser/crops/` and attached to the anchor as X10's `screenshot {path, width, height}`; the sheet shows it as a removable chip (E3's sheet already does).
- **Anchor** (X10): `{ kind: 'browser-element', locator: css, label: '<role> “<name>”', pageUrl, screenshot?, css, role?, name?, a11y?, box? }`. The lead, the tag and the parse are E3's (`src/shared/anchor/message.ts`); this child appends five tag fields.
- **E4a's names used here**: `BrowserTab` (`control`, `suspended`, `placedIn`, `covered`, `loadError`, `crashed`), the tab store's entries (`TabEntry { tab, view, debugger, placement }`), `registerChromeExtra` (the chrome's slot before the overflow menu), `registerContextMenuExtras((params, tab) => MenuItemConstructorOptions[])`, `src/preload/browser.ts` (E4a's empty sandboxed preload; `browser:preload:*` channels reserved for later children), `browser.notice`, `validateBrowserUrl`, `startBrowser`, the e2e scene `e2e/support/browser-scene.ts` and server `browser-server.ts`.
- **Main**, **renderer**, **preload**, **X1 event**, **replay**, **harness**, **scratch profile**: as E1's, E2's and E4a's documents define them. E4d touches the engine host nowhere.

## Design (the residue §3 D and E4's cut leave open, with reasons)

### 1. Ownership and data flow

Main owns comment mode: which tab is armed, the gate on the preload's report, the crop, the anchor. The preload owns the hover UI and the pick itself (what element, what rect) and reports once. The renderer owns the toggle, opens E3's sheet, and never sees a page string before main validated it. One flow: the toggle (or the context menu) → `browser.comment.set {tabId, on: true}` → main arms the tab, sends the preload `{type: 'arm', epoch}`, emits `browser.comment.changed {tabId, on: true}` → the preload outlines the hovered element → a click or a drag → the preload hides its UI, waits two frames, re-measures, sends one `picked` report → main checks the sender, the state, the epoch and the schema, crops the view at the rect, writes the file, builds and validates the anchor, disarms the tab (`reason: 'picked'`), and sends `browser.comment.picked {tabId, appSessionId, anchor, crop}` to the window whose pane owns the tab → that window's renderer calls `openCommentComposer(anchor, {appSessionId})` → E3's sheet (its cover protocol hides the view) → E3's send paths carry the anchor and read the crop. Esc, a navigation, a close, a crash or the agent taking the page disarm the tab and the preload drops its UI.

Why main builds the anchor rather than the renderer or the preload: the page URL is main's (`webContents.getURL()`), the crop is main's, and the validation of page-controlled strings must happen where the renderer cannot be bypassed (A-33, E4a Design §14). Why the preload draws the outline rather than CDP's `Overlay.highlightRect`: the parent binds the preload's hover UI (E4's cut; A-33 names it), a drag marquee has no CDP equivalent, and the in-page overlay needs no debugger attachment (the alternative is in Deferred).

### 2. The toggle and the mode's state (the chrome)

The **Comment toggle** is one `IconButton` (a speech-bubble glyph, `COMMENT_COPY.toggle` "Comment" as its label, `pressed` while the tab is armed, `aria-pressed`) registered through E4a's `registerChromeExtra(CommentToggle)` from App.tsx's E4d block, so it sits in the navigation row before the overflow menu in both surfaces. It is **disabled while `tab.control === 'agent'`** with the title `COMMENT_COPY.toggleAgent` ("Comment is unavailable while the agent is browsing"), and while the tab is suspended, has a `loadError` or `crashed` (there is no page to pick on). (re-pinned: `IconButton` takes no `title`; its `label` is both `aria-label` and `title`, so the disabled toggle's `label` is the reason, `toggleAgent` or `toggleNoPage`, and `toggle` otherwise. The extra's props are E4a's `ChromeExtraProps { tab, appSessionId, surface }`, mounted in `chrome/NavRow.tsx`.) Click → `browser.comment.set {tabId, on: !armed}`. Its state comes from `useCommentMode` (`src/renderer/src/tools/browser/comment/store.ts`: `armed: Map<tabId, true>` fed by `browser.comment.changed`, connected once from App.tsx's E4d block), not from `BrowserTab` (Decision Log 1). While armed and the chrome has keyboard focus, the component's `keydown` listener on `window` turns a plain Escape (no modifiers, not `defaultPrevented`) into `browser.comment.set {on: false}`; Esc inside the page is main's (Design §3). Arming one tab disarms any other armed tab of the app (one picker at a time; a second armed page with a hidden overlay would surprise). No keymap action (E4a's Decision 9).

**Main's state** (`src/main/browser/comment/mode.ts`): per tab `{ armed: boolean, epoch: number, pending: { requestId, at } | null }`. `browser.comment.set {on: true}` is refused with `{on: false}` (no error; the toggle simply stays off, and the answer says why in `reason`) when the tab is unknown, suspended, not placed, under `loadError` or `crashed`, or `control === 'agent'`. Arming subscribes the view's `before-input-event` (Escape `keyDown` → `event.preventDefault()`, disarm `'escape'`; E4a's own key listener keeps running and takes Esc only under find or loading, so the two never conflict), `did-start-navigation` (main frame, not same-document → disarm `'navigated'`; the preload dies with the document anyway), `render-process-gone` (`'crashed'`) and `destroyed` (`'closed'`; a suspension closes the webContents too); `epoch` increments on every arm and every navigation, and goes to the preload so a report from an earlier document or arm is dropped. Disarming unsubscribes, sends `{type: 'disarm'}` to the preload when the webContents is alive, and emits `browser.comment.changed {tabId, on: false, reason}`.

### 3. The preload: hover and pick (A-33's hover UI)

`src/preload/browser-comment.ts` (new; imported by `src/preload/browser.ts`'s E4d block alone, as E4c's `browser-cursor.ts` is, so Rollup inlines it and `bundle.test.ts` holds), sandboxed, `ipcRenderer` only, no `contextBridge`. It lifts E0b's pick (`preload.cjs`) and E2's overlay (`bridge-script.ts`) and replaces E2's capture-phase swallowing with a shield (below): `ipcRenderer.on(COMMENT_CHANNEL.toPreload, (_, message))` with `arm {epoch}`, `disarm`, `pickAt {x, y, requestId, epoch}`.

- **Armed**: the preload appends two nodes of its own to `document.documentElement`, every inline style set through `style.setProperty(…, 'important')` (CSSOM writes are not subject to the page's CSP, where an inline `<style>` element would be): the **shield**, one `maws-comment-shield` element covering the viewport (`position: fixed; inset: 0; pointer-events: auto; z-index: 2147483647; background: transparent`), which catches every pointer event before any page element, frame or shadow host can (Decision Log 3: this is what makes "no click reaches the page" true, and what makes an iframe pickable at all, since events inside a frame never reach the top window's listeners, `findings-pass2.txt:117-125`); and the **overlay**, one `maws-comment-overlay` element (`pointer-events: none`, a 2 px outline and a 12 % fill in `#2f6feb`, no transition, E2's `bridge-script.ts:82-109` lifted) with a **badge** child (`maws-comment-badge`, `textContent` set, never `innerHTML`). The crosshair cursor is main's: `webContents.insertCSS('* { cursor: crosshair !important }')` at arm, `removeInsertedCSS(key)` at disarm (a strict page `style-src` would block an injected `<style>`; `insertCSS` is not subject to it). Each handler on the shield returns at once unless `event.isTrusted` (a page can dispatch synthetic pointer events on MAWS's nodes too). **Hover**: on `pointermove` the element under the pointer is `document.elementsFromPoint(clientX, clientY)` with MAWS's own nodes skipped (every node carries `data-maws-comment`); for an element inside a shadow tree that is the retargeted host (Decision Log 11), for a frame the `<iframe>` element itself; the overlay is placed from its `getBoundingClientRect` and re-placed on `scroll` and `resize`; the badge reads the element's label (`elementLabel(description, 40)`: `button “Save”`, `link “local link”`, `div` when there is neither role nor name) and, on the first hover of an arm, `COMMENT_WORDS.hint` ("Click to comment · drag for an area · Esc leaves"). The page's own `:hover` styles do not react while armed (the pointer is over the shield); accepted. **Wheel** on the shield is prevented and forwarded as `scrollBy(deltaX, deltaY)` on the nearest scrollable ancestor of the element under the pointer (the document when none), so the page still scrolls while the person looks for the element; keys are untouched (the shield takes no focus) and `contextmenu` on the shield is prevented (the native menu's Comment is for the unarmed state). **The pick**: `pointerdown` records the point; `pointermove` with the button down beyond `DRAG_THRESHOLD_PX` (6) switches to **area mode** and the overlay becomes the **marquee** from the down point to the pointer, clamped to the viewport; `pointerup` decides: in click mode the picked element is the element under the `pointerup` point (`elementsFromPoint`, MAWS's nodes skipped); in area mode the marquee is the rect and the picked element is the smallest element whose `getBoundingClientRect` contains the marquee, found from the element under the marquee's centre and walking `parentElement` up to `documentElement`. Then the preload **hides its UI (the overlay and the badge; the shield stays), waits two `requestAnimationFrame`s** (so the presented frame carries neither outline nor badge), **re-measures** (the element's rect again in click mode; the marquee re-derived from its document coordinates minus the current scroll in area mode, so a page that scrolled during the wait is still cropped where the person pointed), **trims** the description to the report's caps (`name` cut to 200 with `nameOverLong: true` when it was longer, `role` and `tag` to 64, `a11y` to 300 with each segment's name already at 40, Design §4), and sends one `picked` report `{ type: 'picked', epoch, requestId: null, mode: 'click' | 'area', description, nameOverLong, rect, scroll: {x, y}, viewport: {width, height} }`, then sends nothing more until the next `arm`. A `describeElement` that cannot name the element (no css within 2,000 characters: a pathological depth) sends `{ type: 'refused', reason: 'tooDeep' }` instead. **Escape** is not the preload's: main hears it first (Design §2) and sends `disarm`.
- **`pickAt {x, y}`** (the context menu's one-shot, CSS px; no shield is up): `document.elementsFromPoint(x, y)` with MAWS's nodes skipped, described and measured at once (no overlay to hide, so no wait), trimmed and sent with the `requestId`; nothing there → `refused {reason: 'noElement'}`.
- **`disarm`**: the shield, the overlay and the badge are removed, the listeners go idle. A document that loads fresh has none of it (the preload starts disarmed; main re-arms only on the person's next toggle).

What the preload never does: act on an untrusted event, read the URL (main has it), decide who clicked (A-33), post anything to the page, keep state across documents, or send a second report for one arm.

### 4. The naming module (`src/shared/browser/describe.ts`, the A-37 "naming side")

DOM-only TypeScript, zod-free so the preload bundles it alone; lifted from `spikes/browser-probe/shared/locator.cjs` function by function:

- `cssPath(el): string | null` as E0b's (`CSS.escape` with the fallback for a context without it; the nearest ancestor-or-self with an id that is unique in the document, else `tag:nth-of-type(k)` steps to `html`'s child), with one rule added: the result must match `CSS_PATH` and be ≤ 2,000 characters, else `null` (the pick is refused as `tooDeep`). No step cap: uniqueness is what the agent needs, and E2's twelve-step cut was for a frame whose anchors no agent resolves.
- `roleOf(el): string | null`: the explicit `role` attribute's first token, else E0b's implicit table extended with the elements ARIA in HTML maps and E0b left out (`summary` → button when it is a `details`' first child, `dialog` → dialog, `menu` → list, `dl` → none, `dt`/`dd` → term/definition, `fieldset` → group, `hr` → separator, `progress` → progressbar, `meter` → meter, `output` → status, `blockquote` → blockquote, `code` → code, `strong` → strong, `em` → emphasis, `time` → time, `iframe` → null, `input[type=email|tel|url]` → textbox, `input[type=file]` → null, `select[multiple]` → listbox, `th[scope=row]` → rowheader, `thead/tbody/tfoot` → rowgroup); `header`/`footer` are `banner`/`contentinfo` only when not inside `article`, `aside`, `main`, `nav` or `section` (the spec's scoping rule, which Playwright follows); `section` and `form` carry their landmark role only with an accessible name (Playwright and the spec agree; E0b's probe section had `aria-labelledby`). Every role emitted is an ARIA role name Playwright's `getByRole` accepts, since E4c narrows by it.
- `accessibleNameOf(el, role): string`: E0b's order (`aria-labelledby` ids, `aria-label`, `label[for]`, a wrapping `label`, `alt`, a button input's `value`, `title`) with the text collapsed (`\s+` → one space, trimmed) and control characters removed; for `input[type=text|search|email|…]` without a label the `placeholder`; for `textarea` and `select` the same label rules; **text content is a name only for the roles ARIA names from content** (`button`, `link`, `heading`, `cell`, `columnheader`, `rowheader`, `option`, `tab`, `menuitem`, `menuitemcheckbox`, `menuitemradio`, `checkbox`, `radio`, `switch`, `treeitem`, `tooltip`, `gridcell`), never for a container (E0b's `locator.cjs:84` named every element by its text, which gives a `list` the name of all its items while Playwright gives it `""`). Why the care: E4c resolves `{css, role, name}` as `locator('css=' + css).and(getByRole(role, {name, exact: true}))` and falls back to `getByRole(role, {name, exact: true})` (its Design §6), so a role or name Playwright computes differently makes **both** paths answer 0 and a correct css ends as `targetNotFound`; the rules here, the omissions below and Design §13's proof keep the two computations agreeing where it is cheap, and Design §11 asks E4c to let css alone win when it matches one element.
- `a11yPath(el): string`: E0b's chain with curly quotes (`main > region “A form” > button “Increment”`), names omitted on `list`, `listitem`, `main`, `form` as E0b did; each segment's name cut to 40 characters (E2's `TEXT_MAX` for page text) and the whole path to 300 from the start with `…` (the innermost segments are the useful ones; Design §9 on why the caps are small).
- `describeElement(el): ElementDescription | null` → `{ css, role, name, a11y, tag, confident }`; null when `cssPath` is null; `confident` is false when an ancestor-or-self carries `aria-hidden="true"` (Playwright's `getByRole` skips such elements, so a role and name sent for one would only make E4c's lookup fail; main then omits `role` and `name` from the anchor and keeps `css`).
- `CSS_PATH`: the regular expression (`u` flag) over the grammar `cssPath` emits (`#<escaped id>` or `<tag>` steps, `:nth-of-type(<n>)`, joined by ` > `; an escaped id admits `\<hex>{1,6} ?`, `\<ASCII char>`, `[\w-]` and any code point at or above U+0080, which `CSS.escape` leaves as it is), exported so main validates a report's `css` with it (Design §9) and E4c may reuse it. No combinator but `>`, no attribute selector, no `:has`, no comma: a selector outside the grammar is refused even when it is valid CSS. `cssPath` tests an id step against the grammar before taking it and, when it fails, continues with `nth-of-type` steps as if the element had no id (never `null` for an odd id; `null` only for the 2,000-character overflow).

Tests (`describe.test.ts`, a `// @vitest-environment happy-dom` docblock, since `src/shared/**` runs under the Node project (`vitest.config.ts`: "shared, main, preload and the hosts run under Node; the renderer runs under happy-dom"); `CSS.escape` polyfilled per the spec in the test when the DOM lacks it, and the fallback path pinned too): E0b's four targets from `spikes/browser-probe/page/index.html` (lifted into `test/fixtures/browser/probe-page.html`): `#increment` / button / "Increment" / `main > region “A form” > button “Increment”`; `body > main > section:nth-of-type(2) > ul > li:nth-of-type(2) > button` / button / "Act"; `#name` / textbox / "Name"; `#\37  > a` / link / "local link"; for each, `document.querySelector(css) === el` (the round trip the agent's `page.locator(css)` relies on; E0b 4/4); plus the discriminating cases the review asked for: the `ul` (role `list`, name `""`), a `div` with text (no role, no name), an element under an `aria-hidden` ancestor (`confident: false`), an `<a>` without `href` (no role), `img alt=""` (role `img`, name `""`), a `button` whose text has a hidden `span` (the name is the text as the DOM has it; Design §13 reads Playwright's answer on the same page), a shadow host, a `section` without a name (no role), a `header` inside `article` (no role), a placeholder-only input, a non-ASCII id (`#한글-id`, `#café`) accepted, a 2,000-character overflow (`null`), and `CSS_PATH` accepting every emitted path and refusing `div, body`, `a[href]`, `:has(a)`, `body >> a`, `text=x`.

### 5. The crop (main, `src/main/browser/comment/crop.ts`)

On an accepted report, before anything reaches the renderer: `zoom = webContents.getZoomFactor()`; the rect in DIP is the report's rect × zoom (a page at zoom reports CSS px and the view's surface is in DIP, E4-0 `:145`), rounded outward (`floor` of the origin, `ceil` of the far edge) and **clamped to the view's bounds** (`view.getBounds()`'s size: an area dragged past the viewport edge is cut at it); an empty intersection → no crop (`crop: 'none'`). `image = await webContents.capturePage(dipRect)` (5 ms; works under a cover too, E4-0 `:207`); the image is in device pixels (1102 × 1510 for a 551 × 755 DIP pane at DPR 2). Then the composer's own image rule (`attachments.ts:11-19`): the longer edge over `CROP_MAX_EDGE` (1568) is scaled down to it (`image.resize({width, height}, {quality: 'best'})`); `toPNG()`; over `CROP_MAX_BYTES` (3.5 MiB, A-34) → `toJPEG(85)` and the `.jpg` extension; still over → no crop (`crop: 'tooLarge'`); a throw from `capturePage` (a page that has never painted, E4-0 `:200-201`; a view destroyed meanwhile) or an image whose `isEmpty()` is true (Electron answers an empty image rather than throwing in some of those cases; a 0 × 0 `screenshot` would fail `AnchorScreenshotSchema` and misreport as `cannotName`) → `crop: 'failed'`. The file is written (re-pinned: `atomicWriteFile` is `src/main/files/atomic-write.ts`'s, text only; the crop's bytes go through `fs.promises.writeFile(path, bytes, { flag: 'wx', mode: 0o600 })`, an exclusive create of a fresh name, and the picked event is sent only after the write resolves; a write that throws, ENOSPC or EEXIST, unlinks any partial file and is `crop: 'failed'`) at `<userData>/browser/crops/<tabId>-<ms since epoch>-<4 random hex>.<png|jpg>` (the directory created; E4a's layout reserves `crops/`; the random suffix keeps two context-menu picks in one millisecond apart), and the anchor's `screenshot` is `{ path, width, height }` from the written image's size. **The file's life**: E3's `side.thread.open` and `side.sendToMain` read it at send; the agent's transcript then carries the pixels as an image block (E3 M0 (b): kept byte-identical on disk), so the file is not needed for replay; a boot-time **sweep** (`sweepCrops(dir)` in `startCommentMode`) deletes crops older than `CROP_RETENTION_MS` (7 days) and the oldest beyond `CROP_FILES_MAX` (200). E3's reader accepts the path because it lies under `<userData>/` (`content.ts:19-21`) and is a PNG or JPEG by magic bytes.

Why `capturePage` and not `Page.captureScreenshot` through `TabDebugger.send`: it needs no attachment (the debugger is attached only when E4c or focus emulation asks), it works while the view is hidden, it is what E4a uses for the placeholder, and the rect the person pointed at is always within the viewport (they clicked it). The CDP route's one advantage, `captureBeyondViewport` for an element taller than the viewport, is Deferred: a drag defines the area the person means, and the viewport is what they saw.

### 6. The anchor and the composer call (X10)

`browserElementAnchor(input)` in `src/shared/browser/comment.ts` (pure, tested; main calls it): from a validated report, the page URL and the crop:

- `css` = the report's css (already matched against `CSS_PATH`, ≤ 2,000); `locator` = `css` (X10's one-string field; E3's lead then reads `element #save on <url>`, which is what the agent needs to call `browser_act`).
- `role` = the report's role when present and `confident` (≤ 64 characters, E4c's cap); omitted when null or not confident.
- `name` = the collapsed accessible name **when it is whole** (the report's `nameOverLong` false, so at most 200 characters, X10's label cap) **and `confident`**, else omitted: E4c narrows the css match by `getByRole(role, {name, exact: true})` and falls back to it, so a cut or doubtful name would make a correct css fail to resolve, while an omitted name leaves the css to do its work (Decision Log 8). An empty name (`list`, `img alt=""`) is omitted too.
- `a11y` = the report's path, ≤ 300, one line (`oneLine`), omitted when empty.
- `pageUrl` = main's URL (below) when at most 2,000 characters (`AnchorSchema`'s cap); over it, the URL without its query and fragment (`origin + pathname`); still over, omitted (the anchor stays valid without it; the lead then reads `element <css>` alone).
- `box` = `{ x: round(rect.x + scroll.x), y: round(rect.y + scroll.y), width: max(1, round(rect.width)), height: max(1, round(rect.height)) }` (document CSS px; the marquee for an area pick).
- `label` = `elementLabel(description, 200)`: `<role or tag> “<name>”` with the name cut to fit 200 (`fit` with `…`), `<role or tag>` alone when the name is empty; curly quotes (Decision Log 7). For an area pick the label is the containing element's, so a comment on a region of a list reads `list` or `region “Results”`.
- The URL is `webContents.getURL()` validated by E4a's `validateBrowserUrl` (http or https; a pick cannot happen on an error page, whose view is hidden); `screenshot` = the crop when written.

The result is parsed with `AnchorSchema` (strict; every field one line and capped) and, projected to `{css, role, name}`, with E4c's `BrowserLocatorSchema`; a failure of either is a `crop`-independent refusal that the renderer toasts (`COMMENT_COPY.cannotName`) and never a thrown error. **X10's extension** (`src/shared/anchor/anchor.ts`, an E4d block inside `AnchorSchema` after `prNumber`): `css?: z.string().min(1).max(2000).regex(ONE_LINE)`, `role?: z.string().min(1).max(64).regex(ONE_LINE)`, `name?: z.string().max(200).regex(ONE_LINE)`, `a11y?: z.string().max(2000).regex(ONE_LINE)`, `box?: AnchorBoxSchema` (`z.strictObject({ x: z.number().int(), y: z.number().int(), width: z.number().int().positive(), height: z.number().int().positive() })`). **The tag** (`message.ts`): `TAG_FIELDS` gains `'css', 'role', 'name', 'a11y', 'box'` appended in that order; `anchorTag` writes `box` as `"<x>,<y>,<width>,<height>"` (one attribute, no spaces; every other new field through `String(value)` as today); `parseTag` turns a `box` attribute matching `/^(-?\d+),(-?\d+),(\d+),(\d+)$/` into the object and fails the parse on any other form; the byte-stability check (`anchorTag(parsed) === line`) keeps holding, so a tag with a reordered or malformed field is text, as E3 intends. The lead line is unchanged (E3's persisted-format contract): `Comment on "button “Save”" (element #save on https://example.test/):`. The agent's text for a side thread is then E3's three parts and one tag:

```
Comment on "button “Increment”" (element #increment on http://127.0.0.1:PORT/comment.html). A screenshot of it is attached:
Make this the primary button.

You are in a side thread forked from the main conversation to handle this one comment. Address it here; the main conversation continues separately and is not waiting on you.

<maws_anchor kind="browser-element" label="button “Increment”" locator="#increment" pageUrl="http://127.0.0.1:PORT/comment.html" css="#increment" role="button" name="Increment" a11y="main &gt; region “A form” &gt; button “Increment”" box="248,312,96,30"/>
```

(`anchorTag` escapes `& " < >` in every attribute, `message.ts:49-51`, so `>` in `a11y`, and in a `css` or `locator` with child combinators, is written `&gt;` and read back by `parseTag`'s `unescapeAttribute`; the agent sees the escaped form, as it does for E6's PR anchors.)

**The composer call** (renderer, `src/renderer/src/tools/browser/comment/connect.ts`): on `browser.comment.picked {tabId, appSessionId, anchor, crop}`, `openCommentComposer(anchor, {appSessionId})` (E3's sheet opens with the title "Comment on button “Increment”", the locator in mono, the "Screenshot · W × H" chip with Remove when `anchor.screenshot` is set; A-31's "attached by default and removable" is E3's existing behaviour, `CommentComposer.tsx:53, 90-97`), and when `crop` is `'tooLarge'` or `'failed'` a toast (`COMMENT_COPY.cropTooLarge`, `COMMENT_COPY.cropFailed`: "Screenshot unavailable; the comment is sent without one", Codex's `snapshotFailed` sense) — a toast rather than a chrome notice because the sheet now covers the page and a chrome line under it would not be read (Decision Log 9). Everything after Send is E3's: `sendComment` strips `anchor.screenshot` into the comment's own `screenshot`, main reads the crop, the thread or the steer carries `[image, text]`.

### 7. The context menu's "Comment" (main)

`registerContextMenuExtras((params, tab) => […])` is called once from `startCommentMode` with one item: `{ label: COMMENT_WORDS.menu ("Comment"), enabled: tab.control !== 'agent' && !tab.suspended && tab.loadError === null && tab.crashed === null, click: () => pickAt(tab.tabId, params.x / zoom, params.y / zoom) }` (`ContextMenuParams.x/y` are view coordinates in DIP, the same E4a hands `inspectElement`; the preload wants CSS px). `pickAt` records `pending {requestId, at}` on the tab (no arm, no hover UI), sends `{type: 'pickAt', x, y, requestId, epoch}` to the preload, and accepts the one report carrying that `requestId` within `PICK_AT_MS` (2,000 ms); the rest of the flow is Design §5 and §6 with `mode: 'click'`. ### 8. Failure semantics

- **The element is gone before the crop.** The crop is of the pixels on screen at the report (two frames after the click); a disappearing element yields a crop of what replaced it, which the person sees in the chip and may remove (A-31). The anchor still names what was clicked; E4c's resolution then answers `targetNotFound` honestly.
- **The page scrolls or re-lays out between pick and crop.** The preload re-measures after the two-frame wait (Design §3), so the rect sent is the rect at capture time within one frame; a scroll after that is bounded by the IPC and `capturePage` (about 1 ms plus 5 ms). Accepted.
- **The page navigates between pick and crop, or during the arm.** `did-start-navigation` disarms with `'navigated'` and bumps the epoch; a report with a stale epoch is dropped; a `pickAt` pending across a navigation expires. The toggle shows off; nothing opens.
- **A cross-site (or any) iframe target.** Pointer events inside a frame never reach the top window's listeners (a same-origin frame is its own `window`; an OOPIF's input is routed to the child widget, `findings-pass2.txt:117-125`), which is why the shield exists: while armed, the pointer is over the shield wherever it is, the frame's page receives nothing, and `elementsFromPoint` in the top document answers the `<iframe>` element itself. The anchor names the frame (`css` the frame's selector, role null, the `title` attribute as the name when present, label `iframe “<title>”` or `iframe`), the crop is the frame's visible area, and the agent is told the frame, not an element inside it. Comments inside third-party frames are Deferred; the e2e pins the behaviour on a same-origin `/b.html` frame (a cross-site frame needs a second origin, which E4c's server has and E4a's does not; the shield makes the two cases the same: the top document never sees inside either).
- **A tab closed, suspended or crashed with the sheet open.** The sheet is E3's and holds the anchor and the crop path; nothing in it depends on the tab. Sending still works: the thread's agent gets the URL and can reopen the page (`browser_tabs open`), the steer still carries the picture. Main's mode state for the tab is gone with the entry (`destroyed` disarmed it).
- **A crop over the cap, or a capture that throws.** `crop: 'tooLarge' | 'failed'`; the sheet opens without the chip and a toast says so (Design §6). The anchor is complete without the picture.
- **The agent starts acting while the tab is armed.** The toggle is disabled under `control === 'agent'`, but `control` decays to `idle` 10 s after an action (E4c Design §8) and the person can arm in that gap; the agent's next `browser_act` would then hit the shield (Playwright's hit-target check sees the shield over the element and retries until its timeout) and E4a's `inFlight` table is already clear by the time a report could arrive, so a check there catches nothing. Main therefore **disarms the moment `control` turns `agent`**: (re-pinned) `startCommentMode` subscribes `store.onUpdated` (`src/main/browser/tabs.ts:165`), which E4a's `setControl` (the only `control` transition, `tabs.ts:360-364`) calls synchronously before it returns, and disarms the tab with `'agent'` when its `control` reads `agent`; the report gate also drops a report when `tab.control === 'agent'`. E4c's `markActing` sets `agent` before its dispatch (its Design §6 step 3), so main's armed state and its report gate flip before `setControl` returns; the shield itself is the preload's node and goes when the preload handles the `disarm` message (asynchronous IPC), which lands well before E4c's click since its dispatch follows a cursor move and Playwright's actionability wait, which retries a hit-target miss (the residual is that IPC latency, accepted). E4c's control machine reads the person's pick click as human input on a page no agent holds and leaves `idle` (its table's first row), so arming and picking never make the agent wait.
- **A legitimate report main refuses** (a `refused {reason}` from the preload; a `picked` report that fails `PickReportSchema`, `CSS_PATH`, `AnchorSchema` or `BrowserLocatorSchema` after trimming; a page URL `validateBrowserUrl` refuses): disarm with `'refused'`; the renderer's `browser.comment.changed {reason: 'refused'}` handler toasts `COMMENT_COPY.cannotName`. The toggle never stays pressed after a pick the person made.
- **A report that is not the person's pick** (a sender not in the tab map; a tab not armed and with no pending `pickAt`; a second report for one arm; a stale epoch; an untrusted event cannot produce one, Design §3): dropped, counted in a per-tab counter the seam exposes, never logged with its payload (E4b's logging discipline), nothing disarmed.
- **Two windows.** The picked event goes to the window whose pane owns the tab (E4a's owner table, `windowId`; re-pinned: `entry.placement?.window`, the owner's `BrowserWindow` itself, `tabs.ts:32-37`); with no owner window alive (the window closed between the pick and the crop), the pick is dropped with `'closed'` rather than broadcast: E3's `openComposer` is per window (`CommentComposer.tsx:34-36`), and two windows each opening the sheet would make two threads from one comment.
- **The composer refuses** (E3's refusals: a screenshot "not under an allowed root", a parent not ready): E3's sheet shows the reason with Retry and "send without the screenshot" (E3 Design §9); nothing in this child.

### 9. Security

- **The preload's channel carries geometry and names only**: `PickReportSchema` (strict) admits `type`, `epoch` (int), `requestId` (string | null), `mode`, `description {css ≤ 2000, role ≤ 64 | null, name ≤ 200, a11y ≤ 300, tag ≤ 64, confident}`, `nameOverLong`, `rect`, `scroll`, `viewport` (finite numbers); no URL, no HTML, no text beyond the accessible name and the path. The preload trims to these caps before sending (Design §3) so a long page string can never make a legitimate pick fail; main validates with the schema, then matches `css` against `CSS_PATH`, re-applies `oneLine` to `name`, `a11y` and `tag`, and builds the anchor through `AnchorSchema` and `BrowserLocatorSchema`; a report failing any step is refused and the tab disarmed (Design §8). `ipcMain.on(COMMENT_CHANNEL.fromPreload)` resolves the sender through E4a's tab map by `event.sender.id` (re-pinned: `store.entryOf(event.sender)`, `tabs.ts:186`, by the `WebContents` object as E4a's permission handlers resolve theirs) and ignores everything else (E4a Design §14's rule for `browser:preload:*`). **Trusted events only**: every shield handler returns unless `event.isTrusted`, so a page cannot pick its own element by dispatching synthetic pointer events (on the shield, on `window` or anywhere). The page cannot send on the channel (`ipcRenderer` is the preload's, in the isolated world).
- **Page-chosen strings reach the agent inside the person's own prompt**: `name` (≤ 200, shown in the sheet's title as the label), the id in `css`/`locator` (shown in the sheet in mono), and `a11y` (≤ 300, 40 per segment; not shown by E3's sheet, which draws `label` and `locator` only, `CommentComposer.tsx:83-89`). A page can therefore put up to about 500 characters of its choosing into the tag of a message sent with the person's authority. The framing marks them as MAWS's anchor fields (a tag the model knows as metadata, E3 Design §2), the caps are E2's scale for page text (`TEXT_MAX` 40 per segment), content names are taken only from roles that are named from content, and nothing else from the page (no text content, no attributes) is carried. This residual is accepted for P1 and recorded; a preview of `a11y` and `name` in the sheet is Deferred (E3's component).
- **No page string becomes markup**: the sheet renders `label` and `locator` as text (`CommentComposer.tsx:83-88`), the chip renders `label` as a text node and `locator` as a `title` attribute (`User.tsx:153-158`), the tag escapes `& " < >` (`message.ts:49-51`), the badge uses `textContent`. `pageUrl` comes from main's `webContents.getURL()`, never from the page or the preload.
- **The css selector is validated and bounded** (`CSS_PATH`, 2,000): main never evaluates it; E4c passes it to Playwright as `css=<css>` (its own prefix rule); the grammar admits no combinator but `>`, so a selector cannot name text or carry `>>`.
- **The crop** is written by main at a path main derives (`crops/<tabId>-<epoch>.<ext>`), read by E3's reader under its root, size and magic-byte checks. Nothing in the renderer reads it (E3's chip shows the size only, A-30).
- **The page is told nothing**: no `postMessage`, no attribute written on the page's elements, no event dispatched into the page; while armed every pointer event lands on the shield and none reaches a page element, a frame or a shadow tree (`:hover` included); the shield, overlay and badge are MAWS's own nodes under `documentElement`, removed on disarm; the cursor is main's `insertCSS`. A page can observe the nodes (the DOM is shared) and remove them: removing the shield ends picking for that arm (the next `pointerup` has no shield to land on; main's `epoch` and Esc still disarm cleanly), which costs the page nothing it did not already have and tells it nothing.
- **Esc, the toggle and the context menu** are the human's: Esc through `before-input-event` (native keys only; a CDP key never raises it, E4a's table), the toggle through the app window's IPC (`isAppSender`), the menu through `Menu.popup`. The agent has no path to arm, pick or crop, and its own input is refused as a pick (Design §8).

### 11. The live proof's shape (G2) and the tab the thread sees

G2 says a side thread's agent resolves the anchor by `browser_act {target: {css}}` **on the same tab**. E4c's `locate.ts` resolves `{css, role, name}` as `page.locator('css=' + css).and(getByRole(role, {name, exact: true}))` with the role-plus-name fallback (E4c Design §6): a role or name that disagrees with Playwright's computation fails both paths, so a correct css answers `targetNotFound`. This child's side of the bargain is Design §4's naming rules and §6's omissions, proved by Design §13's expression. **A cross-child recommendation for E4c, `[parent-impact]` in the hand-back**: when `css` alone matches exactly one element, use it and treat `role` and `name` as hints (to break ties among several matches, and to recover when css matches none), rather than narrowing a unique css match by them; E0b's round trip was 4/4 on css alone, and the agent's `browser_act {target: {css}}` (G2's wording) carries no role or name at all. E4c's executor has not started, so the architect can fold it as a precision of E4c's Decision 16. **The tab**: E4c scopes every tool to the calling session's tabs (P-21 as its Constraints read it), and a side thread is a different `appSessionId` from the parent whose tab was commented on, so as both documents stand the thread's `browser_tabs list` would not show the tab and `browser_act` would answer `tabNotFound`. This is a `[parent-impact]` on P-21's reading (Design §12): the proof depends on the architect's ruling and this child builds nothing around it (an E4d-side workaround, such as handing the thread a tab of its own at the same URL, would break "the same tab" and the owner's picture of one shared page).

### 12. `[parent-impact]`: a side thread shares its parent's tabs

Proposed for the architect, not built here: for the browser tools, the acting session's tab set is its own tabs plus its parent's when `lineage.kind === 'side-thread'` (`SessionRecord.lineage`, X11); `browser_tabs list` lists both (the parent's marked), and a `tabId` check passes for either. Reason: a side thread is the same conversation's branch, forked with the parent's directory, permissions and grants (E3 Design §3), opened to handle a comment on exactly that page; P-21's "the agent sees and drives only its session's tabs" was ruled before side threads met the browser and reads naturally as "the conversation's tabs". The change is E4c's (its `handlers.ts` session check and `browser_tabs list`), one rule; E4d's hand-back carries it. Until ruled, M5 records the outcome as found.

### 13. The unit and e2e proof of G2 without E4c

The e2e's Playwright holds the view's page (`electronApp.windows()`), so for every anchor it picks it runs E4c's resolution expression itself: `page.locator('css=' + anchor.css)` alone has `count() === 1` and resolves to the element the person clicked (compared by the `data-target` attribute the fixture page gives each target; E0b 4/4), and, when the anchor carries `role` (and `name`), `page.locator('css=' + anchor.css).and(page.getByRole(anchor.role, anchor.name ? {name: anchor.name, exact: true} : {}))` has `count() === 1` too, which is the agreement of this child's naming with Playwright's. The unit half is Design §4's round trip (`querySelector(css) === el`). Together they are the G2 proof the cut names ("the unit proof is the locator mapping"); M5 is the live half.

## Decision Log

1. **Comment mode's state lives in main, mirrored by `browser.comment.changed`, not as a `BrowserTab` field.** A field on E4a's model would need defaults in every constructor of a tab (`open`, `adoptChild`, the restore from `tabs.json`) and a touch inside E4a's `update` path, while the state is only the toggle's and the gate's; one event and a small renderer store keep E4a's model and `tabs.json` untouched. Alternative: `BrowserTab.commenting`, which would also make the chrome's store the source; rejected for the merge cost alone.
2. **The naming side is a sibling file, `describe.ts`, not a block in E4c's `locator.ts`.** A-37 allows either. The preload bundles the naming functions and must stay zod-free and small (`electron.vite.config.ts`'s comment on the preload bundle), while `locator.ts` carries a zod schema; two executors writing one file in parallel would also collide at the merge for nothing.
3. **The hover UI is an in-page overlay (E2's pattern) over a full-viewport shield, not CDP's `Overlay` domain and not E2's capture-phase swallowing.** The parent binds the preload's hover UI (E4's cut, A-33); a drag marquee has no `Overlay` equivalent; the overlay needs no debugger attachment and no E4c-style bridge. E2 swallowed pointer events in the capture phase on `window`, which works inside one document but never sees an event inside a frame (a same-origin frame is its own window; an OOPIF's input goes to its own widget, `findings-pass2.txt:117-125`), so a click over a frame would have reached the frame's page and no frame could be picked (the document review's finding); a transparent shield under `documentElement` catches every pointer event in the top document before any element, frame or shadow host, which makes "no click reaches the page" a property of the DOM rather than of listener order, and `elementsFromPoint` with MAWS's nodes skipped names what is under it. The costs, accepted: no `:hover` styles while armed, and a wheel the shield must forward itself (`scrollBy` on the scrollable ancestor). `Overlay.setInspectMode` (DevTools' own picker: compositor-drawn, the click swallowed by Chromium) would be the cleanest element picker if the preload route were not binding and areas were not wanted; it is Deferred as a note.
4. **No new dependency; E0b's locator is lifted, its role table extended, and its name rule narrowed to ARIA's name-from-content roles.** E0b left "adopt a maintained ARIA role computation" open, and its lifted `accessibleName` names every element by its text, which a `list` or a `region` must not have (Playwright gives them `""`). The risk is not one wrong fallback: E4c narrows the css match by role and name and falls back to role and name, so a disagreement fails both paths and a correct css answers `targetNotFound` (the document review's correction of this entry's first draft). The remedy here is three rules (content names for content roles only; `role` and `name` omitted when not confident; `name` omitted rather than cut), Design §13's e2e running E4c's exact expression on a fixture page with the discriminating cases, and Design §11's recommendation that E4c let a unique css match win. `dom-accessibility-api` and `aria-query` would compute names and roles to the spec but add two packages to the preload bundle; if M4's case 3 or M5 shows names Playwright computes differently on real pages, adopting `dom-accessibility-api` (exact version, a production dependency since the preload bundles it) is the one-task remedy, recorded then.
5. **A click picks the element under the pointer; a drag picks the area and the smallest element that holds it.** The parent's §3 D says "an element, an area or several" and the cut says "a click or a drag picks it"; multi-anchor and text selection are out (E4's cut). One anchor per pick with X10's one `locator` means an area must name an element: the smallest container of the marquee is what a person means by "this part of the list", the marquee is kept as `box` and as the crop so the picture shows exactly the area, and the label says the container. Alternative: an area anchor with no element (locator `body`), which gives the agent nothing to act on; rejected.
6. **Esc exits through main's `before-input-event` (page focus) and the toggle's `keydown` (chrome focus); the preload never decides.** A key in the page reaches main first and natively only (CDP keys never raise the hook, E4a's table), so the exit is the human's by construction and needs no preload reporting; E4a's Esc rule (find or loading only) is untouched because this child subscribes its own listener while armed rather than editing `keys.ts`.
7. **The label is `<role> “<name>”` with curly quotes.** The ledger writes `<role> "<name>"`; E3's lead quotes the whole label (`Comment on "<label>"`), so straight quotes would read `Comment on "button "Save"" (…)` and E2's artifact label already uses `“ ”` (`pick.ts:54`). A precision of the ledger's shorthand for the architect, not a change of meaning.
8. **`name` is stored whole or not at all, and only when confident; `role` ≤ 64 and only when confident; `a11y` is a human label capped small.** E4c narrows the css match by `getByRole(role, {name, exact: true})` and falls back to it (its Design §6), so a cut, empty or doubtful name would make a correct css fail to resolve; an absent name leaves the css alone to resolve. The preload trims to the caps before sending and flags `nameOverLong`, so a long page string never refuses a legitimate pick (the review's finding 4). `role` follows E4c's cap. `a11y` keeps E0b's reading ("a human label, not the key", `findings.txt:189-191`), curly-quoted like the label, 40 characters per segment and 300 in all, because it is page text inside the person's own prompt (Design §9).
9. **The crop's failure is a toast, not a chrome notice.** E4a's rule (its Decision 28) keeps its own notices out of toasts because a toast would freeze the page under the cover rule; at the moment the crop fails the sheet has already covered the page, and a chrome line under a sheet is not read. Codex's "Screenshot unavailable; you can still annotate this object" is the sense.
10. **The crop is `capturePage(rect × zoom)` clamped to the view, downscaled to 1568, PNG then JPEG, ≤ 3.5 MiB, under `crops/`, swept after 7 days or 200 files.** The composer's image rule (`MAX_IMAGE_EDGE`) and A-34's byte cap, so the picture the agent receives is the one the composer would have sent; the file is not needed after the send (the transcript carries the image block), so retention is a courtesy for a sheet left open. The CDP route (`Page.captureScreenshot` with a clip through `TabDebugger.send`) is Deferred for elements taller than the viewport.
11. **A shadow-tree element anchors at its host; an iframe's content anchors at the frame element.** A CSS path cannot cross a shadow boundary for `querySelector`, and the main-frame preload cannot see into a frame; both anchors still resolve for E4c (the host, the frame) and the crop shows what was pointed at. Comments inside shadow trees and third-party frames are Deferred.
12. **The pick's report waits two frames with the hover UI hidden, then re-measures.** A crop taken in the same frame as the hide would show the outline (the presented frame lags the DOM change by one or two frames); a page that scrolled during the wait is re-measured so the crop lands where the person pointed (the brief's "a page that scrolls between pick and crop").
13. **Main disarms the moment a tab's `control` turns `agent`, and drops a pick that arrives under `agent`; no in-flight check.** The toggle is disabled under `agent`, but `control` decays to `idle` 10 s after an action (A-37) and the person can arm in that gap; the shield would then intercept the agent's next click (Playwright's hit-target check sees it) and E4a's `inFlight` table would be clear by the time a report could arrive, so an in-flight check catches nothing (the review's finding 9; the first draft had one). `onEmitted('browser.tabs.changed')` (C5's main-side tap, `events.ts:27`) sees every `update` E4a coalesces and disarms before E4c's dispatch, which follows `markActing` by a cursor move and an actionability wait; the preload cannot attribute (A-33), main can.
14. **The picked event is sent to the owner window; with no owner window it is dropped, never broadcast.** Two windows can mount a chrome for one tab (a main tab in one, the panel in another); the person picked in the window whose pane owns the view (E4a's owner table), and a sheet opening in the other window would be a surprise; a broadcast would open E3's per-window sheet in each and make two threads from one comment (the review's finding). `send.ts` does the targeted send through `validateEventPayload` and `eventChannel`, so the X2 registry still governs the payload.
15. **The chip and the thread header open the page in the parent's browser for a side thread, the session's own otherwise.** E3 deferred "opening a `pageUrl` anchor in the in-app browser" to E4; the surface exists now, the action is one `browser.tabs.open {reuse: 'url'}` and E4c's `openBrowserTab` shape, and replay parity's "renders with its label and crop" gains the one click that makes the label useful. A thread's transcript belongs to the child session, whose own browser would mint a second tab for the same page; `browserSessionOf` follows `lineage` to the parent, where the commented tab lives (the same reading Design §12 proposes for the agent). The panel rule holds (no main-view switch).
16. **The context menu's Comment is a one-shot pick at the click point, no mode toggle.** A person who right-clicked an element has already pointed at it; arming and asking for a second click would be a step for nothing. Codex lists Comment in the same menu.
17. **One armed tab at a time.** Arming a tab disarms any other; two armed pages, one hidden behind the panel's selection, would pick on a click the person did not mean as a comment.
18. **The live proof is a Playwright-driven live spec after E4c lands, with a US$0.50 budget, and its tab dependency is `[parent-impact]`.** The engine-only `LiveHost` cannot reach main's browser tabs; the live specs (`c11-live`, `maws-tools-live`) already drive the product app with the installed engine under a scratch home through the relay, which is the shape the standing rules allow (no GUI automation of the owner's desktop). The side thread's access to the parent's tab is E4c's session scoping and the architect's ruling (Design §12); the proof records what it finds and patches nothing.

20. **No settings, no migration, no X1 event, no X9 tool.** Comment mode has nothing to persist (crops are files, the anchor is in the message), emits nothing into the engine's stream (the comment is E3's message), and adds no tool (the agent resolves anchors with E4c's).
