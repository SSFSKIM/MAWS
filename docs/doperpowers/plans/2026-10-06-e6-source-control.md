## Purpose

After E6 the owner finishes a piece of work without leaving MAWS: the right panel's **Source control** tool lists what changed in the session's checkout as Staged, Unstaged and Untracked (and Conflicts when a merge is in progress), each file opening its diff in the same diff view Review draws; a click stages or unstages a file or a whole group; Discard asks first, naming every file it will touch; a message and ⌘Enter commit, with the repository's own hooks running as they would in Terminal.app. Push and Open PR each open a sheet that shows the remote, the branch, the destination and the exact command MAWS will run, and run it only on confirm, under the owner's login-shell environment with their credential helpers, streaming the output into the panel. The summary card's Push state row gains the PR's state and checks from the GitHub CLI, refreshed on a bounded schedule and on demand, and opens the tool. This closes §2 item 11 of the parent ("From the panel the owner stages, commits, pushes and opens a PR from the session's worktree. The summary row shows PR state and checks.") and removes one of the two git reasons the owner still had to open a terminal (P-3).

To see it working: `pnpm dev`, open a session whose directory is a repository the owner has trusted, press "+" in the right panel and choose Source control (or click the summary's push-state row). Every mutation is an ordinary git operation on disk: the agent's next `git status` sees the commit, the terminal sees it, and C4's watcher tells every surface.

## Terms

- **Checkout**: the directory the session's git operations act on, `record.worktree?.path ?? record.directory` (what Summary and Review already use, `src/renderer/src/panel/summary/Summary.tsx:43`, `src/renderer/src/tools/code/review/ReviewTool.tsx:84`). A linked worktree is its own checkout; the main checkout may be shared by several sessions, and every session then sees the same staged set.
- **Read runner**: C4's `createGitRunner` (`src/main/git/runner.ts:73`), hooks and fsmonitor off, transport and credential helpers disabled, `/usr/bin/git` or `MAWS_GIT`, 10 s timeout.
- **Mutating runner**: the read runner's spawn core in a new mode `mutate`: the allowlisted local mutations (`add`, `restore`, `rm`, `clean`, `commit`) under the owner's login-shell environment so hooks and signing behave as in a terminal, with transport and credential helpers still disabled (P-12, parent §8 "the mutating runner never runs remote commands").
- **Remote runner**: a separate spawner for `git push` and `gh …` under the captured login-shell environment with the owner's credential helpers and transport enabled, used only to execute a **plan**.
- **Plan**: main's record of one remote command it is willing to run: the program's resolved path, the exact argv, the cwd, the remote, branch, head and destination it names, bound to one session and checkout, with a one-shot token that expires. The confirm sheet shows the plan; the run takes the token and revalidates what the sheet showed. No remote command runs without a plan, and a plan runs at most once.
- **Trust gate**: the engine's own predicate for a directory (`src/main/sessions/trust.ts:108`, `trustStateOf`: `projects[<trustKey>].hasTrustDialogAccepted === true` in the engine's global config, read with the environment the engine itself receives), read on demand before every `scm.*` command except `scm.status`.
- **Groups**: the four lists the tool shows, derived purely from C4's `GitStatus.files` (Design §5): Conflicts, Staged, Unstaged, Untracked.

## Design (the residue §3 F and P-12 leave open, with reasons)

### 1. Ownership and data flow

Main owns every git fact and every git process: the read service (C4), the mutating runner (E6), the remote runner (E6), the trust gate, the plans and the PR cache. The renderer holds only what it shows: C4's status through `useGit`, the scope diffs through E6's own small store (the same shape as Review's), the tool's view state, and the output of the last remote run. Every `scm.*` command takes an `appSessionId`, never a directory: main resolves the checkout from the read model (`record.worktree?.path ?? record.directory`, as `files.*` resolves its roots), so the renderer cannot point a mutation at a directory the session does not work in. A session with no record answers `internal` ("unknown app session: <id>"), as `files.*` does.

Data flow for a click: the renderer invokes `scm.stage { appSessionId, paths }`; main resolves the checkout, reads trust, reads a fresh `git status`, validates the paths against it, runs `git add`, reads the status again and answers `{ ok: true, status, output }`. Main then asks C4's watcher to refresh the root at once (`GitService.refresh(directory)` → `GitWatcher.refreshNow(root)`: the pending debounce is cancelled and `refresh(root)` runs now, or is marked `again` while one is in flight), so `git.changed` reaches every surface within one status read instead of after the debounce, through the watcher's own compare-and-emit. The renderer never writes a mutation's answered status into `useGit`: an answer that arrives after a newer watcher event would overwrite it, and the watcher, which remembers the newer state, would not repeat it (adversarial review). The answered `status` serves the tool's notice (the commit's sha and subject, the counts) and the tests. A root nobody watches needs no refresh; the tool holds `useGit.watch(directory)` while mounted, so the root is watched whenever the tool is shown.

### 2. The mutating runner mode (G1)

`src/main/git/runner.ts` gains a mode in place of the `checkout` boolean: `gitEnv(env, mode: 'read' | 'checkout' | 'mutate' = 'read', base?: Record<string, string>)`. `read` is today's environment exactly; `checkout` is today's `checkout = true` (hooks and filters run, used by `worktree add`); `mutate` is new:

- **Base environment**: the captured login-shell environment (`base`), minus every key starting with `GIT_` (the owner's or the launcher's git overrides never redirect a MAWS mutation; the read runner drops them the same way by keeping only `PATH` and `HOME`), minus `PARENT_SESSION_VARIABLES` (a hook that runs `claude` must not believe it is inside the session that started the app), minus the `MAWS_` and `ELECTRON_` prefixes (`src/pty-host/env.ts`'s rule). `PATH` and `HOME` are the owner's shell's, so `pre-commit` finds `node`, `pnpm`, `python`, and signing finds `gpg`, `ssh-agent` (`SSH_AUTH_SOCK`) and `GPG_TTY`. The probe showed git prepends its own `libexec/git-core` to a hook's `PATH` and keeps the inherited rest, which is exactly where the inherited rest matters.
- **Overrides** (the same `GIT_CONFIG_*` mechanism): `core.fsmonitor=false`, `credential.helper=` (empty), `log.showSignature=false`, `safe.directory=` (empty); **no** `core.hooksPath`, so the repository's hooks run. Plus `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `GIT_PAGER=cat`, `GIT_EDITOR=true` (a commit with `-m` never opens an editor; `prepare-commit-msg` hooks still run), `GIT_EXTERNAL_DIFF=/usr/bin/false`, `GIT_SSH_COMMAND=/usr/bin/false`, `GIT_ALLOW_PROTOCOL=` (empty), `LC_ALL=C` (git's own messages are matched by exit code, never parsed, but the constant locale keeps hook output readable in the C locale as the read runner does). A hook that fetches or pushes fails under this environment by design; the panel shows its output. Since every inherited `GIT_*` is dropped, no `GIT_CONFIG_PARAMETERS` can reach a mutation.
- **Allowlist**: the mutating runner refuses any `args[0]` outside `add`, `restore`, `rm`, `clean`, `commit` before spawning (a thrown `Error`, which the router answers `internal`; a unit test pins it). Reads the service needs (`rev-parse`, `status`, `log`, `remote`, `symbolic-ref`, `check-ref-format`) go through the read runner.
- **Timeout**: per call, `GitRunOptions.timeoutMs`; the service uses 10 s for `add`, `restore`, `rm`, `clean` and 60 s for `commit` (hooks run linters), with the runner's process-group SIGTERM then SIGKILL unchanged.
- **Output and exit codes**: the spawn core is extracted from `createGitRunner` into an exported `spawnGit(...)` that resolves `{ stdout, stderr, exitCode }` for exit 0 and for any code the caller lists in `acceptExitCodes`, and otherwise throws `GitCommandError(message, stderr, exitCode, stdout)` with **both streams kept** (each bounded to its last 256 KiB), so a failing hook's words are shown whichever stream it wrote to and an `exit 1` diff still delivers its patch (today's callback drops stdout on failure, `runner.ts:94-98`; the adversarial review's finding). `createGitRunner` keeps its `GitRun` string answer and failure mapping over it (`GitRunOptions { timeoutMs?, acceptExitCodes? }` added; `safety.test.ts` and `service.test.ts` unchanged except where they pin `gitEnv`'s second argument), and `createMutatingRunner({ env, captured, execFile })` in `src/main/git/mutate.ts` returns `MutateRun = (directory, args, { timeoutMs }) => Promise<{ stdout, stderr }>`, throwing the same `GitCommandError` on a non-zero exit.

Why the login-shell environment and not the read runner's two variables: a commit from MAWS must be the commit the owner would have made in Terminal.app (the brief's terminal interop: "a commit from the panel is an ordinary commit the agent sees"), and the owner's hooks, signing and `commit.template` depend on their shell's environment. Why transport stays off: P-12 and parent §8 ("the mutating runner never runs remote commands"); a hook that needs the network is a terminal task and says so in the output.

### 3. Validation and the local operations (G1)

`src/main/scm/service.ts` (`ScmService`) resolves the checkout, applies the trust gate (`trustStateOf(checkout, { git: read, env: await captured() })`: the **captured** environment, the same one the session service reads trust with, so `CLAUDE_CONFIG_DIR`, `HOME` and the OAuth suffix name the same file the engine uses; `process.env` serves only `MAWS_GIT` and `MAWS_GH`) and serialises mutations per checkout (one promise chain keyed by the realpath of the checkout, so two quick stage clicks apply in order and never interleave their status reads; a remote run does not join this chain, Design §4).

Every mutation begins with `read.status(checkout)` (C4's service, which answers `NotARepositoryError` → refusal `not_repository`) and ends with another, answered as `status`, followed by the watcher refresh of Design §1. Paths from the renderer are repository-relative strings and are refused (`invalid_input` by schema or a refusal `changed` by the service) when empty, absolute, holding a NUL or newline, holding a `..` segment, or when the fresh status does not list them (exact match on `path`, or on `oldPath` for the source of a rename); only what git itself lists can be acted on. Every path is passed after `--` as `:(top,literal)<path>` (the read service's convention, `service.ts:155-157`), a directory entry (`udir/`) with its trailing slash stripped for `add` and kept for `clean`.

| Command | Fresh-status rule | git (mutating runner) | Notes |
|---|---|---|---|
| `scm.stage { paths }` | each path listed (any group but Staged-only); an unmerged entry is allowed: `add` marks it resolved | `add -- :(top,literal)<p>…` | a worktree-deleted file (`.D`) stages its deletion; an untracked directory entry stages its contents |
| `scm.unstage { paths }` | each path listed with `index !== '.'`, not unmerged | `restore --staged -- <p>…` (a rename passes both `path` and `oldPath`); when `status.head === ''` (no commit yet) `rm --cached -r -- <p>…` instead, since `restore` cannot resolve HEAD | unstaging a rename yields `.D <old>` and `? <new>` (probe); unstaging an added file makes it untracked |
| `scm.discard { entries: [{ path, group }] }` | `group: 'unstaged'`: listed with `worktree !== '.'`, not untracked, not unmerged → refusal `unmerged` otherwise; `group: 'untracked'`: listed as untracked | unstaged: `restore --worktree -- <p>…` (the working tree takes the index's content; a staged part of the same file is kept); untracked: `clean -f -- <p>…`, `-d` added when any entry ends in `/` | the two groups run as two commands in one chained operation; a refusal on validation stops before either runs |
| `scm.commit { message, noVerify }` | at least one entry with `index !== '.'` and none unmerged → refusals `nothing_staged`, `unmerged`; message non-empty after trim → `empty_message` | `commit -m <message> [--no-verify]`, 60 s | the message is one argument (multi-line kept whole, probe); on success `rev-parse HEAD` and `log -1 --format=%s` through the read runner give `commit { sha, subject }` |

A `GitCommandError` from any of these (a hook that exits non-zero, a lock held by another process, an index the agent is rewriting) answers the refusal `git_failed` with `detail` git's first stderr line and `output` the error's stdout and stderr joined (stdout first; the bound of Design §2), so a hook that prints only to stdout is still read; a `GitTimeoutError` answers `timeout` through `CommandFailure` as C4's handlers do. Nothing is retried; nothing is forced (`clean` carries `-f` only because `clean.requireForce` defaults on; no `-x`, so ignored files are never touched; no `--force` anywhere else).

Why the Unstaged group's discard restores to the index rather than HEAD: it is what VS Code's and Codex's "Discard changes" do and the least surprising reading of a row under *Unstaged*; the Staged group has no discard, only Unstage, so throwing a staged change away is two deliberate steps. Why untracked discard is its own group action: it deletes content git never saw, which deserves its own count in the sheet.

### 4. The remote runner, plans and the confirm (G2)

`src/main/scm/remote-env.ts` builds the environment a remote command runs in from the login-shell capture: the capture whole (the owner's `GIT_SSH_COMMAND`, `GIT_ASKPASS`, `SSH_AUTH_SOCK`, `GH_HOST`, `GH_TOKEN`, `GH_ENTERPRISE_TOKEN`, their locale, exactly as their terminal has them) minus the parent-session variables and the `MAWS_`/`ELECTRON_` prefixes, minus `REDIRECTING_GIT_VARIABLES`, the inventory of what moves the repository git acts on or injects configuration: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_CEILING_DIRECTORIES`, `GIT_DISCOVERY_ACROSS_FILESYSTEM`, `GIT_EXEC_PATH`, `GIT_PREFIX`, `GIT_CONFIG`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*` (the review's probe showed an inherited `GIT_CONFIG_PARAMETERS='core.fsmonitor=true'` outranking a `GIT_CONFIG_COUNT` pair that set it false), and minus `GH_REPO` (gh's own override of the repository every command targets; the PR plan binds the repository explicitly instead); plus `GIT_TERMINAL_PROMPT=0` (a missing credential fails fast with git's own message instead of hanging on a prompt that has no tty), `GIT_CONFIG_COUNT=1` with `core.fsmonitor=false` (the one safety key every mode keeps, and every `git` that `gh` spawns inherits it), `GH_PROMPT_DISABLED=1`, `GH_NO_UPDATE_NOTIFIER=1`, `NO_COLOR=1`, `TERM=dumb`. A real-git test pins the precedence: under the built environment with a hostile inherited `GIT_CONFIG_PARAMETERS`, `git config --get core.fsmonitor` prints `false`. Programs are resolved on that environment's `PATH` (`src/main/scm/which.ts`: the first executable regular file named `git` or `gh` across `PATH`'s entries): `git` falls back to `/usr/bin/git`, `MAWS_GIT` overrides it (tests and C4 share the variable); `gh` has no fallback (`gh: missing`), `MAWS_GH` overrides it for a developer. The owner's `PATH` git is preferred over Apple's because their credential helpers are configured for it.

`src/main/scm/remote-runner.ts` spawns `program` with `argv` (no shell), `cwd` the checkout, `detached: true`, stdio `['ignore', 'pipe', 'pipe']`; streams every chunk as `scm.remote.output { appSessionId, token, seq, kind: 'stdout' | 'stderr', text }` (chunks split at 16 KiB; `seq` counts from 1 per run; after 1 MiB in total the rest is dropped and one `truncated: true` chunk says so); on close emits `{ kind: 'exit', seq, exitCode, signal }`. Timeout 120 s (SIGTERM to the group, SIGKILL after 2 s), the same for `scm.remote.cancel`. One remote run at a time per checkout (`busy` otherwise). The run's plan, output (the same cap) and exit are kept in main for 10 minutes per checkout as the **latest run**, which `scm.remote.last { appSessionId }` answers with the `seq` of its last chunk, so a tool that mounts after a reload shows the run, knows whether it is still running, can cancel it by its token and applies only the live events whose `seq` is greater than the snapshot's (adversarial review).

**Plans.** `scm.push.plan { appSessionId, remote? }` and `scm.pr.plan { appSessionId, title, body, base, draft }` compute what main would run and answer a `RemotePlan { token, kind, cwd, program, argv, remote, remoteUrl, pushUrls, repository, branch, head, upstream, expiresAt }` or a refusal. The token is `crypto.randomUUID()`; the plan is held in main for 5 minutes, bound to its `appSessionId` and checkout, and consumed by the first `scm.push { token }` or `scm.pr.create { token }`; a second use, an expired token, a token of the other kind, or a token presented with another `appSessionId` answers `plan_expired`. **Consumption revalidates what the sheet showed** before anything spawns: trust is read again; a fresh status must have `branch === plan.branch`, `head === plan.head` and `behind === 0`; `git remote get-url --push --all <remote>` must equal `plan.pushUrls`; for a PR, `upstream` must be unchanged and `ahead === 0`. Any difference answers `changed` ("<what> changed since the sheet opened; review it again"), consumes the token and makes the sheet re-plan (adversarial review: a remote re-pointed, or a commit made, while the sheet is open must not run under the old confirm). The confirm sheet (Design §8) renders the plan's `program argv` verbatim; the run executes the stored plan, never anything the renderer sends back. This is how "the confirm names the exact command" and "nothing runs without the confirm" are structural rather than a convention.

Push plan rules, in order: trusted; a repository; `status.branch !== null` (else `detached`); remotes read through `git remote` (read runner) and the chosen `remote` must be one of them (default: the upstream's remote, else `origin`, else the sole remote; none → `no_remote`); the destination is `git remote get-url --push --all <remote>` (every push URL, since a `pushurl` may differ from the fetch URL and a remote may push to several; each through `withoutUserInfo`); `status.behind === 0` when an upstream exists (else `behind`: "Pull in a terminal first"; MAWS never force-pushes); the branch name passes `check-ref-format --branch`. Argv: `push --progress [--set-upstream] <remote> refs/heads/<branch>:refs/heads/<branch>` (`--set-upstream` when the branch has no upstream; the explicit refspec so no option parsing can reach a user-named branch and no `push.default` rule redirects it; `--progress` because git prints progress only to a tty otherwise). `upstream` in the plan is `<remote>/<branch>`; `remoteUrl` is the fetch URL (the GitHub link), `pushUrls` the destinations the sheet shows.

PR plan rules, in order: trusted; a repository; not detached; `gh` resolved (else `gh_missing`) and authenticated (else `gh_unauthenticated`, Design §6's status); the branch has an upstream and `ahead === 0 && behind === 0` (else `not_pushed`: the sheet offers Push first; `gh` would otherwise push on its own and prompt); the **repository** is what `gh repo view --json nameWithOwner,url` answers in the checkout under the remote environment (30 s): `nameWithOwner`, prefixed with the URL's host when that is not `github.com` (`HOST/OWNER/REPO`), the same resolution `pr create` would make from the remotes and `gh repo set-default`, now shown in the sheet and bound; gh failing to resolve one answers `no_remote` with its first stderr line; `base` passes `check-ref-format --branch`; `title` has no newline. Argv: `pr create --repo <repository> --head <branch> --base <base> --title=<title> --body=<body> [--draft]` (the `=` forms so a title or body beginning with `-` is never read as an option; `--repo` so the confirmed repository is the one gh targets whatever the environment or a later `set-default` says). The result URL is the first `https?://\S+/pull/\d+` in stdout; the renderer shows it as a link and invalidates the PR state.

### 5. The panel tool's state model (G1)

`src/renderer/src/tools/scm/` holds the tool. **Groups** are pure (`groups.ts`): from `GitStatus.files`, `unmerged = index === 'U' || worktree === 'U' || (index === 'A' && worktree === 'A') || (index === 'D' && worktree === 'D')` (the only codes porcelain v2 writes for `u` records and never for `1` records); `conflicts` = unmerged; `staged` = `!untracked && !unmerged && index !== '.'`; `unstaged` = `!untracked && !unmerged && worktree !== '.'`; `untracked` = `untracked`. A file with `MM` appears in Staged and in Unstaged, as git shows it. Row labels from the character: `M` modified, `A` added, `D` deleted, `R` renamed (from `oldPath`), `C` copied, `T` type changed; conflicts by code (`UU` both modified, `AA` both added, `DD` both deleted, `AU`/`UA` added by one side, `DU`/`UD` deleted by one side).

**View state** (`view-state.ts`, a zustand store handle kept as the X5 state): `{ session, selected: { group, path } | null, hunk, navigate, scrollTop, mode: 'unified' | 'split', collapsed: Set<group>, message: string, noVerify: boolean, sheet: null | { kind: 'discard', entries } | { kind: 'push' } | { kind: 'pr' }, lastCommit: { sha, subject } | null, notice: { kind: refusal | 'error', text, output } | null, request: ScmParams | null }`. The commit message and the Skip-hooks toggle live here, so they survive tab switches and session switches under a pin (they follow `session`) and are gone at restart (a draft commit message is not worth a persisted file; Codex keeps its per thread the same way). A pinned tool shown for another session starts over as Review does (`forSession`).

**Data** (`store.ts`, `useScm`): `hold({ directory, scope: 'staged' | 'worktree' })` ref-counted like Review's, one `git.diff` per key, re-read 250 ms after the git store takes a new status for the directory (subscribe to `useGit` as `review-store.ts:212-223` does); the patch split per file with `splitPatch` within `REVIEW_SCOPE_BYTES_CAP`, else the list alone with `loadFile` per selection; `untracked(directory, path)` fetches `git.diff { scope: 'untracked', path }` lazily for the selected untracked file (Design §7); `status(appSessionId)` through `useCommand('scm.status')` (trust, gh, remotes); mutation actions `stage`, `unstage`, `discard`, `commit` that invoke and, on `ok`, set `lastCommit` or clear `notice` (the lists move when `git.changed` arrives through the watcher's refresh, Design §1; the store applies nothing to `useGit` itself), on a refusal set `notice`; the remote-run state `{ token, kind, plan, lines: string[], bytes, seq, exitCode, running } | null`, seeded from `scm.remote.last` when the body mounts and advanced by `scm.remote.output` events whose `seq` exceeds the last applied (an event of another token replaces the state only when the snapshot is older than it).

**Body** (`ScmShell.tsx`), top to bottom: a header line `⎇ <branch> · <upstream or "no upstream"> · N ahead[ · M behind]` with the Push and Open PR buttons (Design §8) and the gh state when it matters; a notice line for the last refusal or error (its `output` behind a disclosure, monospace, `whitespace-pre-wrap`, tokens only); the four groups as collapsible sections (Conflicts first, hidden when empty; then Staged, Unstaged, Untracked with counts), each row a button that selects the file, with hover actions by group (Staged: Unstage; Unstaged: Stage, Discard…; Untracked: Stage, Delete…; Conflicts: Mark resolved (stage), Open file) and group-header actions (Stage all for Unstaged and for Untracked, Unstage all, Discard all…, Delete all untracked…); the diff body for the selected file through `ReviewView` (lazy, the same `React.lazy` boundary ReviewShell uses, unified by default with a split toggle and wrap toggle, hunk prev/next); the commit form (a `textarea` labelled "Commit message", ⌘Enter commits, a "Skip hooks (`--no-verify`)" checkbox, the Commit button, the last commit's `abc1234 · subject` line); and the Output disclosure for the latest remote run (streamed lines, Cancel while running, the exit line). "Open file ↗" on a row opens the file in a main tab through C8c's `openFile` (a deleted file has none). An untrusted checkout shows one notice ("MAWS runs git here only after you trust the folder in a session") and every action disabled; a non-repository shows C8a's "Not a git repository" sentence and nothing else; a repository with no commits shows the groups (everything is untracked or added) and commits normally.

Tool declaration (`ScmTool.tsx`): `id: 'source-control'`, `title: 'Source control'`, an icon, `pinnable: true`, `multiInstance: false`, `params: ScmParams = { target?: string }` (a repository-relative path, or an absolute path inside the checkout, which the tool makes relative; an `open()` with a target selects it in whichever group lists it, Staged first; E1's `show_pane { pane: 'source-control', target }` passes `{ target }` through unchanged, the ledger's §1 as built 2026-10-06, so no mapping exists between the two), `beforeClose: async () => true` (a draft message is state the host drops with the tab, as Review drops its selection), `dispose` nothing (the watch and holds are the mounted body's), `summary` undefined (the summary's row is E6's edit of PushState, Design §6). Registered from `src/renderer/src/App.tsx` in an E6 block beside `registerCodeTools()` through `registerScmTool()` in `tools/scm/index.ts`.

### 6. PR state and the summary's push-state row (G3)

`scm.status { appSessionId }` answers `ScmStatus { directory, repository, trusted, trustKey, remotes[], defaultRemote, defaultBase, gh, checkedAt }`: trust from the trust reader (the captured environment, Design §3); remotes from `git remote` and `git remote get-url` (read runner; URLs through `withoutUserInfo`); `defaultBase` from `symbolic-ref --short refs/remotes/<defaultRemote>/HEAD` minus the remote prefix, null when unset; `gh` resolved on the remote environment's `PATH` and probed with `gh --version` (first line) and `gh auth status --active` (exit 0 → `ready`; exit 1 or 4 → `unauthenticated` with stderr's first line; a timeout or a crash → `unauthenticated` with the reason), cached 10 minutes per process and invalidated by `refresh`. It is a read in `QUERY_COMMANDS`.

`scm.pr.state { appSessionId, refresh }` answers `ScmPrState { checkedAt, branch, gh, pr | null, error | null }` for the checkout's current branch: trusted and a repository with a remote, else `pr: null` with the refusal's name in `error` (the row explains); `gh pr view <branch> --json number,url,title,state,isDraft,reviewDecision,baseRefName,headRefName,mergeStateStatus` then `gh pr checks <branch> --json name,bucket,state,link,workflow` under the remote environment in the checkout, 30 s each; `pr view` exiting non-zero with stderr matching `no pull requests found` → `pr: null, error: null` ("No PR for <branch>"); any other failure → `pr: null, error: <first line>` ("PR state unavailable · <reason>", which Claude Desktop's bar also keeps apart from "no PR"); `pr checks` exits 8 while pending and 1 on a failure, so its stdout is parsed whenever it is a JSON array, and `[]` or a "no checks reported" failure is `checks.summary: 'none'` ("No checks reported yet", distinct from a failed refresh, as Claude Desktop's bar does); `summary` is `fail` if any bucket is `fail` or `cancel`, else `pending` if any is `pending`, else `pass` if any is `pass`, else `none`. Cached 60 s per `(checkout, branch)`; `refresh: true` bypasses the cache; the cache is dropped for a checkout whenever a push or PR run of that checkout ends.

Polling is the renderer's and bounded: `useCommand('scm.pr.state', { appSessionId, refresh: false }, { staleTime: 60_000, refetchInterval: 120_000, refetchIntervalInBackground: false, enabled })` where `enabled` is `status !== null && status.branch !== null && scmStatus?.trusted && scmStatus.remotes.length > 0`; the summary row and the tool's header share the query key, so two surfaces cost one poll; nothing polls while neither is mounted; a `git.changed` with reason `head` or `refs` for the directory invalidates the query (the push just moved the upstream). Manual refresh: an icon button that invokes `scm.pr.state { refresh: true }` and writes the answer into the query cache.

`PushState.tsx` (E6's edit) keeps its first row as it is (the push text; "Open on GitHub" when the remote is GitHub's), makes the push text a button that opens the tool (`panelHost.addTool('source-control', { appSessionId })`, `aria-label` "Open Source control"; C8a's `getByText` pins still find the text inside the button), and adds a second row for the PR, one of: `Trust this folder to see PR state` (muted); `GitHub CLI not installed · Install` (the action opens `https://cli.github.com` externally, the install state the brief asks for); `GitHub CLI not signed in · Sign in` (the action opens C9's Terminal tool with `gh auth login` typed, through `openTerminal`, so signing in stays in MAWS); `No PR for <branch>`; `PR #12 Open · 3 passed, 1 pending` (the number a link to the PR; `Draft`, `Merged`, `Closed` as the state says; the checks summary in words; `Changes requested`/`Approved` when `reviewDecision` says so); `PR state unavailable · <reason>`; each with the refresh button on the right (`aria-label` "Refresh PR state", `title` the `checkedAt` time). The row hides as today when there is no status or the head is detached.

### 7. `git.diff`'s `untracked` scope (G1)

An untracked file has no diff in any of C4's scopes; Review lists it with `hunks: null`. Source control shows what `git add` would stage, so C4's `GitDiffScopeSchema` gains `'untracked'` (append-only; `GitDiffInput.path` required with it, `base` refused): the service reads a fresh status (its own `status(directory)`) and **requires `path` to be listed as an untracked file entry**, exact match, no trailing slash: git lists only what lies in the working tree, so the listing is the confinement. A directory entry (`udir/`) has no diff and is refused; a path through an untracked symlink (`escape/secret`, where `? escape` is the listing) is not listed and is refused; `.git/config`, an ignored path or any path git does not list is refused; a lexical check alone would read any file the process can open through `--no-index` (the adversarial review's probe read an outside file through a symlinked directory). An untracked symlink itself (`? escape`) is listed and diffs as git shows a symlink: its mode `120000` and the target path as the one content line, never the target's content. The refusal is a `GitCommandError`-shaped failure the renderer shows as "no diff for this entry" (`internal` with the message `not an untracked file: <path>`).

The command runs from the top level: `-c diff.autoRefreshIndex=false diff --no-color --no-ext-diff --no-textconv --no-index -U<context> -- /dev/null <path>` with `acceptExitCodes: [1]`. The probes show the output as `diff --git a/<path> b/<path>`, `new file mode …`, `--- /dev/null`, `+++ b/<path>`, the hunks, and exit code 1 whenever the file exists, an empty file included (it still differs from `/dev/null` by its header, so exit 0 never occurs for a listed file; the authoring draft's "exit 0 for an empty file" was wrong, the review's probe); any other non-zero code is the error it is. `splitPatch` reads the output as `kind: 'added'`. `files` is derived from the patch (`insertions` the count of `+` lines after the header, `deletions` 0, `binary` when the block says `Binary files … differ`), so no second `--numstat` run (whose `-z` form lists `/dev/null` and the path as separate fields, not the shape `parseNumstat` expects).

### 10. Failure semantics and security

- **Envelopes.** `invalid_input` from the router for anything a schema refuses; `timeout` for a runner timeout (through `CommandFailure`, as C4's handlers); `internal` for an unknown session, a thrown allowlist violation, a refused untracked diff or anything unexpected. Everything the owner can act on is a **refusal value** (`ScmRefusal { refused, detail, output }`): `untrusted`, `not_repository`, `changed` (a path the fresh status does not list, or lists in another state; a plan whose branch, head, destination or upstream moved since the sheet opened), `unmerged`, `nothing_staged`, `empty_message`, `git_failed` (git exited non-zero, hooks included; `output` carries what it printed on both streams), `busy` (a remote run already in flight for the checkout), `no_remote`, `detached`, `behind`, `not_pushed`, `gh_missing`, `gh_unauthenticated`, `plan_expired`. A remote run's own failure is its `exit` chunk with a non-zero code; the Output header turns to the danger token and the panel keeps the text.
- **Nothing is executed verbatim.** Every argv is built in main from fields the schema bounded (`paths` ≤ 1,000 entries of ≤ 4,096 chars; `message` and `body` ≤ 64 KiB; `title`, `base`, `remote` ≤ 256) and the service validated against git's own answers (paths against the fresh status, remotes against `git remote`, branches through `check-ref-format --branch`, the PR repository from gh's own resolution); user text goes after `--` or in `--flag=value` form; `spawn` is never given `shell: true`; the remote command runs only through a one-shot plan main recorded, the sheet showed and the run revalidated. The renderer never sends a directory for a mutation; a token is honoured only for the session and checkout it was planned for.
- **Environment.** The mutating runner disables transport and credential helpers whatever the owner's config says (`GIT_ALLOW_PROTOCOL=` wins over `protocol.*.allow`, `runner.ts:50`) and drops every inherited `GIT_*`; the remote runner drops the inventoried redirecting variables and `GH_REPO`, keeps the owner's helpers (P-12's point), and both drop the parent-session variables. Credentials never reach the renderer: remote URLs pass `withoutUserInfo`; `gh` tokens stay in the environment; output is shown as text (a helper that prints a token to stdout would show it, as a terminal would).
- **Bounds.** One mutation chain per checkout; one remote run per checkout; output capped at 1 MiB per run and 256 KiB per stream per mutation; plans expire in 5 minutes; the PR cache is 60 s and the poll 120 s, only while a surface shows it; the latest run is kept 10 minutes.

## Residue decisions (for the owner to confirm at hand-back)

1. **Hooks run by default; "Skip hooks" is a per-commit checkbox in the commit form, not a setting.** It is what `--no-verify` is in a terminal, a decision per commit; no settings version is taken (the ledger reserved none for E6). Alternative: a `scm.runHooks` setting (needs a version and a Settings row for a rarely flipped switch).
2. **Discard semantics.** In the Unstaged group, Discard restores the working tree to the index (a staged part of the same file is kept); in the Untracked group, Delete removes the files; the Staged group has only Unstage. Every discard sheet lists every file behind an acknowledgement checkbox.
3. **Push never forces and refuses when the branch is behind** ("Pull in a terminal first"); a branch without an upstream of its own name on the chosen remote is published with `--set-upstream` (a branch made from `origin/main` and tracking it is re-pointed to `origin/<branch>`, which the sheet says); the owner's `PATH` git is used (their credential helpers are configured for it), Apple's as the fallback; the sheet shows every push destination (`pushurl` included), and a push whose branch, head or destination changed while the sheet was open is refused and re-planned.
4. **Open PR requires the branch pushed and even with an upstream of its own name**, so `gh` never pushes on its own; the repository is the one `gh` itself resolves for the checkout, shown in the sheet and bound with `--repo`; title defaults to the one new commit's subject or the branch name; base defaults to the remote's HEAD branch; Draft is a checkbox; the body starts empty.
5. **PR state** is polled every 2 minutes while a surface shows it, cached 60 s in main, refreshed on demand; `gh` absent shows "GitHub CLI not installed · Install" (cli.github.com); not signed in shows "Sign in", which opens a Terminal tool with `gh auth login`.
6. **Trust gates everything but `scm.status`**: mutations, remote commands and PR state run only in a checkout the owner trusted in a session, read from the same config file the engine reads.
7. **Both runners take the login-shell environment**, so hooks and signing behave as in Terminal.app; local mutations still disable transport and credential helpers (P-12); remote runs drop the variables that would redirect git or gh (`GIT_DIR`, `GIT_CONFIG_PARAMETERS`, `GH_REPO`, …) and keep the owner's helpers.
8. **The commit message draft lives in the tool's state** per session, not in a file.
9. **G4 extends E5's anchor seam** (`pr-line` beside `file-line`); the PR diff surface ships only if E3 has landed when M5 runs.

Questions for the owner beyond these: whether amend (`--amend`) and stash belong in a follow-up (left out here); whether the PR body should default to the commit messages (`gh --fill` style) rather than empty.

- Observation (grounding): C4 reads git in every directory, trusted or not, with hooks and fsmonitor off; trust gates launches and worktree creation, not reads.   Evidence: `src/main/git/register.ts:22-28` (no trust check), `src/main/sessions/start-guards.ts:63`, `src/main/git/runner.ts:79`.
- Observation (probe, 2026-10-06, git 2.55.0 in a scratch repository under `/tmp`): `git restore --staged --worktree --source=HEAD -- new.txt` on a staged new file exits 0 and deletes the file; `git clean -fd -- udir/` removes an untracked directory; `git restore --staged -- b.txt b2.txt` on a staged rename leaves `.D b.txt` and `? b2.txt`; `git restore --worktree --source=HEAD -- a.txt` restores a modification; `git add -- ':(top,literal)z.txt'` stages; a `pre-commit` hook runs under a plain commit and prints to stderr, `--no-verify` skips it, and a multi-line `-m` argument is kept whole. The hook saw `PATH` beginning with git's `libexec/git-core` followed by the inherited entries.
  Evidence: this session's probe transcript (the scratch was removed after).
- Observation (probe): `git diff --no-index -- /dev/null untracked.txt` prints `diff --git a/untracked.txt b/untracked.txt`, `new file mode 100644`, `--- /dev/null`, `+++ b/untracked.txt` and exits 1; `--numstat -z` on the same exits 0 and lists `/dev/null` and the path as separate NUL fields.
