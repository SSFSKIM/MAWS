## Purpose

The engine host gains the artifact store every other P3 child stands on: its own SQLite database, one Yjs v14 document per structured artifact served to renderer replicas and to agent replicas, an update log with provenance that outlives compaction, versions and artifact-wide restore, the `artifacts.*` and `spaces.*` surface, the base agent tools, the detached transport's document channel and the export service. At the end, a schema-agnostic document made by the host's test writer syncs to two renderer windows, survives a restart and a host SIGKILL, is edited while every window is closed in detached mode, lists its versions with authors, restores whole, and replays an idempotent write; File and HTML artifacts behave as X12's deliverables did. Nothing here draws an editor (B, C), the library (L) or a design system (D).

## Decision Log

Residue decisions of this child (the architect folds them into the parent's §12 under P3-A). Anything here that changes a ledger name is also a `[parent-impact]` line in the hand-back.

1. **2026-10-12, event names.** `artifacts.changed {artifactId, kind, revision, change}` and `spaces.changed {spaceId, change}` replace the ledger's `artifact.changed` and `space.changed`: the registry's namespace rule forbids a key outside its namespace, and two one-event namespaces would add a module and a name list for nothing. Same payload as the ledger's plus `change: 'created' | 'updated' | 'deleted' | 'linked'`. `[parent-impact]` (ledger §1 row 2).
2. **2026-10-12, which kinds are Y.Docs.** `document`, `presentation`, `design`, `design_system` and `dashboard` are Y.Docs (§4.2's list); `html` and `file` are **byte kinds**: their content is bytes on disk, each write immutable (X12's version copies), with log rows and versions of their own and no Y.Doc. An HTML artifact is untrusted content rendered in a frame, never co-edited, and a 16 MiB page in a Y type would cost memory for nothing.
3. **2026-10-12, artifact ids and handles.** `Artifact.id` is a host-generated UUID v4. The old free-HTML tool's agent-chosen `id` (`ARTIFACT_ID`) survives as an optional `handle` column: unique among the artifacts linked to one session, resolved over the session and its ancestors (X9's scope, now "the artifacts linked to the ancestors"); every tool that takes an artifact accepts the UUID or a handle in scope. Old skills keep working and the library has one global id. Handles never collide across sessions (the architect's confirmation, 2026-10-12): two sessions that each choose `report` get two artifacts; a handle is stored with the creating session, and resolution looks only at the asking session's lineage (itself, then its ancestors, nearest first), so no global uniqueness is enforced or needed. `artifact_list` returns both `id` and `handle`. Confirmed by the architect with Decision Log 1, 2, 4 and 14 and recorded in the ledger.
4. **2026-10-12, X12 kept working until L (a bounded dual write).** Until P3-L's cutover, every write of a `file` or `html` artifact also writes the X12 deliverable record with **the same UUID as its record id** (the existing `FileDeliverableStore`), so the Deliverables panel, `maws-deliverable://`, `artifact_screenshot` and P2's comment card keep their behaviour and their e2e groups pass unchanged. The store is authoritative; the X12 record is a mirror L deletes with the cutover. Rejected: rewiring the panel to the store (L's scope) and leaving the panel stale (the e2e groups must not change behaviour).
5. **2026-10-12, provenance's stored shape (X29 on v14; parent Decision Log 30, 29 and 36).** `artifact_attributions (artifactId, fromSeq, toSeq, tier: 'update' | 'hour' | 'day', fromAt, toAt, bytes)`: one `update` row per log row, written in the same commit, `bytes` an encoded v14 ContentMap built from the update's content ids, inserts attributed `insert = <actor key of the clientID's binding>`, `insertAt = at`, deletions `delete = <the connection's actor key>`, `deleteAt = at`, times floored to the minute at write. Maintenance merges `update` rows older than 1 hour losslessly (`Y.mergeContentMaps`) into one `hour` row per artifact and hour, and `hour` rows older than 30 days into `day` rows; nothing is ever dropped, so "who edited this" survives every compaction and thinning; the merged map of an open artifact is cached in memory (rebuilt on open, extended per commit). Reference: S3's `s3/lib/provenance.mjs` and S7a's `s7/soak/store.mjs` on P3-0's branch, copied, never imported.
6. **2026-10-12, clientID binding.** `client_actors(artifactId, clientId, actor, firstSeq)`: a clientID is bound to the actor of the connection that first writes structs under it. Insert provenance uses the binding, not the sending connection, so an accepted suggestion credits the suggester (Decision Log 25's pitfall); deletions use the sending connection's actor. A renderer connection may carry structs of a clientID bound to another actor only when they are already in the host doc (they are then no-ops) or the clientID is new; a new struct under a clientID bound to a **different** actor is refused and closes the connection (a forged authorship), except that P3-B's suggestion acceptance will add its own exemption through the service's API.
7. **2026-10-12, the live revision for byte kinds.** One global sequence serves every kind: a byte-kind write appends an `artifact_updates` row with `bytes` NULL and a `content` JSON (`{name, sha256, size, path}`), so `revision` is the same global, rising, sparse seq for an HTML page as for a Y.Doc.
8. **2026-10-12, storage policy: versions, the head, the log and thinning (parent Decision Log 36, S7a; supersedes full V2 states per version).** Versions are rows of `artifact_versions` whose state is stored as **zstd-compressed V2 bytes, `enc: 'full' | 'delta'`**: a `delta` is the V2 diff from the previous retained version's state, a `full` keyframe is written whenever the deltas since the last keyframe would exceed the state's own size; reading a version reconstructs from its keyframe forward. One **`artifact_head (artifactId PK, seq, state)`** checkpoint per artifact (zstd V2 of the live doc at `seq`), rewritten by maintenance and at version writes; **a load is the head plus the log rows after it**. An update row is deleted once the head covers it **and** it is older than 7 days. Thinning applies to `auto` versions only: all kept for 24 hours, hourly to 7 days, daily to 30 days, weekly after; `turn`, `named`, `restore`, `import` and pinned versions (a design-system pin or any `designSystemRef` target) are never thinned; deleting a delta's base re-bases the next delta (or promotes it to a keyframe) in the same transaction. Byte kinds keep their immutable content files and are thinned by the same age rule (content files deleted with their version unless pinned). **Nightly maintenance** (once per 24 h of host uptime, and at host start when the last run is over 24 h old, off the commit path): head rewrite, log pruning, thinning, provenance tiering, `PRAGMA incremental_vacuum`; the database is created with `PRAGMA auto_vacuum = INCREMENTAL` (it must be set before the first table). The owner's **"Delete versions older than…"** is `artifacts.pruneVersions {artifactId?, olderThan}` (every kind but pinned states). zstd is `node:zlib`'s `zstdCompressSync`/`zstdDecompressSync`, **confirmed inside Electron 44.4.5's Node 24.21.0** (2026-10-12, `ELECTRON_RUN_AS_NODE=1 electron -e …`: a 100 kB buffer round-trips); the utility process and the detached supervisor run that Node. Reference: S7a's `s7/soak/store.mjs` and its findings section (the policy text).
9. **2026-10-12, the agent replica's base.** A session's replica is a live, connected Y.Doc plus a **base**: the encoded V2 state and revision captured at the session's last `artifact_read`. A publish computes its diff between the base and the sent content, then applies only that change to the live replica (S6's base-relative rule). Bases are in memory only; after a host restart a publish without a fresh read is refused by layer 1 ("read the artifact first"). Replicas close after 10 minutes without a call and at the session's end; nothing is lost because every write waits for its durable ack.
10. **2026-10-12, the publish's three layers for file kinds (X25).** Layer 1: `baseRevision` must equal the revision this session's last read returned for this artifact, else refused naming the live revision. Layer 2: if no file the agent sent changed between its base and live (by content), the change applies over the live doc and the other files are kept. Layer 3: otherwise refused, naming every file changed on both sides (and, where a kind adapter has a model, the element and property, C's adapter). `force: true` skips layers 2 and 3 for the files sent. The whole map applies in one transaction or not at all; `null` removes a file. The generic file model (A's adapter, used by `design_system`, `design`, `presentation` and `dashboard` files until their owners register adapters) is a root map `files` of path → text type, merged at file level.
11. **2026-10-12, idempotency.** `artifact_ops(opId PRIMARY KEY, artifactId, tool, result, at)` where `opId` is the call's tool-use id; the op row commits in the same transaction as the write's last log row, and a repeated id returns the stored result without applying anything. A call without a tool-use id (none should exist; `toolUseId` is nullable in `McpToolContext`) is applied without a replay guarantee and logged.
12. **2026-10-12, the store's schema version.** `PRAGMA user_version = 1`, migrations as an append-only list (`src/main/index/migrations.ts`'s pattern), every migration in one transaction; a file whose `user_version` exceeds the known count is opened read-only and every write refused with `storeTooNew` (an older app beside a newer store never corrupts it); a file that fails to open is moved aside as `store.sqlite.broken-<epoch>` and a fresh store created, the event logged and surfaced through `artifacts.status`. Pragmas: `auto_vacuum = INCREMENTAL` (at creation, before the first table), `journal_mode = WAL`, `synchronous = FULL`, `fullfsync = ON`, `foreign_keys = ON`.
13. **2026-10-12, the document port route in utility mode.** Main makes one `MessageChannelMain` per open document, hands one end to the host on a new parentPort message `{t: 'doc', channel, artifactId, actor}` (the runtime learns this message type) and the other to the renderer by `webContents.postMessage`; in detached mode main keeps the host end and relays it over a socket channel (M5). The renderer's provider never knows which.
14. **2026-10-12, the `maws-artifact:` scheme.** `maws-artifact://<artifactId>/<revision | 'live'>/<path>` serves byte-kind content (and later an exporter's assets) with X12's headers and `DELIVERABLE_HTML_CSP`; main resolves a path by asking the host (`artifacts.content`), never by opening the host's database. This is the ledger's "new name fixed by A" for serving File and HTML artifacts; `maws-deliverable:` stays until L.
16. **2026-10-12, restore and the `restored` signal (parent Decision Log 29, S3's rulings).** Restore is **one kind-agnostic host operation**, not a per-kind diff: a scratch gc-off doc holding the version's state plus the live state, `Y.undoContentIds` over the changes since the version, shipped to the live doc as one update with origin the restorer's actor (so the log row and provenance credit the restorer and concurrent edits merge by the CRDT rule); the host writes an `auto` version before and a `restore` version after. Per-kind after-effects (the threads mirror, orphans, id repair) are the kinds' `afterRestore` hooks, not A's. Reference: **S7a's `s7/soak/revert.mjs` `revertUpdateFixed`**, copied, not S3's `revertUpdate` (parent Decision Log 36: v14's `Y.undoContentIds` drops a value inserted and deleted since the version, so a map attribute overwritten twice reverts wrong, and S3's version returns 13 undecodable zero bytes on a no-op where the fix returns an empty document's update); S7a's overwrite-twice reproductions are kept as regression tests. The gap is filed upstream as https://github.com/yjs/yjs/issues/814 (parent Decision Log 38): `revertUpdateFixed`'s comment and the overwrite-twice tests cite that URL, and when a `@y/y` release ships the fix the re-pin drops the special handling and keeps the tests (a tracker row in A's hand-back). Replicas are told by a new port frame **`restored` (type `101`): `[101, revision, versionId]`**, sent by the host to every connection of the document after the restore's row commits (after the update frame itself), so an editor can drop undo history across the restore and show "Restored from …"; the provider surfaces it as an event (`onRestored`). A replica that missed the frame (disconnected across the restore) must still end up right (the architect's check, 2026-10-12): on every attach the host sends, after its step 2, the document's latest `restored` frame if the document has any `restore` version, and the provider fires `onRestored` only for a `versionId` it has not seen for this document (its first connect records the id without firing), so a reconnecting editor clears its undo history exactly once per restore it did not witness; B's editor may also key off a `restore` row in the version list it reads. An agent write whose targets vanished through a restore is refused naming them "removed by restore" (for `artifact_publish`: a sent file present in the base and absent live because a restore removed it; B adds the same reason to `artifact_edit`). An `auto` version is also written **when the owner views an artifact whose live revision moved since its last version** (`artifacts.markViewed`), so "See N new changes" has a state to diff from after compaction.

18. **2026-10-12, host hooks for kinds and restore's one behaviour (parent Decision Log 31, S5; 32, the owner).** The service runs each registered kind's `afterUpdate?(live, {update, actor})` hook after every committed update of that kind's documents; what the hook writes lands as its own update and log row credited to the actor of the update that triggered it (X29's `Actor` has no host or system kind, and a repair is a consequence of that write; written through a host replica keyed by that actor so its clientID binds to it; confirmed by the architect 2026-10-12: X29 gains no system actor, the state vector holds one host clientID per actor seen, and a repair after an agent publish credits that session), so B's id repair, its refresh of a comment thread's drifted anchor from the live mark (all extents in one walk, only when drifted) and its stripping of a comment mark with no thread record all land through it; A ships the hook point and runs no repair of its own on the generic model. Restore has **one behaviour for every kind** (the owner's ruling, parent Decision Log 32, which supersedes the flag first written here): it reverts text, comment marks and thread statuses and always keeps the conversations posted since the version (a thread whose passage is gone shows as orphaned). 20. **2026-10-12, the composition hold (parent Decision Log 33, S4).** `PortProvider.holdRemote(on: boolean)`: while held, inbound sync frames (type 0: step 2 and update; a host step 1 is answered at once, since answering it applies nothing locally) are buffered in arrival order and none is dropped, and a `restored` (101) arriving while anything is buffered is buffered behind them so it still follows its update; awareness (1) and ack (100) pass through; clearing the hold applies the buffer in order, **with consecutive buffered updates merged into one (`mergeUpdates`, through the binding module) and applied once** (parent Decision Log 35, S7b: a Korean word holds 1.1 to 1.3 s and buffers 7 to 9 frames; singly 63 to 103 ms and a long task after every word, merged 21 to 27 ms); a buffered step 2 or a `restored` frame keeps its place, splitting the runs it sits between. The provider clears a hold by itself after 5 s (a stuck composition must not part the replica for good); a disconnect discards the buffer (the next step 2 re-delivers everything). B's editor binding sets it at composition start and clears it when composing stops. Reason: a remote update touching the composing text node ends Korean composition early and doubles jamo on both Yjs versions. Built as an M1 follow-up.
21. **2026-10-12, S4's host rules and where they live (parent Decision Log 34).** The rules are schema-aware (they act on block ids), so their bodies are the kinds' (B's document adapter, C's deck adapter); A ships the hook points and the guarantees they need, and the generic model needs none of them. (a) **Forwarding:** an edit that lands in a tombstoned, re-inserted block is garbage-collected on arrival, so the service calls the kind's `beforeApply?(live, incoming: Uint8Array, {actor, step2})` with the **raw incoming bytes before applying them**, applies the update, then applies whatever forwarding edits the hook returns (an update it computed, or a callback run in a transaction) in the **same commit batch**, credited to the incoming connection's actor (through that actor's host replica, Decision Log 18's rule), so forwarded text keeps its author. (b) **Id repair** (B's `afterUpdate`): keep the later insertion of a duplicate after carrying the loser's edits into it, re-id any other duplicate, never delete. (c) **Move detection** per update (a delete and an insert of the same id; a human drag racing an agent move) is the same hook's. (d) The provider logs when the composition hold's 5 s cap fires (an M2 one-line follow-up in `src/artifacts/provider/port.ts`). The writer's dry run on a fresh-clientID clone and `createChecked` validation are B's, inside the batch the host applies as one transaction. Reference: S4's `spikes/p3-store/s4/src/host.ts` (`receive`, `forward`), copied by B, never imported.
22. **2026-10-12, P3-D's requests of A (parent Decision Log 39).** (a) `artifacts.delete` of a `design_system` artifact is refused while any live (not deleted) artifact's `designSystemId` names it, answering `designSystemInUse {artifactIds}`. (c) `ArtifactHost.versionState(artifactId, version: number | {seq: number}) → Promise<Uint8Array>` returns a version's V2 bytes (decompressed, reconstructed from its keyframe chain), over a host command `artifacts.versionState`; B's history preview uses it too. **Decisions.**
- Byte kinds (Decision Log 2, 7): an `html` write stores its bytes at `<userData>/artifacts/<id>/content/<seq>/<name>` (immutable, written to a temp file and renamed before the row commits), appends the log row and a version row (`auto` for an agent's write, `import` for the first, `restore` for a restore); a `file` artifact's content is the referenced path in place (`send_file`'s rule), versions record `{path, at}`. The 16 MiB cap of X12 holds for `html`.
- Versions (§4.7, Decision Log 8): `createVersion(artifactId, {kind, actor, label?, note?, summary?})` captures the V2 state (Y kinds), stored as a zstd delta from the previous retained version or a keyframe per Decision Log 8, with the current `designSystemRef` (the governing system's id and the seq of a retained system version equal to its live state, writing a system `auto` version first when the system moved since its last one; Decision Log 22b) and `assetRefs` (the asset ids the artifact references; for the generic model, every asset of the artifact); the scheduler writes `auto` versions at 2 minutes after the last human update and every 10 minutes of continuous activity (any actor), only when the revision moved since the last version; `endTurn(appSessionId)` writes one `turn` version per artifact the session's replica wrote during the turn (summary: the tool calls' count, B and C refine it); `restore` and `import` versions are written by those operations. Thinning, log pruning, the head rewrite, provenance tiering and incremental vacuum run in the nightly maintenance (Decision Log 8), plus `pruneVersions(artifactId?, olderThan)` for the owner's action.
- Restore (§4.2, Decision Log 16): `restore(artifactId, versionId, actor)` writes an `auto` version of the current state, computes the revert update by S3's `revertUpdate` (a scratch gc-off doc with the version state and the live state, `Y.undoContentIds` over the changes since the version), applies it to the live doc as one update attributed to the restorer (through a replica of the restorer or as a host-originated update credited to that actor; either way one log row with the restorer's actor), writes a `restore` version labelled "Restored from <the version's label or time>", runs the kind's registered `afterRestore` hook if any, and sends `restored` (frame 101) to every connection of the document. Kind-agnostic: it covers every root type (attributes, text, nested children, the generic `files` map). Byte kinds restore by writing the old bytes as a new write. Restoring a version whose content ids were compacted away must still work (the version state holds them).
- `markViewed(artifactId)` (the owner opened the artifact): sets `lastViewedAt`, and writes an `auto` version first when the live revision moved since the artifact's last version (Decision Log 16).
- Idempotency (Decision Log 11): `withOp(opId, tool, artifactId, run)` returns the stored result for a known `opId`; otherwise runs `run`, and the op row is written in the commit of the write's last row. The test writer and every M6 write go through it.
- The change feed: `onChange({artifactId, kind, revision, change})` fires after commit for entity changes, content writes and Y-doc commits (Y-doc commits coalesced to at most one per artifact per 250 ms, the last revision winning); `onSpaceChange`.
