## Terms

- **The schema module:** `src/artifacts/document/schema.ts`, the one Tiptap extension list and the ProseMirror `Schema` built from it, importable in Node (no React, no DOM at import time); every writer, editor, importer, exporter and the history renderer build from it. **Schema parity** is the invariant that one module is the only source and that its storage keys (`name--<hash>` for overlapping marks) are a committed fingerprint CI compares.
- **A tab:** one body fragment of the document. **The tabs map:** the root node `tabs` whose attributes are `tabId → Node('tab') {title, order, body}`, `body` the `Node('doc')` the editor binds (S3's model, `s3/lib/artifact.mjs`); the first tab is created with the document.
- **A thread:** a nested node under the root `threads` keyed by `threadId`, `{tabId, blockId, quote, anchor: {start, end}, status, createdBy, createdAt, resolvedBy?, resolvedAt?, reopenedBy?, reopenedAt?}` with its messages as the node's child sequence (S5's model). **Orphaned** is derived: open and no live text carries the mark.
- **The writer:** the patch writer, pure code over the schema and a Y.Doc, applying an `artifact_edit` batch. **The sandbox:** the agent's replica, on which a batch is applied in one transaction and from which the update ships only when every op validated.
- **The adapter:** the document `KindAdapter` (A's `src/artifacts/host.ts`): `beforeApply` (forwarding), `afterUpdate` (the id repair, move detection, the anchor refresh, the markless-comment strip, the threads mirror), `revertScope` (text, marks and thread statuses; conversations kept), `afterRestore` (orphans, the mirror).
- **History mode:** the editor bound to a throwaway version doc through `configureYProsemirror({ytype, renderer})`, read-only, undo refused.

### D3. The theme: the design system's ground, `--ds-*` with fallbacks, the author colours

### D5. The sentence rule's threshold (parent Decision Log 36, B's)

The writer segments both texts with `Intl.Segmenter(undefined, {granularity: 'sentence'})` (Node 24 and Chromium), pairs sentences by the word diff's hunks, and when a hunk set touches at least half the words of a sentence (`changed ≥ ceil(words / 2)`, words by the word segmenter) it emits one hunk for the whole sentence instead, re-applying on the retained words the marks they carried (comments included, so S5's "orphaned only when all its words go" still holds) and the formatting the agent's markdown expresses. Below the threshold the word hunks stand. Rejected: a character ratio (a long word changed would count as a sentence rewrite); always sentence-level (per S5, a comment on a fixed word would be re-inserted by every agent edit nearby and its characters re-credited).

### D6. The batch's route to 50 ms (parent Decision Log 37's advisory route, taken) and all-or-none without a clone

The writer keeps an id → `{node, parent, path}` index per document, rebuilt lazily from the applied update's changed top-level blocks (the `afterUpdate` hook's view) rather than walked per op; `replace_text` without `block` searches the index's text cache, never a re-serialisation of every block. **All-or-none is settled before any Yjs write:** the writer first computes, in ProseMirror space, the resulting node of every touched parent (the ops applied as PM transforms over the indexed nodes: the quote's uniqueness, the row structure, the move rule against the human carets, `createChecked` on each resulting touched parent, binding per Decision Log 35) and only when every op validated does it open one Yjs transaction on the agent's replica (A's Decision Log 9: synced from the host at a read) that applies the planned `Y.XmlText` operations; a Yjs transaction cannot roll back and the provider ships every local update, so the pre-validation is the atomicity, and the whole-document clone of S4 is dropped. The backstop for a throw inside the transaction (a bug, never a validation failure) is A's write savepoint: as built in M7 (Decision Log 34) the batch is written through A's `writeAs(artifactId, actor, edit)` on the session's host replica, inside the savepoint that `withOp` records in (A's Decision Log 26c), so a throw inside `edit` rolls the frame back and nothing of it is logged or broadcast; `AgentReplica.edit(fn)` (H1 request i, kept by A) remains available for a batch applied on the port replica and the agent replica still carries presence and the human carets. M2 measures the batch on S7b's seed headless (the bar: p95 under 40 ms in Node on this machine, a pre-gate for M9's 50 ms host-loop max in Electron). A `worker_thread` is not built unless M9 is still over. Rejected: the clone dry run (27 to 36 ms p50 at 200 pages, S7b); validating after mutating (unrevertable).

### D7. The agent's read: ranges and `sinceRevision`

`artifact_read` for a document returns `{revision, kind: 'document', tabs: [{id, title, blocks}], markdown}`: the markdown of one tab (`tab` defaults to the first), ranged by `from` (a block id, inclusive) and `count` (blocks, default 200, max 1,000), every block ending in ` ^id` (lists one marker per item, a table one marker for the table and one per row as `<!-- ^id -->` trailing comments, cells positional), chips as `<chip kind="date" iso="…"/>` and the like, comments as `<c:ID>…</c:ID>` milestones, a footer listing open threads (`id · quote · N messages`) and orphans; `sinceRevision` returns only the blocks whose text or attributes changed since that revision (from the host's provenance maps between the revisions, through the attribution's item ids resolved to block ids) plus the ids of deleted blocks, or the whole range when the revision is older than the head's log window (then `complete: true`). Every read captures the session's base (A's Decision Log 9).

### D8. The adapter's bodies on A's hook points

- `beforeApply(live, incoming, {actor, step2})`: S4's `receive` and `forward`, both branches: read the incoming update's content ids; replay onto the live copy each text insertion whose parent is a tombstoned block a recorded carry re-inserted, and, **only for an incremental update (`step2 === false`)**, each deletion that targeted such a block (a sync step 2 carries the sender's whole delete set and must never be replayed, or a reconnect would replay the move's own deletion). The carry registry it reads is per artifact, fed by the writer's `Applied.carries` from the tool handler in the same host process (`adapter.registerCarries(artifactId, carries)`, S4's `registerCarry`), and pruned when the carried blocks are garbage-collected.
- `afterUpdate(live, {update, actor})`: S4's `repair` and move detection (a delete and an insert of one id in the update is a move; duplicates keep the later insertion after `carryCopyEdits`, others re-id, never delete); S5's `refreshAnchors` for threads whose extent drifted (one walk); strip a `comment` mark whose thread is absent; return the thread mirror rows (D8a) and the provenance carries (D8b); refresh the id index.
- `revertScope(live, old)`: the body fragments, the tabs map, and of each thread that exists in both states its `status`, `resolvedBy/At`, `reopenedBy/At` and anchor attributes; **never** a thread's existence or its messages: a thread created after the version stays with its messages (its passage gone, it shows as orphaned) and a reply posted after the version stays on its thread (S5's `restoreKeepingConversation` recreates what a plain revert would remove; the owner's Decision Log 32). M2 proves both cases against the model, M9 against A's real restore.
- `afterRestore(live, {versionId})`: recompute derived orphans, rewrite the mirror, run the id repair once.
- **The hooks' arguments as A built them (A's M2, edc6c5d2, the ledger's X24 row):** `beforeApply` receives the live document read-only; `afterUpdate` and the forwarding callback receive a per-actor host replica identical in content to the live document, so the adapter writes repairs and forwarded edits into that replica, never into `live`; the host-originated write is `writeAs(artifactId, actor, edit)` and the restored frame is emitted by `announceRestored`; a savepoint that cannot roll back fails the whole batch and drops the open documents, so an adapter hook must not throw after a partial write of its own (validate, then write).
- **D8a, the threads mirror.** `KindAdapter` has no storage handle; the adapter returns the mirror rows from `afterUpdate` through a `threads?: ThreadRow[]` field on its result (a request to A, H1c) and A's store writes `artifact_threads`; until A exposes it the renderer reads threads from the doc directly, so nothing in B's acceptance waits on the mirror.
