## Terms

- **The dialect:** Claude's slide format adopted property for property (U1; parent Decision Log 21) with MAWS's supersets: `var(--ds-*)` (Decision Log 12), the asset form `assets/<name>` for `src`, and `data-ph` kept (X28). **A slide file** is `project/slides/<id>.html`, one `<section id>`; **the index** is `project/deck.json` (v4).
- **The IR:** the plain-data slide between files and the model (`SlideIR`, `ElementIR`, `TextBlock`; S6's `ir.ts`). **Canonical:** the serializer's one form; **fixed point:** `serialize(parse(x)) === serialize(parse(serialize(parse(x))))` after one pass.
- **Held:** a slide whose file fails structurally; the model keeps its last good content and the slide's `held {source, reasons}`; a read returns the held source; the editor shows it read-only with its reasons; never trimmed.
- **The model:** the deck Y.Doc's roots `deck` and `slides` (D2). **Flow child / pinned child:** an element in layout flow, or with `position:absolute` (and a positioned `x-connector`); **the flow layer:** all flow content of a container paints as one layer at `FLOW_LAYER = 'a0'` among its pinned children's `z` keys.
- **The adapter:** the presentation `KindAdapter` (A's `src/artifacts/host.ts`): `initial`, `readFiles`, `publish`, `afterUpdate`, `revertScope`, `afterRestore`, `summarizeTurn`.
- **The three-way publish:** the agent's sent files compared with its base (the files it last read) and the live model, property by property (D3).
- **The stage:** the editor's scaled 1920×1080 slide; **the overlay:** the transform layer's handles and guides drawn outside the scaled slide in screen pixels.

### D2. The model (S6's v14 seam, A7)

One Y.Doc per deck, roots of v14 `Y.Node`s:

- `deck`: attributes are `deck.json`'s keys but `order` (`v`, `createdOnFiles`, `lists`, `title`, `cover`, `designSystems` as one JSON value, unknown keys as JSON); `sections`, `faces` and `dsOverrides` are nested nodes (key → JSON) so concurrent edits of different entries merge.
- `slides`: attribute `slideId → <slide>` with `order` (fractional), `style:<prop>`, `attr:<name>` (`data-transition`, `hidden`, `data-section`), `held? {source, reasons}`, `notes` (a `<notes>` node of plain text), `elements` (attribute `elementId → <el>`).
- `<el>`: `tag`, `parent` (`''` for the section, else a container's id), `order` (flow) or `z` (pinned, against `FLOW_LAYER`), `style:<prop>`, `attr:<name>`, `raw?` (svg and x-embed inner markup, opaque), `text?` (a `<doc>` node of `p` or `li` blocks of text with marks as formats `{b}`, `{i}`, `{u}`, `{a:{href}}`, `{span:{color}}`, and `br` nodes inline: `@y/prosemirror` 2's shape). Table rows (`tr`) and cells (`th`, `td`) are elements; rows carry ids the files show; cells carry ids the model mints and the files omit (positional, S6 question 1). Element ids are unique per slide (map keys); equal ids on two slides are intended (magic move).
- `threads`: D9.

Read rules (S6, A2): a parent that is missing or not a container reads as the section; a cycle sends its smallest id to the section; equal sibling keys order by id. Only the host writes the repairs (`repair()` in `afterUpdate`, D5).

### D3. The publish: three-way at property level (X25's deck part; parent Decision Log 26)

A's `publishDoc` calls the kind's `publish(live, base, sent, force)` inside the session's host-replica write, with `base` the files of the state the session last read and `sent` its files map (`null` removes). The deck's `publish`:

1. **Plans before it writes.** Paths: `project/deck.json` and `project/slides/<id>.html` only; any other path, a removed `deck.json`, a slide file whose section id differs from its name, more than 500 slides or 512 files is refused as `FilesError` naming every offending path (nothing written; A answers `invalid {problems}`). Each sent slide is loaded (warnings, notes, held). The base files are loaded with the same loader (a base slide that was held reads as its last good model through the live doc's history; a held base source loads as held).
2. **Compares per key.** For each slide key, element key (`style:*`, `attr:*`, `raw`, `tag`, `parent`, placement), text, notes and deck key or entry: the agent's change is `sent ≠ base`; it is left alone when `sent = base` (not the agent's change, even under force) or `sent = live`; it applies when `live = base`; otherwise it **conflicts**. Text and notes merge at character level when the agent's changed ranges and the live changes since base do not overlap (both diffed from base with `fast-diff` over the exploded block string, S6's `explode`), and conflict as `text` when they do. Placement (flow order and pinned `z` among siblings) is the agent's change only when its sibling sequence differs from base; slide order likewise; a conflict there names `order`.
3. **Names conflicts** as A's `{path, detail}`: `element title: font-family changed since your read`, `element card2: removed since your read`, `slide: removed since your read`, `slide: created since your read` (a new slide id that the live deck already holds), `text of title: changed since your read`, `order: changed since your read`, `deck.json key cover: changed since your read`. Any conflict refuses the whole publish (A's layer 3) unless `force`, which applies the agent's value for exactly the conflicting keys.
4. **Writes once.** One transaction: slides created, removed, held (`held` set, the last good model kept) or cleared, keys set and deleted, text and notes patched (S6's `patchText`, `patchNotes`), placement re-keyed by the longest kept run (S6's `rekey`). A no-op republish writes nothing.
5. **Answers** `{changed, conflicts}` plus `warnings` and `held` (A's outcome and result amended in place, H2-3): `warnings: {path, slide, element?, property?, message}[]` (warnings only; notes counted, `notes: N`), `held: {path, reasons}[]`.

`deck.json`'s `order` lists slides; a slide the list omits shows last (Claude); a new slide file not in a sent order is appended after the last slide. Removing a slide the live deck changed since base conflicts (`slide: changed since your read`).

**Why property level and not Claude's file level:** parent Decision Log 26 widened the merge ("no property changed on both sides") after S6 showed a file-level diff against live writing the agent's stale values over the owner's; §2 item 5's refusal "with the slide's name" is the case where the owner and the agent changed the same property (`[parent-impact]` H2-1 states the reading).

### D4. Element identity without ids in the sent file

Files the agent reads carry every id. An element the agent writes without one takes, in order: the id of the base element at the same place (same parent, same index among its siblings, same tag) when that id appears nowhere else in the sent slide (the agent kept the slot but dropped or never knew the id: a slot it re-wrote stays the same element, so its comments and history follow); else a minted `e<n>-<hash4(slideId, parent path, index, tag)>` skipping every id in the base and sent slides. Minting reads only `base` and `sent`, so A's two calls of `publish` (the live write and the session's new base) mint the same ids, and a replay is A's ledger's. The guide tells the agent to keep ids from its read; a slide whose ids the agent dropped wholesale is a warning ("N elements had no id: re-read to keep their identity").

### D8. The editor (DOM over the dialect, parent Decision Log 15)

- **Canvas.** `SlideCanvas` renders a slide from the model into a `div.maws-slide` (1920×1080, `isolation: isolate`, Claude's semantics in `CANVAS_CSS`: a div or section without `display` is a column, `margin: 0`, under-layer pinned children at `z-index: -1`) and patches the DOM from the seam's change records (one style write per changed key, keyed placement, one text box re-rendered), never importing Yjs. - **Stage and overlay.** The stage scales the canvas by CSS transform; the overlay (handles, marquee, guides, selection outlines, comment pins, other actors' selections) is a sibling in screen pixels, so handles keep their size at any zoom. Every gesture is one transaction with the editor's origin; a drag writes on pointer frames (S6's 6 writes per 3-move drag) and is one undo step.
- **Transform layer** (about PPTist's 1,500 lines, written for this model; react-moveable's MIT math may be borrowed, parent Decision Log 15): selection (click, shift-click, marquee, Escape, Tab through elements); move (pinned: left/top in px, a right/bottom pin converted to left/top on first drag with its value preserved; flow: drag reorders among siblings with an insertion bar; "Detach" converts a flow child to pinned at its rendered box); resize (eight handles, Shift keeps the aspect, Alt from the centre; a text box's width only for flow children); rotate (a handle, Shift by 15°, written as `transform: rotate(Ndeg)` composed with the element's other transforms); snapping within 6 screen px to the slide's edges and centre, the 128 px margins, siblings' edges and centres and equal gaps, guides drawn while snapped, ⌘ suppresses; arrow keys nudge 1 px, Shift 10 px; z-order on pinned elements (front, back, forward, backward through `z` keys, the flow layer fixed); group (`div data-group` with `position: relative`, its members re-parented with offsets kept) and ungroup; delete, duplicate (⌘D), copy and paste within and across decks (the clipboard carries dialect HTML; a paste goes through the loader, ids re-minted on collision).
- **Inspector.** For the selection: fill (colour, gradient stops), border (width, style, colour), radius, shadow, opacity, rotation, position and size in px; text: family (the deck's faces, the system's roles, the basic faces), size, weight, colour, alignment, line height, letter spacing, `data-fit`; image: object-fit, crop (`data-crop`), replace (upload); shape kind; icon name; connector heads and route; table rows and columns add and remove. - **Text in place.** A double-click (or Enter on a selected text element) mounts a Tiptap editor bound by `@y/prosemirror` 2 to the element's `text` node with the slide-text schema (paragraph or list item, text, hard break; marks b, i, u, link https, colour span; no wider than Claude's inline set, S6's `binding-v14`); the binding drives A's provider `holdRemote` from composition start until `view.composing` is false (parent Decision Log 33 to 35); Escape or a click outside ends it.

- **Shell.** Registered with L's registry (`registerArtifactEditor('presentation', …)`): `createState` opens the deck through `ArtifactHost.open` and keeps the handle, the selection and the undo stack per tab (X32's lifetime rule); `dispose` closes once every edit is acknowledged; the X32 header carries the title, the saved state from `DocumentHandle.state()`, the unresolved count, the actions (Present, Comments, History, Theme, Check against the design system, Insert) and the exports (D12); `closeGuard` waits up to 3 s for unacknowledged edits, then asks (B's rule); `onShown` once the first slide is drawn; Mark-up registers the stage through G's `useRegionMarkupSurface`. The deck draws its system's ground under the app's theme: the stage's surround is app chrome, the slide paints its own background.
