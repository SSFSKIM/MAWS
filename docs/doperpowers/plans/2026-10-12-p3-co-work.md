## 1. Purpose

**Higher purpose.** MAWS is a general workstation for supervising Claude Code agents, built to the baseline of the reference apps and then past it (charter §1, D-5, D-20). P0 reached the baseline, P1 moved the agent workflow out of the terminal, P2 made the daily surfaces at least as good as Claude Desktop's. What the owner still does elsewhere is the making of things with the agent that are not code: documents, slide decks, designs. Claude's Artifacts suite (Docs, Slides, Design, Design System, Dashboard) is where that happens today, in claude.ai's services.

**What this phase is for.** A self-hosted Google Docs and Google Slides for MAWS (the owner's words, Decision Log 2): the co-work layer the charter deferred since 2026-10-05, local-first, with the agent editing through MCP tools the way Claude's own tools edit Claude Docs and Claude Slides, the person editing in-app the way they edit in Google Docs, every change attributed to who made it and when, and a version history as good as Google's. It is built for the owner's daily work now and, later, as the base of a product for teachers (P4: sharing, simultaneous editing, a web-hosted MAWS), so its store and editors are designed to grow there without a rewrite.

**The measure (Decision Log 1).** Parity with Claude Desktop's Artifacts suite: on documents, decks, designs, design systems and dashboards, with their library, comments, versions and exports, MAWS does what Claude's artifacts do, and where the two differ MAWS is the one with a real history (diff, attribution, restore) and a real organiser. The owner's artifact work ends in MAWS.

**What it must not be.** Not claude.ai's services (P1 P-4 stands: nothing is stored in or fetched from Claude Docs; the formats are ours, shaped like Claude's so skills transfer where U1 confirms the shape). Not a plugin platform: the editors are the app's own code, not sandboxed type pages (Decision Log 16); only untrusted content (free HTML, embeds, artboards' support files) runs in frames. Not multi-user: sharing, simultaneous editing and a cloud MAWS are P4 (Decision Log 4), but nothing built here may foreclose them (§4.10). Not a redesign of the shell beyond the three shell items the owner asked for (§4.9). Not the browser's chrome (the cua session's).

With every window closed and the host detached, an agent's edits still persist, and the library is right again when a window opens.
2. **A document.** From a session, the agent creates a document and the owner opens it in the panel (or a main tab). It is a Google-Docs-like editor: click anywhere and type; headings, lists, task lists, tables with row and cell editing, code with highlighting, images, dividers, math, diagrams, date and mention chips; tabs within the document; find; the design system's look applied. The same on a slide: a comment pinned to an element follows it when it moves and shows as orphaned when it is deleted.
4. **History.** The artifact's version history lists automatic versions (at human idle, during activity, at the end of each agent turn that touched it) and named ones ("Save version" with a name and a what-changed note), grouped by day with runs folded, each row with its author chips; a version previews read-only with Show changes on: insertions in the author's colour, deletions struck through, "N changes" with ↑ ↓; it renders with the design system and assets of its time; Restore brings back the whole artifact's content (its tabs, comment marks and thread statuses and properties, or its slides and deck properties) as a new version and never destroys, and keeps every conversation posted since the version: replies stay, a thread whose passage is gone shows as orphaned (the owner's ruling, Decision Log 32); Compare takes any two; a "See N new changes" pill appears when an agent changed the artifact since the owner last looked and opens that comparison. Right-clicking a selection says who edited it and when, including edits older than the last compaction.
5. **A deck.** The agent builds a deck from a brief: deck.json and one slide file per slide in the dialect (§4.5). ## 4. Design

Everything below is advisory inheritance unless marked **[binding]** with its joint-view reason. Children expand their own sections in place; a child that overturns advisory content records a dated line in §12 under its id.

**4.1 The artifact entity and the library** **[binding — every child reads and writes it, and it replaces X12's per-session records].** An artifact is a top-level entity independent of sessions (Decision Log 5): `{id, kind, title, spaceId?, projectId?, createdBy: Actor, createdAt, updatedAt, lastViewedAt, pinned, designSystemId?, linkedPath?}` with kinds `document | presentation | design | design_system | dashboard | html | file`. **The engine host owns the durable store** (Decision Log 20a): one SQLite database of its own, `<userData>/artifacts/store.sqlite` (WAL; tables `artifacts`, `spaces`, `artifact_sessions`, `artifact_updates`, `artifact_versions`, `provenance`, `actors`, `artifact_threads`, `artifact_assets`; its own schema version, a slot per X15), opened by the host alone, with bytes under `<userData>/artifacts/<id>/` (assets, version states, the file of a File artifact in place as today). Main holds only derived library state in its index (the list rows and the FTS text index), rebuilt from the host's `artifact.changed` events and reconciled by one host read at every connection, so the library is right after a detached edit, a host restart or an upgrade; main never opens the host's database. Sessions are linked, not owners: `artifact_sessions {artifactId, appSessionId, role: created | edited | viewed | commented, lastAt}`; a side thread's scope rule (X9's ancestor resolution) becomes "the artifacts its ancestors are linked to". A Space is a named folder, at most one per artifact, optionally linked to a project directory, in which case the Space's linked artifacts mirror to `<dir>/artifacts/` on every save as read-only exports (`.md` for a document, a deck folder for a presentation; Decision Log 8); `projectId` is a fact from the creating session, filterable, never a Space. Today's deliverables import at the cutover as `file` and `html` artifacts with their session links; the `deliverables.*` IPC and the panel tool are replaced by `artifacts.*` and an Artifacts tool (Decision Log 9: the word is Artifacts everywhere); `send_file` stays and creates a File artifact. The library is a main tab beside Overview (§2 item 1), and the panel's Artifacts tool is the session's own list with "All artifacts" one click away; an editor opens in the panel by default and in a main tab on demand (P1 A-2 carried), both replicas of one document (§4.2). Search is a local FTS index over titles and extracted text, maintained on save.

**4.2 The document store** **[binding on the model — the editors, the agent tools, history, attribution and P4's collaboration all stand on it; advisory on table layout].** Every artifact of kind document, presentation, design, design_system or dashboard is one Yjs `Y.Doc` (Decision Log 2, 11). The authoritative copy lives in the engine host's document service (`src/engine-host/documents/`), which already hosts the MCP tool server and outlives windows in detached mode (E10); the renderer's editors are replicas synced over one `MessageChannelMain` port per open document carrying y-protocols sync and awareness frames (the thin provider of `research/p3-yjs-store.md` §2; two windows or a panel and a main tab are two replicas of one host doc); each writing agent session edits through its own replica synced in-process by the same protocol, never straight into the host doc, so authorship is known per update. Persistence is the `artifact_updates` log (one row per update: `seq, actor, at, bytes`, appended under WAL with `synchronous=FULL` before the update is acknowledged or broadcast) compacted into `artifact_versions` states (full V2 states, gc on); **compaction keeps provenance** (Decision Log 20c): a `provenance` table of `(clientID, clock range) → (actor, at)` rows and the per-update delete sets, written as each update lands and never merged away, so "who edited this selection and when" and the author colours of a diff survive compaction and thinning (older rows bucket to the minute after 30 days). Versions are rows of `artifact_versions {seq, at, actor, kind: auto | turn | named | restore | import, label?, note?, summary?, enc: full | delta, bytes (zstd), designSystemRef: {id, versionSeq}?, assetRefs[]}`, each stored as a zstd V2 delta from the previous retained version with a full-state keyframe when the deltas would exceed the state, and one `artifact_head` checkpoint per artifact so a load is head plus tail (S7a, Decision Log 36: full states cost 178 MB and 4.4 GB of writes for one normal 200-page document over six months, the policy 9.2 MB); an update row is dropped once the head covers it and it is older than 7 days; only `auto` rows thin (all kept for 24 h, hourly to 7 days, daily to 30 days, weekly after), `turn`, `named`, `restore`, `import` and pinned versions kept; provenance rows merge losslessly into hour rows after 1 h and day rows after 30 days (`tier`); nightly maintenance on a database created with `auto_vacuum=INCREMENTAL`; the owner can delete versions older than a date; an `auto` version is also written when the owner views an artifact whose live revision moved since its last version, so "see N new changes" has a state to diff from after compaction (Decision Log 29); a retained version pins the design-system revision and the assets it referenced, and assets and design-system states are kept while any retained version references them (Decision Log 20g). History renders with v14's `DiffRenderer(prevDoc, nextDoc, {attributions})` over two throwaway gc-off docs loaded from version states; the editor enters through `configureYProsemirror({ytype: the version's fragment, renderer})` and leaves with `{ytype: live, renderer: null}`, the live doc never written; undo and redo refuse while the binding is not on the live doc, and a transaction filter refuses local changes in history (Decision Log 29, S3). **Restore is artifact-wide** (Decision Log 20b): one kind-agnostic host operation that reverts the changes since the version (S7a's `revertUpdateFixed` on a scratch gc-off doc holding the version and the live state, pushing the stack item directly, since v14's `Y.undoContentIds` drops a map attribute overwritten twice since the version and returns an undecodable 13 zero bytes when nothing changed; the overwrite-twice reproductions are regression tests; Decision Log 36), shipped as one update credited to the restorer, an `auto` version before and a `restore` version after, `restored` signalled to the replicas, every bound editor clearing its UndoManager on landing; per-kind adapters handle only the after-effects (the threads mirror, orphans, the id repair); a concurrent edit in content the restore keeps survives, and an agent batch whose targets a restore removed is rejected naming the blocks "removed by restore"; y-prosemirror's `restore` meta is not used (Decision Log 29 replaced Decision Log 20b's per-kind diff-apply: a name-paired structural diff grafts a concurrent edit into a replaced block). **The live revision** is the host's update sequence per artifact, returned by every read and every write; checkpoints are rows in the log, not the only reference points. The four `y-attributed-*` marks (insert, delete, format, attrs) on every node type and the `--attributed` variants of the strict containers (blockquote, listItem, taskItem, callout) are in every schema from day one, and schema parity between every writer and editor is an invariant checked in CI (one schema module, importable in Node, no React node views). Undo is Yjs's `UndoManager` scoped to the local binding and blocked while history is shown. The port provider holds inbound sync frames while the editor is composing (`holdRemote`, set by the binding on composition start and cleared when `view.composing` is false, a 5 s cap on the provider), awareness and ack frames passing, the buffered updates flushed as one merged update when the hold clears (Decision Log 33, 35; S4 and S7b). **Yjs v14 (Decision Log 25, S1's verdict 2026-10-12): `@y/y` 14.0.0-rc.28 and `@y/prosemirror` 2.0.0-15 pinned exactly, one `@y/y` forced by a pnpm override, the binding code in one module, S1's suite the gate for any re-pin, every document tagged with its binding version; provenance is v14's native attribution maps, persisted as one encoded `ContentMap` per update with times floored to the minute at write and merged by the host only when bucketing (Decision Log 29) (the custom clock-range rows of Decision Log 20c are superseded); suggestion mode is the agent's opt-in (`mode: 'suggest'` on a write, or an artifact set to "agent edits as suggestions"), direct edits the default (the owner's ruling, Decision Log 27); the verdict flips back to v13 only if S3, S4 or S7 finds a v14-only failure.** The detached host's transport gains a binary, length-prefixed channel for document frames (an X13 amendment through the ledger); until it lands, detached mode serves documents through the live host only, labelled. Awareness carries the human's and each agent's cursor and the blocks an agent is editing (§2 item 2).

**4.3 The agent's formats and tools** **[binding — one protocol shaped like Claude's so skills transfer, and one namespace the ledger owns].** The `maws` server gains one artifact namespace (names fixed in the P3 ledger before any sibling codes against them; the shapes here): `artifact_list` (the library, filters, a Space), `artifact_describe_type` (the kind's guide and format reference, printed on create as Claude Code prints a type's `format.md`), `artifact_create` (a kind, a title, initial content in that kind's format; the existing free-HTML create keeps its name and becomes kind `html`), `artifact_read` (a document as markdown with block ids, ranged; a deck as its files; versions by number; always returning the live revision), `artifact_edit` (documents: one atomic batch of block operations, §4.4), `artifact_publish` (file kinds: a files map with `null` removals, `baseRevision`, the three concurrency layers of Claude's protocol: the "you haven't read the latest revision" guard, a merge when no sent file changed, a refusal naming the changed files; `force` as the last resort; the whole map lands as one transaction or not at all), `artifact_upload_asset` and `artifact_list_assets`, `artifact_comments`, `artifact_reply`, `artifact_resolve`, `artifact_screenshot` (kept), `artifact_export`. **Every write is idempotent** (Decision Log 20d): the call's tool-use id is the operation's identity; the host records each applied batch or publish with its result and replays the result for a repeated id, so a crash between commit and reply never duplicates content. Each kind's guide (`SKILL.md`-shaped) and format reference are MAWS files under `src/artifacts/types/<kind>/`, versioned, returned by `artifact_describe_type` and attached to the creating turn, so the agent learns the dialect the way it learns Claude's. The default design system's guide is attached on create without asking (Claude's rule). **4.4 Documents** **[binding on the schema invariant, ids, comment marks and the edit tool's semantics; advisory on the block list].** A document is a Y.Doc with a `tabs` map (ordered; Claude's project → tab → node, Google Docs' tabs) and one `Y.XmlFragment` per tab bound through Tiptap 3's Collaboration; its schema (one module) has paragraph, heading 1 to 3, bullet, ordered and task lists, quote, code (shiki), table (row and cell ids), image (an asset), divider, callout, math (KaTeX, as the transcript renders it), diagram (mermaid), chart (a Dashboard block, bound to data), and inline marks bold, italic, underline, strike, code, link, highlight, `comment {threadId}` (overlapping allowed, non-inclusive; BlockNote's shape; the mark's attributes are its storage key on both Yjs versions, so the mark is frozen at one attribute and orphaned is derived: open, and no live text carries the mark; Decision Log 31) and the four `y-attributed-*` marks; chips are inline nodes: date, mention (a person, a session, an artifact), dropdown (a status). Every block carries a short id (`^` syntax in the agent's markdown, an 8-character nanoid in the doc; UniqueID keeps them through split and paste, the host repairs missing and duplicate ids after each applied update, and every writer ids what it writes). The agent reads GFM with `^id` markers and `<chip …/>` markers, ranged ("from `^h7`, 40 blocks"); a read may ask `sinceRevision` for only what changed (Claude Docs' `sinceRev`); it writes `artifact_edit(artifact, baseRevision, ops[])` with `replace_text {block?, old, new, all?}` (exact and unique, else an error listing candidate blocks; validated by its quote, not by its block's revision, so the human typing elsewhere in the paragraph does not reject an intact quote; Decision Log 34), `replace_block {id, markdown}`, `insert {after | before, markdown}`, `delete {id}`, `move {id, after}`, `set_cell {table, row, col, markdown}` (checking the table's row structure too), and two shapes borrowed from Claude Docs (Decision Log 21): a `pending {intent}` block the agent inserts as a placeholder and fills section by section (drawn as a labelled placeholder until filled), and `answering: <threadId>` on a batch, which posts the edit as the thread's answer. **The batch is atomic** (Decision Log 20d): the host validates every op's target against `baseRevision` first (only the targets, so the human's typing elsewhere never conflicts) and applies all or none; a rejection names the conflicting blocks with their current text; the response carries the new revision, one line per op and new ids. **The patch writer** (Decision Log 20e) applies every op on the agent's replica and never through `updateYFragment`: same-type text changes as a multi-hunk word diff of `Y.XmlText` operations with explicit attributes; a block whose type changes keeps its id and its marks, which are re-mapped onto the new text by the diff (a comment whose text is gone becomes an orphan with its stored quote); `move` re-inserts the block's node with its id and marks and records a move in provenance (authorship of the text unchanged), never re-inserting a block that holds a live human caret: the writer re-inserts the span the block jumps over instead, or rejects with "retry" when carets sit on both sides (re-inserting the composing block sent the following keystrokes into the neighbouring block, and ProseMirror rebuilds a composing block when its siblings move); the caret follows the id across a re-insert; the host reads incoming bytes before applying them and replays an edit that landed in a tombstoned, re-inserted block onto the live copy (otherwise it is garbage-collected on arrival); the host's id repair resolves a duplicate created by a concurrent move by keeping the later insertion after carrying the loser's edits into it and tombstoning the other, re-ids any other duplicate and never deletes, and detects a move per update (a delete and an insert of the same id) so the rule also covers a human drag racing a move; a batch dry-runs on a fresh-clientID clone, then applies as one transaction; validation against the renderer's exact schema with `createChecked` at every level (`check()` accepted a list item replaced by a heading); provenance applies the writer's carries, so a move or type change credits no characters to the agent, and history marks retyped and moved blocks (S4, Decision Log 34). Comments are the mark plus a `threads` map in the Y.Doc (threads sync, version and restore with the text) mirrored to `artifact_threads` for the library and the side-thread link; a thread is a nested node `{tabId, quote, anchor, status, messages}` with its messages as a sequence (one JSON value lost a resolve racing a reply), storing its quote and a relative-position pair for orphan display that the host refreshes from the live mark at its per-update hook when it drifted (it collapsed in 10 of 30 edits); resolve and reopen write only the threads map, and comment create, resolve and reply sit outside undo; a paste deduplicates a comment that already exists and a drag-move counts the source as gone (Decision Log 31); P2's card (X21) is the UI, with `CardTarget {kind: 'artifact', artifactId, threadId}` beside the existing two and the Side thread or Send to main routes unchanged; Resolve and reopen are new. The design system applies as a theme: the editor's CSS reads `--ds-*` tokens (§4.6) and the built-in default system is MAWS's own look (Decision Log 7). Import: Markdown and HTML into a document (B owns the schema, so B owns the importers); DOCX through a tolerant reader. Export: PDF (the print path), DOCX (an in-house serializer over `docx` mapping the design system to the Word theme and named styles, comments as Word comments, optionally the changes since a version as tracked changes), Markdown (GFM, ids stripped), HTML (standalone, tokens inlined).

**4.6 Design systems** **[binding on the object's shape, the token format and the CSS names — documents, decks, designs, the exporters and the agent all read them; the owner's choice of definition, Decision Log 22].** A design system is the designer skill's object, not Claude's: *a project's committed visual law that new work must obey* (`~/Developer/GitHub/designer/skills/designer/SKILL.md` 2.3.1, `references/guidelines-authoring.md`), the triad of a stance, a token file and `DESIGN.md`, with a precedence chain (the brief per surface > a supplied reference, local > the design system, global > sampled ingredients > defaults) and a QA protocol that checks built work against its own law. ## 8. Risks and mitigations

- **The scale.** P3 is the largest phase: four editors, a store, a protocol, exporters. Mitigation: the spikes first and the S1 and S7 gates; the frontier rule (E is cut at its dispatch; B and C are reassessed at theirs; D's and H's scope is bounded); children land independently so the owner uses documents before decks exist.
- **Two processes, one truth.** The host owns the store and main owns the library's view. Mitigation: main never opens the host database; derived rows rebuild from events and one read at reconnect; A's acceptance includes main absent, reconnection and an upgrade.
- **The frozen snapshot path.** y-prosemirror 1.x's history has five "not planned" bugs (attribute changes invisible, code blocks). Mitigation: S3 measures them on the real schema; the history renderer is one module so v14's `DiffRenderer` can replace it; S1 may choose v14 outright.
- **Schema drift deletes content.** A binding that cannot build a node deletes it in the live doc. Mitigation: one schema module, the CI parity check, writers validate before applying, the host repairs ids after each update.
- **Human and agent in one block.** Mitigation: the patch writer's word-level hunks, the batch's target-only validation and all-or-none rule, idempotent writes, S4 with Korean IME composition under remote updates (the terminal's C1 lesson), structural edits with comments and concurrent moves as S4 and S5 gates, awareness showing the agent's blocks. Binding for P3-B after S4 (Decision Log 34): the composition hold on the port provider driven by the binding, and the caret following the block id across a re-insert; without them Korean composition fails 36 of 54 cases and 3 of 6 re-insert moves.
- **History that lies.** A restore that brings back prose but not threads, a diff coloured by a forgotten author, an old version drawn in today's colours. Mitigation: artifact-wide restore per kind (S3), provenance kept through compaction, the design-system and asset pins on retained versions.
- **PPTX fidelity.** PowerPoint wraps differently and never recomputes autofit. Mitigation: embedded fonts, explicit sizes, width slack, an optional "lock lines" mode, render-and-compare in CI, "Slides as pictures" as the fallback export.
- **The dialect drifts from Claude's.** Claude's list may change weekly. Mitigation: the list is adopted property for property with U1's record as the corpus; the loader's warnings name every dropped thing; held slides lose nothing; the format reference is attached on create; a token-using deck resolves to literals for Claude.
- **The connector bridge may have no route.** Mitigation: H is a spike first; E's dashboards bind to files regardless.
- **The detached host.** Documents need a binary channel the JSON-lines socket lacks. Mitigation: S2 builds it; until then detached mode serves documents through the live host only, labelled.
- **Scale on the owner's machine.** A 200-page document with two windows and agent replicas may make typing or engine supervision unusable while being correct. Mitigation: S7 with bounds, blocking B and C. S7b (Decision Log 37): held at 200 pages with two windows and two agents once the hold, its merged flush, touched-parent validation, the awareness fix and the idle unload apply; the residual is the patch writer's host-loop max, P3-B's 50 ms-per-batch check.
- **Storage growth.** Mitigation: gc on, version thinning with provenance kept, S7's soak with a published policy.
- **Portability drift.** An editor that imports Electron once is never web-hosted. Mitigation: `src/artifacts/` with a lint rule against Electron, Node and `window.maws` imports; connector calls through the adapter.
- **The owner's time.** Three sittings' worth of surfaces. Mitigation: F's sitting sheet is written as children land; documents can be sat on before decks exist.
