## Purpose

After this child the owner's artifacts have a home. A main tab beside Overview, **Artifacts**, lists every artifact the owner and the sessions made: All, Pinned and By Space; a type filter with counts; date groups (Today, Yesterday, the days of the last week, months, Older); search over titles and text; "Make something new" cards per kind; each row with its title, kind, Space, project, last editor and time and the sessions that touched it; Pin, Rename, Move to Space, Duplicate, Export and Delete. A Space is a named folder, optionally linked to a project directory, whose artifacts are mirrored read-only into `<dir>/artifacts/` on every save so an agent's grep finds them. The panel's Deliverables tool becomes the **Artifacts** tool (the session's list, all artifacts one click away, File and HTML artifacts viewed on the new store with P2's comment card unchanged), and every artifact opens in its kind's editor in the panel or in a main tab through one registry B, C, D and E fill. The deliverables the owner's sessions made before P3 are imported as File and HTML artifacts with their sessions, and `deliverables.*` is gone.

The library is right after a detached edit, a host restart and an upgrade, because main's index is only a derived view: rebuilt from the host's change events, reconciled by one read at every host connection, and never read from the host's database.

To see it once landed: `pnpm -C <worktree> dev` against a scratch user-data directory (never the owner's), open a session, ask the agent to make an HTML page and send a file, and click Artifacts in the sidebar.

What does not change: the engine and its wire (D-1); the host store, the `artifacts.*` handlers, the export service and the editors (A, B, C, D, E); P2's comment card and its anchors' behaviour; X12's persisted ids, which are artifact ids from the cutover on (Decision Log 4 below).

## Surprises & Discoveries

- 2026-10-13 (grounding): there is no FTS5 anywhere in the repository yet; `node:sqlite` in Electron 44.4.5 (SQLite 3.53.4) and in the test Node (3.51.3) both build FTS5 with the `trigram` and `unicode61` tokenizers (checked against in-memory databases by the grounding read).
- 2026-10-13 (grounding): X12 record ids are UUIDs and A's mirror writes new records under the artifact's UUID (A's Decision Log 4), so one id names a delivery in the transcript, a side thread's anchor, a main tab and the store from the cutover on; the import keeps it (Decision Log 4 below).
- 2026-10-13 (grounding): `artifacts.list` returns neither the session links nor who last edited; X23's IPC has no read of the links at all (`ArtifactStore.links` is internal). The library's rows need both, and its search needs text, which no command returns (Decision Log 2).
- 2026-10-13 (grounding): no in-tree producer writes X12's `screenshot` kind and no renderer surface shows a download's `sourceUrl`; both are carried by the import only as far as the entity can hold them (Decision Log 5).
- 2026-10-13 (grounding): B expects its editor's tab-lifetime state to be created by "the tab's `createState`" (B's D13); the registry carries an optional `createState`/`dispose` pair so that holds whichever surface mounts the editor (Decision Log 7).

- 2026-10-13 (M1): the host runtime answers a registered command without a handler `internal: this host has no handler for <name>` and an unregistered one `unknown_command`; main's sync logs either and keeps the index. Adding host commands changes the wire fingerprint (`src/shared/ipc/wire-fingerprint.ts`), so a detached supervisor of an older build reads as incompatible, as for A's additions. `'../index'` from `src/main/library/` resolves to the app entry; the index is `'../index/index'`. FTS5's `snippet()` under trigram counts about one token per character and returns a column's start when the column has no match.

3. **2026-10-13, the text extractor is generic and portable.** `src/artifacts/library/text.ts` (no Node, Electron or `window.maws`; §4.10): a Y.Doc's text is every `Y.Text` and `Y.XmlText` reached by walking its root types, maps and arrays depth-first (a document's paragraphs, a deck's text boxes and notes, a design system's law), whitespace-joined in document order; an `html` artifact's text is its markup with `script`, `style` and tags removed and entities decoded; a `file` artifact's text is its content when it is UTF-8 text of at most 1 MiB, else its name. Every text is capped at 256 KiB. No kind registers an extractor: the walk needs no schema, so B, C, D and E owe nothing. The host extracts on `library.text`; main fetches it when a row's revision moved past the indexed text's.

20. **2026-10-13, M2's decisions (4d3b10fc, 6d41ccf1; its report).** (a) The text walk on v14: a node's text runs, its child nodes and its node-valued attributes are text, plain attribute values and embeds are not; roots and attributes are read sorted by name so one state gives one text; a node is told apart by its methods (`toArray`, `attrEntries`), since `@y/y` is importable only in A's binding module.
