## Purpose

The owner and an agent can work on a document containing real charts and tables without executing the agent's code. The agent creates a Dashboard from markdown, writes a CSV, binds it once with `artifact_dataset`, and reads back its columns and row count. The owner inspects the source, comments on a chart and edits nearby prose; replacing the data changes every bound view but not those edits. History, restore, duplication, restart and four exports keep the exact snapshot and provenance each view showed.

## Execution constraints

- One Y.Doc, B's roots plus `datasets`. Bytes are immutable artifact assets. No watchers, page runtime, renderer byte fetch, CSP widening, live connector calls or second durable dataset authority. The host parses; readers share its immutable-ref result. E3 owns the query lifecycle; its reserved descriptor shape is kept.

## Interfaces and dependencies

Existing shared names are the ledger's E rows. `src/artifacts/dashboard/datasets.ts` owns `DATASETS_ROOT = 'datasets'`, `DATASET_LIMITS`, `readDataset(doc,id)`, `setDataset`, `removeDataset` and XE5's descriptor. `parseDataset(bytes,format)` in `parse.ts` is portable and DOM/React-free, called only by the host. `spec.ts` owns the closed view grammar; `states.ts` owns error and status wording. The host route is `artifacts.readDataset {artifactId,ref,format,offset?,limit?}` and `ArtifactHost.readDataset(artifactId,ref,{format,offset?,limit?})`, returning `{columns,rows,total,truncated}`. The required format is `'csv' | 'tsv' | 'json'`, supplied from the captured file descriptor; E3's query snapshots are validated JSON. This additive format parameter is approved and recorded by the architect in parent Decision Log 8 after the adversarial review. SHA-only asset deduplication can give CSV and TSV interpretations the same ref, so neither the first asset's name/MIME nor a lookup of the current descriptor supplies a correct immutable read identity. Reads validate artifact/ref ownership on every call, even cache hits; raw asset refs never imply authority. Dataset read pages are bounded by row count and encoded bytes; the consumer continues at the number of rows actually returned, never assumes `limit` rows. Ref + format identifies cached parsing; cache is bounded, non-authoritative, and reconstructed on restart.

X25's `artifact_dataset` takes `baseRevision`; it never uses the generic file publisher. B's adapter selection becomes kind-aware so provenance carries reach the adapter that actually receives the write. X26's `ViewEnvironment.renderChart` and exporter `renderView` remain additive and absent for documents. The renderer must also know the **displayed document**, not only the live handle: history creates a separate read-only editor and chart descriptors must come from that preview's Doc. The chart node view owns a disposable subscription to that Doc's datasets; descriptor updates need not change the chart atom, so ordinary atom-attribute redraw alone is insufficient. Its lifecycle cancels stale async paints and releases subscriptions on update/destroy.

Checkpoint 1 additions, approved by the architect in the parent's Decision Log 6 and recorded in the ledger before implementation: a disposer return on `renderChart` (currently proposed `void`) and plumbing the displayed Doc through `DocumentEditorProps`/`ViewEnvironment`; bounded-read constants (`DATASET_READ_MAX_ROWS`, `DATASET_READ_MAX_BYTES`); any store transaction primitive proved necessary by M2; a `dashboard` entry in `ARTIFACT_COMMENT_LEADS` and `artifactKind` on the document comment surface; widening `DocumentExporter.kind` to `'document' | 'dashboard'` so D's existing `governDocumentExporter` wraps both. M1 is independent of these requests.

The approved store signature is `ArtifactStore.writeWithAssets(artifactId: string, actor: Actor, assets: {bytes: Uint8Array; name: string; mime: string}[], edit: (doc: Doc, assets: {assetId: string; ref: string}[]) => void, options?: WriteOptions): Promise<number>`. `WriteOptions` is the existing service interface; prepare runs final CAS before registration, edit receives refs, existing adapter hooks run, inFrame writes the op result and session link. `uploadAsset` shares the extracted placement/dedupe internals but keeps its public behavior. The derived mutation index uses existing `storage.getMeta/setMeta`, no schema migration. Read caps are 2,000 rows and 1 MiB encoded JSON per page (candidates until measured); a single row too large explicitly refuses.

**Boundary decisions (checkpoint 1, parent Decision Log 6).** CSV/TSV use strict quoted-field parsing, UTF-8 (optional BOM), header required with unique nonempty names; JSON is an array of flat records with the union of keys in first-seen order and missing cells null. Empty values are null; inference tests all non-null values, not a sample; numeric strings must be finite and strict (identifiers with leading zero remain text), dates use an unambiguous ISO calendar/date-time grammar. Mixed values retain their original scalar value and produce counted warnings rather than silently coercing to zero. `rowKey`, when supplied, names a column of unique non-null scalar values; failure refuses the entire bind. Dates and source times use explicit UTC formatting so machine locale/time zone cannot change output. No data-point comments in this cut (the parent's deferred list); rowKey leaves that future identity decision open.
