## Purpose

A dashboard can keep a granted connector's read-only data current without an agent turn. Its owner grants the tool from the existing source sheet, sees real rows with the tool and fetch time, and can refresh or revoke there or from the header. Hiding the dashboard stops its calls; loss of a live route explains the pause without starting an engine. History retains the data actually shown, while live refresh does not accumulate every obsolete snapshot forever.

### R1 — Retention, X23 amendment [parent-impact]

Recommend **the latest two distinct successful snapshots per query**, plus every ref used by any current dataset, every retained-version pin and every active reader hold. Repeated identical content advances fetch provenance without consuming another distinct slot. Non-query/user-uploaded assets are never candidates. A current descriptor in another dataset protects a shared/deduplicated ref; an upload/bind that adopts a managed asset promotes its live use rather than making it collectible.

Evidence: `store.ts`'s `assetIds` pins every registered row at each version; refusing to remove pinned rows causes every later version to repin them forever. `versions.ts` pin queries concern design-system versions, not assets. Therefore **retirement removes an asset from future version capture without changing any existing version's assetRefs**, accepted by the architect. Proposed **host artifact-store schema 3** (a concrete proposal; A-owned allocation pending):

- `artifact_assets` gains `querySnapshot INTEGER NOT NULL DEFAULT 0` (1 marks a registration E3 created for a query snapshot) and `retiredAt INTEGER` (null means active). Existing rows migrate to `querySnapshot = 0`, `retiredAt = NULL`: every other kind and every ordinary asset keeps the all-registered-assets policy.
- New bounded table `artifact_query_snapshots(artifactId, datasetId, assetId, lastUsedSeq INTEGER NOT NULL, PRIMARY KEY(artifactId, datasetId, assetId))` with a composite foreign key to `artifact_assets` and `ON DELETE CASCADE`. It is E3 management metadata, not dataset data, and holds **at most two membership rows per live query**. Retired snapshots are not listed anywhere: they are identified solely by `querySnapshot = 1 AND retiredAt IS NOT NULL`, so there is no unbounded membership history and no tombstone list.
- A successful descriptor commit, in the same write frame, upserts the membership row for the new ref with `lastUsedSeq` = the refresh revision, then trims that query to its two highest `lastUsedSeq` values. Reuse counts: A -> B -> A -> C leaves A and C (A was reused after B), never B and C; ordering survives shared refs and restart because it is durable, not in memory. The protected set is the union over every query membership and every current descriptor, so a ref shared by two datasets stays active while any other owner still uses it. A ref that falls out of the union is retired (`retiredAt` set) in the same frame; it leaves future version capture but keeps every existing version's asset refs.
- Membership lifecycle. Replacing a query source with another source, or removing the dataset, clears that query's membership rows. Restore resets membership to the single managed ref the restored descriptor holds and reactivates the refs it needs (clearing `retiredAt`) **before** the new version captures assets. Duplicate (live or version) starts membership from its current refs only and its first import version pins only the assets its copied state references. Prefer not copying retired query snapshots that its state cannot name; a retained snapshot actually named by the selected version remains required and is reactivated in the copy. No original version history, holds or grants are copied. This overturns the initial after-import-pin retirement order, per the architect's M1 ruling. Explicit adoption of a managed asset by a file dataset clears `querySnapshot` and `retiredAt` for that asset and removes its query memberships, so it is ordinary and never collectible. A dedupe hit on an ordinary asset never enrolls it in collection.
- `lastUsedSeq` is the committed refresh revision; it orders distinct snapshots including reuse. Repeated identical content advances fetch provenance and refreshes that snapshot's `lastUsedSeq` without consuming another distinct slot.

Exact migration DDL (schema slot 3 allocated by E Decision Log 48):

```sql
ALTER TABLE artifact_assets ADD COLUMN querySnapshot INTEGER NOT NULL DEFAULT 0 CHECK (querySnapshot IN (0, 1));
ALTER TABLE artifact_assets ADD COLUMN retiredAt INTEGER;
CREATE TABLE artifact_query_snapshots (
  artifactId TEXT NOT NULL, datasetId TEXT NOT NULL, assetId TEXT NOT NULL, lastUsedSeq INTEGER NOT NULL,
  PRIMARY KEY (artifactId, datasetId, assetId),
  FOREIGN KEY (artifactId, assetId) REFERENCES artifact_assets(artifactId, assetId) ON DELETE CASCADE
);
```

The max-two membership invariant is enforced inside the same publication write frame, not by a trigger that could delete another query's shared membership.

Proposed operations: `ArtifactStore.removeAsset(artifactId, ref): Promise<{status:'removed'|'retained'|'notFound'}>` retires an E3-managed registration and collects it when unprotected; `retained` means its bytes remain protected, not that future versions repin it. `ArtifactStore.retainQuerySnapshots(artifactId, datasetId, ref, revision): void` is the in-frame operation above, called after successful snapshot replacement; it refuses outside an existing write frame. `ArtifactStore.collectRetiredAssets(artifactId?: string): void` is post-commit-only and runs after nightly thinning, after manual `pruneVersions`, on hold release and at store reopen. Current-content protection is checked synchronously in the retention frame; no physical unlink happens inside that rollbackable savepoint. Collection composes with `removeUnreferenced`'s post-commit pattern: synchronously recheck no live descriptor, retained-version asset-id pin, hold or same-hash asset reference before removing metadata and bytes. Failed cleanup may leave an orphan, never a broken committed ref.

New managed snapshot names contain a freshly generated UUID (`query-<uuid>.json`), so E3 never reuses a retired ref. A reupload deduplicating to an existing retained row keeps that row's original immutable ref; after the row is collected a new refresh receives a new UUID ref. A cached old promise cannot outlive its byte hold.

**Version cadence proof (architect accepted).** `artifact_dataset` calls `writeWithAssets` then `DocumentService.writeAs`, neither of which creates a version. `store.committed` (1391–1408 at the pin) schedules the existing human-idle 2-minute and continuous-activity 10-minute autos; `endTurn` (1037–1038) creates a session turn version, not a per-call version, and 1038's checkpoint arm is byte-kind-only. Page-owned refreshes use human attribution and never invoke `endTurn` or create turn versions. A continuous 30-second page schedule therefore produces at most **144 cadence auto versions per day**, each pinning the active snapshots of its moment, not 2,880 refresh versions (owner save/view/restore actions can add their ordinary versions). Tests exercise many refreshes before and across the 10-minute boundary. Collection follows both nightly thinning (`maintenance.ts:83–87`) and manual prune. F's policy wording is **latest two per query plus whatever your version history still pins**. No write variant is needed.

Restore reactivates refs the restored live descriptor needs before its new version captures assets; version duplicate copies the exact pinned rows, live duplicate copies active/current rows; copies carry managed classification but no reader holds or grants. Ref-based file binding and copy must hold or synchronously revalidate their source across asynchronous reads. No current/historical descriptor may refer to collected bytes. Every successful refresh runs `collectRetiredAssets(artifactId)` immediately after its durable commit, so unpinned retired bytes do not wait for an unrelated hold release or maintenance; nightly thinning/manual prune collect the rest when their pins drop. New tests cover savepoint rollback, restart collection, thinning, dedup/shared use, same-name reupload, restore during refresh and both duplicate forms.

### R1b — Capture-to-hold atomicity [A-owned prerequisite, approved for E3 M1 in Decision Log 48]

The adversarial review verified a capture-to-hold gap: a reader that captures a descriptor and only then asynchronously asks for a hold can lose the bytes in between. Three instances: export state captured before the `SnapshotReader` exists; the source sheet's cloned descriptors before its async holds resolve; and the Download path, which resolves a path and opens a save dialog before it holds anything. N alone does not protect an arbitrarily long open sheet or export, and no timer grace or renderer cache substitutes for a hold. The prerequisite is bounded, A-owned and needs its own architect ledger entry before code.

Proposed host primitive: `ArtifactStore.holdAsset(artifactId, ref): {release(): void}`, plus

`ArtifactStore.captureWithAssets<T>(artifactId, capture: () => {value: T, refs: readonly string[]}): Promise<{value: T, release(): void}>`

which runs `capture` after the `readCommitted` barrier and acquires every hold synchronously in the same turn, with **no await between capture and acquisition**. Admission is per artifact: at most 64 hold groups and 256 distinct refs, each group at most 64 refs; over the cap fails closed with a named error rather than evicting another owner's hold.

- Proposed main-only `artifacts.captureDatasetState {artifactId,versionId?} -> {revision,bytes,assetHoldId}` atomically captures a dashboard's current or retained state with holds for its dataset refs. Existing `artifacts.state` and `artifacts.versionState` remain unchanged: versionState is renderer-callable, so an optional hold flag there would bypass main's window-owned handle map. The calling main-process export owns release in `finally`, on abort and on connection loss. Hold ids are bound to the caller connection: a connection cannot release another owner's hold, and owner destruction releases all its holds.
- The renderer's earlier `holdDataset` is replaced by `ArtifactHost.holdDatasets(artifactId, refs): Promise<{release(): void; readonly invalidated: Promise<void>}>`, backed by proposed main-owned `artifacts.holdDatasets {artifactId,refs} -> {holdId}` and `artifacts.releaseDatasets {holdId} -> {released:boolean}`, atomic all-or-none. Main maps the unforgeable handle to the requesting webContents and its host hold; the shared host client identity alone is never the owner. Another window cannot release it, and destruction/navigation of its owner releases it even if the renderer never calls release. The source sheet validates and acquires holds for **all** its captured refs before it exposes the snapshot, and retains them until close. Opening a source label transfers or duplicates an existing painted-cache hold; the cache keeps the hold through consumption, eviction and dispose.
- The architect approved the hold's `invalidated` promise: it resolves on loss of its backing host hold, fed by existing `artifacts.resync`, no new event/IPC. Compare generation across acquisition (subscribe before awaiting it), so a resync during a pending hold cannot be missed; ordinary release cleans up listeners. Settled reader cache is invalidated; an in-flight read re-holds the same immutable ref once or reports named unavailability. A candidate capture whose hold cannot be acquired is never shown and never silently becomes the latest: it fails with a named snapshot-unavailable error.
- Downloads take their own hold before path resolution and the save dialog and keep it through the copy, whatever the sheet does meanwhile. A preview is held while displayed. An export captures state and hold atomically and never retries against newer state during ordinary refresh. **Host restart is an explicit exception (architect's M1 ruling):** holds are process-lifetime and old ids are invalid; sheets/exports invalidate those ids and degrade to a fresh capture of the latest with a coherent new descriptor/rows pair, never silently mix old labels with new bytes, crash or use a time grace. Bound retries to one recapture and surface unavailability if the host does not stabilize. Tests cover an open sheet and in-flight export across restart. L's lazy mirror holds its captured refs through writing, or re-reads the entire descriptor and retries once on missing bytes.
- Required tests: delayed acquire against collection, multiple datasets in one hold, sheet closed during download, rollback of a partial group, owner destroy, and the hold caps.

### R2 — First snapshot and shared query inputs [parent-impact]

The existing required `QuerySource.snapshot:{ref,at}` cannot represent a configured query before the owner grants it. The architect rules `snapshot: {ref,at} | null` for queries only; null means **never fetched**, zero rows/columns and `updated` absent. A file descriptor keeps its required source/ref and updated fields unchanged. Fetched queries require updated as before. `snapshotOf` returns null for the unfetched arm; every source/read/export/mirror/history consumer handles it without requesting bytes. The view uses the existing no-data presentation labelled `not fetched`, with Refresh and Start when paused; the `artifact_read` footer also says not fetched. No fabricated fetch time or prior file relabelled as new connector data. Once fetched, errors/revoke/pauses retain snapshot, columns, rows and successful updated provenance.

Extend `ArtifactDatasetInput` with the reserved `source?: {kind:'query',server,tool,args,schedule?,staleAfter?}` and `refresh?: true`. **Architect ruled two mutually exclusive modes:** source configures without calling (and excludes path/ref/remove/refresh); refresh:true requests one fetch of an already-configured query (and excludes source/path/ref/remove and title/description/rowKey metadata). Configuration is one replayable E2-style write. A new query or changed identity gets snapshot:null and no updated; identity is server/tool/args with canonical sorted-key serialization (argument key order alone is not a change). An unchanged identity preserves its snapshot, successful provenance, columns/rows, state and retention membership while updating schedule/staleAfter. Omitted title/description/rowKey are preserved; explicit title/description apply; a supplied changed rowKey is validated against retained rows before commit, and invalid rowKey refuses the entire call without any write. Policy and metadata changes are not new query identities (architect's M2 ruling). Refresh is a separately replayable operation: refusal writes nothing; tool/validation failure records only the guarded error state, preserving any previous snapshot. Replay is checked before I/O and returns the first durable result. The guide says configure, ask the owner to grant the tool, then refresh. No grant is created by this tool.

### R3 — Result normalization and trusted commit [parent-impact]

H's result is the whole MCP envelope, not rows. Code-grounded evidence: the recorded engine wire `spikes/p3-connectors/fixtures/engine-mcp-call.jsonl` (seq 11 and 13) returns `content` as a JSON string and `structuredContent` as `{series, at, rows: [{t, v}, ...]}`, an object with an own `rows` array, not a bare array. Recommend this closed normalization: reject `isError:true`; when `structuredContent` is present it alone is authoritative and must be either a flat-object JSON array or an object with an own `rows` array (other metadata keys are ignored; no path guessing, no other key names); if it is present but invalid there is no fallback to the text. Without `structuredContent`, accept exactly one text content block (or the wire's string `content`) whose JSON parses into either accepted form. Reject images/resources/multiple text blocks and nested or nonfinite data. The extracted array alone goes through the existing host `parseDataset(...,'json')` and `rowKeyProblem`, once. Snapshot bytes are the admitted array's JSON, never the MCP envelope. Parser failures use bounded local diagnostic wording, not arbitrary server error text. The E3 fixture server should use the standard `{rows: [...]}` structured envelope. This adds no source selector and no view grammar.

A renderer forwarding `callTool`'s result into an upload is rejected: H's `ConnectorCalls.take` drops its grant fence before that later write. Recommend the minimal additive form: **optional dataset sink options on the existing H surface**, `ConnectorSurface.callTool(request, options?)` and `watchTool(request, listener, options?)` with `options = {dataset: {id, baseRevision?}}`. Existing H callers and fakes are unchanged, and the HTML relay never passes options. The optional `dataset` travels beside the request on the existing `connectors.call` / `connectors.watch` commands, never inside the untrusted HTML request. The host start receives the trusted sink and the verified actor (human for page surfaces, session for `artifact_dataset`); before dispatch it verifies the request's server, tool and args against the authoritative query descriptor, captures the current mutation identity, and rechecks it at the final write. A page watch omits `baseRevision` so each invocation captures a fresh host base; agent input carries a required `baseRevision`. Source metadata and read-only truth stay in the host, and a watch is recreated on a change of source configuration, never on a successful snapshot. Proposed additive context fields `ConnectorRouteCallContext.dataset?` and `publishable?` are ledger proposals for H/HD. No second renderer source and no new page commands are introduced.

The route result remains in the host until main has rechecked the native lease and performs the private sink's take (never before the native check, never with renderer bytes). **Architect-approved phased take:** preserve the immediate `connectors.take` command and generic H behavior. The first publishable/native-rechecked dataset take starts asynchronous host consumption. Dataset takes use the explicit `ConnectorDatasetTake` / `ConnectorDatasetTakeSchema` union beside `ConnectorOperationOutcomeSchema` in `shared/ipc/schema/connectors.ts`: `{status:'publishing',operationId}` while consumption runs, `{status:'dataset',...}` for completed metadata once, then `{status:'failed',reason}` with closed reasons `stale | validation | toolError | timeout | revoked`. Duplicate takes coalesce on the same consumption; the existing operation-id event fires when it settles. Generic H takes retain their nullable outcome contract. No first-null/second-null heuristic is permitted (architect's M2 correction). The operation stays registered/cancellable through consumption; one `CONNECTOR_OPERATION_DEADLINE_MS = 180000` in `shared/artifacts/connectors.ts` covers routing, call and consume together, not a new budget per phase. `main/connectors/engine-route.ts` re-exports it on an E3-marked line to preserve H imports/tests; there is no independent host grace timer. The request times out at that deadline unless publication was already admitted; an admitted publication awaits its durable commit or rollback and settles from that host-owned outcome (architect's post-fix ratification), never from a racing main reply. Event, reconciliation and deadline take paths all invoke the synchronous native recheck immediately before dispatch. No new connector commands. Private `ConnectorRouteCallContext.dataset` is `{id,baseRevision?,requestId?}` and `publishable` is `() => boolean`; requestId is host-issued for agent operations only and is excluded from page schemas. `connectors.take` adds optional `dataset: ConnectorDatasetTake` beside H's `outcome`, which is null when the dataset field is present; absent keeps generic H behavior. Main returns dataset success metadata in the page's existing `ok:true` result JSON slot, never row values, or a typed `failed {reason: stale | validation | toolError | timeout}` in that slot. Revoked uses H's existing refusal path, no new refusal enum. A committed validation/tool error-state write returns the failed phase to the page while the agent receives its host-recorded durable dataset error answer. These phase results steer control flow only; views render the descriptor's authoritative state. No-route/no-grant refuses with no durable write. That host take keeps cancellation and the existing grant fence live through validation, final `writeWithAssets.prepare`, and commit; it never accepts renderer-supplied result bytes or a claimed fingerprint. Route D implements the same result-consumer seam after its as-built ledger row; it does not introduce a second selection route. **Agent one-shot (architect ruling).** `artifact_dataset {refresh:true}` does not need a visible lease: it is an owner-initiated live turn, its actor is the asking session, and a standing grant is required. It uses route E only when the asking session itself holds the server; otherwise route D when available; otherwise it reports unavailability. It performs no engine acquisition, starts no timer and counts no watch. Its result bytes stay in the host with the grant fence held through the atomic write, and only the outcome returns to the renderer. Page-owned refreshes keep H's visibility requirement unchanged. The agent request reaches the same broker, permission check and host sink through a private main/host request-response operation. Proposed private transport, following A's export-bridge request/answer pattern: host event `maws.artifact.datasetRefresh {requestId}` (id only), main-only host read `artifacts.datasetRefreshRequest {requestId}` returning the pending artifact/dataset/base/session and query call context, and main-only reply `maws.artifact.datasetRefreshed {requestId,outcome}`. The request registry is bound to the original live tool operation/session, carries its idempotency scope and abort signal, and validates that the sink's request id belongs to that operation; neither renderer nor HTML can claim session attribution. The host records a successful/error-state write's replay answer in its publication frame; the private reply resolves only that host-registry-owned durable answer, never substitutes main's metadata, and also settles no-route/no-grant refusals without a write. `maws.artifact.datasetRefreshed` belongs to an explicit `maws.mainOnlyCommands` partition wired into `names.ts`; A's renderer-bridged `artifact.exported` is a lifecycle precedent, not an authorization precedent. The agent path uses an internal asking-session-only route-E resolver, no synthetic lease; shared revoke/delete/stop cancellation includes agent operations. Missing-main, session close, abort and the existing 180-second connector deadline cancel the request and its underlying call; completion is at most once. Only the opaque id is broadcast; source arguments and outcomes stay on main-only reads/replies. These exact names and the H/HD route-context additions are checkpoint proposals requiring ledger entry before implementation; E3 does not bypass H's call machinery.

**Terminal ownership after admission (architect's M2 residual ruling, both paths).** The host owns every dataset operation's terminal outcome. Before synchronous savepoint admission, deadline/cancellation prevents publication. After admission, a caller awaits durable commit or rollback rather than reporting nothing published. At the page's 180-second deadline the broker sends existing `connectors.cancel` and takes the authoritative host answer: a pre-admission cancel wins and the next take returns failed timeout; after admission cancel returns `cancelled:false`, and the broker awaits the next take's durable dataset/error outcome within the flush bound. No main-side admitted flag is needed. The agent registry follows the same rule through its admission tracking. Committed-terminal notification is guaranteed even if best-effort postcommit collection throws; cleanup failure cannot strand a committed request. The take schema rejects a populated generic outcome alongside dataset, while preserving generic H `{outcome:null}` with no dataset as not-ready.

**Linearization and transitions.** Configuration/source replacement, restore and remove advance E2's existing per-dataset mutation identity. Each call captures that identity before dispatch; final prepare requires it unchanged, artifact live/nonlegacy, read grant fence held, operation not cancelled and, for page-owned work, its main lease still admitted (an agent one-shot instead requires its originating tool request still live). Successful host savepoint is the publication point; cancellation/revoke received before it prevents all snapshot/descriptor/retention writes. A hide/close sends cancellation through the existing main-to-host operation channel; a call already committed before that cancellation is not rolled back. Main rechecks native visibility before asking to commit, with no await between that check and dispatch. Failure-state writes use the same identity guard so an old failure cannot replace a newer success. Retention retires the no-longer-kept snapshot registrations in the same write frame. No grant or watch state is stored in content/history.
