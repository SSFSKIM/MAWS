## Purpose

A dashboard can keep a granted connector's read-only data current without an agent turn. Its owner grants the tool from the existing source sheet, sees real rows with the tool and fetch time, and can refresh or revoke there or from the header. Hiding the dashboard stops its calls; loss of a live route explains the pause without starting an engine. History retains the data actually shown, while live refresh does not accumulate every obsolete snapshot forever.

## Checkpoint residue and interfaces

The following are **proposals awaiting the architect's ledger/rulings**, not authorization to implement. E2 already exports `QuerySource`, `DatasetState` and `snapshotOf`; its query slot and `stale`/`paused` states exist but have no live behavior. ### R1 — Retention, X23 amendment [parent-impact]

Recommend **the latest two distinct successful snapshots per query**, plus every ref used by any current dataset, every retained-version pin and every active reader hold. Repeated identical content advances fetch provenance without consuming another distinct slot. Non-query/user-uploaded assets are never candidates. A current descriptor in another dataset protects a shared/deduplicated ref; an upload/bind that adopts a managed asset promotes its live use rather than making it collectible.

Evidence: `store.ts`'s `assetIds` pins every registered row at each version; refusing to remove pinned rows causes every later version to repin them forever. `versions.ts` pin queries concern design-system versions, not assets. Therefore **retirement must remove an asset from future version capture without changing any existing version's assetRefs**. The store needs an active/history-only distinction, not just SQL deletion. Recommend a new host-store schema slot, allocated by the architect, adding asset lifetime metadata (active/retired/collected, with existing rows active). Only E3-managed snapshot registrations enter this lifecycle. The authoritative table/field names are A-owned and await ledger allocation; do not encode them in product code yet.

Proposed public operation: `ArtifactStore.removeAsset(artifactId, ref): Promise<{status: 'removed' | 'retained' | 'notFound'}>` retires the live registration; `retained` means bytes remain because a retained version or reader holds them, not that the obsolete asset remains in future version pin sets. Current-content protection is checked synchronously in the same frame that recomputes the query retention set. Physical deletion follows durable metadata and a synchronous last-reference recheck, never an unlink inside a rollbackable savepoint. Collection repeats when versions thin, holds release and the store reopens. Tombstones reserve ref/name identity permanently so a cached old ref can never resolve to different bytes. A collected identical-hash reupload may rehydrate its same immutable identity; a different payload cannot reuse it. Assets are deduplicated within each artifact, so deleting one registration never removes bytes another registration still uses.

Restore reactivates refs the restored live descriptor needs before its new version captures assets; version duplicate copies the exact pinned rows, live duplicate copies active/current rows; copies carry managed classification but no reader holds or grants. Ref-based file binding and copy must hold or synchronously revalidate their source across asynchronous reads. No current/historical descriptor may refer to collected bytes. New tests cover savepoint rollback, restart collection, thinning, dedup/shared use, same-name reupload, restore during refresh and both duplicate forms.

**Reader lifetime is part of the request.** E2's `SnapshotReader` pages immutable refs, and the source sheet keeps a captured descriptor through replacements and later Download. N alone does not protect an arbitrarily long open sheet/export. Propose `ArtifactHost.holdDataset(artifactId, ref): Promise<{release(): void}>`, backed by `artifacts.holdDataset {artifactId,ref} -> {holdId}` and `artifacts.releaseDataset {holdId}`. A hold is scoped to its requesting main/window connection, transient, bounded by the existing surface lifetime and released on close/disconnect; it protects bytes, not permission. Main exporters acquire the equivalent store hold for the full export/capture. The sheet holds until close, preview while shown, and the reader holds across paging. Host `ArtifactStore.holdAsset(artifactId,ref): {release(): void}` supplies the same primitive to in-host readers; no timer-based grace or renderer cache substitutes for a hold. Exact cap/owner cleanup must be specified with the architect before this interface is built.

### R2 — First snapshot and shared query inputs [parent-impact]

The existing required `QuerySource.snapshot:{ref,at}` cannot represent a configured query before the owner grants it. Recommend `snapshot: {ref,at} | null`, with null meaning **never fetched**, zero rows/columns and an explicit status, not a fabricated empty successful fetch or a mislabelled prior file. `snapshotOf` returns null for this arm; every source/read/export/mirror/history consumer handles it without requesting bytes. `updated` records configuration actor/time until success, but query fetch labels use snapshot.at; with null they say `not fetched`. Once fetched, errors/revoke/pauses retain snapshot, columns, rows and successful updated provenance.

Extend `ArtifactDatasetInput` with the reserved `source?: {kind:'query',server,tool,args,schedule?,staleAfter?}` and `refresh?: true`. Query source excludes path/ref/remove; refresh-only addresses an existing query; source-only configures without calling. Source plus refresh is one requested operation: a successful result and its configuration commit together; a refused call writes nothing, while a tool/validation failure on an already-configured source records its guarded error state and keeps its snapshot. Initial configuration plus a failed refresh must not manufacture fetched data; recommend retaining the new null-snapshot configuration with the error as the completed tool operation, explicitly returning its state. Replay is checked before I/O and returns the first durable result. No grant is created by this tool.

### R3 — Result normalization and trusted commit [parent-impact]

H's result is the whole MCP envelope, not rows. Recommend this closed normalization: reject `isError:true`; when `structuredContent` exists it must itself be a flat-object JSON array, with no fallback to conflicting text; otherwise accept exactly one text content block containing that JSON array (or the wire's string content containing it). Reject images/resources/multiple text blocks/`{rows:…}` and nested/nonfinite data. The existing host `parseDataset(...,'json')` and `rowKeyProblem` perform dataset validation once. Snapshot bytes are the admitted array's JSON, never the MCP envelope. Parser failures use bounded local diagnostic wording, not arbitrary server error text.

A renderer forwarding `callTool`'s result into an upload is rejected: H's `ConnectorCalls.take` drops its grant fence before that later write. Recommend **trusted dataset-target calls/watches through the same H broker/lease**, with dataset identity carried to a host result consumer while the existing operation/fence is still held. Proposed `ConnectorDatasetTarget = {id:string, baseRevision:number}` and trusted `ConnectorSurface.callDataset(target)` / `watchDataset({id,intervalMs},listener)`; dataset source/server/tool/args are loaded authoritatively in the host, not accepted as a second renderer source. Existing generic HTML call/watch methods and their wire results stay unchanged. Proposed owner-window commands `connectors.datasetCall`, `connectors.datasetWatch`; a host-side refresh target includes the verified actor (human for surface calls, session for `artifact_dataset`), source mutation identity, and operation id. These names and the route transport extension need H/HD agreement before implementation.

The route result remains in the host until main has rechecked the native lease and asks for its trusted take/commit. That host take keeps cancellation and the existing grant fence live through validation, final `writeWithAssets.prepare`, and commit; it never accepts renderer-supplied result bytes or a claimed fingerprint. Route D implements the same result-consumer seam after its as-built ledger row; it does not introduce a second selection route. Agent requests reach the same broker/permission/host sink through a private main/host request-response operation, with the asking session as actor and no engine acquisition. The exact transport names for that reverse request are a shared-name request, not permission to call the engine directly from E3.

**Linearization and transitions.** Configuration/source replacement, restore and remove advance E2's existing per-dataset mutation identity. Each call captures that identity before dispatch; final prepare requires it unchanged, artifact live/nonlegacy, read grant fence held, operation not cancelled and its main lease still admitted. Successful host savepoint is the publication point; cancellation/revoke received before it prevents all snapshot/descriptor/retention writes. A hide/close sends cancellation through the existing main-to-host operation channel; a call already committed before that cancellation is not rolled back. Main rechecks native visibility before asking to commit, with no await between that check and dispatch. Failure-state writes use the same identity guard so an old failure cannot replace a newer success. Retention retires the no-longer-kept snapshot registrations in the same write frame. No grant or watch state is stored in content/history.

| Event | Required transition |
|---|---|
| Visible live query with schedule | One H watch for that dataset/surface; H applies its 64-global cap and interval-after-completion semantics |
| No schedule | No periodic watch; explicit Refresh may call once while visible |
| Hidden/inactive/preview/closed | Stop/suspend watches; cancel pending calls; no source polling or engine acquisition |
| Grant absent/revoked | H parks timerless; keep previous snapshot, show permission explanation; a new grant wakes it |
| Eligible route absent | Keep snapshot, show `paused: no live session`; H retries resolution on the schedule; Start is owner-only |
| Valid result, guard holds | One asset+descriptor+retention commit, human/session attribution, state ok |
| Tool/validation failure, guard holds | Error state only, previous successful snapshot/provenance unchanged |
| Guard lost/source changed/restored/removed | Discard success and failure; no descriptor write and no automatic retry over the new source |

Multiple surfaces may own H watches; each captures its own mutation identity, so only the first current completion commits and later stale completions discard. Rebuild a watch on source settings change, not on each refreshed snapshot/state update; otherwise watch creation would produce an immediate refresh loop. Historical preview may inspect/grant-independent metadata but has no mutating controls or watch.

### R4 — Schedule, stale wording and grant UI

Recommend source.schedule integer seconds **30–86,400 inclusive**, absent means manual only; refuse out-of-range agent input rather than silently change its declared schedule. H's interval clamping remains defense at its own boundary. staleAfter is a positive integer seconds, independent of the refresh schedule; staleness begins at `snapshot.at + staleAfter*1000`, not at the next failed fetch. No snapshot cannot be stale. A successful fetch clears stale/error/paused; failure or permission pause never moves successful fetch time.

Recommend a pure `datasetStateAt(descriptor, now)` projection in E2's states module for elapsed staleness, with an explicit time input, rather than durable writes solely because the clock advanced. Live view timers update only the label while visible; they never call a tool or start an engine. Export captures one clock value for all labels, previews preserve their stored status/time, and all stale wording remains `DATASET_STATES.staleSince`. Permission/no-snapshot explanations are local closed strings in that same module; the specific no-route string remains `paused: no live session`. Ask the architect to ratify this interpretation of the reserved descriptor state.

Use query declarations, not a new server browser: the agent supplies server/tool/args, and owner source-sheet controls show that pair and Allow read-only / Revoke / Refresh / Start. H's grant call verifies read-only truth; the UI does not assert it. Header `Datasets` opens the same sheet/list, allowing the same controls without a second Settings/Connectors product surface. Captured source rows/time never mutate underneath an open sheet: controls act on a separately identified live query only while its captured source identity still matches; after replacement they explicitly require reopening to inspect the new snapshot. Existing H `artifactSessionContext`, `startArtifactSession` and its empty-message guard supply Start. No new capability-discovery API is needed for this acceptance.
