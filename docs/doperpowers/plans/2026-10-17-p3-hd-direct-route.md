## Purpose

An artifact that has permission to read a configured connector should keep refreshing after its session's engine quits. MAWS will make its own MCP connection to a verified server, under the same artifact permission and visible-page lifetime as the existing engine route. For an HTTP connector requiring OAuth, the owner connects MAWS itself once; no Claude Code credential is borrowed. The owner can see the configuration source and disconnect MAWS without changing the engine's grant.

The observable path is the existing HTML artifact and its Connectors sheet: declare and Allow a fixture tool, read through the engine, stop the engine, then read through MAWS directly without another artifact grant. The new `e2e:connectors-direct` scene proves that transition, stdio and HTTP transport, and MAWS's own OAuth through a scratch authorization server. No real account or model turn is needed.

## Acceptance

1. **Same page, same permission.** The HTML fixture used by H declares and receives a read grant. With its eligible engine alive, `via.route` is `engine`. After that engine exits and no eligible engine is live, a refresh succeeds with `via.route` `direct`, no sessionId and the same grant fingerprint. Starting an eligible engine again restores E on the next refresh. Each refresh makes exactly one tool call; neither an in-flight failure nor a route change triggers a second submission. Engine/session counts prove no timer acquires or holds an engine.
2. **The existing lifecycle still applies.** Actual native hide/minimize plus surface visibility pauses direct calls and watches; showing catches up once. Revoke and delete stop queued calls and suppress late/retained results, including a consumed-once result. A duplicate and a restored version gain no grants. H's tests remain unchanged and pass. Call-log silence, not only UI labels, is the proof.
3. **Verified direct connections.** A stdio fixture and an unauthenticated HTTP fixture are reached from engine-reported, fingerprint-matched file entries. The trusted sheet names the verified file/scope, while unverifiable entries say engine-only. A changed file or ambiguous report does not silently connect a different server. MAWS's stdio PID is distinct from the engine's; its environment is the launch-attested SDK-minimal baseline plus exactly the configured env (no other inherited keys), it starts on demand, closes after the idle bound, and disappears when main disconnects or quits. No background token refresh or source calls continue without main.
4. **Own OAuth.** The toy protected MCP server and authorization server from the spike complete MAWS's first DCR/state/PKCE/resource-bound flow via an ephemeral listener bound only to `127.0.0.1`. A second connection and a scratch app relaunch use the safeStorage-encrypted stored grant on Electron's **mock keychain** without another browser or client registration. Native production Keychain custody is explicitly unverified in this automated lane and belongs to the owner's packaged-app sitting in P3-F (Decision 98). Refresh-token rotation is saved before another refresh can use the old token. Disconnect fences new direct work, attempts advertised revocation and forgets the local grant even if the revocation endpoint is unavailable. A different server or issuer never receives that token. Cold provenance is re-established by a scratch no-model engine observation after a host restart, never restored from disk.
5. **Authority at the write.** Tests pause immediately before stdio's stdin write and HTTP's actual fetch admission, revoke/delete/change mode while paused, and prove no tools/call reaches either fixture. Once grants admit at most one concurrent call. Cancelling during connection, authorization, refresh or transport preparation leaves no later send, resurrected credential or leaked fence. Already-transmitted remote effects are not claimed reversible; cancellation suppresses their result and never retries them automatically.
6. **Custody and bounds.** No new status/config/credential persistence or public broadcast; only encrypted OAuth records persist in MAWS userData. For MAWS-owned OAuth the direct host receives only transient access credentials, not refresh tokens/client secrets; explicitly configured stdio env/HTTP headers are used transiently under Decision 98's separate file-entry rule. Missing/unavailable safeStorage fails closed, never plaintext. Loopback timeout, wrong state, duplicate callback, failed token exchange and app shutdown close the listener. Owner-only journal directory/files are created as 0700/0600, including rotated segments, without changing X8's faithful contents.

### Source truth and lifetime

Keep a bounded **host-memory observation cache**, populated only from a live `mcp_status` response tied to the exact session launch and canonical effective directory. A complete newer report replaces that launch's older set, including removal/disabled entries; late answers from replaced launches cannot repopulate it. Engine exit does not delete the last observation while main stays attached: that is what permits engine-less refresh. Main disconnect or host shutdown clears observations; no journal or persisted cache recovers them. A cold app therefore needs a live observation before D is available, even when an OAuth grant already exists. Explain that condition in the trusted sheet rather than falsely calling a saved credential a verified source.

Retain identity, tool annotations, observation generation/time, source locator and comparison digests, never raw headers, configured env or OAuth fields. Host-only launch context retains the SDK-minimal environment keys as captured in that engine's actual launch plan (HOME, PATH, SHELL, TERM, USER, LOGNAME), with explicit attested spawn cwd; no other inherited environment is forwarded. An unresolved command or missing launch-resolution fact is engine-only. D uses this same narrow PATH/cwd context, not the host's current process environment; tests distinguish two PATHs and cwd-sensitive arguments. Raw status is used locally and discarded; X8's pre-existing engine journal remains unchanged. Limit to 128 directory contexts and 256 servers per context; exceeding the bound refuses new direct observations rather than evicting an active identity into another meaning. A malformed/overbound newer report invalidates an existing context's direct eligibility instead of leaving its older positive snapshot usable; clearing the cache also invalidates in-flight reads. Clear on main detach; no TTL timer performs external work. Multiple reports for the same directory/server must agree on source and identity before D may use one; conflicting reports mean engine-only, not last-writer precedence.

Scope labels are not paths. Current retained evidence (`spikes/p3-connectors/fixtures/engine-mcp-call.jsonl`, seq 5) names `source:user`, `project`, `dynamic`, and omits stdio env. **Decision 98 admits user/local** when the actual live launch environment (HOME or CLAUDE_CONFIG_DIR, plus cwd) identifies one file and JSON location (`mcpServers[name]` or `projects[exactCwd].mcpServers[name]`). The engine already chose the scope; locating that scope's unique file is lookup, not precedence. Never use today's process environment or a filesystem search. Project scope may be promoted only if a probe proves the cwd's `.mcp.json` entry matches the reported fingerprint and its approval record is readable in the same user file; otherwise project remains engine-only, with plugin/dynamic/enterprise/managed/SDK/claude.ai deferred. A no-model scratch probe grounds supported scopes/config-home behavior before promotion.

**Decision 98 admits the whole identified file entry after visible-field fingerprint match**, including env and headers, for MAWS's own instance. Rejecting all omitted env would defeat ordinary stdio configurations, so that initial recommendation is withdrawn. Re-read and re-match at every use: missing or visible-field mismatch means changed, never a second source lookup. `${VAR}` and `${VAR:-default}` expansion uses only the exact environment MAWS handed that engine; another reference or unresolved value refuses. The launch context holds a host-private reference to those existing launch facts, never a renderer/IPC serialization of that environment. Omitted file fields are read at spawn/connect, used transiently, then dropped: no cache, journal, IPC answer or log. No engine OAuth token or secure storage is read; HTTP auth uses MAWS's own discovery, not the file's engine client registration. Unsupported helpers/manual-client options are engine-only, not executed speculatively. H's fingerprint algorithm stays unchanged so a route change alone never re-grants. A connection may retain an in-memory digest, not omitted field values, to detect configuration change before reuse.

A complete snapshot's negative observations count: absence or disablement in another report for the same config-home/cwd context conflicts with a retained positive, even after that reporting engine exits. A newer report replaces only its own launch's snapshot; late responses from an older request cannot roll it back. Cross-launch contradiction remains engine-only until the attachment resets and a fresh observation establishes an unambiguous context. No last-writer choice erases contrary provenance. Tests cover positive→exit→absent/disabled→exit and delayed responses.

### Actual-write authority

Recommend the **SDK client and transport in the engine-host process**, commanded and scheduled by main. Main holds UI, leases, connection credentials and OAuth; the host holds the artifact store, once-consumption, direct operation and final synchronous fence. A main-side SDK client plus an IPC admission answer is rejected because revoke/delete can commit before main's later write. Moving the grant store into main is rejected because it breaks A/H authority and detached-host guarantees.

Use a separate direct operation table with the same start/take/cancel contract and result retention as E; do not weaken or mechanically refactor E to share a subtly different boundary. Connection initialization and tools/list complete before durable once authorization, so an unavailable/auth-required server does not burn an unused grant. A fence is allocated before that authorization, checked after every async preparation, then checked at actual transport admission. It stays held through an untaken result and breaks on the same store events as H. Main disconnect closes operations, transports and transient credentials synchronously with invalidation; process closure can finish asynchronously within the shutdown bound. Register all cleanup with `onClientGone`, not only normal quit.

SDK 1.32.1 source establishes the admission boundaries: `Client.callTool → Protocol.request → StdioClientTransport.send` reaches stdin.write synchronously, but `StreamableHTTPClientTransport.send` always awaits `_commonHeaders` before fetch. Use the official SDK Client with a small MAWS-owned stdio Transport adapter (SDK `ReadBuffer`/`serializeMessage`, explicit minimal launch environment plus configured env, bound cwd, detached owned process group, bounded group termination, no inherited stderr). This avoids stock stdio close's direct-child-only cleanup and makes the actual write guard MAWS-owned. Bound inbound framing as well as completed result size; no unbounded unterminated stdio line or HTTP body.

For HTTP, use the stock transport with an injected fetch, **no authProvider**, `reconnectionOptions.maxRetries: 0`, and no resumption token or listChanged subscription. Suppress the unnecessary standalone SSE GET with the SDK-supported 405 response. Bind each tools/call's JSON-RPC id to its operation at transport.send; guard that id at the actual injected fetch, after all awaits. A tools/call lacking an armed synchronous admission fails closed. Apply both the operation abort signal and connection signal to the request. Connection-only initialize/tools-list traffic is subject to source/credential/lifetime fences, not an artifact tool grant; cancelled notifications are sent only for a previously admitted request. Avoid aborting a completed SDK request because its retained listener can send a spurious cancellation. Transport/session errors discard the connection, not replay the call. No automatic retry of tools/call after any ambiguous send; route changes affect the next request only.

MAWS-owned instances are pooled by canonical directory, verified source generation and server identity, never server name alone. Startup is demand-driven and shared for concurrent requests. Maximum 64 direct connections; an over-cap request is unavailable rather than spawning unboundedly. With no in-flight operation, close after 5 seconds; do not keep a process merely because a watch will be due later. Hidden/closed work releases its demand. Close prevents late startup from re-registering a client; shutdown aborts work, closes streams, terminates an uncooperative owned child within 5 seconds and proves PID exit. Exclusive-resource failures stay unavailable/engine-only in the trusted status, not a retry storm or a fallback engine acquisition. No change to engine-owned server lifetime.

### OAuth custody and owner controls

Recommend `@modelcontextprotocol/sdk` **1.32.1**, the spike's exact root dependency, not v2 split packages. Main implements the SDK provider using an encrypted, versioned record file under `<userData>/connectors/`; create directories/files owner-only and replace atomically. SafeStorage encryption availability is required for both save and read. Use the installed Electron asynchronous availability/encrypt/decrypt APIs after app readiness, so a credential-store wait cannot block main's event loop; key-rotation re-encryption goes through the same serialized store write. Official Electron safeStorage documentation and the installed electron.d.ts confirm these APIs; the synchronous methods can block for user interaction. Store identity binds canonical server resource URL, server/config identity and discovered issuer. SDK issuer binding, resource indicators and PKCE remain authoritative; callback state is explicitly validated by MAWS. Do not invent discovery or token parsing that the SDK already supplies.

Owner Connect is also a bounded metadata-discovery gesture: it may initialize the attested server and call tools/list without any artifact tool grant, but never tools/call. This breaks the first-OAuth bootstrap cycle: an engine may report needs-auth and no tools, yet the owner can connect MAWS, discover tools, then grant one normally. Tool metadata is bound to source generation and credential epoch, held only for the main attachment, invalidated on Disconnect/source change, and rechecked on the actual connection before every tool call. Ordinary route resolution remains metadata-only; ungranted page calls cannot trigger discovery or consent.

Main alone holds refresh tokens, registration information, verifier and safeStorage access. Host receives an access token only for an attested server generation and operation/connection lifetime; no secret rides an event broadcast, journal, diagnostic error, page result or renderer IPC. Refresh uses the SDK's `refreshAuthorization` with stored metadata/client/resource, only on demand while main is connected, serialized per server and saved atomically before releasing the refresh lock. Preserve the old refresh token when rotation is omitted and stamp the validated issuer on saved tokens. SDK `auth()` is reserved for owner Connect/Reconnect: it can re-register or open a browser on a failed refresh, so it is not the background-refresh primitive. A 401 marks the rejected credential epoch unusable for the next demand without replaying the current tools/call. No proactive timer. Host transports do not own a refresh provider or initiate a browser. The resource fetch attaches an access token only to its exact verified resource URL and refuses transport redirects rather than forwarding a bearer to another resource; discovery/token-endpoint traffic stays main's SDK-auth responsibility. Authentication failures park D as unavailable; a watch never opens consent. Revoke/Disconnect increments an in-memory credential generation before any await; late refresh/flow responses cannot save or start work under the old generation.

A stable opaque `connectionId` identifies each stored MAWS grant independently of current source eligibility. The owner sheet includes stale saved records matching its named servers, labelled with their original source and not usable for calls; Disconnect takes this id and can forget it even after a cold start or a removed/replaced file. Only stored issuer metadata is used for bounded best-effort revocation. Connect/Reconnect and token delivery still require current attestation; saved records never become provenance.

Disconnect's linearization is explicit: main blocks new starts immediately, invalidates its credential epoch and removes local credentials; the host's `directClose` invalidates that epoch and aborts old operations before acknowledging. Every token-bearing start and every final HTTP fetch compares the host credential epoch as well as the artifact fence. The UI shows disconnecting until the host acknowledgment; if the host is lost, its main-disconnect cleanup closes the transport, and local forgetting still succeeds. A still-connected but unresponsive host is reported pending/unconfirmed, never falsely advertised as fully disconnected. Tests pause at admission and withdraw credentials with the artifact grant unchanged.

Flow states: `disconnected → connecting → connected`; cancellation/timeout returns disconnected, stored-grant failure becomes `needsReconnect`, and Disconnect from any state cancels the flow, blocks D and deletes local state. Reconnect is an explicit replacement flow under a new generation and new registration for its new loopback redirect; a failed replacement does not revive withdrawn credentials. An ordinary new connection from a stored grant is different: it reuses the saved registration/tokens without a browser. All encrypted-file mutations are serialized with generation checks at commit, so a pending save cannot race Disconnect's deletion into restoring a grant. Bind the callback listener to `127.0.0.1`, random port, one outstanding flow per server, 120 s timeout; exact callback path, method, state and single-use code. No wildcard or localhost listener. Only user-initiated Connect/Reconnect may invoke the system browser. DCR unsupported means owner-visible unavailable/engine-only; manual client IDs and hosted CIMD are outside this child.

Add trusted **per-server rows inside H's existing Connectors sheet**, separate from per-tool Allow/Revoke. They show source/scope and direct connection state, with Connect/Reconnect/Disconnect as appropriate. Disconnect does not revoke artifact tool grants or touch route E's OAuth; copy says it disconnects MAWS only. The visual stance is adopted from H and X7/X32: compact operational rows, token-only light-default surfaces, existing Sheet/button weights, text status and visible keyboard focus; no new Settings panel or design system. At narrow widths controls wrap below their identity rather than compressing names off-screen. The page runtime and portable ArtifactHost need no OAuth methods.
