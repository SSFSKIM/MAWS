## Purpose

A document's comment threads sit beside the passages they anchor, as in Google Docs, instead of a rail the owner opens and closes (obs 1, Decision Log 6): the `margin` mode of the editor's comment surface, built on the margin algorithm five open-source editors share with Liveblocks' `AnchoredThreads` as the reference implementation (Apache-2.0, Tiptap and ProseMirror, MAWS's stack), with Docs' product surface over it (Expand, Minimize, Hide; the All comments panel; the keys). The shared card X36 (`ThreadCard`) is this child's and is what B2's pin popover draws. The 200-page typing path keeps its bound with the margin open.

## Scope and what the code says (M0 grounding)

The threads list is `ThreadsRail` (`aside.doc-rail[aria-label="Comments"]`, `article.doc-thread[data-thread]` with `.doc-thread-quote-text`, `.doc-thread-tab`, `data-status`, `data-orphan`, a Reply textbox, Resolve and Reopen, a `region "Resolved (N)"`), toggled by the toolbar's "Comments N" and the X32 header's Comments action through `rail: 'comments' | 'history' | null` held by the tab's state. The page is `.ds-doc` (the scroll box, `overflow-y: auto`, `container-type: inline-size`) holding `.ds-doc-page` (`max-width: var(--ds-page-width, 8.5in); margin: 0 auto`).

## Design (the residue, decided here)

Numbers marked **[LC-1]** are set from Liveblocks', Overleaf's and Docs' documented behaviour and are re-based by LC-1 (§"LC-1" below) without a design change; each is one named constant.

**D1. Where the margin lives.** `MarginThreads` is rendered inside the page's scroll box (`.ds-doc`), as the page's flex sibling: `.ds-doc` becomes a flex row (`align-items: flex-start; justify-content: center`), `.ds-doc-page` keeps `width: min(100%, var(--ds-page-width))` and `flex-shrink: 0` (its width never depends on the column), and the column `.doc-margin` is `position: relative; flex: 0 0 var(--doc-margin-width)` whose entries are absolutely positioned at their resolved `top`. So the page and the column scroll together natively (scrolling runs no layout, R4), the page plus the column centre as one unit and the page moves left by half the column when the first thread appears (N6, Decision Log 6), and the column's `min-height` (the last card's bottom plus the gap) grows the scroll height so no card is lost (L6). The spec's "inside `.doc-page-frame`" is satisfied transitively; the frame-level overlay stays for the modes that are not the margin. The column carries `data-markup-occluder` (a mark-up still of the page is the page). Rejected: a frame-level column translated on scroll (a layout on every scroll, against R4).

**D2. The layout is a pure function** (`src/artifacts/comments/margin-layout.ts`): `layoutMargin({entries: [{id, anchor, height}] in document order, active, gap, shift})` → `{tops: Map<id, top>, height}`, L1 to L7: no active thread, a plain downward stack; an active thread pinned at its anchor with the downward pass `max(anchor, previous bottom + gap)` and the upward pass `min(anchor, next top − gap − height)`; the top clamp re-running the stack downward (L5, the only case the active card leaves its anchor); the bottom growing the height. Deselect relaxes to L1 (Liveblocks; Overleaf's sticky pin rejected so the layout needs no history) **[LC-1 item 3]**. Order is document position of the earliest live range, ties to the older thread. Gap `MARGIN_GAP_PX = 8` **[LC-1 item 2]**, active shift `MARGIN_ACTIVE_SHIFT_PX = 12` **[LC-1 item 2]**.

**D3. The tiers read the side space beside the page, never the window** (`margin-tiers.ts`): `sideSpace = W − P` with `W` the scroll box's client width and `P` the page's rendered width; cards when `sideSpace ≥ CARD_MIN + 2G` at width `min(CARD_MAX, sideSpace − 2G)` with `CARD_MAX = 300`, `CARD_MIN = 200` **[LC-1 item 6]**; else the icon rail (`ICON_PX = 24`, icons closer than one icon's height merged into a count **[LC-1 item 7]**), the column reserving `min(ICON + 2G, sideSpace)` and the icons overlapping the page's right padding when the side space is short (the page keeps its width; Docs' icons sit in the page's margin); under a body of `RAIL_BESIDE_FROM_PX = 720` (P3-F1's, not re-based) the margin is off and today's drawer applies. A `ResizeObserver` on the scroll box and the page supplies `W` and `P` (N4). Minimize gives the icon rail at any width; Hide an empty margin with the passage highlights kept **[LC-1 item 7]**.

**D4. The margin is reserved only while a thread or a compose card is open on the shown tab**: the column's width is the tier's while the shown tab has an open live thread or hosts the compose card, else 0 (the page centred). Moves caused by activation, an add or a resolve animate `top` 200 ms `cubic-bezier(.4,0,.2,1)` **[LC-1 item 2]**; moves caused by an edit, a resize, a font load or the first layout do not; `prefers-reduced-motion` gives 0 ms.

**D5. Only the human activates a thread [binding].** The display plugin activates on a click (as today, the innermost of overlapping passages, L7) and, new, on a local caret move into a passage (a transaction with `selectionSet`, no `docChanged`, not a binding transaction); a caret leaving a passage by the keyboard keeps the active thread (Overleaf's sticky pin for the caret only) **[LC-1 item 5]**; a click on uncommented text clears it (today's). A remote edit (a binding transaction) maps the decorations and keeps `active`; a threads-map change (an agent's reply, resolve or new thread) rebuilds with the old `active`; awareness never reaches the plugin. The margin's own activations (a card click, J and K, the panel's item) go through `setActiveThread`. `rail` gains `'margin'`: the editor reports `'margin'` through `onRailChange` when a margin thread becomes active with no rail open (so an active margin thread and the history rail or the panel are one slot) and `null` when the active thread clears; the header's Comments action toggles `'comments'` ↔ (`'margin'` if a thread is active, else `null`), which is Z5's round trip with the same active thread.

**D6. The shared card (X36).** `ThreadCard` in `src/artifacts/comments/ThreadCard.tsx` with the ledger's props `{thread, active, compact, onActivate, onReply, onResolve, onReopen, draft, onDraftChange}` plus `onNext`, `onPrevious`, `onExit` (J, K, U and Escape), `position` (`{index, count}` for the group's name, K1), `showQuote` (the panel keeps the quoted passage; the margin and the popover do not), `tabTitle`, `readOnly`. `thread` is `ThreadCardThread`, the subset `ThreadState` and `DeckThreadState` share (`id, quote, status, orphan, messages, createdBy, createdAt`). Compact: the first message and the two latest replies, "N more" between; active: every message and the reply field (focused on activation by a card click or R; not on activation by the caret or a passage click, so the text keeps the keyboard). Keys on a focused card outside a text field: R, E, J, K, U, Escape. The author chip from `actorDisplay`. The card's draft (the reply field's text) is the host's through `draft` and `onDraftChange`, so a hidden card keeps it. Styles in `src/artifacts/comments/comments.css`, app tokens.

**D7. The compose card in the margin.** The compose card is P2's card (the comment to a session) hosted by `CommentCardHost`, which gains `layout="margin"`: in flow (`relative`), the card `position: relative; width: 100%`, placed by the new pure `marginCard(box)` in `src/artifacts/comments/placement.ts` beside the moved `placeCard`, `dockCard`, `stripCard`, `stripMax`, `caretOf`, `pinOf` and the constants (the renderer's `side/card/placement.ts` re-exports them). `MarginThreads` renders `comments.overlay({...reach, layoutKey, placement: 'margin'})` inside the entry of the thread the card is on, which it learns through the new `CommentOverlayProps.hosting(threadId | null)` (the renderer's `DocumentCardHost` calls it beside `setActive`), and that thread's `ThreadCard` yields to the card while it is up; the entry's height is measured like any other, so the stack re-lays as the card grows. Outside the margin (the drawer tier, Hide, the panel open) the overlay is drawn over the frame as today, so exactly one host draws the card. `CommentPlacement` (`tools/code/anchor/anchor.ts`) gains `{kind: 'margin', host: 'document', anchorY, stackIndex}` and `{kind: 'pin', host: 'slide' | 'design', pinRect}` (the X21 amendment; the document's `opened` passes `margin` while the margin is on). The frame's scroll no longer bumps the margin's key: `PageFrame` keeps `moved` (edits, resizes, A2's growth) for `layoutKey` and adds `scrolled` for the frame-level overlay's own key, so R4 holds and the compose card, in the scroll content, follows the page by construction (tracker rows 92 and 93 retired as §4.3 says).

**D8. Compose rules (C1 to C8).** An Add comment button beside a non-empty text selection at the selection head's line **[LC-1 item 8]**, in the column (the icon tier shows it too), hidden while a compose card is up. ⌘Enter posts (`comment-form.ts`'s Enter sends today; ⌘Enter added as a second send key, Enter kept). ## Surprises & Discoveries

1. **Tiptap's `keyboardShortcut` command captures the handler's transaction** and replays its steps alone, so a chord that sets a selection and a meta cannot be driven through it in a test; the activation suite dispatches real keydown events on the view instead. Tiptap's parser names the control key `Ctrl`, not `Control`.
2. **happy-dom defines no `clientWidth`** and lays nothing out: the margin suite runs over a geometry stub that defines the getter on both prototypes and answers every rect from a scene (`margin-test-support.ts`).
3. **The MacBook's display cannot reach the groups' 1600 × 900 window** (`launchMaws` waits for `innerWidth === 1600` and times out), so `e2e:document` and `e2e:document-app` run only on the mini, as the gate-offload rules already place them; the local run on this machine is not evidence.
4. **A card host that is not mounted closes its card**: with the overlay rendered only in the hosting thread's entry, nothing drew the compose card before a thread was named; the margin keeps a slot for the surface's host while no card is up (M4's report found the same gap from its side).
5. **The compose card flew in from the column's top.** The mini read the hosted card 177 px, then 25 px above its line: the host sets `hosting` at the Comment click, a microtask before the display draws the thread's decoration, so the first pass placed the entry by the "drawn nowhere here" rule at the column's top and the next, animated, moved it to its anchor over 200 ms. The rule stays for a thread of another tab; an entry located for the first time after an unlocated placement is written without a transition (the fix wave), and the harness case polls for the settled card. Found only on the mini: happy-dom runs no transition, and no unit case read the card between two passes.
6. **A2 fills `growRef` only when a comment surface exists** (`if (!comments) return`), while the margin follows edits with or without one; merged as written, the layer's growth would not have re-laid the margin without a surface. The merge widened the guard to `!comments && !margin` with a parameterised case in A2's `provisional.dom.test.tsx`, whose frame-level overlay case now mounts with Hide (in jsdom the body is not narrow, so the margin hosts the overlay and the frame-level key is the constant `marginKey`).
7. **A click on a passage of an unfocused page can leave the caret where it was.** The app margin case clicked the first passage after the panel's round trip (the keyboard on the toolbar, the page's own selection still the second passage from its Comment) and the owner's words landed above the second passage. A DOM probe on the mini read the selection before, right after and 300 ms after the click: the second passage's range all three times, re-normalised after the click to the mark's text node end, which is how ProseMirror writes its state selection to the DOM. So the click's native caret was overwritten by the page's stale selection: ProseMirror re-syncs the DOM to its state 20 ms after a focus unless it has read the DOM's change by then, and the activation's work on the mini (the card's render, the layout pass) ran past that. The thread still activated, since the display's `handleClick` reads the clicked element, not the selection. The case focuses the page with a plain-text click first; the race itself is a residue row (deferring the activation's render to the next frame would close it, at the cost of a frame on every click).

### Design

**F1. The settle** (`src/artifacts/document/editor/comments/margin-settle.ts`, pure, its clock injectable). `changed()` marks the margin stale (the time of the oldest unread change kept) and (re)arms a quiet timer, `MARGIN_SETTLE_QUIET_MS = 600` after the last change (Docs' settle, LC-1 item 2), and, once per stale period, a ceiling timer at `MARGIN_SETTLE_MAX_MS − MARGIN_SETTLE_IDLE_MS` (900 ms) after the first. Whichever fires first asks `requestIdleCallback` for the pass with a `MARGIN_SETTLE_IDLE_MS = 100` timeout; a change while the pass is due is read by that pass. Every pass, whatever caused it, calls `settled()`, which cancels whatever is owed. **The bound:** once the edits pause, the pass starts within 700 ms of the last change; under changes that never pause, never later than 1,000 ms after the first change it reads; a task already running on the main thread when the pass falls due excepted. In happy-dom (no idle callback) the pass is a task of its own.

**F2. What is immediate.** The page frame's frame callback now tells the margin what moved the passages: `resize` when the frame's own `ResizeObserver` fired since the last callback (the window, the panel: a pass in that frame, as before), else `edit` (the editor's `update` and A2's growth through `growRef`). **F4.
