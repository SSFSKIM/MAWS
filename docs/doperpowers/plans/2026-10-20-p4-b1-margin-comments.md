## Purpose

A document's comment threads sit beside the passages they anchor, as in Google Docs, instead of a rail the owner opens and closes (obs 1, Decision Log 6): the `margin` mode of the editor's comment surface, built on the margin algorithm five open-source editors share with Liveblocks' `AnchoredThreads` as the reference implementation (Apache-2.0, Tiptap and ProseMirror, MAWS's stack), with Docs' product surface over it (Expand, Minimize, Hide; the All comments panel; the keys). The shared card X36 (`ThreadCard`) is this child's and is what B2's pin popover draws. The 200-page typing path keeps its bound with the margin open.

## Scope and what the code says (M0 grounding)

The threads list is `ThreadsRail` (`aside.doc-rail[aria-label="Comments"]`, `article.doc-thread[data-thread]` with `.doc-thread-quote-text`, `.doc-thread-tab`, `data-status`, `data-orphan`, a Reply textbox, Resolve and Reopen, a `region "Resolved (N)"`), toggled by the toolbar's "Comments N" and the X32 header's Comments action through `rail: 'comments' | 'history' | null` held by the tab's state. Activation is the display plugin's `handleClick` (the innermost of overlapping passages) and the rail's Show; nothing activates on a caret move. The page is `.ds-doc` (the scroll box, `overflow-y: auto`, `container-type: inline-size`) holding `.ds-doc-page` (`max-width: var(--ds-page-width, 8.5in); margin: 0 auto`).

## Design (the residue, decided here)

Numbers marked **[LC-1]** are set from Liveblocks', Overleaf's and Docs' documented behaviour and are re-based by LC-1 (§"LC-1" below) without a design change; each is one named constant.

**D1. Where the margin lives.** `MarginThreads` is rendered inside the page's scroll box (`.ds-doc`), as the page's flex sibling: `.ds-doc` becomes a flex row (`align-items: flex-start; justify-content: center`), `.ds-doc-page` keeps `width: min(100%, var(--ds-page-width))` and `flex-shrink: 0` (its width never depends on the column), and the column `.doc-margin` is `position: relative; flex: 0 0 var(--doc-margin-width)` whose entries are absolutely positioned at their resolved `top`. So the page and the column scroll together natively (scrolling runs no layout, R4), the page plus the column centre as one unit and the page moves left by half the column when the first thread appears (N6, Decision Log 6), and the column's `min-height` (the last card's bottom plus the gap) grows the scroll height so no card is lost (L6). The spec's "inside `.doc-page-frame`" is satisfied transitively; the frame-level overlay stays for the modes that are not the margin. The column carries `data-markup-occluder` (a mark-up still of the page is the page). Rejected: a frame-level column translated on scroll (a layout on every scroll, against R4).

**D2. The layout is a pure function** (`src/artifacts/comments/margin-layout.ts`): `layoutMargin({entries: [{id, anchor, height}] in document order, active, gap, shift})` → `{tops: Map<id, top>, height}`, L1 to L7: no active thread, a plain downward stack; an active thread pinned at its anchor with the downward pass `max(anchor, previous bottom + gap)` and the upward pass `min(anchor, next top − gap − height)`; the top clamp re-running the stack downward (L5, the only case the active card leaves its anchor); the bottom growing the height. Deselect relaxes to L1 (Liveblocks; Overleaf's sticky pin rejected so the layout needs no history) **[LC-1 item 3]**. Order is document position of the earliest live range, ties to the older thread. Gap `MARGIN_GAP_PX = 8` **[LC-1 item 2]**, active shift `MARGIN_ACTIVE_SHIFT_PX = 12` **[LC-1 item 2]**.

**D3. The tiers read the side space beside the page, never the window** (`margin-tiers.ts`): `sideSpace = W − P` with `W` the scroll box's client width and `P` the page's rendered width; cards when `sideSpace ≥ CARD_MIN + 2G` at width `min(CARD_MAX, sideSpace − 2G)` with `CARD_MAX = 300`, `CARD_MIN = 200` **[LC-1 item 6]**; else the icon rail (`ICON_PX = 24`, icons closer than one icon's height merged into a count **[LC-1 item 7]**), the column reserving `min(ICON + 2G, sideSpace)` and the icons overlapping the page's right padding when the side space is short (the page keeps its width; Docs' icons sit in the page's margin); under a body of `RAIL_BESIDE_FROM_PX = 720` (P3-F1's, not re-based) the margin is off and today's drawer applies. A `ResizeObserver` on the scroll box and the page supplies `W` and `P` (N4). Minimize gives the icon rail at any width; Hide an empty margin with the passage highlights kept **[LC-1 item 7]**.

**D4. The margin is reserved only while a thread or a compose card is open on the shown tab**: the column's width is the tier's while the shown tab has an open live thread or hosts the compose card, else 0 (the page centred). Moves caused by activation, an add or a resolve animate `top` 200 ms `cubic-bezier(.4,0,.2,1)` **[LC-1 item 2]**; moves caused by an edit, a resize, a font load or the first layout do not; `prefers-reduced-motion` gives 0 ms.

**D5. Only the human activates a thread [binding].** The display plugin activates on a click (as today, the innermost of overlapping passages, L7) and, new, on a local caret move into a passage (a transaction with `selectionSet`, no `docChanged`, not a binding transaction); a caret leaving a passage by the keyboard keeps the active thread (Overleaf's sticky pin for the caret only) **[LC-1 item 5]**; a click on uncommented text clears it (today's). A remote edit (a binding transaction) maps the decorations and keeps `active`; a threads-map change (an agent's reply, resolve or new thread) rebuilds with the old `active`; awareness never reaches the plugin. The margin's own activations (a card click, J and K, the panel's item) go through `setActiveThread`. `rail` gains `'margin'`: the editor reports `'margin'` through `onRailChange` when a margin thread becomes active with no rail open (so an active margin thread and the history rail or the panel are one slot) and `null` when the active thread clears; the header's Comments action toggles `'comments'` ↔ (`'margin'` if a thread is active, else `null`), which is Z5's round trip with the same active thread.

**D6. The shared card (X36).** `ThreadCard` in `src/artifacts/comments/ThreadCard.tsx` with the ledger's props `{thread, active, compact, onActivate, onReply, onResolve, onReopen, draft, onDraftChange}` plus `onNext`, `onPrevious`, `onExit` (J, K, U and Escape), `position` (`{index, count}` for the group's name, K1), `showQuote` (the panel keeps the quoted passage; the margin and the popover do not), `tabTitle`, `readOnly`. `thread` is `ThreadCardThread`, the subset `ThreadState` and `DeckThreadState` share (`id, quote, status, orphan, messages, createdBy, createdAt`). Compact: the first message and the two latest replies, "N more" between; active: every message and the reply field (focused on activation by a card click or R; not on activation by the caret or a passage click, so the text keeps the keyboard). Keys on a focused card outside a text field: R, E, J, K, U, Escape. The author chip from `actorDisplay`. The card's draft (the reply field's text) is the host's through `draft` and `onDraftChange`, so a hidden card keeps it. Styles in `src/artifacts/comments/comments.css`, app tokens.

**D7. The compose card in the margin.** The compose card is P2's card (the comment to a session) hosted by `CommentCardHost`, which gains `layout="margin"`: in flow (`relative`), the card `position: relative; width: 100%`, placed by the new pure `marginCard(box)` in `src/artifacts/comments/placement.ts` beside the moved `placeCard`, `dockCard`, `stripCard`, `stripMax`, `caretOf`, `pinOf` and the constants (the renderer's `side/card/placement.ts` re-exports them). `MarginThreads` renders `comments.overlay({...reach, layoutKey, placement: 'margin'})` inside the entry of the thread the card is on, which it learns through the new `CommentOverlayProps.hosting(threadId | null)` (the renderer's `DocumentCardHost` calls it beside `setActive`), and that thread's `ThreadCard` yields to the card while it is up; the entry's height is measured like any other, so the stack re-lays as the card grows. Outside the margin (the drawer tier, Hide, the panel open) the overlay is drawn over the frame as today, so exactly one host draws the card. `CommentPlacement` (`tools/code/anchor/anchor.ts`) gains `{kind: 'margin', host: 'document', anchorY, stackIndex}` and `{kind: 'pin', host: 'slide' | 'design', pinRect}` (the X21 amendment; the document's `opened` passes `margin` while the margin is on). **D8. ## LC-1 — Docs' margin geometry: what to measure, in which states (runs in the owner's account, X39's rules; not this child's to run)

Setup: one Google Doc in the "MAWS UX check" folder, a 1920 × 1080 window at @2x, the browser's devtools open to read card rectangles from the DOM (`[data-docs-comment-id]`-like nodes; Docs draws text on a canvas, so anchor y comes from a screenshot of the highlight); the window swept from 1600 px down to 600 px in 20 px steps for the width items. Each item names the document state it is measured in and the constant it re-bases.

1. **Card top against the anchor** (P1 to P6; re-bases none, confirms `passageRect`'s first-line rule). States: a one-line passage; a passage wrapping three lines; one spanning two paragraphs; a passage starting in a heading, in a table's right-hand cell, in a list item; a block comment on an image; a passage beginning at a soft wrap. Measure the card's top minus the first highlighted line's top, in px.
2. **Gap, active shift, animation** (re-bases `MARGIN_GAP_PX`, `MARGIN_ACTIVE_SHIFT_PX`, the 200 ms and its easing, and whether edit-caused moves animate). States: three comments on three consecutive lines, none active; then the middle one active (click its card); then type a paragraph above them. Measure the vertical distance between consecutive cards (the gap), the active card's horizontal offset from the inactive column (the shift), the transition's duration and easing (devtools' animations panel or a frame-by-frame recording), and whether the cards move with or without a transition when the paragraph is typed.

## Decision Log

1. **2026-10-20 (the executor), the column inside the scroll box (D1).** The spec's "absolutely positioned column inside `.doc-page-frame`" is read as a column that scrolls with the page: inside `.ds-doc`, the page's flex sibling. The frame-level reading would re-place every card on every scroll, which R4 forbids and which is the very defect row 92 names; the scroll-box reading makes rows 92 and 93 moot by construction. Advisory content (§4.3 binds the card, the activation rule and the view states' names), so recorded here, not as a parent impact.
2. **2026-10-20 (the executor), `rail: 'margin'`'s meaning (D5).** Reported by the editor when a margin thread is active with no rail open, cleared when the active thread clears; the header's Comments action toggles the panel against it. Rejected: `'margin'` as a mode the owner selects (the margin is the default surface, so a selectable mode would be the panel's negative), and `'margin'` as a synonym of `null` (nothing would read it).
3. **2026-10-20 (the executor), the panel keeps its accessible name "Comments".** The margin and the panel are mutually exclusive on screen, so a region "Comments" (the margin) and a complementary "Comments" (the panel) never coexist, and the e2e cases that read `complementary "Comments"` keep their locators; the panel's visible heading says "All comments".
4. **2026-10-20 (the executor), the view states in the View menu as three flat actions** (the action table has no submenu or checked state) and in the editor's toolbar as a radio menu beside "Comments N". Rejected: a submenu (a new menu shape for one feature) and replacing "Comments N" with a menu (every rail e2e case would need a second click).
5. **2026-10-20 (the executor), the draft rule opted into by host (D8).** `CardFrame.keepDraftOnEscape` is set by the document host; the browser and code hosts keep their Escape until their owners adopt the rule (a residue row), since changing a surface outside this child's section without its e2e in the gate is not this child's to do.
9. **2026-10-20 (the executor, at M4's return), M4's readings adopted.** The `margin` placement carries a required `hostId` (one host draws the card) and an optional `stackIndex` (the surface cannot know the stack's order; the margin lays the entry); the host's layout follows the overlay's own `placement`, the placement kind being informational to the store; `CardFrame.draftOf` and an initial `text` for `useCommentForm`, so a card re-mounted between the slot and an entry keeps its typed text (X36's hidden-card rule); a blur discard closes without restoring focus (`onDiscard`) and a null `relatedTarget` (a window blur) keeps the card; Escape-kept goes through `onEscapeKept = restoreFocus`; the C5 body click is every host's, the Escape and blur rules opt-in; `focusDraft` finds the field by `data-card-serial`; a register entry is dropped when its card is no longer this host's composing card, when its host goes for good, or when the text is blank; `draft()` is scoped to this host (a draft on another host of the same artifact is not refocused: a residue row). An inactive compose card after Escape has no styling of its own yet (a residue row).
8. **2026-10-20 (the executor, at M2's return), M2's readings adopted.** The card compacts only while inactive (`compact && !active`), and the panel passes `compact={false}` so it lists every thread whole as before; the card is `role="group"` everywhere (an `<article>` still); the tab dot reads the threads map through `useOpenThreadCounts` rather than `useThreadStates` (which rescans every tab's marks after each typing pause; the strip is always mounted), orphans being open either way; the panel's J and K move focus without activating; the panel passes no `onExit`, so the drawer's Escape is as it was; the old `.doc-thread*` rules leave `chrome.css` for `comments.css`'s `.thread-card*`, the e2e hook classes kept as second classes. A new `.tsx` under `src/artifacts/` outside the directories `tsconfig.node.json` excludes compiles under the classic JSX runtime and fails the node typecheck ("React is not defined"): a B2 popover file outside `slides/editor` or `design/editor` needs an entry (told to the architect for B2).
7. **2026-10-20 (the executor, at M1's return), M1's readings adopted.** `layoutMargin` takes no shift (the shift is horizontal and moves no top; the margin applies `MARGIN_ACTIVE_SHIFT_PX` to the active entry's transform); L5's clamp walks down from each card's upward-pass floor rather than from its anchor, so the active card moves only by the overshoot; an active id outside the entries lays out as none; a body of 0 px (not laid out) is not narrow, as `useRailLayout` reads it; `marginCard(box)` caps the card at `max(320, 0.6 × the scroll box's height)` (the anchored card's own cap; the card sits in the scrolling content, so nothing cuts it); the portable placement's rect type is private. `side/register.ts`'s `openComment` sends any placement but `card` to the sheet: M4 routes `margin` (and B2 `pin`).
