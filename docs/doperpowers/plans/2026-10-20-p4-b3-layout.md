## Decision Log

Residue decisions, grilled against the code at `65143ebe4`; each is the executor's to apply, and a milestone that finds one wrong records a dated line here rather than diverging.

1. **2026-10-20 — The state's home.** The ledger's `MainSplit` is the existing `TabSet` (`src/shared/ipc/schema/layout.ts`): `TabSetSchema` gains `floating: z.strictObject({ sessionTabId: z.string() }).optional()`, absent while docked (never `null`, never `undefined` written). `main.tabs` keeps version 2 and B3 takes no X15 slot: a new reader reads an older value unchanged; an older build reading a value written *while a split floats* rejects `main.tabs` (strict) and falls back to its default tabs, the same downgrade cost `regions` 4 accepted at P3-G; while docked the value is byte-identical to today's.
2. **2026-10-20 — Which pane floats.** A pane can float exactly when its active tab is a `session` tab (an `agent` tab has no composer and clamps). The squeezed pane floats; with two sessions, whichever is squeezed past the threshold floats; with no session, both sides clamp at their floor. "A" is the other pane, of any kind (the prior art's open decision "two sessions in the split", settled by keying on the squeezed pane's kind as §3.4 suggested).
3. **2026-10-20 — The pixel rule.** `splitDrag(width, x, canFloat: {left, right})` in `main/split.ts` is pure: `x` is the left pane's pointer-implied width in px from the region's left edge. Each side's floor is `min(320, floor(width / 2))` (a main region narrower than 640 px splits evenly rather than overlapping; `MAIN_MIN_WIDTH` is 480). Left: `canFloat.left && x < 160` → armed left; else `x < floor` → held at the floor. Right mirrored on `width − x`. Armed iff below the threshold at each move: the same limit both ways (no hysteresis), so 159 arms and 161 disarms with the pane held at 320. The divider's 1 px column is ignored in the arithmetic (the worked numbers: W = 1500, x = 400 gives 400). The model's `setSplitRatio` drops the 25-75 % clamp for a sanity clamp to [0.01, 0.99] (a non-finite ratio reads 0.5); the pixel bounds are the divider's and the render's.
4. **2026-10-20 — The drag is transient.** The divider keeps the live width and the armed side in the main area's own state (or a transient store field); nothing reaches `main.tabs` until release. Release, not armed → `setSplitRatio(left / width)`; release, armed → `floatSplit` with that pane's session tab, `splitRatio` untouched (so Dock returns `r0` with nothing to restore). `pointercancel` or a lost capture → nothing written (docked at `r0`). Keyboard on the divider keeps the Resizer's rules within the pixel bounds (arrows 8 px, Shift 32, Home/End to the floors, Enter and double-click to 0.5) and never floats. The generic `app/Resizer.tsx` stays as it is for the regions; the split divider owns its pointer handling (the Resizer clamps before `onChange`, which hides the raw value the arm needs).
5. **2026-10-20 — Rendering through the gesture.** While armed, S stays mounted at 0 px (its column and strip collapsed, the divider at the edge under pointer capture) so a disarm is lossless; on float S's `Pane` is not rendered in the main area and the card is S's only mount; A's `Pane` keeps its position among `MainArea`'s children through arm, disarm, float and dock, so A's editor never remounts. While floating there is no divider and no `DropEdge`. The rendered widths clamp the stored ratio to the floors at every width (the resize rule: a window resize only clamps, never floats or docks).
6. **2026-10-20 — Validity is normalised, not policed.** After every model transition (`onSet`) and at hydration (`repairMain`), `floating` is dropped when the set no longer has two panes, its tab is not the active tab of a pane, or that tab is not a session tab. This one rule gives the §3.3 rows: A's last tab closing → S shows full width; S's session tab closing → A alone (S's pane emptied) or the split docked at `r0` on S's next tab; any tab change in S docks; a tab set switch leaves the other set's float stored and hidden.
7. **2026-10-20 — Focus.** A float (release or Expand) marks S's session for focus on mount (`markFocusOnMount`), so the card's composer takes the keyboard, and sets `focusedPane` to S: the card stands for S (the panel shows S's session, ⌘W closes it), as P3-G's card stands for the shown session. A press or focus in A focuses A as today; a press or focus in the split card focuses S. While a split floats with its card closed to the pill, `focusedPane` moving to S (a sidebar click, attention navigation, ⌘⇧\) opens the card and focuses its composer. Dock marks S's composer for focus and keeps `focusedPane` on S.
8. **2026-10-20 — One card at a time.** `floatPanel` (the divider past the maximum, ⌥⌘B, the header's Float) docks a floating split first; `togglePanelFloat` with a split card up docks that split and does nothing else (⌥⌘B docks the split card first; a second press floats the panel). 25. **2026-10-20 — R-1's verdict: the explicit carry, the UndoManager lifted into the tab state; no keeper now.** The spike (`spikes/p4-reparent/findings.txt`, merged from `worktree-agent-a17270890baefaf56` at `0dd68ec14`; Electron 44.4.5, Chromium 152.0.7977.130, React 19.3.0, TipTap 3.31.3, @y/prosemirror 2.0.0-15, MAWS's own `collab.ts` binding) found reparenting possible but not free: `moveBefore` keeps an iframe's window, focus, a CSS transition and an unfocused scroller, but both it and `insertBefore` collapse the selection, and with the focus inside a tall contenteditable `moveBefore` scrolls it to 0; a reverse portal keeps the React instance (0 remounts over 6 moves) but its events reach the keeper's React ancestors, never the destination pane's (`onPointerDownCapture` pane focus would go silent), and it reads the keeper's contexts. A keeper would need an offscreen parking holder, a per-kind focus-and-scroll fix-up after every move, pane handlers moved to native listeners, and a keep-alive policy for hidden tabs to help row 147 at all. The explicit carry costs less and fixes more: the hold hand-off (Decision Log 19) plus a small memento per kind (scroll; selection as Y relative positions; whether it had focus), and, for documents, an UndoManager per document tab owned by the tab state and swapped into each new view (`tr.setMeta(yUndoPluginKey, { undoManager })`, the swap @y/prosemirror 2 supports: the view's destroy then detaches it, and two trusted ⌘Z after a remount undid edits made before it). That also fixes row 147's undo for an ordinary tab switch, since the hold outlives the body. What stays: an iframe-backed view (the html and file viewers, the design-system canon) reloads at its top when it moves, and a remount still redraws (the row's other half). A keeper becomes the better pick only for a kind whose live state sits in a frame, is costly to save and whose reload the owner would notice; it would be scoped to that kind.
