## Purpose

P5 makes MAWS one app over the owner's machines. Every child before this one builds the new way in beside the old: the hub serves the desk's phase-1 protocols and the new ones side by side, the endpoint module runs unenrolled on every machine that runs master, and sminos keeps its own uplink until an enrolled endpoint welcomes it. O14 is the move itself. After it:

- each of the owner's machines, the devcloud acceptance VM first, then the mini, then the MacBook, is enrolled under its own key and its own name in the signed org state, talks to the hub only through its endpoint, and runs its sminos local-only, with the phone still answering and the logs still readable on every machine not yet moved;
- a devcloud VM enrolls itself at boot under a delegation and retires itself when it is deleted, with no hand in it;
- the shared org key of desk phase 1, the one secret every machine and browser held, is retired: no wrapped copy at the hub, no phase-1 route, no machine coding anything with it.

**How to see it working.** On a cut-over machine, `sminos daemon status` says `uplink: RL10 (local-only)` and `mawsd keys --json` says `"enrollment": "org-listed"`; a `sminos say` from it reaches a session on a machine not yet moved, and one from that machine comes back labelled `(unverified, legacy)`; its daemon runs no DX2 uplink, and the hub lists it `listed`. After the final brief, `mawsd endpoint status --json` on every machine says `"legacyKey": false`, and `curl -sI -X POST https://desk-hub.opencognita-platform.workers.dev/machine/stream` answers 404.

The document has two parts. **The shared build** (M1 to M5, one PR each) is what a `doperpowers:plan-executor` builds from this document and the code. **The briefs** (B0 to B4) are the runbooks the owner's session runs, one machine at a time, each step with its check and its undo, the owner at every gate; a brief is run by the session that owns this document, never by a plan-executor, and the mini only through `mini-ops` at the owner's request.

## Terms

- **DX1** is desk phase 1's coding: HMAC-SHA-256 under the shared **org key** over every log event, RPC, request and settlement (`sminos_codes.py`, `apps/desk-web/src/log/verify.ts`). **DX2** is sminos's own uplink to the hub, SSE down and `POST /machine/frames` up (`sminos_uplink.py`). **DX6** is the browser's RPCs and cards through the hub. **DX7** is phase-1 enrollment: a code carrying the org key, redeemed by `sminos hub enroll` into `~/.claude/sminos/daemon/hub.json`, which holds the machine's Access service token and the key. In this document "the legacy key" is that org key.
- **The endpoint** is `src/endpoint/`, the module inside `mawsd` that holds the machine's key and its only hub connection (**RL1**), serves device channels (**RL2**) and the sminos socket (**RL10**). Its state is `<profile>/mawsd/endpoint/` (O10's Interfaces §E); `<profile>` is `~/Library/Application Support/MAWS` on macOS and `${XDG_CONFIG_HOME:-~/.config}/MAWS` on Linux.
- **Enrollment states** are the endpoint's: `none`, `hub-confirmed` (the hub minted its credential) and `org-listed` (a signed org state lists its key, or a live certificate covers it). The endpoint serves RL10, writing `rl10.json` and binding the socket, only while `org-listed` (P5 Decision Log 55).
- **The cutover** of a machine is sminos's switch: the first RL10 `welcome` whose identity is complete (`org`, `hub`, `name`, `ref`, `enrolled`) writes `~/.claude/sminos/daemon/identity.json`, and from then on the daemon starts no DX2 uplink, codes nothing, and refuses `hub enroll`, `hub check` and `hub leave` (O12 M5). A machine with that file is **cut over**. Its `hub.json` stays until B4, because sminos answers the endpoint's `legacy-key?` from it.
- **Dual-coding** is the endpoint signing each outbound event v2 and adding the DX1 `mac` as well, so machines not yet moved can read it; **single-trust inbound** is the cut-over machine taking execution input only through RL2 and RL4, never from a DX1 code (RL §9). **Re-attestation** is a cut-over machine signing its own phase-1 history once, so it stays verifiable after the key retires.
- **A delegation** is an org-state entry `{id, pub, prefix, expires, maxUses, offlineRevokeS, owners}` whose private key lets a booting VM certify itself under a name beginning with `prefix` (RL §5.3); **a certificate** is the VM's own signed `MachineCert`; **a provisioning code** is the text a secret store holds so the boot can redeem one.
- **A brief** is a runbook: ordered steps, each with what to do, how to check it held, and how to undo it. **`[owner]`** marks a step that waits for the owner's word or hand. **`[mini-ops]`** marks a step the owner asks the mini-ops session to run on the mini; nothing in this document runs on the mini any other way.

## Acceptance

P5's O14 items 1 to 5 hold per machine, and its final brief's five effects hold at the end. They are checked as follows (commands in Concrete Steps and in the briefs), with four items this document adds (6 to 9).

1. **Re-enrollment.** Each machine is `org-listed` under the name it had on DX2 (`mawsd keys --json`), by a member's code for the Macs and by a certificate under the devcloud delegation for the VM; the VM's ref starts with the delegation's id and `_` (`mawsd status` prints `machine <id>_…`); the hub's `GET /api/machines` lists each with `key.listed: true`; until listed, `mawsd endpoint status` shows `hub-confirmed` and the machine executes nothing from outside (O10 acceptance 3's cases hold).
2. **History.** For every project the machine wrote to and every writer under its current and former names, the hub holds a history attestation signed by the machine key covering every DX1 event (`mawsd endpoint attest-history --check` prints `verified` for each writer and no `missing`). Drawing them as "attested at migration by `<machine>`" is O7's and O8's (Decision Log, below); this child proves the record verifies.
3. **Single-trust inbound, dual-coded outbound.** A `sminos say` from a cut-over machine arrives on a machine not yet moved as readable words (`sminos chat` there shows it with no `(unverified)` mark); one the other way arrives on the cut-over machine as `(unverified, legacy)`; a DX6 RPC at a cut-over machine fails `unsupported` at the hub, which the hub's own test pins (`apps/desk-hub/src/objects/project.ts`'s browser `rpc` on an RL1 machine) and no brief exercises, since the VM has no card and the mini's cards are on web-cards before it moves.
4. **The phone.** A question from a cut-over mini reaches the phone through O13's web-cards and is answered there; the VM is answered by nobody and needs nothing; the MacBook's own sessions are local.
5. **sminos.** `sminos daemon status` says `uplink: RL10 (local-only), running (<pid>)`, `sminos hub show` prints the identity marked `cut over`, and `GET /api/machines` shows the machine `listed` with its DX2 presence `online: false` once its last lease lapses (an RL1 machine's presence reaches the relay alone, P5 Decision Log 37); the sminos installed is at or above 1.26.0 before the endpoint enrolls; `hub.json` is present until B4 and `mawsd endpoint status --json` says `"legacyKey": true` until B4.
6. **A VM provisions and retires itself.** A devcloud VM created with `--project maws` under M3's devcloud boots, installs `mawsd` with its delegation's prefix, redeems the provisioning code from Secret Manager, is `org-listed` under a certificate and cut over, with no hand in it; `devcloud vm down` retires its certificate and frees its hub row, so `GET /api/machines` no longer lists it and a recreated VM may take its name; a forced delete prints the admin command that does the same from the Mac.
7. **Production is administered only on purpose.** Every `deployment org` command refuses production unless `--production` is given and `config.json`'s `orgGenesis` matches the hub's genesis; staging and loopback work as before; nothing prints a key, a token, a pairing secret or a code except the one line a code is shown on, once.
8. **The undo of each brief step works as written**, exercised at least once in B1: a cutover undone leaves the VM on DX2 with a working credential, and redone cuts it over again.
9. **The final state.** On every machine `mawsd endpoint status --json` says `"legacyKey": false` and `"legacyRetired": true`, `hub.json` is gone, an event from one machine arrives at another verified v2-only (no `mac` in the stored event, `sminos chat` shows it plain); at the hub, `GET /api/org/keys` answers `410 retired` with no copies, and `/machine/stream`, `/machine/frames`, the browser's `rpc`, the v1 codes and the org-key routes answer 404; `X-Desk-Build` names the build M5 produced.

### M1 — The v2 provisioning code, its redemption and the certificate's retirement (MAWS)

**At its end.** A `smns-provision-v2.` code exists as a codec in `apps/org-protocol`; `mawsd endpoint provision` redeems one from stdin into a live certificate under the delegation, keeping what the retirement later needs; `mawsd endpoint retire` retires that certificate and frees the machine's hub row, so a recreated VM can take the name. A code that carries the legacy key leaves the endpoint dual-coding from its first event, with no `hub.json` on the machine at all.

**Touches.** `apps/org-protocol/src/provisioning.ts` (new; exported from the package's index), `apps/org-protocol/test/provisioning.test.ts` and the vectors; `src/endpoint/cli.ts`, `src/endpoint/enroll.ts`, `src/endpoint/state/store.ts`, `src/endpoint/status.ts`, `src/endpoint/index.ts`; `test/endpoint/enroll.test.ts`, `test/endpoint/cli.test.ts`, `test/endpoint/status.test.ts`. Nothing in `apps/desk-hub` (its routes exist) and nothing in `src/mawsd` (O2's; `mawsd endpoint <cmd>` passes through).

**Decisions.**
- **The codec lives in `org-protocol`, beside `enrollment.ts`**, as `smns-provision-v2.` + base64url of UTF-8 JSON, the shape Interfaces §A fixes: `enrollDelegated`'s fields but `name`, plus an optional `legacy`. P5 Decision Log 35 said "beside `smns-enroll-v2.`", which turns out to live in `apps/desk-hub/src/protocol/identity.ts` with the phase-1 vocabulary that retires at B4; a code that outlives the retirement belongs with the enrollment MAC in the package every consumer imports. Unknown fields are refused, `privateJwk` must be a P-256 private JWK whose public point equals the delegation's `pub` in the state (checked at redemption, not at decode), and the decoder's refusals are named strings as the v1 decoder's are (`not smns-provision-v2`, `damaged`, `no <field>`). The hub never sees the code: it sees the token.
- **The code may carry the legacy key during the migration window** (`legacy: {org, key}`, the DX1 org key as base64url, the same bytes today's v1 code carries). `provision` stores it as `legacy.json` exactly as RL10's handover would, so the endpoint never asks `legacy-key?` and dual-codes from its first event. This is what lets a VM born after M3 skip DX2 entirely: no `sminos hub enroll`, no `hub.json`, no DX2 row at the hub to go stale (the carry note's stale machine), no credential to die at redemption. Rejected: enrolling new VMs on DX2 first so sminos can hand the key over, which creates the very row the delete hook was asked to clean up, and which has no in-place path to a certificate (`409 name-taken`). The field leaves the code at B4 (M2's `code strip-legacy`). RL §5.3's rule that a code carries no org key is the member code's; the provisioning code is a secret-store artifact that holds the org key today.
- **`mawsd endpoint provision [--name N] [--wait [s]] [--json]`.** The code comes on stdin or a hidden prompt, never argv (O2's `secret` field, as `enroll`). The name defaults to the machine's host name lower-cased (on a devcloud VM that is `DEVCLOUD_NAME`, which is also sminos's name), and `--name` overrides it; a name outside the prefix is refused before any hub call, as is a ref without `<id>_` (`enrollDelegatedInto`'s checks, surfaced with their reasons: `ref-prefix`, `name-prefix`). It then runs `enrollDelegated`, writes `delegation.json` (Interfaces §B: the delegation's id, prefix and private JWK, 0600) and `legacy.json` when the code carries one, and waits for the certificate to be live (`org-listed`) up to `--wait` (default 300 s), exiting 0 when it is, 4 while `hub-confirmed`, 1 on refusal, 2 with no endpoint module, 3 with no daemon. It is idempotent on a machine already `org-listed` under the same delegation (exit 0, nothing posted), so a boot step may rerun it. Rejected: teaching `enroll` both prefixes under one verb, which would make the attended flags (`--replace`) meaningless for a certificate and the certificate's (`--not-after`) meaningless for a member code.
- **The endpoint keeps the delegation key.** RL §5.3 accepts that a VM under a delegation holds its key (every VM under it can read the secret store anyway, and the remedy for a compromised VM is revoking the delegation), and the retirement record must be signed by it (RL §5.2). Rejected: re-reading the secret store at departure, which fails exactly when departure is already in trouble (a reclaimed spot VM, a VM whose ADC is gone).
- **`mawsd endpoint retire [--not-after <ISO>] [--json]`** signs `CertRetirement {org, keyId, notAfter}` with `delegation.json`'s key under `smns-cert-retire-v1`, `notAfter` defaulting to now plus 60 s of skew margin (RL §5.2: set once the key is gone, with a margin), posts it to `POST /machine/cert-retirements`, then `DELETE /machine/enrollment` so the hub row and its credential go too (both are needed before a recreated VM may take the name: `apps/desk-hub/test/org-delegations.test.ts`), stops the hub link, removes `rl10.json` and the socket, and exits 0 printing `retired: <name> (certificate <keyId> not after <ISO>); the hub row is gone`. It refuses on a machine with no `delegation.json` (`not-delegated`, exit 1): an enrolled machine's key is retired by an admin's state change, never by itself. It is idempotent: a second run finds no credential and exits 0 saying so. After it, the endpoint is unenrolled (`enrollment: none`) and sminos, cut over, waits for an endpoint that never comes; the VM is about to be destroyed, which is the only reason to run it.
- **Status** gains `delegated: boolean` and the retirement's outcome is not status: a retired machine has none.

**Does not touch.** The admin side that mints a delegation and emits the code (M2). devcloud (M3). The attended `enroll`. The hub.

**Proves.** Acceptance 1's delegated half and item 6's machine half. Tests: the codec's vectors (round trip, each refusal, the optional `legacy`); `provision` against the local hub with a delegation the local `OrgAdmin` signs, end to end to `org-listed`, the certificate served beside the state; a code whose key doesn't match the state's `pub` refused at redemption with nothing posted; a ref without the prefix and a name outside it refused before any hub call; `legacy` kept at 0600 and no `legacy-key?` asked at the first RL10 hello (the fake sminos sees none; `status().legacyKey` true); a second `provision` on a listed machine posting nothing; `retire` freeing the name (a recreated fake VM under the same delegation enrolls under it) and leaving no row in `GET /api/machines`; `retire` refused on an attended enrollment; the status redaction test extended to `delegated`.

### M4 — History re-attestation (MAWS)

**At its end.** A cut-over machine signs its DX1 history once, per project and writer, the hub keeps and serves the attestation beside the project's log, and anyone holding the org state can verify that a writer's phase-1 events up to a sequence number are the ones the machine wrote. After B4 the attestation is the only thing that vouches for those events.

**Touches.** `apps/org-protocol/src/history.ts` (new), `types.ts` (the domain), its vectors and tests; `apps/desk-hub/src/objects/project.ts` (the table and routes), `src/worker.ts` (routing), `apps/desk-hub/test/history-attestations.test.ts` (new); `src/endpoint/cli.ts`, `src/endpoint/history.ts` (new), `src/endpoint/hub-http.ts`; `test/endpoint/history.test.ts` (new).

**Decisions.**
- **A record per (project, writer), not a re-upload.** Stored positions are immutable at the hub (`log-store.ts`'s `sameEvent`; a re-signed resend is a `conflict`), so history can't gain a `sig` in place. The record is Interfaces §D's `HistoryAttestation {org, project, writer, upTo, digest, created}` signed by the machine key under `smns-history-attest-v1`, where `digest` is the running SHA-256 over the canonical body of each event from seq 1 to `upTo`, `mac` excluded (`h_0 = ''`, `h_i = SHA-256(h_{i-1} ‖ canonical(event_i without mac))`), so a verifier with the stored events recomputes it in one pass. RL8 offered a per-event path or a checkpoint; the checkpoint costs one signature per writer and one hash per event, and binds the whole prefix, so a hub that dropped or altered an event inside it fails the check as a whole. The machine attests only events whose `mac` it verifies under the legacy key as it builds the digest; a writer whose events include one that fails is reported and not attested (`attest-history` prints `skipped <writer>: seq N fails its code`), since the machine can't vouch for a body it didn't write.
- **Who signs, for which writers.** The machine key signs, for every writer under its current name and every former name `machineNames` binds to its ref (the endpoint's head holds both), in every project of the org state's `projects` whose log it can read; the machine's own project included. `hub/<member>` writers (desk-web's words) are nobody's to attest: RL §9's "history is imported as inert records" is what they stay.
- **The source of the events is the hub.** The endpoint reads its own writers' stored events with its service token through a new machine-principal read, `GET /machine/projects/<id>/log?writer=<w>&after=<seq>`, paged at about 1 MiB like the org-state read (Interfaces §D); it does not read sminos's files (O6 and O10 refused that coupling) and the log plane's `hello`/`have` is sminos's connection, not a reader. If the Project DO already serves a member read of the same shape, the executor opens it to the machine principal rather than adding a second; the payload is the same.
- **`mawsd endpoint attest-history [--project <id>] [--check] [--json]`.** Without `--check`: for each project and writer, page the events, verify each code, fold the digest, sign, post `POST /machine/projects/<id>/attestations`, and print one line per writer (`attested <project>/<writer> through <upTo>`), `skipped` lines as above, and a summary; it is idempotent (a stored attestation at the same `upTo` is left alone; after a cutover no DX1 event is added under an own writer, so a rerun changes nothing). With `--check`: fetch the stored attestations (`GET /machine/projects/<id>/attestations`), recompute each from the stored events and print `verified`, `mismatch` or `missing` per writer, exit 0 only when every writer is `verified`; this is acceptance 2's check and B4's precondition. It needs the legacy key for the first form (held until B4) and the org state for both.
- **The hub keeps the newest per writer** (`attestations(writer, upTo, record)` in the Project DO's SQLite, `CREATE TABLE IF NOT EXISTS`, no migration tag), accepts a record only when its signature verifies against the head's machine key or a live certificate for the signer's ref and `writer`'s name is bound to that ref (a courtesy check, as every hub check is), refuses a lower `upTo` than stored (`409 stale-attestation`), and serves them to members (`GET /api/projects/<id>/attestations`) and machines. Verification by readers is `org-protocol`'s `verifyHistoryAttestation(record, events, head, certificates)`.
- **Readers draw it later.** The app's "attested at migration by `<machine>`" is O7's log views and O8's project channel (P5 §8); sminos labels nothing by it, because a DX1 event is a peer message on every machine whatever its attestation says. The endpoint's inbound path is unchanged by M4; M5 is where "no legacy key" meets a v1 event.

**Does not touch.** The endpoint's inbound verification (`log-relay.ts`). sminos. desk-web.

**Proves.** Acceptance 2. Tests: the record's vectors (sign, verify, a changed event, a dropped event, a wrong writer binding, a retired key at and after `notAfter`); the hub storing, refusing a lower `upTo`, a bad signature and an unbound writer, and serving; the endpoint attesting two projects with a current and a former name against the local hub and a seeded DX1 log, skipping a writer with a bad code, idempotent on rerun; `--check` reporting `verified`, `mismatch` after the test alters a stored event in the local hub, and `missing`.
