### The released spread, and the estimate for O3-D

spine-3 released only 2,256 KiB, where the other two released about 7 MB.

**Cause.** The spine root composes no quiet collection (`@shared/host/idle-collect`), and `idleReading`'s release runs the runtime's plain `gc()` twice. That is a full mark-compact, but not the `last-resort` flavor that shrinks the young generation and returns its pooled pages. The released window therefore keeps whatever new-space sizing the loaded phase left, which varies from run to run: P5 Decision Log 133's pattern. The readers agree (40,065 then 37,809 KiB; top 39M then 37M). The case logs whether gc ran, but not the heap before and after.

At the architect's ruling, `idleReading` stays as it is so the series stands. Changing it is residue.

**No bound.** The reading is diagnostic (D18, O3 §11), and the case asserts nothing against a bound.

**Estimate for O3-D.** O3-D's own measurement settles this. The nearest bound is `DAEMON_IDLE_BOUND`, 99,145 KiB, which leaves `MAWSD_HEADROOM_KIB` = 33,048 KiB beside the engine host's baseline of 66,097.

- Against that headroom, the released readings sit at +775, +567 and −4,761 KiB. The loaded readings are 6.4 to 7.0 MB over.
- Net of the 13,153 KiB runtime floor, which `mawsd` already pays, the spine adds 19.1 to 24.7 MB released (26.3 to 26.9 MB loaded).
- Next to `mawsd`'s own 29,409 KiB (the A-B-A daemon window), that totals about 48.5 to 54.1 MB against 33,048 KiB.
- The spine in `mawsd` inherits `mawsd`'s `idleCollector`, and its release should call `dropped()`.
- The arithmetic points to §11's cold core and re-execution, not release alone.

The architect carries this into O3's Decision Log as a parent-impact note on O3-D's acceptance.
