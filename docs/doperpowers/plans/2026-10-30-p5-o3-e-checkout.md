## Purpose

After O3-D the spine runs in `mawsd` on the daemon shape, but the services that read a session's checkout still run in the app: the read-only git service and its repository watcher (`git.status`, `git.diff`, `git.watch` and `git.changed`), the `@` menu's file listing (`git.lsFiles`), the Files pane and editor (`files.*` with `files.changed`) and source control (`scm.*` with `scm.remote.output`). So today a remote panel's diff, file tree and editor have no machine-side service to read (O7 M4 waits on this), a machine with no app answers nothing about its checkouts (`e2e:machines`' Environment card shows no branch for a daemon-only machine), and an upload from another device has nowhere to land.

O3-E moves those services into `mawsd`. After it, on the daemon shape:

- **The checkouts are the machine's.** `git.*`, `scm.*`, `files.*` and `git.lsFiles` are `machine`-owned commands that `mawsd` serves on `machine.sock` to every client, their events (`git.changed`, `files.changed`, `scm.remote.output`) fanned out like the spine's. The app forwards them through its router's `host` binding, as it forwards `session.*` since O3-D; another machine's app reads them over the O6 link; the endpoint can dispatch them (O7 M4 adds the offer rows).
- **A watch belongs to the client that asked.** Each `machine.sock` client's pages count their own `git.watch` and `files.watch` holds, released when the page or its connection goes (survey §4.2), exactly as main counted them per window. Reveal and open-externally reach the asking client through the client port (OX4).
- **Mutations run under the services' ledger.** `scm.stage`, `scm.commit`, `scm.push`, `files.write` and the new upload are `machine`-owned acts, so `machine.op` claims them and a remote act runs once (O3X7).
- **Uploads have a home.** `files.upload` writes bounded bytes into the session's attachments directory on its machine, so a message's paths are the machine's (O7's C8, P5 §5).
- **The Linux watch does not go dark.** On Linux (`mawsd` on the devcloud VMs) the repository watcher and the engine host's store watcher use a directory-level watch tree MAWS owns, instead of Node's recursive `fs.watch`, which O3-G measured taking a watch per file, holding the loop for seconds on a burst and failing silently at the inotify limit. macOS keeps FSEvents.
- **The laptop pays nothing more while idle.** The checkouts compose with the spine: loaded when the spine loads, released when it releases, never resident in `mawsd`'s cold core.

The embedded shape (`supervisor.shape: embedded`) still composes everything in main, so the app works in either shape.

**How to see it working.** On a scratch profile on the daemon shape, open MAWS, start a session in a repository, open its Files pane and its Environment row; `mawsd status` shows the spine `loaded`; edit a file outside MAWS and the pane updates (`files.changed` came from `mawsd`); `mawsd logs --follow` shows `[git] …` lines for the watched root. Start a second machine's app over the O6 link (`e2e:machines`' scene) and its Environment card shows the branch of a checkout only the daemon-only machine has. Concrete Steps has each command; the e2e groups named in Acceptance prove each behaviour on the gate's Macs.

### M1 — The watch tree: a directory-level watch MAWS owns on Linux, for both watchers

**At its end.** `src/shared/fs/watch-tree.ts` exists (Interfaces §A): `watchTree(root, options, listener)` returns a handle with `close()` and `on('error', …)`, watching the root and every directory under it that the prune predicate admits with one non-recursive `fs.watch` each, walked asynchronously, adding a directory when its parent reports its creation, closing a directory's watch when it is removed, naming each event by the path relative to the root (what both watchers' classifiers read), reconciling on a slow timer and after bursts, and reporting a watch call's `ENOSPC` or `EMFILE` as an `'error'` with that `code` after closing the partial tree. `recursiveWatch(platform)` (same module) answers the `WatchFn` the platform uses: the tree on Linux for `recursive: true`, Node's `fs.watch` everywhere else and for `recursive: false`. `src/services/git/watcher.ts` takes it as its default watch, gives the tree a git-aware prune (Interfaces §B) and treats an exhaustion error as the root's `polling` state. `src/engine-host/fs/watcher.ts` takes it as its default watch with the store's prune. On a Mac nothing changes. The VM run records the numbers.

**Decisions.**
- The tree lives in `src/shared/fs/` (beside `atomic-write.ts`), neutral ground the engine host and the library both import; it imports Node's builtins alone, so the services chunk and `mawsd`'s graph admit it (D13). Rejected: a module under `src/services/` that the engine host imports (lint rule B fences the library), or two copies.
- The tree never watches a file: inotify names a directory's changed children, which is all either classifier reads (O3-G item 1). An event in a directory is reported with the child's relative path; the directory's own removal closes its watch and is reported by its parent.
- The prune predicate is the caller's (§B for git: what git ignores, read once at the root's watch start by `git ls-files -o -i --exclude-standard --directory` and for a directory created later by `git check-ignore`, batched per reconcile; and `objects/`, `lfs/` under the git dir and the common dir). The tree keeps every ancestor of an admitted path and prunes only a directory the predicate names (O3-G item 2: the prune is never "classifies null", since `refs/` classifies null and the refs under it matter). The store's prune drops only subtrees every path of which classifies null (`tool-results/` and `memory/` under a session's directory, by `classifyStoreEvent`); the executor confirms each against the classifier.
- The walk is asynchronous with bounded concurrency (an `opendir` per directory, at most 8 in flight), so the loop is never held for a tree (O3-G item 3); a watch is placed on a directory before its children are listed, so a child created during the walk is seen by its parent's watch or by the listing, and a child seen twice is watched once.
- Exhaustion: a watch call that throws `ENOSPC` or `EMFILE` closes every watch the tree holds and emits `'error'` with the throw's `code` and the directory's path (O3-G item 4); the tree is then closed and emits nothing more. The repository watcher's `onError` today only warns; from M1 an error whose code is `ENOSPC` or `EMFILE` puts the root in `polling`: its handles closed, `git status` read every `POLL_MS` (5 s, doubled to 10 s after a status timeout as `BACKOFF_MS` already does) with `git.changed` emitted when the projection moved, one log line `[git] watch exhausted under <root> (<code>): polling`, and the state kept until the root is unwatched (no re-attempt: a budget that was short stays short while the other trees hold it). The store watcher keeps its re-open after `REOPEN_MS` for other errors and, for an exhaustion code, logs once and stays `failed` with its reconcile scan the fallback (`src/engine-host/fs/service.ts`'s `reconcileMs`, untouched). Rejected: a wire field saying a root polls, since no surface reads it yet (D12).
- Reconciliation (O3-G item 5): the tree re-walks its admitted directories every `RECONCILE_MS` (120 s) and once, `BURST_SETTLE_MS` (1 s) after a burst (at least `BURST_EVENTS` (200) events within 1 s); a re-walk that finds a directory it did not watch, or one that follows a burst, emits one event with `filename` null, which both watchers already read as a rescan (the git watcher's `changed(root, 'worktree')` runs one status; the store watcher's `rescan` readdir-diffs the root); a quiet re-walk that finds nothing emits nothing, so an idle root costs a directory listing every two minutes and no status. The numbers are advisory; the executor keeps them as named constants.
- The handle's `on('error')` and `close()` are the only surface; the tree logs nothing itself (the callers log). A watch call's `ENOENT` (the directory vanished between the listing and the watch) drops that directory silently; `ENOENT` at the root itself throws from `watchTree` as `fs.watch` would, so a caller that cannot open a root fails its call as today.
- Linux-only integration cases run on the pool (`describe.runIf(process.platform === 'linux')`): a scratch tree with real inotify; events relative to the root; a directory created after the watch has its children reported; a removed directory's watch closed (its descriptor gone from `/proc/self/fdinfo`); a 2,000-file burst in one new directory names every file within 1 s. Exhaustion is not inducible without `sysctl` and is pinned with the injected fs (the Nth watch throws `ENOSPC`); the VM's arm proves it real.
- The VM measure (Interfaces §G) is this milestone's proof for acceptance 6 and needs the architect's go for the VM; its numbers and verdict go into Surprises & Discoveries, and a miss of a bound is a finding for the architect, not a widened bound.

**Does not touch.** The classifiers, debounces and projections of either watcher; main; `mawsd`; the wire; `src/engine-host/fs/service.ts` and `register.ts` (the in-flight branches' files: the engine host takes the tree through `watcher.ts`'s default alone).

    export type WatchListener = (event: string, filename: string | null) => void; // filename relative to the root, '/'-joined as fs.watch gives it on the platform; null: rescan the root
    export interface WatchHandle { close(): void; on(event: 'error', listener: (error: NodeJS.ErrnoException) => void): unknown }

      prune?(dir: string): boolean | Promise<boolean>;  // `dir` relative to the root; true: never walk or watch it (its ancestors are watched regardless)
      reconcileMs?: number;                             // RECONCILE_MS, 120_000
      burst?: { events: number; windowMs: number; settleMs: number }; // BURST_EVENTS 200 within 1_000 ms; BURST_SETTLE_MS 1_000
      concurrency?: number;                             // directories listed at once, 8
      fs?: Pick<typeof import('node:fs/promises'), 'opendir' | 'lstat'> & { watch: typeof import('node:fs').watch }; // tests
    }
    export function watchTree(root: string, options: WatchTreeOptions, listener: WatchListener): WatchHandle;
    // The platform's recursive watch: `watchTree` on Linux for `recursive: true`, `fs.watch` otherwise.
    export type WatchFn = (path: string, options: { recursive: boolean; prune?: WatchTreeOptions['prune'] }, listener: WatchListener) => WatchHandle;
    export function recursiveWatch(platform: NodeJS.Platform = process.platform): WatchFn;

`watchTree` places the root's watch synchronously (so a caller's `ENOENT` at the root throws from the call, as `fs.watch` does) and walks the rest asynchronously. Every error but the root's `ENOENT` reaches `on('error')`; an exhaustion code (`ENOSPC`, `EMFILE`) closes the tree first. `close()` closes every watch, cancels the timers and emits nothing more. Both watchers' `WatchFn` types (`src/services/git/watcher.ts`, `src/engine-host/fs/watcher.ts`) are satisfied by `recursiveWatch()`; the git watcher passes its prune per call.
