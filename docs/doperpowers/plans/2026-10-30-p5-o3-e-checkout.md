## Purpose

After O3-D the spine runs in `mawsd` on the daemon shape, but the services that read a session's checkout still run in the app: the read-only git service and its repository watcher (`git.status`, `git.diff`, `git.watch` and `git.changed`), the `@` menu's file listing (`git.lsFiles`), the Files pane and editor (`files.*` with `files.changed`) and source control (`scm.*` with `scm.remote.output`). So today a remote panel's diff, file tree and editor have no machine-side service to read (O7 M4 waits on this), a machine with no app answers nothing about its checkouts (`e2e:machines`' Environment card shows no branch for a daemon-only machine), and an upload from another device has nowhere to land.

O3-E moves those services into `mawsd`. After it, on the daemon shape:

- **The checkouts are the machine's.** `git.*`, `scm.*`, `files.*` and `git.lsFiles` are `machine`-owned commands that `mawsd` serves on `machine.sock` to every client, their events (`git.changed`, `files.changed`, `scm.remote.output`) fanned out like the spine's. The app forwards them through its router's `host` binding, as it forwards `session.*` since O3-D; another machine's app reads them over the O6 link; the endpoint can dispatch them (O7 M4 adds the offer rows).
- **A watch belongs to the client that asked.** Each `machine.sock` client's pages count their own `git.watch` and `files.watch` holds, released when the page or its connection goes (survey §4.2), exactly as main counted them per window. Reveal and open-externally reach the asking client through the client port (OX4).
- **Mutations run under the services' ledger.** `scm.stage`, `scm.commit`, `scm.push`, `files.write` and the new upload are `machine`-owned acts, so `machine.op` claims them and a remote act runs once (O3X7).
- **Uploads have a home.** `files.upload` writes bounded bytes into the session's attachments directory on its machine, so a message's paths are the machine's (O7's C8, P5 §5).
- **The Linux watch does not go dark.** On Linux (`mawsd` on the devcloud VMs) the repository watcher and the engine host's store watcher use a directory-level watch tree MAWS owns, instead of Node's recursive `fs.watch`, which O3-G measured taking a watch per file, holding the loop for seconds on a burst and failing silently at the inotify limit. macOS keeps FSEvents.
- **The laptop pays nothing more while idle.** The checkouts compose with the spine: loaded when the spine loads, released when it releases, never resident in `mawsd`'s cold core.

The embedded shape (`supervisor.shape: embedded`) still composes everything in main, so the app works in either shape.

**How to see it working.** On a scratch profile on the daemon shape, open MAWS, start a session in a repository, open its Files pane and its Environment row; `mawsd status` shows the spine `loaded`; edit a file outside MAWS and the pane updates (`files.changed` came from `mawsd`); `mawsd logs --follow` shows `[git] …` lines for the watched root. Start a second machine's app over the O6 link (`e2e:machines`' scene) and its Environment card shows the branch of a checkout only the daemon-only machine has. Concrete Steps has each command; the e2e groups named in Acceptance prove each behaviour on the gate's Macs.

### Orientation

Terms used throughout:

- **The checkouts:** git's read service and repository watcher (`src/services/git/{service,watcher,runner,porcelain}.ts`, `git.*` and `git.changed`), the `@` menu's lister (`src/services/git/ls-files.ts`, `git.lsFiles`), the files service (`src/services/files/{service,watch,allowlist,admission}.ts`, `files.*` and `files.changed`) and source control (`src/services/scm/`, `scm.*` and `scm.remote.output`), composed today by `startCheckouts` (`src/services/checkouts-root.ts`) over the spine's view, in main on both shapes (`src/main/index.ts`, after the spine). The worktree service (`git.worktree.*`) moved with the spine at O3-D and is not O3-E's.
- **The spine's root:** `startSpine` (`src/services/spine-root.ts`), which `mawsd`'s seam composes at each load (`src/mawsd/spine-seam.ts`) and main's embedded root composes once; its parts stop in order through `stopParts`, and its `settled()` waits for every part's work in flight (`src/services/work.ts`) before a release or a yield.
- **The front** (`src/mawsd/front.ts`): `machine.sock`'s service: the bus the root registers on (`register` refuses a name not owned by `machine`; `emit` refuses a name not in `REGISTRY.machineEvents`), one `FrontClient` per welcomed connection minting a `ClientRef` per page (`src/shared/host/client-refs.ts`; a page's `clientGone` or the connection's end ends its refs), the client port (`src/mawsd/client-port.ts`) and the streams.
- **The daemon shape** (`supervisor.shape: daemon`, the owner's): main composes no spine; its router binds `machine` as `host`, so a `machine`-owned command from a page is forwarded to `mawsd` with the page's client id (`src/main/ipc/router.ts`, `dispatchToHost`), and `mawsd`'s events reach the windows through main's host supervisor, which checks each name and payload against the registry and relays it through main's `emit` (`src/shared/host/host-supervisor.ts`, the `relayed` branch; `src/main/ipc/events.ts`); `MACHINE_EVENTS` gates what the front will emit at all (`front.ts`'s `emit`) and what the manifest lists. **The embedded shape:** main composes the spine and answers `machine` names through its embedded binding (`registerMachineHandler`, outputs validated as a host runtime validates them). Main's own in-process calls of a command go through the router's local route (`dispatchLocal`), which refuses a main-only name first, as a page's call would be refused (Interfaces §D gives main's own calls a route past that refusal).
- **A watch tree:** the directory-level watch of Interfaces §A: one non-recursive `fs.watch` per directory, never per file, walked and maintained by MAWS, presenting the handle shape both watchers already inject (`WatchFn` in `src/services/git/watcher.ts` and `src/engine-host/fs/watcher.ts`: `(path, {recursive}, listener) => {close, on('error')}`). **The store watcher:** the engine host's watch over the engine's `projects/`, `jobs/`, `tasks/` and `sessions/` (`src/engine-host/fs/watcher.ts`, `StoreWatcher`).
- **inotify's limits:** per user on Linux, `fs.inotify.max_user_watches` (64,104 on the devcloud image) and `max_user_instances` (128); a watch call past them fails `ENOSPC` or `EMFILE`; a queue overflow (`max_queued_events`, 16,384) is reported by the kernel on descriptor -1, which libuv drops, so Node never sees it (O3-G).
- **The ledger:** `<profile>/spine-ops.jsonl`, opened by `startSpine` under `spine.lock`; `machine.op` claims any `machine`-owned command whose grade is an act (not `list`, `view`, `client`, `internal`) and runs it through the bus's `invoke` (`src/services/machine-ops.ts`, `claimable`).
- **The attachments directory:** where `files.upload` writes (Interfaces §F): `<working directory>/.claude/desk-uploads/<appSessionId>/`, lane A's layout (`src/services/lane-a/media.ts`, `UPLOADS`, `EXCLUDE_LINE`) keyed by the app session id.

How the parts fit on master. `startCheckouts` takes `{view, bus, clientPort, engineEnv, env}` and returns `{files: {readResolved}, stop}`; main hands `readResolved` to `registerLibraryFiles` for `library.read` (`src/main/library/files.ts`). Watches are counted per `ClientRef` id and released on `onGone` in `registerGitHandlers` and `registerFilesHandlers`; in main a ref is a page (`src/main/ipc/clients.ts`), in `mawsd` a connection's page. The three checkout events are emitted through the bus's `emit` and are link events already (`src/main/machines/link-surface.ts`, `LINK_RULES.names`). `COMMAND_BUDGETS_MS` (`src/services/command-budgets.ts`) gives a moved command a deadline past main's 10 s where its own waits need one; main's `machine` host applies it (`src/main/hosts/daemon.ts`, `machineBudgetsMs`).

### Plan of Work

### M1 — The watch tree: a directory-level watch MAWS owns on Linux, for both watchers

**At its end.** `src/shared/fs/watch-tree.ts` exists (Interfaces §A): `watchTree(root, options, listener)` returns a handle with `close()` and `on('error', …)`, watching the root and every directory under it that the prune predicate admits with one non-recursive `fs.watch` each, walked asynchronously, adding a directory when its parent reports its creation, closing a directory's watch when it is removed, naming each event by the path relative to the root (what both watchers' classifiers read), reconciling on a slow timer and after bursts, and reporting a watch call's `ENOSPC` or `EMFILE` as an `'error'` with that `code` after closing the partial tree. `recursiveWatch(platform)` (same module) answers the `WatchFn` the platform uses: the tree on Linux for `recursive: true`, Node's `fs.watch` everywhere else and for `recursive: false`. `src/services/git/watcher.ts` takes it as its default watch, gives the tree a git-aware prune (Interfaces §B) and treats an exhaustion error as the root's `polling` state. `src/engine-host/fs/watcher.ts` takes it as its default watch with the store's prune. On a Mac nothing changes. The VM run records the numbers.

**Touches.** `src/shared/fs/watch-tree.ts` and `watch-tree.test.ts` (new), `src/shared/fs/watch-tree.vm.test.ts` (new; Interfaces §G), `src/services/git/watcher.ts` and its test (the prune, the polling state, the default watch), `src/services/git/service.ts` (hands the watcher the git runner's ignore reads, §B), `src/engine-host/fs/watcher.ts` and its test (the default watch, the store's prune per root in `open()`, the exhaustion branch in `onError()`), `test/support/` if a fake fs helper is wanted by both watcher tests, `vitest.config.ts`'s `TIMING_NODE_TESTS` if the real-inotify burst case needs the timing project.

**Decisions.**
- The tree lives in `src/shared/fs/` (beside `atomic-write.ts`), neutral ground the engine host and the library both import; it imports Node's builtins alone, so the services chunk and `mawsd`'s graph admit it (D13). Rejected: a module under `src/services/` that the engine host imports (lint rule B fences the library), or two copies.
- The tree never watches a file: inotify names a directory's changed children, which is all either classifier reads (O3-G item 1). An event in a directory is reported with the child's relative path; the directory's own removal closes its watch and is reported by its parent.
- The prune predicate is the caller's (§B for git: what git ignores, read once at the root's watch start by `git ls-files -o -i --exclude-standard --directory`, and for a directory first seen later by one `git check-ignore --stdin` per batch window of at most 250 ms, the watcher's own debounce, the directory held unwatched until its verdict and then watched with one event naming it, so a file written there before the verdict is caught by the status that event runs; and `objects/`, `lfs/` under the git dir and the common dir). The tree keeps every ancestor of an admitted path and prunes only a directory the predicate names (O3-G item 2: the prune is never "classifies null", since `refs/` classifies null and the refs under it matter). The store's prune drops only subtrees every path of which `classifyStoreEvent` nulls: under `projects/`, a second-level directory whose name is not a session id (`projects/<slug>/memory/`, whose every path fails the `SESSION_ID` test) and `tool-results/` under a session's directory (`projects/<slug>/<session id>/tool-results/`); `memory/` under a session's directory is a sidecar and stays watched. The executor pins each pruned subtree against the classifier, the counterexample under a valid session id included. Rejected: deciding a late directory's verdict at the next reconcile (writes inside it unseen for up to two minutes) or watching it at once and closing on an ignored verdict (a `pnpm install` would place thousands of watches to close them again, which can itself exhaust the budget).
- The walk is asynchronous with bounded concurrency (an `opendir` per directory, at most 8 in flight), so the loop is never held for a tree (O3-G item 3); a watch is placed on a directory before its children are listed, so a child created during the walk is seen by its parent's watch or by the listing, and a child seen twice is watched once.
- Exhaustion: a watch call that throws `ENOSPC` or `EMFILE` closes every watch the tree holds and emits `'error'` with the throw's `code` and the directory's path (O3-G item 4); the tree is then closed and emits nothing more. The repository watcher's `onError` today only warns; from M1 an error whose code is `ENOSPC` or `EMFILE` puts the root in `polling`: its handles closed, `git status` read every `POLL_MS` (5 s, doubled to 10 s after a status timeout as `BACKOFF_MS` already does) with `git.changed` emitted when the projection moved, one log line `[git] watch exhausted under <root> (<code>): polling`, and the state kept until the root is unwatched (no re-attempt: a budget that was short stays short while the other trees hold it). The store watcher keeps its re-open after `REOPEN_MS` for other errors; for an exhaustion code, whether thrown at the root's open (`open()`'s catch, the flat `sessions/` root on native `fs.watch` included) or reported later through the handle (`onError()`), it logs once, stays `failed`, and enqueues `{kind: 'rescan', root}` every `STORE_POLL_MS` (30 s, the store service's own reconcile period) until stopped, the store's analogue of git's polling, since the service's periodic reconcile reads sidecars only and a dark `projects/` root would otherwise report no new transcript. Rejected: a wire field saying a root polls, since no surface reads it yet (D12); leaving a `failed` store root to the sidecar reconcile (the darkness the tracker row names).
- Reconciliation (O3-G item 5): the tree re-walks its admitted directories every `RECONCILE_MS` (120 s) and once, `BURST_SETTLE_MS` (1 s) after a burst (at least `BURST_EVENTS` (200) events within 1 s); every re-walk watches the directories it finds unwatched and then emits one event with `filename` null, which both watchers already read as a rescan (the git watcher's root watch runs one status as `changed(root, 'worktree')`, its git-dir watch as `'index'` and a common-dir watch as `'refs'`; the store watcher's `rescan` readdir-diffs the root), so a modification inotify's queue dropped in a directory the tree watches is found within one period, since a dropped event changes no directory set and no burst need have been seen. The cost is one `git status` per watched root per period on Linux (45 ms for MAWS, 392 ms for the kernel tree, O3-G), emitted as `git.changed` only when the projection moved. The store's tree reconciles every `STORE_RECONCILE_MS` (600 s) instead, since a null event costs it a readdir-diff of `projects/` and the store service already reconciles sidecars every 30 s and rescans at each settle; §G's store arm reads that rescan's cost. The numbers are advisory; the executor keeps them as named constants. Rejected: a quiet re-walk that emits nothing (no recovery for a dropped modification; O3-G's item 5 names the status on the slow timer).
- The handle's `on('error')` and `close()` are the only surface; the tree logs nothing itself (the callers log). A watch call's `ENOENT` (the directory vanished between the listing and the watch) drops that directory silently; `ENOENT` at the root itself throws from `watchTree` as `fs.watch` would, so a caller that cannot open a root fails its call as today.
- Linux-only integration cases run on the pool (`describe.runIf(process.platform === 'linux')`): a scratch tree with real inotify; events relative to the root; a directory created after the watch has its children reported; a removed directory's watch closed (its descriptor gone from `/proc/self/fdinfo`); a 2,000-file burst in one new directory names every file within 1 s. Exhaustion is not inducible without `sysctl` and is pinned with the injected fs (the Nth watch throws `ENOSPC`); the VM's arm proves it real.
- The VM measure (Interfaces §G) is this milestone's proof for acceptance 6 and needs the architect's go for the VM; its numbers and verdict go into Surprises & Discoveries, and a miss of a bound is a finding for the architect, not a widened bound.

**Does not touch.** The classifiers and debounces of either watcher, and the repository watcher's projection but for the re-stat pass §B names; main; `mawsd`; the wire; `src/engine-host/fs/service.ts` and `register.ts` (the in-flight branches' files: the engine host takes the tree through `watcher.ts`'s default alone).

**Proves.** Acceptance 6, and the tracker row "P5 O3-E and O14 (`src/engine-host/fs/watcher.ts`)"'s closing condition (the store watcher uses the tree). Tests pin: the tree over a fake fs walks asynchronously (a listing that resolves later does not hold a watch placed earlier), watches no file, prunes what the predicate names and keeps every ancestor of an admitted path, adds a directory from its parent's event (watched within the batch window, with one event naming it) and from a reconcile, reports a removed directory and closes its watch, reports `ENOSPC` and `EMFILE` once with the code and the path after closing the partial tree, on a later tick when the root's own watch threw (the repository watcher enters `polling` from it), and emits a null-filename event after a burst and after every slow reconcile (a tracked file modified with its callback withheld, the timer advanced, `git.changed` follows; a known file beneath an untracked directory likewise, through the re-stat pass); a late directory's listing is reported entry by entry (a new `jobs/<id>/` holding `state.json` before its watch opened reaches the store as a `job` change, and a new task list its `taskList`, with no slow timer); `recursiveWatch('linux')` returns the tree for `recursive: true` and `fs.watch` for `recursive: false`, and `recursiveWatch('darwin')` returns `fs.watch` for both; a file written in a directory created after the watch is reported within the watcher's debounce; #### A. The watch tree (`src/shared/fs/watch-tree.ts`)

    export type WatchListener = (event: string, filename: string | null) => void; // filename relative to the root, '/'-joined as fs.watch gives it on the platform; null: rescan the root
    export interface WatchHandle { close(): void; on(event: 'error', listener: (error: NodeJS.ErrnoException) => void): unknown }
    export interface WatchTreeOptions {
      prune?(dir: string): boolean | Promise<boolean>;  // `dir` relative to the root; true: never walk or watch it (its ancestors are watched regardless)
      reconcileMs?: number;                             // RECONCILE_MS, 120_000
      burst?: { events: number; windowMs: number; settleMs: number }; // BURST_EVENTS 200 within 1_000 ms; BURST_SETTLE_MS 1_000
      concurrency?: number;                             // directories listed at once, 8
      fs?: Pick<typeof import('node:fs/promises'), 'opendir' | 'lstat'> & { watch: typeof import('node:fs').watch }; // tests
    }
    export function watchTree(root: string, options: WatchTreeOptions, listener: WatchListener): WatchHandle;
    // The platform's recursive watch: `watchTree` on Linux for `recursive: true`, `fs.watch` otherwise.
    export type WatchFn = (path: string, options: { recursive: boolean; prune?: WatchTreeOptions['prune'] }, listener: WatchListener) => WatchHandle;
    export function recursiveWatch(platform: NodeJS.Platform = process.platform): WatchFn;

`watchTree` places the root's watch synchronously (so a caller's `ENOENT` at the root throws from the call, as `fs.watch` does) and walks the rest asynchronously. A directory first seen after the walk (its parent's `rename` event, or a reconcile) is held until `prune` answers, then watched, and its initial listing is reported entry by entry (one `rename` event per entry, files and directories alike, each by its relative path, the directory's own event last), so a file written there before its watch opened reaches the caller's classifier by name (a `jobs/<id>/state.json` is a `job` change, a file in a new source directory a `worktree` change) and §G's burst into a new directory names every file. Every slow reconcile and every burst settle ends in one event with `filename` null. Every error but the root's `ENOENT` reaches `on('error')` on a later tick, never thrown and never before `watchTree` returned, the root's own watch's `ENOSPC` or `EMFILE` included (both callers attach their listener after the call and would otherwise answer `internal` or hear nothing); an exhaustion code closes the tree first. `close()` is idempotent, closes every watch, cancels the timers and emits nothing more. Both watchers' `WatchFn` types (`src/services/git/watcher.ts`, `src/engine-host/fs/watcher.ts`) are satisfied by `recursiveWatch()`; the git watcher passes its prune per call.
