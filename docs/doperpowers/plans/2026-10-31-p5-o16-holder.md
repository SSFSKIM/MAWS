## Purpose

Today a lane B session is a child of the engine host: the process that holds its Query also holds its pipes. So an engine host cannot be replaced while a session runs, and `mawsd` serves an older engine host "until its sessions are idle" (O2 M3, E10 §6). On a server that never idles, with a session kept by a background shell or a cron, that day never comes: an upgrade either never takes effect or, at the owner's Restart now, ends every lane B session and reopens each with `--resume`, losing its background shells, its Monitors and its MCP tasks (`background-work-handoff.md` §2). An engine-host crash loses the same.

After O16, every lane B process the engine host launches runs under a **session host**: a small native process that owns `claude`'s pipes, numbers its output, applies its input exactly once and signals it only on a fenced request. The engine host keeps the Query, the `maws` tool server and the hooks, and can be stopped and started around a running session: a new engine host, of another build or the same, finds the session hosts in a roster, re-attaches as the one writer, replays what it missed from each host's ring, re-initializes the engine and goes on. An engine-host upgrade, a `mawsd` restart and an app upgrade, each mid-turn, leave the turn completing, no input applied twice and a pending permission shown once (P5 acceptance 13). The servers' idle release stops being a wall clock: a session is released after 24 hours only once its work state is verified empty, with the release armed through the observer bridge's `turn.step` gate so no turn from any origin is lost in the window between the verdict and the signal (OX10, owner F2).

**How to see it working.** On a scratch profile on the daemon shape, start a session and ask it to run `sleep 300 &` in the background; `mawsd status` lists the session's host (`session hosts  1 (adopted 0)`); run `mawsd restart --engine-host`: the engine host's pid changes, the session's pid and launch id do not, the transcript keeps streaming, the shell's pid lives, and `mawsd status` reads `session hosts  1 (adopted 1)`. Then replace the app bundle with another build and relaunch: the same. Concrete Steps has each command; the e2e groups named in Acceptance prove each behaviour on the gate's Macs and the acceptance run on a devcloud VM proves it with the real engine.

### Orientation

Terms used throughout:

- **The engine host:** E10's detached supervisor (`src/engine-host/index.ts` dispatching to `detached.ts`), one per profile, holding each lane B session's `EngineSession` (`session.ts`: the Query, the `maws` tool server, the hooks, the broker, the queue) in the process table (`process-table.ts`), served over `host.sock` to its one client, `mawsd` (`src/mawsd/daemon.ts`, the relay and the permanent link). Its files are `<profile>/supervisor/` (`supervisor-files.ts`). **The manager**, in holder design terms, is this process.
- **A session host:** the new native process (`native/session-host/`, binary `maws-session-host`) that spawns one `claude -p` with piped stdio, numbers every stdout and stderr line into a ring, applies stdin by offset, holds the writer fence, writes its roster entry and serves one Unix socket (Interfaces §A, §B). One per launch; its id is the launch id (`launch.ts` `mintLaunchId`), so the journal, the roster and the request ids name one process by one id (D5).
- **The host transport:** `src/engine-host/holder/transport.ts`, an `EngineTransport` (`transport.ts`'s interface: `frames`, `stderr`, `write`, `endInput`, `kill`, `exited`) over a session host's socket instead of a child's pipes, so `EngineSession`, `OutboundWriter`, `ControlClient`, the ladder and the normaliser run unchanged (Interfaces §C).
- **The roster:** `<profile>/supervisor/hosts/<launchId>.json`, written by each session host at every state change; the manager reads the directory at start to adopt (Interfaces §B, §D).
- **The checkpoint:** the highest host sequence (`hseq`) the launch's journal holds; the session host keeps every line above the acknowledged one, so a new manager replays from the checkpoint exactly, or learns of a gap (Interfaces §C).
- **The handover:** an engine host's exit that detaches its hosted sessions instead of ending them, and its successor's adoption of them; asked by `mawsd` with the socket layer's stable `exit {when: 'now'}` when the engine host's welcome lists `host.holder` (Interfaces §D, D9).
- **The gate:** OX10's server, `<profile>/supervisor/gate.sock`, where sminos's observer bridge inside a lane B process connects and answers the reap fence's `arm` and asks `turn` (Interfaces §E).
- **The reap:** the release of an idle session (`idle`, the role's clock; `budget`, memory pressure) as a state machine over the gate: verified empty → armed → final check → signalled, SIGTERM only, no SIGKILL for `idle` (Interfaces §F).
- **Verified empty:** `work-state.ts`'s snapshot with `unknown === null` and `crons.length === 0`, no non-ambient task in `backgroundTasks`, and the descendant veto clear (Interfaces §F); `budget.ts`'s `isIdleRow` already says most of it.
- **The stub:** the e2e replay engine (`e2e/support/launch.ts` `writeReplayEngine`, a script the engine host spawns through `MAWS_E2E_ENGINE_BIN`), a real process that plays a fixture; under O16 it runs under a real session host, so the scenes exercise the host without the engine.

How the parts fit on master. `launcher.ts` builds a `LaunchPlan` (`launch.ts` `buildLaunch`: the binary, the flags, the environment with `SMNS_MEMBER` and `MAWS_LANE=B`, the pinned `--session-id`) and reserves an `EngineSession` whose `spawn` is `ipc.ts`'s `spawnEngine(plan)`; `session.ts` `run()` spawns, wraps the transport in an `OutboundWriter` and a `ControlClient`, journals every row through `record` (`journal.ts`, synchronous appends), initializes, and ends the process through `session-ladder.ts` (end_session, SIGTERM, SIGKILL). The table writes `live.json` (`live-ledger.ts`) at every launch and exit; `detached.ts` sweeps a dead predecessor's rows at start. `supervision.ts` sets the idle release's policy from the role (`role.ts`; `SERVER_RELEASE_MS` 24 h, the laptop's the idle exit's), `idle-release.ts` fires `session.stop('idle')` when a row's clock is due and `isIdleRow` still holds, `budget.ts` names the hard reasons, and `work-state.ts` keeps the crons from the Stop callback (`host-hooks.ts`) and the tasks from `background_tasks_changed`, unknown on an `adopted` launch until the first signal. `mawsd` reaches the engine host through `@shared/host/detached-transport` with `buildPolicy: 'replace'`: another build with nothing live is replaced at once, with sessions live served and asked `exit {when: 'idle'}`; a crash is the ladder's restart; `beforeSpawn` refuses a spawn from a replaced bundle (Decision Log 161). sminos's bridge (`bridge.tsx`) observes a marked session, refuses every control and rewrites nothing in `turn.step`.

**What exists at its end.** `native/session-host/`: a Go module (std only, `go 1.25`, no dependency) building `maws-session-host`, which, given a token on its stdin and its socket path on argv, serves Interfaces §A over the socket, spawns the launch it is given at `commit`, keeps the ring, the offsets, the fence and the roster of §B, signals its child on request, records the child's exit and lingers, then removes its files and exits. `native/session-host/prebuilds/{darwin-arm64,linux-x64,linux-arm64}/maws-session-host` committed, built by `scripts/build-session-host.sh` (`pnpm build:session-host`) with `-trimpath -buildvcs=false -ldflags='-s -w'` from the private toolchain, reproducible byte for byte; `scripts/check-session-host.sh` rebuilds each from source and compares bytes, run by the gate's static job through `actions/setup-go` at the version `native/session-host/go.version` names (a `.github` hunk for CI-opt). `electron-builder.yml` carries the darwin build into `Resources/session-host/` through `extraResources` (the `peer-auth` precedent); `scripts/mawsd-pack.mjs` copies the pack's platform build into `bin/` (M4 proves it). `src/engine-host/holder/files.ts` names the binary per shape (packaged: `process.resourcesPath`; a checkout: the prebuilds directory; `mawsd`'s Linux release: `<release>/bin/`).

**What it touches.** `native/session-host/` (new: `main.go`, `host/` for the process, `ring/`, `proto/`, `roster/`, each with tests), `scripts/build-session-host.sh`, `scripts/check-session-host.sh`, `package.json` (`build:session-host`), `electron-builder.yml`, `scripts/mawsd-pack.mjs`, `.github/workflows/gate.yml` (the static job's step), `src/engine-host/holder/{files,protocol}.ts` and `src/engine-host/holder/binary.test.ts` (the real-binary tests, darwin and linux; skipped where no prebuild matches the platform).

**Decisions.**
- The language is Go (D3), std only, one module, no cgo (`CGO_ENABLED=0`), so the Linux builds are static ELF and the Mac build links `libSystem` alone.
- The protocol is NDJSON control lines plus two length-prefixed byte records for output and input (Interfaces §A), so a 64 MiB line is never JSON-escaped on the hot path; the line cap is the engine host's `MAX_LINE_CHARS` (64 MiB): an unterminated line past it is dropped with a `problem` record, the child left to the manager's verdict (today's transport kills it: `transport.ts`).
- The ring holds what the writer has not acknowledged, up to `RING_CAP` 8 MiB; the manager acks after each journal write (D6). Past the cap the oldest lines go and `firstSeq` moves, so a `read` below it answers a gap, never a guess.
- stderr lines share the ring's sequence (`err` records), so one checkpoint covers both streams and the journal's `stderr` rows are replayed too.
- The writer fence is a `uint64` the host keeps from its first writer (1); `attach writer` with a fence at or under the current is refused, a superseded writer's connection is told `fenced` and every later write from it refused; the fence is written to the roster at each change and read back at the host's own restart never (a host does not restart: its death ends the session, D7). Observers read only.
- The host's own signals: SIGTERM, SIGINT or SIGHUP to the host sends SIGTERM to the child's process group, waits `HOST_EXIT_GRACE` 5 s, and exits; a host whose death would leave an unreachable engine (E10 M0 Q1: an engine with no stdio finishes its turn and runs on) takes the session down cleanly instead (D7). SIGKILL of the host is the sweep's case (M3).
- After the child's exit the host serves `hello`, `read` and the exit record for `LINGER` 10 minutes, or until the writer sends `release`, then removes its socket, token and roster entry and exits 0.
- The roster entry is written with a temp file and rename, 0600, at `ready`, `committed`, `running` and `exited` (Interfaces §B); the socket is 0600 in the 0700 `hosts/` directory, made and checked as `@shared/host/private-listen` makes them (the host re-implements the checks: lstat, the uid, the mode, no symlink).
- Peer identity: the uid boundary and the token, as every socket of `mawsd` (O2 M8); no peer-credential check.
- Process start identity: the host records its own and the child's `procStart` as `supervisor-files.ts` reads them (`ps -o lstart=` under `LC_ALL=C TZ=UTC`, on both platforms), so `isSameProcess` compares like with like.
- Logging: `<hosts>/<launchId>.log`, 0600, one line per state change and problem, capped at 1 MiB (truncated at open past it).
- Build: `go.version` pins the toolchain; the script refuses another; the three targets are built from one machine (`GOOS`/`GOARCH`, `CGO_ENABLED=0`, so a Linux runner builds the darwin target too); the CI check rebuilds all three on the pool's Linux runner and compares bytes, Go's builds being reproducible across build hosts under `-trimpath`; `unit:darwin`'s real-binary tests run the committed darwin build besides.
- The binary is resolved at each spawn from the engine host's own build location (`sessionHostBinary()`, §H). After an app bundle swap an old engine host spawns the new bundle's session host, which speaks the same protocol major; a protocol major bump is its migration's to handle (OX1's rule, applied to this protocol).

**What it does not touch.** The engine host's launch path (M2). `mawsd`. The gate.

**Proves.** Acceptance 4's build half. Tests: `go test` (the ring's cap, gap and ack; offsets' duplicate and gap; the fence's CAS; the roster's atomic writes; signal relay; the linger). `binary.test.ts` drives the committed binary with `/bin/cat` as the child: auth before anything (a wrong token gets no byte), `hello` after auth, `launch` and `commit` spawning `cat` with the given argv, cwd and env (the env read back through the child), `out` records sequenced from 1, `read` exact and `gap` after the cap, `stdin` applied once and `duplicate` on a resend, a second writer at fence+1 superseding the first (`fenced`, its write refused), `signal SIGTERM` ending `cat` and the `exit` record, the linger and `release`, SIGTERM to the host ending `cat`, and the socket's fallback path when the directory's path is long.

**What it touches.** `src/engine-host/holder/{transport,client}.ts` (new), `launcher.ts`, `ipc.ts` (`spawn`), `launch.ts` (`buildEnvironment`: `MAWS_HOLDER_SOCKET`; `SMNS_MEMBER` takes the spawner the caller names, which `spawnHosted` sets to the host's pid), `journal.ts` and `@shared/wire/journal` (`hseq`), `session.ts` (`record` passing the host sequence; the owed-interrupt mark), `session-status.ts` and `@shared/engine/status.ts` (`holder`), `process-table.ts` (the live ledger's rows carry `holderId`), `work-state.ts` (the Stop's `background_tasks` read, if M0's question 3 says the snapshot does not follow re-initialize), `src/mawsd/cli.ts` (`status`), `src/engine-host/store/file-session-state-store.ts` and `@shared/engine/session-state-store` (`owedInterrupt`). **Decisions.**
- The spawn is `spawn(binary, [socketPath, '--hosts', hostsDir], {detached: true, stdio: ['pipe', logFd, logFd]})` then `unref()`, the token written to its stdin and the stdin closed: no token on argv, in the environment or in the child's environment (holder design §3.1). The host listens first, then reads its token from stdin; a connection that arrives before the token is read waits inside the auth window. The manager polls the socket path with connect attempts for up to `HOST_START_MS` 5 s; the host's `hello` is the ready signal.
- `commit` is sent only once the writer is attached, so the first frames of the engine are held in the ring for a connection that already reads: nothing is lost between spawn and attach.
- The manager's offset starts at 0 on a fresh launch and at `stdinApplied` on an adoption (M3); the `OutboundWriter`'s `write` resolves at the host's `applied` (the §4.6 delivery truth moves one hop: the bytes reached the host, which reached the pipe before answering), a `duplicate` resolves as delivered, a `gap` or `fenced` rejects with `TransportClosed`.
- The ack is coalesced: at most one per 50 ms or 64 rows, and one at each write's settle, so the ring's unacknowledged bytes stay near zero at idle (the session host's footprint then reads the binary's own, D3's 3 MiB).
- `MAWS_HOLDER_SOCKET` is set on every hosted launch from M2, though nothing listens until M5 (O12 M4's observer, when built, treats a refused connect as no gate).
- The owed interrupt (D12): `session.interrupt` sets `owedInterrupt: true` in the state file before its control request is written and clears it when the response arrives or the write failed; an adoption that finds it set sends `interrupt` before anything else (M3).
- The crash of a session host (its pid gone, the socket closed): the transport reports `exited` with the host's last exit record if any, else `{code: null, signal: 'SIGKILL'}` and a `transport_error {code: 'host_lost'}` row; the session ends as a crash and its child, if alive, is the sweep's (M3).

**What it does not touch.** Adoption, the handover, the exit order (M3). The gate (M5). The sweep (M3).

**Proves.** Acceptance 1's precondition and acceptance 5's hop in place. Tests pin: a launch's `spawn` row names the binary as `bin` and the host as `holder`; the stub under a real host plays the permission fixture end to end on the hosted path (`e2e:supervisor-daemon` and `e2e:supervisor` cases (a), (b), (e), (m) green unchanged); `hseq` present on every `in` and `stderr` row and monotonic; acks trim the ring (the host's `hello` after a quiet second reads `ring.bytes` 0); a write's `duplicate` on a resend; a session host killed with SIGKILL ends the session as a crash with `host_lost`; the status's `holder.pid` is the host and `pid` the engine; `SMNS_MEMBER` in the child's environment is the host's pid (read back through a stub that prints its environment).

### M3 — Adoption and the handover

**What exists at its end.** An engine host that starts over a profile with live session hosts adopts them: for each roster entry whose host answers `hello` with the right token, it attaches as writer at the host's fence + 1, opens the launch's journal in append mode continuing its `seq`, reads the checkpoint, replays from it (exact, or with a gap row and a notice), re-initializes, answers orphaned `mcp_message` calls, sends an owed interrupt, and serves the session as before with the same launch id and pid. An engine host's exit detaches its hosted sessions after draining its in-flight tool calls, except `host.stopAll` and the quit path's stop, which end them. `mawsd` replaces a capable engine host of another build at once (`exit {when: 'now'}`), sessions live or not, and `mawsd restart --engine-host` does the same on demand. The sweep stops only what no live host holds. `WIRE_MINOR` 13 with `host.holder` on the engine host's welcome.

**What it touches.** `src/engine-host/holder/{roster,adopt}.ts` (new), `detached.ts` (the start order: roster read before the sweep; the exit order's detach mode), `live-ledger.ts` (rows with a holder are skipped by the sweep while the holder lives; a dead holder's child is swept by the roster's child identity), `supervision.ts` and `ipc.ts` (`shutdown(mode)`), `session.ts` (the adopted construction: no spawn, `reconnect {trigger: 'host_restart'}` rows, `host_attach` and `host_detach` meta rows, the orphan answers), `journal.ts` (`resume` from the tail), `launcher.ts` (`adopt(entry)` beside `launch`), `broker.ts` (unchanged: it re-accepts pending requests from the initialize response and drops duplicates by id), `src/shared/host/detached-transport.ts` (`welcomed`: `otherBuild && (liveSessions === 0 || capable)` replaces now), `src/shared/host/socket-protocol.ts` (`HOLDER_CAPABILITY`, `PEER_CAPABILITIES.engineHost`), `src/shared/ipc/wire.ts` (13; `WIRE_CAPABILITIES`), `src/shared/ipc/schema/{host,daemon}.ts` (`host.supervisorStatus.holder`; `daemon.restartEngineHost`), `src/mawsd/{daemon,cli}.ts`, `src/renderer/src/stores/notices.ts` (the crash toast's copy), `e2e/supervisor.spec.ts` (cases (c), (n)), `e2e/cross-build.spec.ts`. **Decisions.**
- Adoption order at start (D10): listen → read `hosts/` → for each entry with a live host, adopt (bounded `ADOPT_MS` 10 s per host, in parallel) → then the sweep over `live.json`'s rows that no adopted host holds, and over roster entries whose host is dead but whose child (pid and `procStart`) lives (SIGTERM, the grace, SIGKILL, as today's sweep). The welcome's `liveSessions` counts adopted rows from the first welcome, so `mawsd`'s connect burst sees them.
- The checkpoint is the last `hseq` of the launch's latest journal file (`<launchId>.jsonl` or its highest rotation), read from the file's tail; the journal writer resumes `seq` and the rotation index from the same read (D6). A `read {fromSeq: hseq + 1}` answering `caughtUp {gap}` writes `meta host_attach {replayed: 'gap', firstSeq}` and a `session.notice` ("Some output was lost while the engine host was restarting; the conversation on disk is complete."); the stream's events continue from the journal's `seq` either way.
- Re-initialize: the adopted session runs `session.ts`'s handshake as a resume does (`initialize` with the app's hooks, `get_status`, the grant re-application skipped, the queue recovered); the initialize response's pending requests reach the broker as today; a `control_response` for a request id the new `ControlClient` never sent is logged and dropped (the old manager's reads; nothing waits on them).
- Orphaned tool calls: every `in` `control_request` of subtype `mcp_message` carrying a `tools/call` with no `out` `control_response` in the journal's tail is answered, before `initialize`, with a tool error whose text is exactly "MAWS's engine host restarted while this tool ran. Its result is unknown and its effect may have completed; check before retrying." (holder design §3.3's orphan rule: never a retryable error). The in-process asks (`session-maws.ts`'s ask table) are cancelled on the old side at detach (their items settle `lost`, as at an exit) and the engine re-raises nothing for them; their `maws.ask` calls are among the orphans answered.
- The detach (the exit order's step 2 for hosted rows, D9): stop admitting launches; wait up to `DETACH_DRAIN_MS` 10 s for every session's in-flight tool calls and asks to settle (`toolServer.inFlight`, `askTable.asyncCount`); write `meta host_detach {reason, ackedSeq}` and close each journal; close the host connections without `release`; keep `live.json` (its rows name their holders); exit 0. `host.stopAll` and `engine.shutdown`'s quit-with-stop keep today's ladder for every row. `exit {when: 'idle'}` from a client whose hello listed `host.holder` behaves as `exit {when: 'now'}`: nothing is live in the old sense, and waiting serves nothing; from a client that listed it not, it arms the idle exit as today.
- A roster entry of another protocol major is not adopted: logged, counted in `holder.failed`, left running with its child, and its session shows as one with no process; that major's migration owns the rest.
- `mawsd`'s side: `detached-transport.ts` replaces at once when the welcome lists `host.holder`, logging `supervisor pid N runs build B with S sessions live under session hosts; replacing it` and arming no idle exit. Across a wire major the refusal line carries no capability, so the client still writes `exit {when: 'idle'}` and waits; a capable host whose client's hello listed `host.holder` (the client adopts) treats that as `exit {when: 'now'}`, detaches and exits, and the client's next retry finds no lock and spawns its own, which adopts (D11). A capable host asked by a client that listed no `host.holder` (a downgrade to a build before O16) keeps E10's wait, since that client would sweep what it cannot adopt. `daemon.restartEngineHost` (machine-owned, `z.void()` in and `{pid, adopted}` out) asks the engine host `exit {when: 'now'}`, waits for its pid to die, spawns and adopts; `mawsd restart --engine-host` calls it.
- The crash toast (E10 §1's `supervisor.crashed`) reads, when the successor adopted every row that was live, "The engine host stopped unexpectedly (exit <code>); its N sessions were re-adopted." and, when some were not, "...; N sessions were re-adopted, M were interrupted. Their transcripts are on disk; open one to resume." The main-side count comes from the successor's first `host.supervisorStatus` (`holder.adopted`).
- The `adopted` launch kind (`work-state.ts`) is used as it exists: tasks and crons unknown until a snapshot or Stop; the status's `work.unknown: 'adopted'` reads so in Session info.
- Lane B's operation ledger stays where it is (`ops.jsonl`, `ops.ts`), reopened by the successor as any restart reopens it (P5 Decision Log 45): a claim left in progress is settled as `op-ledger.ts`'s open settles it today; no change.

### M5 — The gate and the verified-empty release

**What exists at its end.** The engine host serves OX10 on `gate.sock` (Interfaces §E): observers connect with `hello`, heartbeat, answer `arm` with `armed` and ask `turn`. **Decisions.**
- The gate is the engine host's, not the session host's (D13): the final check's inputs (the work state, interest, the queue, the descendant count) live in the engine host, so the decision and the signal order are one event-loop turn there; the session host only relays the signal.
- The reap's linearization point is `IdleRelease.fire()`'s synchronous step: it re-reads the row's status, the interest union, a fresh `ps` for the descendant veto and the gate's state, and calls `session.stop(reason)` in the same step; an event that landed before the step is reflected, one after it meets `signalled`. Arming is asynchronous (the observer answers over a socket): `fire()` with an observer connected and no `armed` fence sends `arm` and returns, and the `armed` answer schedules the step again at once; a `turn` that arrives meanwhile cancels (`proceed`, the clock restarts at the turn's end as a turn does today). The lease is `LEASE_MS` 10 000, renewed by a second `arm` when the step runs later than `armedAt + LEASE_MS - 1000`.
- An observer is healthy while its last `hb` is under `OBSERVER_SILENCE_MS` 15 000 old; an unhealthy observer is dropped, its fence disarmed, and the row is treated as "no observer" from then (the owner's Q1 answer), logged once.
- `turn.origin` adds `peer` beside O12's four, with `delivery` the inbox delivery id (Interfaces §E; D14): the settlement O16 defines is that sminos settles a `peer` delivery to a marked session only when the observer reports its turn `proceed` (or proceeds on the lease's expiry), and keeps it owed on `stop`; the engine host's answer carries nothing more. O12 M4 builds the observer and the settlement.
- `stop`'s reason text is exactly "The holder ended this session; reopening it continues the conversation." (O12 M4's text), which the bridge streams as the turn's one chunk.
- An `idle` reap whose SIGTERM the engine ignored past the ladder's `term` wait (3 s) ends there: the row stays live, `work.unknown` reads `reap_term_ignored`, a `reap {phase: 'term_ignored'}` row is journaled, the fence is disarmed, and the clock starts again from that moment (holder design §3.2 step 5). `budget` keeps SIGKILL (charter §4.4; not O16's to change).
- The descendant veto's reading is M0's question 4's (D17): descendants outside `claude`'s process group, or, if MCP servers sit outside it, those whose start time postdates the last turn's end; the executor records which in the Decision Log.
- The budget release runs through the same state machine, so a memory-pressure release never signals into a turn either; its candidate choice (`budget.ts` `evaluate`) is unchanged.

**What it does not touch.** The session host binary. Adoption. sminos.

**Proves.** Acceptance 2, and the OX10 fixture for O12. Tests pin, over a fake observer and a fake session: no release while any of a client's interest, a kept mark, a turn, a non-ambient task, a listed cron, unknown work or a descendant holds; a release with no observer on verified-empty alone; with an observer: `arm` before any signal, no signal before `armed`, no signal past the lease, a `turn` before the step answered `proceed` with the reap cancelled and the fence disarmed, a `turn` after the step answered `stop`, an observer silent 15 s dropped and the row released as unobserved; SIGTERM ignored → `reap_term_ignored`, no SIGKILL, the clock restarted; the budget release armed the same way. `e2e:supervisor-daemon` case (m): with a fake observer on `gate.sock` for the no-tab session, the release's `arm` arrives, the scene answers `armed`, the session is released; repeated with a `turn` sent after `armed`, the scene reads `proceed` and the session stays live for another period.

### Interfaces and Dependencies

#### A. The session host protocol (M1; the engine host's client in M2)

Over the host's Unix socket, newline-delimited JSON, one object per line, plus two byte records. The first line the client writes is `auth`; a wrong or missing token within 2 s closes the connection with nothing written. Every object has `t`. Unknown fields are ignored and unknown `t`s answered `{"t":"error","message":"unknown t"}`, so the protocol grows additively within its major (`hello.protocol` 1); a client refuses to adopt a host of another major and leaves it running.

Client → host:

    {"t":"auth","token":"<64 hex>"}
    {"t":"attach","role":"writer"|"observer","fence":<uint64>}                              writer: fence must exceed the host's; the previous writer is told `fenced`
    {"t":"launch","appSessionId","engineSessionId","argv":["<bin>",…],"cwd","env":{…}}     writer, once, before commit; the host records the ids in its roster and keeps env in memory only
    {"t":"commit"}                                                                            writer; the host forks; never twice (a second commit is `error`)
    {"t":"read","fromSeq":<uint64>}                                                           replay from max(fromSeq, firstSeq), then live records on this connection
    {"t":"ack","seq":<uint64>}                                                                writer: the ring drops every record at or below seq
    {"t":"stdin","offset":<uint64>,"len":<n>}\n<n bytes>                                      writer: applied iff offset == stdinApplied
    {"t":"end"}                                                                               writer: closes the child's stdin
    {"t":"signal","name":"SIGTERM"|"SIGINT"|"SIGKILL","group":<bool>}                         writer: to the child, or its process group
    {"t":"release"}                                                                           writer, after the child's exit: the host removes its files and exits now
    {"t":"hb"}                                                                                optional; the host keeps no liveness clock on its clients

Host → client:

    {"t":"hello","protocol":1,"holderId","pid","procStart","appSessionId","engineSessionId","state":"ready"|"committed"|"running"|"exited",
     "child":{"pid","procStart"}|null,"fence":<uint64>,"writer":<bool>,"stdinApplied":<uint64>,"ring":{"firstSeq","lastSeq","bytes"},"exit":{"code","signal","at"}|null}
    {"t":"spawned","pid","procStart"} | {"t":"spawnFailed","message"}                       the answer to commit
    {"t":"attached","fence","stdinApplied","ring":{…}} | {"t":"refused","reason":"fence"|"role"}
    {"t":"out","seq":<uint64>,"len":<n>}\n<n bytes>                                          one stdout line, without its newline
    {"t":"err","seq":<uint64>,"len":<n>}\n<n bytes>                                          one stderr line, in the same sequence
    {"t":"caughtUp","lastSeq":<uint64>,"gap":<firstSeq>|null}                                 after a read's replay; gap when fromSeq < firstSeq
    {"t":"applied","offset":<stdinApplied after>} | {"t":"duplicate","applied"} | {"t":"gap","applied"} | {"t":"fenced","fence"}
    {"t":"exit","code":<int>|null,"signal":<string>|null,"at":<iso>}                          the child's exit, from waitpid
    {"t":"problem","kind":"line_budget","length":<n>}                                         a line over 64 MiB dropped
    {"t":"error","message"}

Constants, in `native/session-host/host/limits.go` and mirrored in `src/engine-host/holder/protocol.ts`: `LINE_CAP` 64 MiB, `RING_CAP` 8 MiB, `LINGER` 10 min, `HOST_EXIT_GRACE` 5 s, `AUTH_WINDOW` 2 s, `FRAME_CAP` 64 MiB + 256 bytes for the byte records.

#### E. OX10 as adopted: the gate (M5; the observer is O12 M4's)

On `gate.sock`, newline-delimited JSON, many clients, no token (the uid boundary; the socket reveals no session data and takes no control), served by `@shared/host/socket-server`'s many-clients mode with a runtime per connection. The engine host sets `MAWS_HOLDER_SOCKET=<its path>` in every hosted launch's environment.

Observer → host:

    {"t":"hello","protocol":1,"session":"<engine session id>","pid":<claude's pid>}     first; the host keys the observer by pid to its row's child
    {"t":"hb"}                                                                            every 5 s; silence past 15 s drops the observer
    {"t":"armed","fence":<n>}                                                             the fence is installed in turn.step
    {"t":"turn","fence":<n>,"origin":"query"|"cron"|"task"|"peer"|"unknown","delivery":"<id>"?}   before next() in the main loop's turn.step, while a fence is installed

Host → observer:

    {"t":"welcome","protocol":1}
    {"t":"arm","fence":<n>,"leaseMs":10000}                                               renewed with the same fence before the lease ends
    {"t":"disarm","fence":<n>}
    {"t":"proceed","fence":<n>} | {"t":"stop","fence":<n>,"reason":"The holder ended this session; reopening it continues the conversation."}

Rules (O12 M4's, with O16's additions): the host signals only after `armed` and within `leaseMs` by its own clock less 1 s; the observer, on `stop`, calls no `next` and streams the reason as the turn's one chunk; with no answer to `turn`, it proceeds after the lease has expired by its own clock plus one heartbeat; a `turn` whose fence is not the armed one is answered `proceed`. The settlement: sminos defers settling an inbox delivery to a marked session until the observer reports the turn it started as `proceed` (or proceeds on the lease's expiry), carrying the delivery's id as `delivery`; on `stop` the delivery stays owed and is delivered after resume. With no observer connected, or one dropped for silence, the row is released on verified-empty alone (owner Q1's default; a `no` makes such a row never release and its status say `gate: 'absent'`).

The fixture `spikes/protocol-probe/fixtures/p5/p5-o16-gate.jsonl` records one exchange of each kind (arm → armed → turn → proceed; arm → armed → signal → turn → stop; arm with no answer → disarm; renew) from M5's tests, as the conformance replay O12 M4's bridge test runs.

#### F. The reap and the release rule (M5)

`src/engine-host/holder/reap.ts`:

    export type ReapState = 'idle' | 'arming' | 'armed' | 'signalled' | 'term_ignored';
    export interface ReapDeps { gate: Gate; current(): EngineSessionStatus | null; interest(): boolean; descendants(): number; stop(reason: 'idle' | 'budget'): Promise<StopResult>; now(): number; log(line: string): void }
    export class Reap { constructor(session: EngineSession, deps: ReapDeps); due(reason: 'idle' | 'budget'): void; cancel(why: string): void; readonly state: ReapState }

Transitions: `idle` --due, verified empty, observer--> `arming` (send `arm`); `arming` --`armed`--> `armed` (the step runs at once); `arming`/`armed` --`turn`, or any veto at the step--> `idle` (`proceed`, `disarm`, the row's clock restarts); `armed` --step: verified empty, lease live--> `signalled` (stop); `idle` --due, verified empty, no observer--> `signalled`; `signalled` --`turn`--> `stop` answered, state unchanged; `signalled` --exit--> the row is released (the table's `released` set, as today); `signalled` --SIGTERM ignored (`idle` only)--> `term_ignored` → `idle` after the journal row, with `work.unknown = 'reap_term_ignored'` until the next status that clears it (the next Stop, as any unknown).

## Owner questions

- **Q1. A lane B session with no observer connected.** The sminos plugin may be absent from a machine, or a session's bridge may be off (a secrets guard outside it, `bridge.tsx`'s `judgePlace`). May such a session be released on verified-empty alone, on both roles? **Recommended: yes.** Without the bridge no peer message can reach the session, and verified empty rules out a cron fire and a task notification; what remains is an engine-started turn in the milliseconds between the final check and SIGTERM, and that turn's trigger is in the engine's own transcript. The alternative, never releasing such a session, keeps every unbridged session on a server for good, which is the cost F2 exists to give back. The document plans the yes; a no changes one branch in `reap.ts` and the status's `gate: 'absent'` wording.

## Surprises & Discoveries

- Observation: the engine's own `--bg` supervisor and claude-ssh both hold the durable unit in a per-session process and replace the manager above it; the engine host's E10 shape already has every piece but the per-session process (the lock, the token, the socket, the orphan ledger, the journal as a durable record of every frame), so the holder is a transport swap plus adoption, not a new supervisor.
  Evidence: `holder-tui-spike.md` §A1 and `desktop-ssh-helper-protocol.md` §3.1 to §3.2 against `src/engine-host/{detached,live-ledger,journal}.ts` at master `33935b949`.

  Evidence: `src/shared/host/detached-transport.ts` `welcomed` (the `otherBuild && liveSessions === 0` branch) and `src/shared/ipc/wire.ts` `V2_LINK` (the frozen `v2.exit`).

The split judgement, at dispatch (the section's instruction): no cut; the release rule is a milestone track of its own inside this document.** The holder (M1 to M4) is one state machine across two processes (the fence, the roster, the checkpoint): one spec. The gate and the verified-empty release (M5) have a different state owner (the engine host's idle release and sminos's bridge), a different verification (race tests and the VM spike) and a different failure mode (a lost turn), which trips decomposing's signal in form; they depend on the holder for nothing (the gate is the engine host's, the descendant veto reads the table's own `ps`), so they are a track the controller may run beside M2 to M4. Rejected: a second child (O16-B): a second document, PR and review cycle for two milestones whose executors would read the same files (`idle-release.ts`, `budget.ts`, `work-state.ts`) and whose acceptance P5 binds into one section; the architect may still cut it, since the track's milestones touch nothing M1 to M4 touch beyond `process-table.ts`'s sample.
- **D3. The session host's language is Go, std only.** Measured on this MacBook, prototypes of one shape (D-listed in Surprises):

The ring's cap (8 MiB, D6) bounds the loaded case for either native language.
- **D4. The host protocol carries output and input as length-prefixed byte records beside NDJSON control lines.** A 64 MiB line is the engine host's own cap; JSON-escaping it on the relay would double its memory and time on both ends. Rejected: NDJSON for everything (simple, but the hot path pays), and a binary codec throughout (the engine's PTY-host frames: a second codec with no reader in the repository).
- **D5. One `claude` process per session host, named by the launch id.** The holder design's four identifiers map onto what MAWS already names: `holderId` is the launch id (`mintLaunchId`, one per process, the journal's and the request ids' prefix); `processEpoch` is constant (a host never respawns: a resume after a release is a new launch, a new host); `engineSessionId` is the lineage `durable-crons.ts` already keeps; `bindingGeneration` is the writer fence. Rejected: a host that respawns `claude` (a second process state machine for a case nothing asks for).
- **D6. The ring holds what the writer has not acknowledged, up to 8 MiB; the manager acks after each synchronous journal write, with no fsync.** The journal is MAWS's durable record of every frame, which claude-ssh lacks, so holding acknowledged output in the host is waste: an idle session's host then carries the binary alone. 8 MiB covers about 10 s at 800 KB/s, more than the handover's gap (sub-second) or a crash's (the restart ladder's first step, 0.5 s, plus adoption); past it the gap is exact and noticed. The ack after the page-cache write is enough: a process crash keeps the page cache, and a machine crash ends everything. Rejected: claude-ssh's unconditional 16 MiB (its only copy of recent output); an fsync per line (the journal does none today).
- **D7. No transient scope on Linux; a session host's own SIGTERM takes its child down.** O2's `KillMode=process` and the user manager already keep every child of the unit across a `mawsd` restart and a logout (O2 M8), so the session host inherits the engine host's protection with nothing added; M4's VM run proves it. A host told to exit by signal sends SIGTERM to its child's group first, because an engine with no stdio runs on unreachable (E10 M0 Q1) and the sweep would have to find it. Rejected: `systemd-run --user --scope` per host (O2 rejected it for the children; it buys nothing under `KillMode=process`); a host that exits leaving its child (the sweep's case, left for SIGKILL alone).
- **D8. No direct spawn after M2.** A launch whose session host fails to start is refused `host_unavailable` with a notice naming the host's log, never spawned directly: two shapes of row in one engine host would make adoption, the sweep and the exit order each two-way. Rejected: a fallback to today's spawn.
- **D9. The handover is an exit that detaches.** Every exit path of a capable engine host but `host.stopAll` and the quit path's stop detaches its hosted rows after a bounded drain; `mawsd`'s existing `exit {when: 'now'}` on a build mismatch is the trigger, sent now when the welcome lists `host.holder`, and `daemon.restartEngineHost` sends the same on demand. Rejected: a `handover` value for `exit`'s `when` (a frozen protocol-2 enum, a major), and a `host.handover` command (a second path to the same exit order).
- **D10. Adoption runs before the sweep, and the sweep kills only what no live host holds.** A row of `live.json` naming a holder with a live host is that host's; a roster entry whose host is dead and whose child lives is swept by the child's recorded identity; a row with no holder is a pre-M2 process, swept as today. Rejected: a sweep that trusts `live.json` alone (the roster is written by the host and survives the manager's crash between a launch and the ledger's rewrite).
- **D11. Across a wire major, a capable engine host hands over on the client's `exit {when: 'idle'}` when the client's hello listed `host.holder`.** The refusal line is frozen and carries no capability, so the client cannot tell a capable refused host from an older one and keeps writing `exit {when: 'idle'}`; the host can tell an adopting client from its hello, and an adopting client's "when idle" is served at once, since the sessions survive the exit. A client that listed no `host.holder` gets E10's wait: it would sweep what it cannot adopt. So the client's hellos (`PEER_CAPABILITIES.app` and `daemonToEngineHost`) list `host.holder` from M3 as well as the host's welcome. **[parent-impact]** P5 §2's "an upgrade across an OX1 major ends its lane B sessions" no longer holds after O16 for an engine host at or after M3; the architect may amend it at landing. Rejected: reading the roster directory as the capability signal on the client side (true of the host's state, but a host of a build before M3 never wrote one, and a client's guess should not decide an exit).
- **D12. The owed interrupt is a state-file mark.** Set before the interrupt's control request is written, cleared at its response or failed write, sent first by an adopter; the queue's `uncertain` already covers submissions. Rejected: re-sending every unanswered host-issued request (a `set_permission_mode` applied twice is harmless but a second `interrupt` after a completed one cuts the next turn).
- **D13. The gate is the engine host's.** See Surprises. Rejected: the session host serving `MAWS_HOLDER_SOCKET` (the final check's inputs would cross a socket; a separate token-free socket per host for the bridge, since the manager's token never reaches `claude`'s environment).
- **D14. OX10 gains `origin: 'peer'` and `delivery`, and the settlement is the observer's report.** The architect asked O16 to define the settlement P5 Decision Log 19 named; the bridge reads the delivery's id from the inbox row it starts a turn for, and sminos settles on `proceed`. Rejected: a settlement message from the engine host to sminos (the engine host knows no delivery ids).
- **D15. An `idle` reap never escalates to SIGKILL; `budget` keeps it.** The holder design §3.2 step 5 for the idle release; charter §4.4's budget release is the memory's and not O16's to soften. Rejected: no SIGKILL for either (a budget release that fails leaves the machine over its budget with nothing to do).
- **D16. `WIRE_MINOR` 13 at M3, re-read at landing and set one past master's.** The sibling children each take the next free number; the manifest is regenerated from master's entries at each merge.
- **D17. The descendant veto reads the table's `ps` with `pgid`, synchronously at the step.** One `ps` per release attempt (about 10 ms), a rare event, rather than a 10 s-stale sample at the moment of truth. Its reading (outside the group, or started after the last turn) is M0's question 4.
- **D18. The session host's cost is read by its own measured case with its own bound, outside acceptance 14's two-process bound.** P5 defines the bound as `mawsd` plus the engine host; a session host exists only with a live session, which the idle scene's replay never spawns. Rejected: folding it into the idle bound (which would change the bound's definition P5 fixed).
