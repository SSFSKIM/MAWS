## Purpose

After O3-E the spine and the checkouts run in `mawsd`, but four services that are plain Node still run only in the app: the connectors (the broker an artifact page's connector calls and watches go through, route E over a live session's engine and route D over MAWS's own MCP connections, MAWS's own OAuth with its sealed grants, the owner's per-server rows, the engine's MCP sign-in, and the agent's dataset refresh), the owner's Send to (Notion through route D, Drive through the `gws` CLI), the library's reach to a stored file (its path, its bytes, open and reveal), and Discover's catalog, whose engine reads and file watch are the machine's while its network sources are the person's. So today an agent's `artifact_dataset {refresh: true}` settles `noClient` when the app is closed (P5 acceptance 2's carve-out), a connector signs in only on the Mac the app runs on, Send to has no machine-side service for O7 to reach, and route D's grants are Chromium `safeStorage` ciphertext a non-Chromium daemon cannot open (U7).

O4 moves them. After it, on the daemon shape:

- **Connectors are the machine's.** The broker, both routes, MAWS's own OAuth, the owner's rows, the engine's sign-in and the dataset refresh run in `mawsd`, composed with the spine. An artifact page's `connectors.*` lease commands, the owner's `connectors.servers/connect/reconnect/disconnect`, the grant commands (`artifacts.connectorGrants/grantConnectorTool/revokeConnectorTool`) and `connectors.signIn/signInCancel` are `machine`-owned and served on `machine.sock`. A lease belongs to the client that opened it, as it belonged to a window; the owner window's veto is a fact the app reports.
- **The agent's dataset refresh completes with the app quit** (P5 acceptance 2): the engine host announces it to its permanent client, `mawsd`'s broker runs it through the session's own engine, and answers it.
- **Route D's grants have a custody of their own (U7).** They are sealed under a software key the machine holds (`<profile>/connectors/oauth/key`, 0600 in a 0700 directory, out of Time Machine), the same class as the device and machine keys until signed builds exist (RL §5.1). The records sealed under Chromium's `safeStorage` survive the move: at the app's first launch after the update, main, which still has `safeStorage`, opens each and hands it to `mawsd` to re-seal, with at most one Keychain prompt per profile; a record the app cannot open is listed by its id and is forgotten or reconnected once (P5's "one prompt each"). After that, no connector ever asks the Keychain again, on any machine.
- **Consent opens on the client.** The owner's Connect, the engine's sign-in and `gws`'s login open their URL through the client port on the client that asked (OX4; `noClient` when none can), and the machine listens for the callback on its own loopback, which on the app's own machine is the browser's host. The relayed callback for a remote client is O7 M5's, on the seam Interfaces §E leaves.
- **Send to is the machine's** but for its export step, which stays in the app until O5 brings exports to the machine: `delivery.status`, `delivery.connect`, `delivery.cancel` and `delivery.receipts` are `machine`-owned; `delivery.send` stays the app's, exports as today and hands the export's path to the machine's `delivery.deliver`, which sends it and keeps the receipt. Receipts live in `mawsd` for its life, so they survive the app.
- **The library's file reads are the machine's.** `library.content`, `library.read`, `library.openExternally` and `library.reveal` are `machine`-owned, `library.read` reading the files service in process; `library.exportFormats` (the app's exporter registry) and `library.saveAs` (a copy to a path the client chose) stay the app's until O5.
- **The catalog splits by owner.** Its machine half, the engine's reads per cwd and the watch over the engine's plugin state, is a `mawsd` service (`catalog.engine`, `catalog.engineRefresh`, `catalog.engineChanged`); the person's half, the network sources cached under the profile, the icons and the join, stays the app's, and `catalog.home/query/item/refresh/icon/postures/sources` keep their shape.
- **The laptop pays nothing more while idle.** Everything of O4 composes with the spine: loaded when it loads, released when it releases, never in `mawsd`'s cold core.

The embedded shape (`supervisor.shape: embedded`) still composes everything in main through the same roots, so the app works in either shape.

**How to see it working.** On a scratch profile on the daemon shape, open MAWS, open an HTML page with a connector widget and the Connectors sheet: `mawsd status` shows the spine `loaded`, `mawsd logs --follow` shows `[connectors] …` lines as the page's lease opens and refreshes; Connect a route D server: the browser opens on this Mac, the callback lands on `mawsd`'s listener, the sheet reads `connected`; quit the app while a dashboard's agent refresh is in flight and reopen: the refresh completed (the dashboard's dataset moved while no app ran). Send a document to the fixture Notion from its header and read the receipt in the library's row after a relaunch. Concrete Steps has each command; the e2e groups in Acceptance prove each behaviour on the gate's Macs.

**Decisions.**
- The custody is a software key file, not the Keychain through `security` nor a native addon (D4). The Keychain re-prompts every unsigned or ad-hoc rebuild for the app and any other binary alike, `/usr/bin/security` is its own partition and prompts once per item, and a LaunchAgent's dialog may show on a screen no one watches; a key file prompts never, works on Linux unchanged, and is the class RL §5.1 and O10 M9 already accepted for the device and machine keys until signed builds exist. Rejected: reading the app's "MAWS Safe Storage" item from `mawsd` and reimplementing OSCrypt (the format is ten lines, Decision Log D3, but it adds a second reader of the Keychain item with the same grant fragility, and `security`'s prompt under launchd); libsecret on Linux (a session bus a headless VM lacks).
- The whole directory `<profile>/connectors/oauth/` leaves Time Machine, key and records together (D5): a restored Mac reconnects, as it re-registers its device keys; a backed-up record with no key would only ever be an unreadable row. Rejected: excluding the key alone.
- The sealed format: line 1 `maws-connector-oauth/2`, line 2 base64 of `nonce ‖ ciphertext ‖ tag` (12, n, 16 bytes), the connection id as AAD so a file copied under another id never opens (D6). The record schema (`RecordSchema`, version 1) is unchanged, so the adoption re-seals the same JSON.
- `list()` reports a v1 file as `legacy` from its first line alone, touching no sealer; `read(id)` of a legacy file answers `null` as a missing record does, so the provider's `state(identity)` for an identity whose only record is legacy is `disconnected` (the owner's Connect), and the owner's rows show the legacy record by id under the unreadable rows' treatment (Forget by id, `oauth-provider.ts`'s `ids()` path). Rejected: a new owner-facing state (a wire change in `ConnectorServerRow`'s enum, breaking under OX1).
- The adoption driver is main's: it reads with main's sealer, calls `adopt` and never deletes a file; `mawsd`'s adopt replaces the v1 file atomically with the v2 record under the same name (M2). A denied or temporarily unavailable `safeStorage` ends the pass for that launch (Decision Log D3: Electron's `OSCryptAsync` initialises once, so a denied prompt is not retried in process); the next launch tries again, and the owner's remedy for a record they will not allow is Forget.
- Lint: the moved files import `node:*`, `@shared/*`, `@modelcontextprotocol/sdk` and `zod` only; `src/main/ipc/router.ts`'s `CommandFailure` (used by `sign-in.ts`? the executor checks each import) is replaced by `@shared/ipc/errors`'s shape the services already throw.
