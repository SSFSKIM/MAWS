## Purpose

**U8c-1.** When an agent enters or leaves a git worktree through the engine's worktree tool, the engine moves the session's transcript file, with its folder, to another place in its store. Today (build F included) three things go wrong at that moment: a terminal session's Background tasks stop changing, an open transcript of one of the session's agents stops reading, and the session is told removed and listed as archived for an instant. After this landing the readers go on reading across the move and nothing is told removed.

**U8c-2.** The owner's agents usually move themselves into a worktree soon after a session starts, by the worktree tool or by a shell `cd` into a worktree made with `git worktree add`. Today the window follows the first kind only by re-filing the session, and the second kind not at all: after a `cd` the Environment card names the launch folder, Review and Source control diff it, Files lists it and a new terminal opens in it, while the agent works somewhere else. After this landing the card says where the agent is (the folder, the branch git reports there, and one muted line "moved from …"), Review, Source control and Files show that folder, a new terminal starts in it, the sidebar marks the session as in a worktree, and all of it returns when the agent comes back. It is the same for a session MAWS runs and a session started in a terminal, here, and for a session MAWS runs on another machine.

How to see it working. U8c-1: the test that renames a real transcript under the real readers fails on master and passes on the branch, on Linux and on macOS. U8c-2, on the wave's build: in a session whose repository has a worktree, have the agent enter it (by `EnterWorktree`, then again by `cd`); within the turn the card shows the worktree's folder and branch with "moved from <the launch folder's name>", Review lists the worktree's changes, Files opens on it, a new terminal starts in it, a terminal opened before says it is still in the launch folder, and the session's sidebar row carries the worktree mark; have the agent leave, and all of it returns. In the suites: a test that replays the probe's two recorded sessions through the summary and the index and asserts one answer for both (M2), and the suites named under each milestone.

## Words used here

- **The filed folder:** the folder build F's record names, `record.worktree?.path ?? record.directory`: where the engine files the session. The engine moves it on `EnterWorktree`, `ExitWorktree` and a `/cd`, and the index re-files the record with it; a shell `cd` does not move it. U8c-2 leaves its meaning and its movement as they are.
- **The home:** the folder the engine files the session under, read from the transcript: the tail's last `relocated` row's `relocatedCwd`, else the first row's `cwd`. The filed folder is the home as the index located it.
- **The launch folder:** the folder the session was launched in, which does not move while the agent moves inside one repository. In the selector, `launch`.
- **The working folder:** the checkout the agent's main loop is working in now (UC-4). In the selector, `path`. **The agent's folder:** the folder itself, which may be a sub-folder of that checkout; in the selector, `cwd`. **Moved:** `path !== launch`.
- **The selector:** `workingFolder(record)` in `src/shared/sessions/working-folder.ts` and the hook `useWorkingFolder(appSessionId)` in `src/renderer/src/sessions/working-folder.ts` (U8a). Every reader of the session's folder asks it.
- **A row:** one line of a session's transcript file (`<config home>/projects/<slug of a folder>/<session id>.jsonl`; a **project folder** is one `<slug>` folder). Rows the engine writes for a message carry `cwd`; bookkeeping rows (`relocated`, titles, modes) do not. **The newest row's folder** is the `cwd` of the last row that carries one.
- **A move by the tool / by `cd`:** the two ways the probe recorded (`spikes/protocol-probe/findings-uxwave-U8-working-folder.txt`). By the tool the home moves, the transcript file moves with it, and the rows' `gitBranch` follows; by `cd` none of that happens, and only the rows' `cwd` says so.
- **The same repository:** two folders whose common git directory is the same (the `.git` folder of the main checkout, which every linked worktree's own git directory points back to).
- **The summary:** what the engine host reads of a transcript from its first and last 64 KiB (`summarize` in `src/engine-host/fs/summarize.ts`, `TranscriptSummary` in `src/shared/wire/store.ts`), sent as `fs.sessionChanged` on every change of the file. **The index:** the machine's SQLite store of session records (`src/services/index/`); `upsertFromSummary` in `sessions.ts` turns a summary into the record.
- **A follow:** the engine host reading one transcript forward and sending its rows as events (`Follow`, `ChainFollower`, `FsService` in `src/engine-host/fs/`). **A scan:** one pass of `FsService` that lists every transcript in the store (`pass`, through `Discovery.list`).
- **The routes** (law 5): a session MAWS runs; a terminal session; a session on another machine.
- **Build F:** `f1852de3a`, the build on the owner's machines, which may open the same profile again after this build has written to it, and may be the build of the window or of the host on the other side of a link.
- **The VM:** the wave's build machine, where every check of an executor runs. **Class 1a:** typecheck, lint, the unit suite and the probes on GitHub Actions through `scripts/ci-gate.sh`. **The Mac lane:** the gate's job `unit:darwin`, which runs on macOS the unit files that hold a case guarded `skipIf(process.platform !== 'darwin')` (`scripts/darwin-unit-files.sh` finds them by that text). **The tracker:** `docs/tech-debt-tracker.md`, a table of findings left unfixed, each with its evidence and what would close it.

### M3 — What may be read there (U8c-2)

## Interfaces and Dependencies

### §A. The summary's field (M2)

In `TranscriptSummarySchema` (`src/shared/wire/store.ts`):

    newestCwd: z.string().nullable().optional(),

The `cwd` of the newest row in the tail window that carries one and is not a sidechain row (`isSidechain !== true`); null when the tail window holds no such row; absent from a producer that does not read it. `summarize` takes it from the tail only, newest first, and never from the head: a head's newest folder in a long file is old. A last line still being written counts by its start, as the summary's other tail facts do. It is optional because the summary is sent between builds (`fs.sessionChanged`) and kept as JSON in the index.

### §B. The index's rule (M2)

`upsertFromSummary` writes every column it writes today, by today's rule, from today's inputs. It then writes two more (§C), from three folders of the summary: **H**, its first row's (`directory`); **R**, the home its tail names (`relocatedCwd`), which may be null; **C**, its newest row's (`newestCwd`).

- **C absent**, or the location the record was filed at has no realpath (the home is gone): both columns null.
- **H, `R ?? H` and C are one string:** both columns null, and nothing is read.
- **Otherwise.** Let *home* be the location the record was filed at (`locate(R ?? H)`), *filed* its `worktreePath ?? realpath`, and *directory* its `realpath`.
  - *launch* is filed; except when R is not null and is another string than H, the first row's folder resolves, and `repositoryAt` answers one `commonDir` for it and for directory: then launch is `first.worktreePath ?? first.realpath`, with `first = locate(H)`.
  - *at* is `checkoutIn(launch, C)` when C is a folder, else null.
  - `launch_folder` is written when launch is not filed, else null.
  - `agent_folder` is written when *at* is not null and `at.checkout` is not filed or `at.cwd` is not directory; else null. Its `branch` is `branchName(summary.gitBranch)` when `at.workTree` is null or is the work tree `repositoryAt` answers for directory, else `headBranch(at.workTree)`; its `linked` is `at.linked`.

`index/source.ts` warms H as well as `R ?? H` for a summary whose R is not null and differs from H, so that `locate(H)` runs no git on main's thread.

In `src/services/index/projects.ts`:

    export interface Repository { commonDir: string; workTree: string; linked: boolean }   // each path a realpath
    export function repositoryAt(folder: string): Repository | null;
    export function checkoutIn(launch: string, folder: string): { checkout: string; cwd: string; workTree: string | null; linked: boolean } | null;
    export function headBranch(workTree: string): string | null;

`repositoryAt` resolves the folder and takes the nearest `.git` at or above it. A directory: `commonDir` is its realpath, `workTree` the folder that holds it, `linked` false. A file `gitdir: <G>`: `commonDir` is the realpath of what `<G>/commondir` names (relative to `<G>`), or of `<G>` when it has none; `workTree` is the folder that holds the file; `linked` is whether `commonDir` is not `<G>`'s realpath. None up to the root, or anything unreadable: null. It is synchronous, as `locate`'s reads are, and mirrors only this much of git (no `core.worktree`, no bare repository, no mount boundary): it decides what is shown, never what may be read, which §G decides with git's fuller reader. `headBranch` reads the `HEAD` of the work tree's git directory and answers the name after `ref: refs/heads/`, else null (detached, unreadable, no repository).

`checkoutIn`, with `c` the folder's realpath, `rc = repositoryAt(c)` and `rl = repositoryAt(launch)`; "at or under" is at a segment boundary:

| the folder | answer |
|---|---|
| does not resolve | null |
| `rl` null (the launch folder is in no repository): `rc` null and `c` at or under launch | `{ checkout: launch, cwd: c, workTree: null, linked: false }` |
| `rl` null, anything else | null |
| `rc` null, or `rc.commonDir` is not `rl.commonDir` (no repository, or another) | null |
| in the launch folder's own work tree, at or under launch | `{ checkout: launch, cwd: c, workTree: rl.workTree, linked: rl.linked }` |
| in the launch folder's own work tree, elsewhere | `{ checkout: rl.workTree, cwd: c, workTree: rl.workTree, linked: rl.linked }` |
| in another work tree of the same repository | `{ checkout: rc.workTree, cwd: c, workTree: rc.workTree, linked: rc.linked }` |

    export function workingFolder(record: Folders): WorkingFolder {

      const path = record.agentFolder?.checkout ?? filed;

    export function workingWorktree(record: Folders): { path: string; branch: string | null } | null {

    export function workingBranch(record: Folders & Pick<SessionRecord, 'branch'>): string | null {
      const at = record.agentFolder;
      return at === undefined ? (branchName(record.worktree?.branch) ?? branchName(record.branch)) : branchName(at.branch);
    }
