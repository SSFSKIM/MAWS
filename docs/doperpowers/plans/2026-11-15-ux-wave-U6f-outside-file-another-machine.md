## Purpose

A session can run on another machine: a second Mac, a Linux host. From this Mac its chat, its files inside its folders, its terminal and its source control already work over the machine link. A file outside its folders does not: a link to one in the conversation is refused, a file the agent sent from outside opens but cannot be saved, and File ▸ Open File… (U6e's command) is unavailable with such a chat in front, because the system's file chooser shows this Mac's files and the session's files are on the other machine.

After this landing both work there as U6e makes them work here. A file from outside the session's folders on the other machine opens when that machine's own evidence admits it (the session's transcript there names it, the session's agent sent it, or the person chose it), is editable, and is saved on that machine only when the person presses Save, under the same write rule. Open File… with such a chat in front shows a chooser MAWS draws of that machine's folders and files; the file picked opens beside the chat. Both are limited to a person who may already open a terminal on that machine: the right is checked on that machine, for every request, by the same decision that admits a terminal. This build's window offers them to the people who own that machine, of whom the machine asks no confirmation; whether a member with a terminal grant who does not own it gets them too, one confirmation per request, is the owner's to say (Card 4). For anyone else, and for a machine that runs an older build, the item is unavailable and says why, and what such a person can see of that machine does not change.

How to see it working: on this Mac open the chat of a session that runs on a second machine, whose transcript links a text file outside its folders there. Click the link: the file opens beside the chat, editable, and its path's tooltip reads "Save writes to <its path> on <the machine's name>". Type a word and press ⌘S: the file on the second machine holds the word, and that machine's daemon log has one line naming who wrote it and when. Press ⌘O: a sheet lists the second machine's home folder; walk to a file and open it; edit and save it; quit and relaunch: the tab is there and saves again.

## Words used here

U6e's words hold as it defines them: **the folders** (a session's roots), **outside**, **the daemon** (`mawsd`), **main**, **the page**, **named by a counted form**, **a grant**, **chosen**, **sent**, **added**, **the real path**, **the pin**, **MAWS's own folders**. New here:

- **The other machine**: the machine a session runs on when that is not this Mac, reached over a machine link. **This Mac**, or **the device**: the Mac whose app window the person looks at.
- **The machine link**: the sealed channel (RL2) between this Mac's main and the other machine's endpoint, direct or relayed by the hub, which sees sealed frames only (`apps/org-protocol/src/channel.ts`). A machine reached this way is "over RL2" (`isOverRl2`, `src/renderer/src/lane-b/remote-session.ts`). Another profile of this Mac, reached over a socket, is not one, and nothing here changes for it.
- **The endpoint**: the part of the other machine's `mawsd` that answers a machine link (`src/endpoint/`). **The offer table** (`OFFERS`, `src/endpoint/offers.ts`) lists every name that crosses; a name with no row is refused `not-offered`. A **row** says whether the name is a `call` (a read) or an `act`, who runs it, and where its target is read.
- **The grading function**: `Authorizer.authorize` (`src/endpoint/authorize.ts`), the one function that decides every request of a link, in eight steps: the row, the grade, the device's class, the caller's standing, the effect, the machine's policy, the class's words, presence. **A grade** is what a command asks of its caller: a rank on a session (`list` to `manage`) or a right on the machine (`spawn`, `shell`, `machine-admin`).
- **The terminal's row**: the row of `pty.spawn` in the offer table, with the grade the registry declares for `pty.spawn` (`src/shared/ipc/grades/pty.ts`; today `shell`, a right on the machine held by its owners and by a member a grant names). **At the terminal's grade**: a caller the grading function admits on that row. **Below it**: everyone else.
- **A step-up**: the device's signature of one act after the person confirms it with Touch ID or the login password (`src/main/device/step-up.ts`). The grading function asks one for a `shell` act of a member who is not one of the machine's owners, and none of an owner.
- **A claimed act**: an act the endpoint admitted and handed to the machine's services through `machine.op` (`src/services/machine-ops.ts`), which writes a claim (the member, the device, the operation's id) into the services' ledger before the command runs and hands the claim to the command's handler as `HandlerContext.op` (`src/shared/ipc/client.ts`). A handler sees `remote: true` for every request the endpoint dispatched, and `op` only for a claimed act.
- **The ledger**: `<profile>/spine-ops.jsonl` on the other machine (`src/shared/host/op-ledger.ts`), one record per operation id, so that an act runs once and a lost answer is asked again by its id.
- **A capability**: a word an endpoint lists in its handshake once it serves an addition (`src/endpoint/capabilities.ts`); the device sends the addition to no endpoint that does not list it (`REMOTE_NEEDS`, `src/shared/ipc/remote-unavailable.ts`).
- **The standing**: what the page knows of a session's machine when it draws a control (`RemoteStanding`): its name, the link's phase, the capabilities listed and whether the person is one of its owners, as main reads the org state it holds. It decides how a control is drawn and never what the machine allows.
- **An app page**: a live page of a window the app made as an app window (U6e's `isAppPage`: `pageOf(client)` among the web contents of `appWindows()`); a presentation window, the repair window, a frame and a caller with no page are none.
- **The send window**: the time within which an act not yet put on a channel may still be sent: from its making to its `sendBy`, which for a save is the pending bound (`REMOTE_ACT_PENDING_MS`, 60 seconds). After it the act is never sent.
- **The chooser**: the sheet MAWS draws for Open File… when the files are on another machine. The system's chooser, which U6e uses on this Mac, cannot show them.
- **A private folder**: a folder macOS protects by its privacy settings (Desktop, Documents, Downloads and the like; `src/shared/machine/home-folders.ts`). Reading inside one may raise a privacy prompt on the machine that reads.

## The write rule on another machine

U6e's five lines hold on the other machine, read by its daemon. What each becomes when the page and the daemon are on two machines:

1. **Evidence.** The other machine's daemon writes a file outside a session's folders only when it holds, itself, evidence that admits the file for that session: its transcript names the path by a counted form, the person chose the file, or the session's agent sent it. The rule of a counted form is U6e's as built, read by that machine's daemon over its own transcript and changed by nothing here: the agent's own text, a tool call's input, and the person's own text, which is the text of a `user` row or a queued prompt whose origin is the person's and from which U3a's reader reads no other arrival, at most its one text by position, and only where no reader of a form MAWS writes as the person's claims any part of it (`rowClaim`, `personsOwn`, `src/shared/files/named.ts`; the guard of who sends as the person, `test/support/person-sends.ts`). A peer session's message, a notification, an answer MAWS composed and a tool's result admit nothing. The choice is the one piece of evidence that begins on the device: it is an act of its own at the terminal's grade, and the daemon makes the record (condition (d)). U6e's stated bound holds here as there: a member who may send a message into the session can make its transcript name a path, and that message stays in the transcript; the read and the save still need the terminal's row.
2. **The sender.** Two checks in a row. On this Mac, only a live page of an app window causes an outside act, however the act comes about. U6e's guard in the router lets the four names through for such a page alone, before anything is forwarded. And where main itself turns another request into an outside act (the adapter's keyed read, which becomes `files.readOutside`; the copy of "Open externally"; the copy a file's frame is drawn from), it does so only for a caller the same predicate admits, `isAppPage`, and answers every other caller (`dispatchLocal`, `invokeOwn`, a window that is no app window) the plain read, with no act. One predicate, at every place an act can begin. On the other machine, the endpoint admits the act only on the terminal's row, for the member and the device the channel proved, and the services run it only as a claimed act.
3. **The real path.** The save names the real path the file had on the other machine when it was shown, and that machine's daemon refuses it when the path no longer resolves there. The read and the save are two operations, and the link may drop between them: nothing is held open across them, and the save alone carries what it must hold to (the pin and the hash).
4. **The content.** The save carries the hash of the content the person was shown; other content on that machine's disk answers `conflict`. The save is one operation id: the ledger there runs it once, and a lost answer is asked again by that id ("The sequences that must hold", R5).
5. **Never.** For a caller below the terminal's grade; for a remote request that is no claimed act; a file in one of MAWS's own folders on that machine; through `files.write`; a file only an added record or only a tool's result admits; a create, a rename, a watch or a reveal outside the folders.

**What it does not stop, beyond U6e's list.** A fault in the app window's own page code, for an owner of a machine: it can list that machine's folders, choose a file and then read and save it with no press. The same page can already open a terminal there, since `pty.spawn` is a command of the page, so no reach is added: this is the reason the conditions take the terminal's row (condition (a)). This build asks only for an owner, of whom the machine asks no confirmation.
