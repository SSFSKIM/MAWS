# U11 · Settings, connectors and the Org pages

> **A child of the UX wave.** Root: `docs/doperpowers/specs/2026-11-12-ux-wave-design.md`. Read it first: it holds the wave's purpose, its laws (law 1 to law 8), the contracts UC-1 to UC-15, the ordering and the record. This file is this child's section of that document. Where this file and a contract's statement in the root differ, the root binds; report the difference. **Grain:** plan. Items are named by their ids in the register, `docs/doperpowers/evidence/ux-wave-2026-11/register.md`.

- **Purpose:** Four smaller surfaces stop getting in the way. A connector that needs a sign-in can be signed in from the chat that uses it, whichever kind it is; until now the two kinds the owner meets most (a connector a plugin brings, and one added in MAWS's own Settings) had no Sign in anywhere and sent the person to a terminal. The dialog that lists a chat's connectors is one line per connector, is called Connectors wherever it is named, and says once what its switch reaches. A new chat shows its plugins, connectors and skills before the first message instead of a blank pane or "Available once the session starts". Settings is grouped so that its Engine section is no longer the place every setting landed, each row reads in one line, and a search finds a row by its words. On the Org pages every refusal says what to do next or who can act, every sheet reads as modal over the window, and the project Channel says when it is offline, lines up under classic scrollbars, cuts names sensibly, and can be opened without a right-click. Customize answers 'what do I have' and 'what can I find' at its top level, with the kind as a filter, and every plugin, skill and connector has an image, a connector's site icon where Google's favicon service has one. A plugin's connectors are listed with the others and can be signed in from there. The model a person picks in a chat is the model the sessions that follow start on, in MAWS and in the terminal alike, and the permission mode new sessions start in is set in one place in Settings. Another machine's connector list stays current without a Touch ID per read.

- **Acceptance:**
  - **A1 · A plugin's connector signs in from its chat** (l8-settings-01). In a session MAWS runs whose plugin brings a connector that needs a sign-in, "+" › Connectors › "Connectors in this chat…" shows the row as "Sign in needed" with Sign in. Pressing it opens the service's consent page in the browser; after consent the row reads Connected with its tool count. Holds for a session on this Mac and for a session MAWS runs on another machine (the browser opens on this Mac, the credential is kept on that machine). In a terminal session the dialog is unchanged: it lists connected servers only and points at the terminal's `/mcp`.
  - **A2 · MAWS's own list signs in too** (l8-settings-01). The same, for a server added under Settings › Sessions › MCP servers. Customize › Connectors › My items offers Sign in on that server's row while a session MAWS runs on this Mac holds it, and "Open a session, then sign in" while none does. The tracker row of 2026-10-21 (a needs-auth server with no sign-in) closes.
  - **A3 · The Connectors dialog reads at a glance** (l8-settings-04).
