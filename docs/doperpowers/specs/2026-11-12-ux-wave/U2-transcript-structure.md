> **A child of the UX wave.** Root: `docs/doperpowers/specs/2026-11-12-ux-wave-design.md`. Read it first: it holds the wave's purpose, its laws (law 1 to law 8), the contracts UC-1 to UC-15, the ordering and the record. This file is this child's section of that document. - **Purpose:** A long turn stops being a wall of rows. Consecutive tool calls read as one line that says what was done, while the turn runs and after it; opening the line shows today's rows with the agent's thinking in the order it happened, in the shape thinking already has. The closed turn's line says what the turn did instead of counting calls. The to-human view (the agent's messages to the person, the work between them folded under "working record") is drawn by the to-human mod where a mod can draw, and by MAWS applying the same rule where none can; MAWS's own report bar at the top of the pane, its per-turn "Working record · N tool calls" row and its "To you" label are gone. A turn the person did not start is no longer named as if another session had worked.

Words used below. A **run** is the spec's tool run. Its **caption** is the one line a collapsed run draws. The **turn line** is the line under a prompt that reads "Worked for …" (in code the `divider` row). A **stretch** is the working record between two rows the person reads in the to-human view. **The mirror** is MAWS's own application of the mod's fold rule.

## O-29 · consecutive tool calls fold into one line   (carries O-26)
- **Today:** Consecutive groupable calls form a `group` row (`transcript/model/groups.ts`, `groupItems`), but the view draws every call's row, flat, under a summary line (`view/rows/Group.tsx`); nothing folds. That shape was built on 2026-10-23 (`5ab559bcd`, the fix for l2-transcript-01), which gave the rows Claude Desktop's look and left out Desktop's fold. A running turn's work is open, so a live turn lists every call. A call the person allowed through a permission prompt, a denied call and a call that returned an image are rows of their own and end the group (`classify.ts`, `classifyTool`).
- **After:** on every route.
  - **What joins a run.** Every call that is a tool row today: reads and searches, edits and writes, shell calls, web calls, skills and tool loading, MCP calls, the scheduling tools. Also: the bookkeeping calls that are hidden today (TodoWrite, the Task tools, entering and leaving a worktree, entering plan mode), as ordinary steps; the `maws` server's artifact calls that are plain rows today (l6-artifacts-12); a call the person allowed. Thoughts join the run they fall in and never end it.
  - **What ends a run.** Assistant text. A request's row (U1; UC-3). An arrival's row and a sent message's row (U3). A subagent's row (l2-transcript-14, kept). A denied call and a call whose result is an image, which stay rows of their own. The rows the `maws` server's ask, file delivery, artifact creation and publication draw, the pane-opening call and the computer-use call, each as today.
  - **One call.** A finished run of one call is drawn as that call's row, with no caption, as today and as Desktop does.
  - **The caption** is Claude Desktop's (its caption builder, `web/app/v1/c24951e9f-DKQNorfR.js`, over the name table in `shared-162-Bfx1pPYM.js:31347-31401`), with three additions of MAWS's own, marked in the table: a lowercase verb and a counted noun for each part, joined by `, `, the first letter capitalised. The order is Desktop's (`c24951e9f-DKQNorfR.js:1176-1183, 1291-1337`): first the parts of the calls that have a category (every row of the table but the last), in the order each kind first occurred; after all of them the parts of the calls that have none (the last row), in the order each label first occurred.

    | step | one | several |
    |---|---|---|
    | Read | `read a file` | `read # files` |
    | Write of a new file | `created a file` | `created # files` |
    | Edit, MultiEdit, Write over a file | `edited a file` | `edited # files` |
    | NotebookEdit | `edited a notebook` | `edited # notebooks` |
    | Bash, PowerShell; added by MAWS: the shell's output, kill and monitor calls | `ran a command` | `ran # commands` |
    | Grep | `searched code` | `searched code` |
    | Glob; added by MAWS: LS | `searched for files` | `searched for files` |
    | WebSearch | `searched the web` | `searched the web # times` |
    | WebFetch | `fetched a page` | `fetched # pages` |
    | TodoWrite; added by MAWS: the Task tools | `updated todos` | `updated todos` |
    | entering, leaving a worktree | `moved to a worktree`, `left the worktree` | `moved to # worktrees`, `left # worktrees` |
    | any other call (MCP, `maws`, Skill, tool loading, scheduling) | its row's label, lowercased | `{label} # times` |

    The three additions are MAWS's own. Desktop gives a category to Bash and PowerShell, to Glob and to TodoWrite; a shell's output, kill and monitor calls, LS and the Task tools have none there, and read as the last row's calls do, by their own row's words (`{words} # times`; `c24951e9f-DKQNorfR.js:1103-1123, 1198-1225, 1313-1334`). MAWS counts each under the row named because the call does what that row says, and MAWS already classes it so (`transcript/model/classify.ts`: the shell's output, kill and monitor calls are commands with Bash; LS lists files and is an exploration call beside Glob; the Task tools keep the todo list and are bookkeeping with TodoWrite).

    Files are counted once each; everything else is counted by call. When every file step of the run touches the same one file, the file parts merge and name it (`Read and edited copy.ts`), as Desktop does. Failed calls annotate their part, `ran 3 commands (1 failed)`, and calls the person's Stop interrupted do the same, `(1 stopped)`, as Desktop's caption does. Desktop's two other marks are left out: `(# blocked)`, because the turn line already counts denied and blocked calls and a blocked call's row says it; and marking a whole part as failed when every call in it failed, which the count already says. With five or more parts the first three are kept and the rest read `and # more actions`, the number being the calls in the parts left out. The run's added and removed lines trail the caption, `+33 −5`, when nothing in it is running.
  - **Folded by default,** while the turn runs and after it. The reader's click on the caption opens the run onto its rows, in order, drawn as today (the bordered block, each row opening its own input and output); another click closes it. The state is kept per tab as today's `expandedGroups`.
  - **While it is live.** The caption reads the running call's own running label (what its row reads when opened); with no call running it reads the counted caption so far.
  - **While one of its calls waits for the person's permission** (UC-1's predicate, by tool-use id), the run stays as the reader left it: a request neither opens it nor closes it, and its line can be clicked as at any other time. A collapsed run's line then reads the waiting call's own waiting label in place of the caption, in the words U1 gives the call's row ("Waiting for approval: `cmd`" for a shell command, "Waiting for approval: <file name>" for a file change, "Waiting for approval: <tool>" otherwise; l4-approvals-04), with the waiting glyph in the warning tone and no spinner, timer or line counts. A waiting call takes the line over a running one, and the oldest takes it when several wait; at the answer the line reads the running label or the caption again. Where a request names no call (a terminal's bridge gave it no id; U1), the line keeps its caption and the card at the end is the only sign. Nothing is opened for the request, because nothing has to be: the prompt is answered at the card at the transcript's end, in the full transcript and in the to-human view alike (U1). In the to-human view, mod-drawn or mirrored, a run inside a folded working record stays folded with it: there the card at the transcript's end is the request's whole drawing (U1). A jump to a call inside a run (find, the turn line's denied count, "open creating turn") opens the run, as it does today.
  - **The turn's own fold stays** in a plain transcript: a closed turn's work folds under its turn line and a running turn's work is open, with its runs collapsed. The to-human view replaces it (O-30).
  - **The mod site.** The run's row is asked at the engine's `ToolGroup` site with its real open state, and a mod's answer can open it (as today) or draw in its place (O-30).
