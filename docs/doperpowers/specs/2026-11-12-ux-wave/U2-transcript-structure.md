> **A child of the UX wave.** Root: `docs/doperpowers/specs/2026-11-12-ux-wave-design.md`. - **Purpose:** A long turn stops being a wall of rows. Consecutive tool calls read as one line that says what was done, while the turn runs and after it; opening the line shows today's rows with the agent's thinking in the order it happened, in the shape thinking already has. The closed turn's line says what the turn did instead of counting calls. The to-human view (the agent's messages to the person, the work between them folded under "working record") is drawn by the to-human mod where a mod can draw, and by MAWS applying the same rule where none can; MAWS's own report bar at the top of the pane, its per-turn "Working record · N tool calls" row and its "To you" label are gone. A turn the person did not start is no longer named as if another session had worked.

- **Acceptance:**
  - **A1** (O-29, O-26; all three routes). In a turn with two or more consecutive tool calls and no text between them, the transcript shows one line for the run, both while the turn runs and after it. A click opens the run onto the calls' rows in order, as they are drawn today; a click on a row opens its input and output; a click on the run's line closes it. The same recorded session shows the same runs when MAWS runs it, when it is a terminal session, and when it is on another machine.
  - **A2** (O-29, O-15; unit test and visible). A run with five or more kinds of step shows the first three and `and N more actions`.
  - **A3** (O-29; a session MAWS runs, a terminal session driven through its bridge). Words used below. A **run** is the spec's tool run. Its **caption** is the one line a collapsed run draws. The **turn line** is the line under a prompt that reads "Worked for …" (in code the `divider` row). ## O-29 · consecutive tool calls fold into one line   (carries O-26)
- **Today:** Consecutive groupable calls form a `group` row (`transcript/model/groups.ts`, `groupItems`), but the view draws every call's row, flat, under a summary line (`view/rows/Group.tsx`); nothing folds. That shape was built on 2026-10-23 (`5ab559bcd`, the fix for l2-transcript-01), which gave the rows Claude Desktop's look and left out Desktop's fold. A running turn's work is open, so a live turn lists every call. A call the person allowed through a permission prompt, a denied call and a call that returned an image are rows of their own and end the group (`classify.ts`, `classifyTool`).
- **After:** on every route.
  - **What joins a run.** Every call that is a tool row today: reads and searches, edits and writes, shell calls, web calls, skills and tool loading, MCP calls, the scheduling tools. Also: the bookkeeping calls that are hidden today (TodoWrite, the Task tools, entering and leaving a worktree, entering plan mode), as ordinary steps; a memory recall (#351); the `maws` server's artifact calls that are plain rows today (l6-artifacts-12); a call the person allowed. Thoughts join the run they fall in and never end it.
  - **What ends a run.** Assistant text. A request's row (U1; UC-3). An arrival's row and a sent message's row (U3). A subagent's row (l2-transcript-14, kept). A denied call and a call whose result is an image, which stay rows of their own. The rows the `maws` server's ask, file delivery, artifact creation and publication draw, the pane-opening call and the computer-use call, each as today.
  - **One call.** A finished run of one call is drawn as that call's row, with no caption, as today and as Desktop does.
  - **The caption** is Claude Desktop's (its caption builder, `web/app/v1/c24951e9f-DKQNorfR.js`): parts in the order each kind first occurred, a lowercase verb and a counted noun, joined by `, `, the first letter capitalised.

    | step | one | several |
    |---|---|---|
    | Read | `read a file` | `read # files` |
    | Write of a new file | `created a file` | `created # files` |
    | Edit, MultiEdit, Write over a file | `edited a file` | `edited # files` |
    | NotebookEdit | `edited a notebook` | `edited # notebooks` |
    | Bash, PowerShell and their output, kill and monitor calls | `ran a command` | `ran # commands` |
    | Grep | `searched code` | `searched code` |
    | Glob, LS | `searched for files` | `searched for files` |
    | WebSearch | `searched the web` | `searched the web # times` |
    | WebFetch | `fetched a page` | `fetched # pages` |
    | TodoWrite and the Task tools | `updated todos` | `updated todos` |
    | entering, leaving a worktree | `moved to a worktree`, `left the worktree` | `moved to # worktrees`, `left # worktrees` |
    | a memory recall | `recalled a memory` | `recalled # memories` |
    | any other call (MCP, `maws`, Skill, tool loading, scheduling) | its row's label, lowercased | `{label} # times` |

    Files are counted once each; everything else is counted by call. When every file step of the run touches the same one file, the file parts merge and name it (`Read and edited copy.ts`), as Desktop does. Failed calls annotate their part, `ran 3 commands (1 failed)`. With five or more parts the first three are kept and the rest read `and # more actions`, the number being the calls in the parts left out. The run's added and removed lines trail the caption, `+33 −5`, when nothing in it is running.
  - **Folded by default,** while the turn runs and after it. The reader's click on the caption opens the run onto its rows, in order, drawn as today (the bordered block, each row opening its own input and output); another click closes it. The state is kept per tab as today's `expandedGroups`.
  - **While it is live.** The caption reads the running call's own running label (what its row reads when opened); with no call running it reads the counted caption so far.
  - **Forced open** while one of its calls waits for the person's permission (UC-1's predicate): the run is drawn open and the caption does not close it, so the call the prompt is about is in view above the prompt. In the to-human view, mod-drawn or mirrored, a run inside a folded working record stays folded with it: there the card at the transcript's end is the request's whole drawing (U1), and nothing is forced open. A jump to a call inside a run (find, the turn line's denied count, "open creating turn") opens the run, as it does today.
  - **The turn's own fold stays** in a plain transcript: a closed turn's work folds under its turn line and a running turn's work is open, with its runs collapsed. The to-human view replaces it (O-30).
  - **The mod site.** The run's row is asked at the engine's `ToolGroup` site with its real open state, and a mod's answer can open it (as today) or draw in its place (O-30).
- **Why this, not that:** The owner asked for it twice (O-26, O-29) and named the to-human view's fold as the model; Desktop folds every group by default, live or finished (`c96d752d0-CjYhuD9j.js`, its `groupOpensByDefault`), and forces one open only while a step awaits approval (`c4a9ee384-Cvn3dOsn.js`, where the group's open state is or-ed with the pending steps). Desktop's wording was chosen over the CLI's ("ran N shell commands") because the owner named Desktop as the answer for engine-tied surfaces and because Desktop's caption already carries edits, failures and line counts, which the CLI's default view does not. The strongest alternative was to keep today's flat rows and fold only by turn: it loses the live case, which is the one the owner showed. **Departures from Desktop:** a subagent's call and a sent message stay rows of their own and end a run, where Desktop rolls them into the group ("ran 2 agents", "messaged another session"): the subagent row is the owner's `keep`, and the message row is U3's with behaviour attached to it; both are counted in the turn's caption (O-15). Skills are steps here and cards there. A call the person allowed joins its run, as in Desktop; that reverses C6's rule that a call the person decided stands alone, without which a session in the default permission mode would form no runs.
- **Not included:** No cap and no inner scroller on an opened run (the charter's first design bounded it; the owner asked that it open onto today's rows, and a row's opened output does not fit a bounded box). No setting for the default fold. No view modes (Desktop's Normal, Thinking, Verbose). The engine's own tool summaries stay off. Sent messages inside a run: see Waiting.

## O-27 · thinking in the order it happened, in the shape it has   (carries O-25)
- **Today:** Inside a group every thought is classed hidden (`model/cells.ts`, `thinkingCell`), and the view draws all of a group's hidden cells after all of its calls, under one disclosure labelled `Internal activity` (`view/rows/Group.tsx`), in a 224-pixel scroller. So thinking reads out of order and behind a wrapper. The order is not lost: the group's cells are kept in event order. A thought outside a group is a thought line (`view/rows/Thinking.tsx`).
- **After:** on every route.
  - **Position.** In an opened run a thought is drawn at its place among the calls. The bordered block of tool rows ends above it and a new block starts below it.
  - **Shape.** It is drawn by the same component that draws a thought outside a run: the muted line, the chevron first, `Thought for 12s` (or `Thought` where no duration is known), opening onto the text in today's bounded text box. It has no row in the bordered block, no status mark and no trailing chevron.
  - **Which thoughts get a line inside a run.** One with text. One without text whose measured duration is ten seconds or more, as a line with nothing to open (#479). No other.
  - **Never two in a row.** Thoughts with no call between them are one line: their durations added, their texts in order. The merge comes first and the ten-second test is made on the merged line. A textless thought after a run's last call is a trailing line under the last block when it passes the test. A single call is not a run and has nothing to open, so a textless thought beside it gets no line.
  - **The wrapper goes.** There is no "Internal activity". The bookkeeping calls it also held are ordinary steps (O-29).
  - **While a thought streams** it is drawn as a thought line carrying the live thinking label (the tier and the time, or the latest summary line, with today's shimmer and warming colour), directly under the live run's caption, or as the turn's last row when no run is open. When it ends it takes its place by the rules above.
  - **The caption carries no thinking time.**
- **Why this, not that:** The owner chose "own step, in order" and added two conditions. *Shape:* one component for both positions is the strongest form of "keep it a same shape, just different position"; drawing thoughts as rows of the tool block is what the owner ruled out. *Length:* the conditions conflict with drawing every thought. Measured over sixty recent session files on the owner's MacBook (kinds and counts only): in runs of eight or more calls there are 0.61 thoughts per call; 94% of thoughts have no text; only 3% of thoughts follow another with no call between. Every thought as a line would make an opened run of twenty calls about thirty-two lines, twelve of them reading `Thought for 3s` with nothing behind them. Under this rule the same run opens to about twenty-one to twenty-four lines: the calls, about one thought with text, and at most three long textless ones (at most 23% of textless thoughts last ten seconds, by an upper bound from the files' timestamps). Ten seconds is where the live label first changes its words ("Still thinking"), so a thought earns a line when it lasted long enough for the app to have remarked on it. The alternatives are in the drawn example for the owner to choose between: every thought a line; no line for any textless thought. Attaching the thought to the call that followed it (the owner's second option) was not chosen by the owner. **Departure from Desktop:** Desktop hides thinking in its default view and shows it as steps only in its Thinking view; the owner asked to see it, and asked for no view switch.
- **Not included:** The thinking mark (PR #144) is the visual renewal's and is rebased onto this line. A thought's start time in a terminal session (tracker row 631) is blocked on the engine.

## #479 · a thought with no text keeps its time
- **Today:** A finished thinking block with no text has no row (`derive.ts`, `blockRow`: W1, "nothing to disclose"), so its duration is shown nowhere. On the current model nearly every thought is such a block.
- **After:** In a session MAWS runs, a textless thought of ten seconds or more is a `Thought for Ns` line at its place in an opened run, with no chevron (O-27). A shorter one leaves no line; its time is in the turn's duration. Outside a run (before the answer, or in a turn with no tools) a textless thought has no row, as today. In a terminal session, a session on another machine and history read from disk, a textless thought leaves no line anywhere: a duration exists only for a block MAWS saw streaming (`blockRow` computes it from the block's start and end events), and the transcript file records no start.
- **Why this, not that:** The cut's line was "a textless thought shows as a Thought for Ns step inside its group"; the owner's later condition on length bounds it, and the answer wins over the cut. A line for every textless thought is the case the owner feared. Folding the time into the caption (the CLI's "Thought for 12s, read 3 files") was rejected with O-27: Desktop's caption has none and the turn line gives the duration. Outside a run the line would be added to nearly every turn.
- **Not included:** Summing thinking time per run or per turn.

## O-15 · the closed turn's line says what the turn did
- **Today:** `Worked for 3m 12s · 13 tool calls` (`model/copy.ts`, `dividerCopy`). What the calls were is known (`turnPhrases`) but shown only in the line's `⋯` popover (`view/rows/Divider.tsx`). The charter's §5.3 binds this wording.
