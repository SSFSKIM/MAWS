- **Purpose:** Once this child lands the owner sends without thinking about modes. Enter always sends. While the agent works, Enter hands the message to the running turn and ⌘Enter keeps it for after the turn. A message that has not been read yet is drawn once, in a stack above the composer, where it can be sent now, taken back with ↑, edited or deleted. ## Sending: one design for l3-input-01, -02, -03, -04, -05, -08, -15 and X-049

Eight items are one change. This part states it once; the items that follow say what each one contributes and why.

**Words.** A *waiting message* is one the person sent and the agent has not read yet. It waits in one of two ways. *At the next step*: the engine holds it and reads it at the running turn's next tool boundary (in code, a pending steer of priority `next`). *After the turn*: MAWS's own queue holds it and sends it when the turn ends (in code, a `queued` entry of the app queue in the engine host). A message that Stop held back is an after-the-turn message in a paused queue. *The stack* is the list above the composer frame, and the only place a waiting message is drawn. *Send now* delivers a waiting message at once without stopping the agent's work where the engine can do that.

**What each key and control does, for a session MAWS runs.** "A request waits" means the turn is held at a permission prompt or a question that blocks it; a question the agent asked without waiting changes nothing in this table.

| act | no turn runs | a turn runs | a request waits |
|---|---|---|---|
| **Enter**, the box has text | Sends; the turn starts. After a Stop, with held messages in the paused queue, this one goes ahead of them. | Sends at the next step: the message joins the stack and the agent reads it at its next tool boundary. Behind a running command or MCP call it waits until that call ends, unless the person presses Send now (l3-input-01). | As while a turn runs. The agent reads it after the request is answered. |
| **⌘Enter**, the box has text | As Enter. | Queues for after the turn: the message joins the stack and is sent when the turn ends. | As while a turn runs. |
| **Enter** or **⌘Enter**, the box is empty | Nothing. | Nothing. | Enter: nothing. ⌘Enter: allows once the permission prompt in view, under U1's guards (the prompt in view for 400 ms, no menu or other field holding the keyboard); a question's and a plan's keys act only with focus inside their form (U1; UC-6). |
| **Shift+Enter**, **Option+Enter** | A new line. | A new line. | A new line. |
| **The button** | An up arrow, Send; greyed while the box is empty. A play triangle, Resume, while the queue is paused and the box is empty. | The box empty: a square, Stop. The box has text: the queue mark, which does what Enter does. | As while a turn runs. |

**Where a waiting message is shown.** In the stack, and nowhere else: not as a bubble in the transcript, not on the session's row or tab. The transcript draws a message when the engine has read it, at the place it was read. Messages the engine joined into one (every message waiting at the next step when a Send now is pressed, or when the turn ends by itself) are drawn as the one message the engine wrote: one bubble, where the first of them stood. **The stack.** One bordered list directly above the composer frame, present only while something waits.
- Rows are in the order they will be read: messages at the next step, oldest first, then messages after the turn, oldest first.
- A row is the message's text clamped to two lines (attachments and pasted chips named as today, `[Image #1]`, `[Pasted text #1 +40 lines]`), and at its right end when it goes: "Next step", "After the turn", or "Held" in a paused queue. - On hover or keyboard focus a row shows: Send now (an icon button), Delete (a bin), and a "…" menu with Edit and with the move to the other kind of wait ("Queue for after the turn" on a next-step row, "Send at the next step" on an after-the-turn row; both exist today as Hold and as the caret's item). Send now's title while a turn runs is "Sends this now; what the agent is running keeps running"; on a next-step row while more than one message waits at the next step it is "Sends the 2 waiting messages now; what the agent is running keeps running", with their number.
- Edit takes the message back into the composer, text and attachments, as ↑ does (l3-input-04 has the steps). It is offered only while the composer is empty, and says "The box holds a draft" otherwise. The inline editor inside a row (`QueueEdit.tsx`) goes.
- With one or two rows there is no header. With three or more the stack folds to one line, "N queued · Next: <the first row's text>", with a caret that opens it; open, it scrolls past five rows. Whether it is open is kept per session for the window's life, not saved.

**How Send now reaches the engine.** One new host command, for a message at the next step:

```
session.steer.sendNow { appSessionId, messageUuid } → { outcome: 'delivering' | 'stopped' | 'nothing_waiting' }
```

It writes the engine's control request `interrupt { send_now: true, message_uuid }`, exactly as the probe recorded it, and returns the engine's own answer (`send_now` in the response). An engine that does not know the key (by the bundles' text, one before 2.1.287; the second pass ran 2.1.283) takes the request for a plain interrupt, and its answer, which has no `send_now`, reads `stopped`. The command does not pause MAWS's queue. The request names one message, and the engine delivers with it every message that waits at the next step, written as one user message under the last one's uuid; each still gets a `started` of its own, at which its row leaves the stack. `delivering`: the engine moved what could be moved. What follows depends on what was moved: for a shell command the engine ends the turn (`result` of subtype `success` with `terminal_reason: aborted_tools`) and starts the message as the next turn; for an MCP call the message is read in the same turn, with no `result` between; with a permission request pending the request is withdrawn, the turn ends the same way and the message runs next. (Corrected 2026-11-13: this named a foreground subagent call where it now names an MCP call. Under MAWS's launch the engine ran the subagent in the background four times of four in the second pass, so that case does not occur.) `stopped`: nothing could be moved, so the engine ended the turn (`aborted_streaming`) and the message runs next. `nothing_waiting`: the engine had already read the message, or never held it; nothing is shown.

What tells a send-now end from a Stop is read from the frames the host already journals; nothing new is recorded. The engine host's normaliser keeps the set of messages sent now and marks a turn's end (`endedForMessage`, an optional field on X1's `turn.ended`) when that set is not empty and the end is an aborted one. A stop counts only if it took effect. A message leaves the set when it is withdrawn, so the Stop square, which holds what waits before it interrupts, reads "You stopped" before the move and after it, with the message held. A plain interrupt that holds nothing changes the reading only when the end is the interrupt's own (`error_during_execution`); after the move it does nothing at all, and the end is the Send now's. (Corrected 2026-11-13: this said a turn that ends aborted after a send-now "with no Stop of the person's in between" is a send-now end, and that the host keeps a record of its own.) A marked end reads "Ended for your message after `<duration>`" and not "You stopped" (today's digest reads `aborted_tools` as a stop), it raises no "finished" notice, and it does not pause the queue. Read back from the engine's transcript file once the session's launch is gone, the mark is lost: a turn cut behind a command reads as an ordinary end, and one cut while the agent wrote reads "You stopped" (a limit, logged as debt). In every case that ends the turn, the engine reports the lifecycle of the prompt that had started the cut turn as `cancelled` after `started`: that is the turn's cut, not a message the engine dropped, and it must not draw "Not sent" (a test pins it).

A call the engine moved reads "Moved `<name>` to the background after `<duration>`", and its row stays running until its task's end is heard, across the turn's close, for as long as the process that started it lives. A shell command is known as moved by a flag in its result; any other call, by a task of its own that had not ended when its result arrived.

Send now on an after-the-turn row, or on a held one, hands the entry to the engine at priority `now` (`session.queue.promote` with `now`), one step. That message goes alone: it is never joined with one that waits at the next step. A `now` message does what the request does only once the engine has registered the running shell command as a task, about three seconds into the call (the third pass). Pressed earlier it moves nothing: the command runs to its own end and the message is delivered then, its row reading "Next step" meanwhile, where the request, written at that same early moment, waits for the task and then moves the command. Nothing is built for the early case in this child's first landing: it is what the build on the owner's machines does today, and it is logged as debt. (Corrected 2026-11-13: this said that a `now` message does what send-now does.) With no turn running it is the same promote. Esc is Send now on the first row; only a fresh press of Esc acts, and a held key's repeats are consumed.

Send now on a next-step row is offered only where the engine host that serves the session is known to take the command. After an app update the engine host of the earlier build keeps serving its live sessions until they are idle or handed over. For such a session that control is drawn disabled with "The engine host is finishing an update; this works once it has handed the session over", Esc on such a first row says the same line and stops nothing, and everything that host can do stays offered: ⌘Enter, Stop, ↑, Edit, Delete, "Queue for after the turn", and Send now on a held or an after-the-turn row.
