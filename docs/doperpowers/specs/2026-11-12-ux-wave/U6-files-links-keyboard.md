> **A child of the UX wave.** Root: `docs/doperpowers/specs/2026-11-12-ux-wave-design.md`. - **Purpose:** Once this child lands, opening a file never takes the conversation away: a file opens beside the chat, as a tab inside the Files side surface, and moves to the main area only when the owner asks. Files shows what changed and finds a file by name. A link the agent writes opens in MAWS whatever form it takes (a path, a `file://` URL, a PDF, a localhost address), and when it cannot open, the notice says why in plain words. "Open in" hands a file or the session's folder to an editor, a terminal or Finder. The keyboard reaches everything: chords for the side surfaces, Back and Forward, zoom, a palette that opens on what was used last, and one table behind the menus, the shortcut sheet and every child's new chord.

    - **The shape.** `ActionSpec` gains three things, and nothing else changes:

      ```ts
      menu: 'app' | 'file' | 'edit' | 'view' | 'go' | 'help' | null; // 'edit' is new: placed after the Edit menu's own items
      submenu?: string; // the submenu of its menu the item sits in ('Find', 'Tabs', 'More surfaces', 'Comments')
      fixed?: true;     // a key its own editing surface handles (Enter in the composer): listed, never dispatched, not rebindable
      ```

    - **Stored rebindings.** A rebinding the person stored wins over a default a later build gives another action: while their override holds a chord, the action that has it as its default reads as unbound (`effectiveChord`), and nothing stored is rewritten. A `fixed` row takes no rebinding. While build F may run on the same profile (UC-14), a row whose id F does not know takes none either: F's reader of `settings.json` is closed over its own action ids, and one unknown id fails its whole read of the client settings. Such a row is dispatched and listed like any other, but no route stores an override for it and Settings › Keyboard draws no control to change it. The ids F knows are one constant under `src/shared/keymap/` (they are the table as it stood before this wave), deleted with this rule when F is no longer a build to go back to.
    - **How a chord reaches the right region.** Two mechanisms exist in the code and a new chord picks one.
      - `sink: 'menu'`: the chord is the accelerator of a menu item (`menuTemplate`, `src/main/menu.ts`). macOS hands the key to the focused element first; if nothing there takes it, the menu item fires, main emits `layout.action`, and the renderer runs the handler (`runAction`), which finds its own target (the focused pane's session, the terminal that holds the keyboard). A menu chord therefore works wherever the keyboard is, including inside a terminal (`terminalKeyFilter` passes every ⌘ chord but ⌘C, ⌘V and ⌘A) and inside a page of the in-app browser (`keyAction` in `src/main/browser/keys.ts` takes only the page's own chords).
      - `sink: 'renderer'`: the key is matched in the page before any editor sees it (`dispatchKey`, a capture-phase listener) and reaches a `useKeyChord` binding by its `scope`. `app`: anywhere. `composer`: only when the key is typed inside an element marked `data-key-sink="composer"`. `pane`: only inside the binding's own element, which must hold the keyboard; never from a text field, a button, an open menu or dialog, or during input-method composition. Pane and composer rows never go in the menu, which cannot see focus.
      - **Focus first.** A region that has its own meaning for a key keeps that key while it holds the keyboard; everywhere else the key is the app's. This is the rule behind "⌘F acts on the focused region", and it needs no new machinery for a `menu` chord: an editor keeps a key simply by handling it. So a chord an editor may keep is a `menu` row; a chord that must win even inside an editor or a terminal (⌘. stop, ⌘L) is a `renderer` row with scope `app`.
      - **F6.** A child that adds a region to the window marks it so that F6 stops there: the stops are read from the DOM (`regionStops` in `src/renderer/src/keymap/shell-navigation.ts`: `#region-sidebar`, each `[data-pane]`, `[data-region="cards"]`, each `[data-surface]`).

## l5-code-11 (with the remainder of l5-code-13) · a file opens beside the chat, as a tab of the side column

- **Today:** Every place that opens a file calls `openFile` (`src/renderer/src/tools/code/open-file.ts`), which opens a main tab and selects it, so the transcript leaves the screen. Review's Open on a file, a change receipt's file row, a path link in the transcript (`TranscriptLink`), a row of the Files tree (`activate` in `FilesTool.tsx`) and the agent's `show_pane` for a file all go through it. Only an artifact can move between the side column and the main strip (`panelTabMoves` in `src/renderer/src/shell/transfer.ts`). Inside a side surface that has several tabs, the strip scrolls but does not bring the selected tab into view (`src/renderer/src/panel/TabStrip.tsx`).
- **After:**
  - **Where a file opens.** Beside the chat, as a tab of the side column. By the owner's answer of 2026-11-12 on O-36 the tools beside the chat are tabs of one strip (U8's item, which this one is built with), so each open file is a tab there, beside Review's, the terminals' and the others', and Files has no strip of its own. Opening a file adds its tab (or selects the one it has), at the line asked for, and shows it in place of the tab in view; where the person has made two groups it goes to the group that already holds a file (U8's rule), so a file opened from Review does not take the diff's place there. Files keeps its tree as a column at the left of the file shown, in every file's tab, with one state for the session (which folders are open, its width, whether it is folded away). With no file open, Files is one tab, "Files", that shows the tree alone, and the first file opened takes that tab. The transcript and the main tab strip do not change. When the tab is too narrow for both, the tree column folds away and a button in the file's bar brings it back.
  - **One preview tab.** A single click opens the file in the session's one preview tab, whose title is drawn in italics, and the next single click replaces it.
