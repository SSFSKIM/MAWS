S1 of board #90 — an extension popup in a MAWS-hosted view (Electron 44.4.5, Chrome 152.0.7977.130)
Spec: cua docs/doperpowers/specs/2026-10-08-maws-browser-chrome-design.md, Plan of Work S1. Run 2026-10-08 on the
owner's Mac from the MAWS worktree on branch 90-browser-chrome.

How: `node spikes/extension-popup/run.mjs` (hidden window) and `node spikes/extension-popup/run.mjs --show` (window on
screen, as MAWS's would be). run.mjs builds three variants of the fixture probe extension in scratch/ (gitignored):
mv3 = spikes/browser-probe/ext/test-ext copied unchanged plus pages/popup.* and pages/options.* (action.default_popup,
options_ui.page), its sw.js gaining one onConnect answerer; mv3-nopopup = the same without a popup, its sw.js gaining a
chrome.action.onClicked listener that records clicks in storage; mv2 = mv2/ (a persistent background page) plus the same
pages (browser_action.default_popup, options_page). It fetches Dark Reader 4.9.133 (chrome-mv3 and chrome MV2 zips)
and Refined GitHub 26.10 by pinned release URL into scratch/, then launches node_modules/.bin/electron on main.mjs with
user data in scratch/userData (fresh each run). main.mjs: one persist: partition, a frame preload registered on its
session (MAWS's registration), an http page view standing in for a tab, every extension loaded with
allowFileAccess:false, then each default_popup in a WebContentsView of that session { sandbox, contextIsolation,
enablePreferredSizeMode } laid over the window and resized to each preferred-size-changed (clamped 25-800 x 25-600).
Full output: results/run.txt (hidden) and results/run-show.txt (on screen); the lines below are quoted from them.

VERDICT: promote. The spec's criteria, literally: the fixture popup loads (yes, MV3 and MV2), gets the ping's reply
(yes, from the MV3 service worker and from the MV2 background page, by sendMessage and by connect), and sizes itself
(yes, preferred-size-changed fires and the view takes the size). M3 builds the popup view as designed.

== Reading ==
1. Popups host. A default_popup page in a WebContentsView of the partition session loads, runs chrome.runtime, reaches
   its background both ways, and reports its preferred size; MV2 and MV3 alike.
2. chrome.tabs.query({ active: true, currentWindow: true }) never answers the page tab. Hidden window: []. On screen:
   [the popup itself] (id of the popup's webContents, active: true, windowId 0), because Electron's "active" follows
   the focused webContents. tabs.query({}) lists every webContents of the session as a tab, all windowId 0: the page,
   the popup, MV2 background pages, offscreen documents. So an extension whose popup acts on "the current tab" sees
   nothing or acts on itself. Settings copy candidate: "Popups that act on the current page can't see it here."
3. The background sees the popup as a tab: sender.tab is set for the popup's messages (fromTab = the popup's id).
   Chrome leaves sender.tab unset for popups; an extension that branches on it treats its popup as a content script.
4. chrome.windows is undefined in popups; chrome.action exists in an MV3 popup; in an MV2 popup neither
   chrome.browserAction nor chrome.action exists, so an MV2 popup calling browserAction.* throws.
5. Preferred size: the first preferred-size-changed fires with the page's first layout (344x104, "running…"), later
   ones as content grows (344x179 on screen). In a never-shown window only the first arrives. M3 must keep resizing on
   every event, not take the first. Dark Reader: 276x516 in one event.
6. onClicked: no API. session.extensions offers load/remove/get only; ServiceWorkerMain offers ipc/send/startTask
   (main-to-preload IPC, no extension event dispatch); CDP Extensions.triggerAction is not implemented. The worker's
   chrome.action.onClicked.addListener exists, so extensions register without error, and nothing ever fires it. M3
   draws an action without a popup as present-but-inert with the tooltip.
7. window.open and target=_blank in the popup reach setWindowOpenHandler on the popup view's own webContents
   (disposition foreground-tab); a same-frame link reaches will-navigate on that webContents. window.open('options.html')
   arrives there too, as a chrome-extension:// URL. M3's gating (activation, linkTarget, http(s) only) sits on those two
   hooks.
8. chrome.runtime.openOptionsPage() fails with lastError "Could not create an options page." and creates no
   webContents; an extension's own "settings" button that calls it does nothing. Loading options.html directly in a
   view works (title, chrome.runtime.getManifest()), so MAWS's own "Options" entry (openExtensionPage) is sound.
9. The session's frame preload runs in every extension document: popups, options pages, MV2 background pages and
   offscreen documents (the "preload documents" line). MAWS's browser preload therefore already runs today in the
   background pages and offscreen documents of imported extensions, not only in the popups M3 adds; M3's early return
   for non-http(s) covers all of them.
10. Public extensions: their popups host as well as the fixture's; what fails is their backgrounds on Electron's API
   gaps (chrome.permissions here), which E0b already measured. A public extension's popup is useful exactly when its
   background runs.
11. Incidental: service workers listed by getAllRunning() 1.5 s after load varied by run (three in the hidden runs,
   none on screen); the popup's first message starts the worker either way. capturePage on a view in a never-shown
   window rejects with UnknownVizError (stills were taken from the on-screen run).
