## S1 — Yjs v13 or v14

**Verdict: v14 (`@y/y` 14.0.0-rc.28 with `@y/prosemirror` 2.0.0-15, pinned exactly).** Every functional gate passes;
the data gate passes (no loss, no corrupt encoding, v14 reads v13 bytes); API stability does not: `@y/prosemirror`'s JS
API broke twice in September 2026 and is still moving. Judged non-blocking because the API MAWS touches sits in one
module and the persisted bytes are Yjs's binary format. Confidence: high on function, moderate on maturity.

Method: Node 22 with happy-dom, real Tiptap 3.31.3 editors, replicas wired through y-protocols sync and awareness frames
via a host hub that logs every update as `{seq, actor, at, bytes}` (the `artifact_updates` shape). No Electron run
(the DOM input path and IME are S4's).

### 1. Binding in Tiptap 3.31.3 (two editor replicas and an agent replica)
- v14 26/26 checks, v13 25/25 on the same checks (verified: `node spikes/p3-store/s1/v14/s1-binding.mjs`,
  `node spikes/p3-store/s1/v13/s1-binding.mjs`; `s1/out/v14-binding.txt`, `v13-binding.txt`): typing and splits sync;
  paste gets fresh ids and strips foreign ones; `Y.UndoManager` scoped to the binding (A's undo removes only A's edit;
  undo-all restores the original ids; redo); remote carets; the agent replica's caret from a Node-side relative position
  renders; an `editing: {blocks}` awareness field reaches the editors.
- The v14 custom extension is 54 code lines (`s1/v14/collab.mjs`, `YCollaboration`: `syncPlugin`, `yCursorPlugin`,
  `yUndoPlugin`, undo and redo commands and keys, binding in a microtask). Schema hardening is 75 more lines
  (`s1/v14/schema.mjs`, adapted from upstream's MIT `yhub-tiptap-demo/src/schema.js`): the four `y-attributed-*` marks,
  marks allowed on containers, codeBlock admitting them, the `--attributed` variants, guards on TrailingNode, Link and
  tables. No Tiptap fork.
- v14 merges one concurrent case better (verified): both replicas offline press Enter at the start of the same
  paragraph; v13 duplicates the paragraph and its id, v14 gives two empty paragraphs. A concurrent mid-paragraph split at
  different offsets duplicates the tail on both (a split is "delete tail + insert node").

### 2. UniqueID
- Ids survive split (the first half keeps the id), paste (fresh ids) and undo on both versions (verified).
- Pitfall (verified): UniqueID skips only transactions with v13's `y-sync$` meta; v14's binding marks remote changes
  `y-sync-transaction`, so stock UniqueID on v14 writes ids into remote blocks from every peer. Fix without a fork:
  `UniqueID.configure({filterTransaction: tr => !isBindingTransaction(tr)})` (`s1/v14/collab.mjs`), and name the extension
  `collaboration` so UniqueID takes its collaborative path. Tiptap core's `Delete` extension also filters only `y-sync$`
  (source: `@tiptap/core` dist line 5572): set `coreExtensionOptions.delete.filterTransaction` the same way.
- The host's id repair stays required on both versions (writers that omit ids, concurrent splits; verified on v13's
  concurrent-Enter duplicate).

### 4. Suggestion mode for an agent edit (v14)
- 18/19 checks (verified: `node spikes/p3-store/s1/v14/s1-suggest.mjs`; re-run by the executor, 18/19).
- Topology: the host keeps the base doc and a suggestion doc (`gc:false, isSuggestionDoc:true`); the agent edits its
  own replica of the suggestion doc; the human's editor shows `DiffRenderer(baseReplica, suggestionReplica,
  {attributions})` in view mode. Four hunks render attributed to the agent, deletions struck; the owner's typing goes
  to base; per-hunk accept and reject land in base and the suggestion doc converges; a second live proposal renders;
  reject-all clears it.
- The one failure: accepting a text-only range inside an inserted paragraph returns true but leaves pending structs in
  the reviewer's base replica; accepting by the node range (`from-1 … to+1`) works. Accept buttons pass block ranges.
- Accepted content keeps the agent's clientID, but the base log credits the accepting port: provenance must map a
  suggestion doc's clientIDs to the suggester.
- v13 equivalent (estimate, not built): a fork doc per proposal, a structural diff into a custom overlay, per-hunk Y
  ops onto base; a home-grown DiffRenderer of about 1.5k to 3k lines, fragile on tables and attributes.

### Verdict reasoning
Gates: binding, UniqueID, undo and cursors pass; DiffRenderer with log-built attributions passes 13/13 where v13 does
8 to 10; suggestion mode passes with one range pitfall; the Node writer passes; data passes; API stability fails
literally. v14 still, because (1) the one-way risk is about data and the data passes; (2) the API MAWS touches is small
(`syncPlugin`, `configureYProsemirror`, `DiffRenderer`, the ContentMap helpers, `pmnodeToDelta`/`ynodeToPmnode`, the
mark names) and fits one module, so a re-pin edits that module, not documents; (3) a shipped editor runs this stack on
the same Tiptap; (4) v13's gaps land on §2 item 4, the differentiator (attribute and format changes invisible, no
times, a home-built suggestion engine). What would flip it: the architect reading "an API expected to break" as
blocking; a v14-only failure in S3, S4 or S7 (IME under `y-sync-transaction`, large-document first sync); a wish for zero
dependency churn before P4.

Executor's note on the residual risk: the binary encoding is stable, but how `@y/prosemirror` maps ProseMirror into
`Y.Node`s (mark storage keys such as `name--<hash>` for overlapping marks, the attributed variants) is binding-level
and could change between prereleases; that would be a content normalization of stored documents, not an unreadable
store. P3-A should keep S1's suite as the re-pin gate and store a binding-version tag per document.

### Pitfalls (verified unless marked)
1. UniqueID on v14 needs `filterTransaction`; filter core `Delete` too (source).
2. Undo and redo commands set `tr.setMeta('preventDispatch', true)`, else "Applying a mismatched transaction".
3. Bind after the EditorView constructor returns (a microtask): Tiptap's dispatch needs `editor.view`.
4. A mark's `excludes` changes its Y storage key (`Code.extend({excludes})` stored `code--<hash>`); overlapping marks
   (the `comment` mark) are stored as `name--<contenthash>` (source: CAVEATS). Writers produce marks through
   `pmnodeToDelta` with the editor's exact schema: schema parity is also key parity.
5. The `--attributed` variants carry every canonical attribute including the id; add them to UniqueID's `types`.
6. Without a renderer, a remote node-attribute change logs a one-time `y-attributed-attrs … swallowed` warning; content
   unaffected (`s1/v14/probe-attrs-warning.mjs`).
7. Partial accept inside an inserted block leaves pending structs; accept by block range.
8. An accepted suggestion is credited in the log to the accepting port; credit the suggester by clientID.
9. `@y/prosemirror` declares `@y/y` a dependency, not a peer: dedupe to one copy (the guard is `__ $YJS14$ __`), pin
   exact, install by version (the `latest` tags are stale).
10. A v13 client must never open a P3 document (it throws).
11. Concurrent mid-paragraph splits duplicate the tail on both versions.
12. Upstream docs lag: `@y/y`'s README still documents v13 types.
13. Awareness timers keep a Node process alive; scripts exit explicitly.

## S2 — The host document service, the port and the detached channel

**Verdict: the topology holds on Yjs v14** (`@y/y` 14.0.0-rc.28, `@y/protocols` 1.0.6-rc.1, lib0 1.0.0-rc.36, exact pins,
one copy each in every bundle, verified), in real Electron 44.4.5, v13 kept for comparison: a utility-process host owning
a `node:sqlite` store serves two hidden renderer replicas over one `MessageChannelMain` per document plus an in-process
agent replica; acknowledged edits survive a SIGKILL; a detached host keeps taking an agent's edits with main gone and a
later main relays a renderer over a binary channel on the same socket. Nothing failed on v14 alone. The §4.2 changes
below were accepted by the architect (spec Decision Log 26; ledger X13, X24).

§4.2 changes:
1. An `ack` frame (MAWS type 100, `[durableFrames, revision]`) and commit-before-reveal: no frame revealing an update
   leaves the host before its row commits; commits are grouped per event-loop turn.
2. `PRAGMA fullfsync=ON`: on macOS `synchronous=FULL` alone does not flush the drive cache (SQLite docs, source).
3. Untrusted updates are pre-checked (gaps, missing origins or parents, unknown deletes refused); a doc left with pending
   state or a skip hole is evicted and reloaded.
4. Provider handshake: after connecting, a replica sends only step 1 and awareness until it has answered the host's
   step 1 (else its own edits arrive as a gap).
5. Provenance is v14's native attribution, stored as encoded ContentMaps beside the log (shape below).
6. Log rows in V1 (the wire format), versions as V2 states; the live revision is the global log `seq` (rising, sparse per
   document, never reused after compaction).

Reproduce (from the repository root; `<Electron>` = `node_modules/electron/dist/Electron.app/Contents/MacOS/Electron`;
every Electron run through waitload20 and with-slot): build v14 `S2_YJS=14 node spikes/p3-store/electron/build.mjs`
(to `/tmp/p3-s2/build/electron-v14`; one harness source with the `s2/src` modules redirected to their `s2/v14`
siblings), v13 `node spikes/p3-store/electron/build.mjs`; seeds: bundle `s2/check/seed-v14.ts` (v13: `seed.ts`) with
esbuild and run it with `ELECTRON_RUN_AS_NODE=1` for 1 MB and 5 MB; scenarios `S2_OUT_DIR=spikes/p3-store/s2/out
S2_BASE=/tmp/p3-s2/<run> <Electron> /tmp/p3-s2/build/electron-v14/main.cjs --scenario=sync|latency|kill|fuzz`
(`S2_FULLFSYNC=1`, `S2_KILL_FLOOD=1`); detached `S2_BUILD=/tmp/p3-s2/build/electron-v14
S2_AGENT=ddoc:sess-detached:120:150 zsh spikes/p3-store/electron/run-detached.sh`; Node checks: bundle
`s2/check/{service-check-v14,socket-check-v14,v14-probe,v14-gap-probe,v14-attr-bench}.ts` and run each under
`ELECTRON_RUN_AS_NODE=1`. Outputs in `s2/out/` (`-v14` suffix; v13 files unsuffixed). Executor re-check: `kill-v14.json`

### 1. The document service (verified)
`DocumentService` (`s2/v14/host/document-service.ts`) over `SqliteDocumentStorage` (`s2/v14/host/storage.ts`): WAL,
`synchronous=FULL`, fullfsync switchable; tables `updates (seq, docId, actor, at, bytes)`, `versions` (V2, gc on),
`attributions` and `actors`. `integrated()` appends the row and its attribution into a lazily opened batch; broadcasts,
step-2 replies and acks wait in the outbox until `flush()` commits; `commitFailed()` drops the live docs and closes their
connections, so no replica learns of content the store lacks. A restart from the store equals the live doc.

### 2. What v14 changes for the host (verified, `out/v14-probe.json`, `out/v14-gap-probe.txt`)
- A same-client gap is no longer parked (v13) but integrated behind a `Skip` placeholder (`store.skips`): the content is
  visible, the `update` event carries it, the state vector stops at the hole, and a newcomer's step 2 copies the hole.
  Unchecked, the host would log and broadcast a document with a hole.
- A missing origin or parent and unknown deletes are still parked silently (`pendingStructs`/`pendingDs`, no `update`
  event), and `encodeStateAsUpdate` appends the parked bytes to every step 2, so each newcomer inherits them.
- `checkV1` (`s2/v14/yjs.ts`) mirrors v14's `getMissing`, treating ids inside a skip as missing, and refuses gaps;
  `hasPending` (pending structs, pending deletes, non-empty skips) makes the service evict. Of 2,000 mutated valid updates
  applied unchecked, 1,482 threw, 374 left parked state or a hole, 144 applied cleanly; `checkV1` refused every non-clean
  one (`checkPassedButParked` 0).
- Client ids are 53-bit, not u32 (SQLite INTEGER and varuints hold them; nothing may pack one into 32 bits). One node type
  (`Y.Node`) holds text and children together. The provider changed only in its imports (`@y/y`,
  `@y/protocols/awareness`); the service only in its seam and the attribution write.

### 3. Provenance as ContentMaps (verified)
Write: per integrated update, `attributionOf` (`s2/v14/yjs.ts`) → `Y.createContentIdsFromUpdate(v1)` →
`Y.createContentMapFromContentIds(ids, [insert = actor, insertAt = at], [delete = actor, deleteAt = at])`, encoded and
stored as one `update` row in `attributions` in the same commit as its log row. Compaction (`compact`): one transaction
inserts the version, deletes the folded update rows and merges their attribution rows (`Y.mergeContentMaps`) into one
`merged` row with exact times. Thinning (`thin`): `bucketAttribution` floors times to the minute so a run of one actor's
keystrokes coalesces into one range. Read: every row of a doc merged into one ContentMap, cached until the next append
(what DiffRenderer and AttributionsRenderer take).

| Test | Before | After |
|---|---|---|
| Node check (`out/service-check-v14.json`), who wrote it | agent text `session:s1`, human text `human`, a deletion `human` | unchanged after compaction (103 rows folded to 0) and restart |
| Node check, thinning to the minute | 379 B, 20 human insert ranges | 139 B, 2 ranges, answers unchanged |
| Electron (`out/latency-fullfsync-v14.json`, 906 keystroke rows) | 46,083 B of update rows | compaction 9,733 B; thinning 51 B (1 range); "who wrote" still `human` |
| Bench (`out/v14-attr-bench.json`, 2,040 updates) | 15 µs and 53 B per update | merge 24.7 ms → 33 KB; minute buckets 7.9 ms → 479 B |

Proposed persisted shape: `artifact_attributions {artifactId, fromSeq, toSeq, kind: update | merged, bucketMs, bytes}`:
one `update` row per log row in the same commit; compaction merges the folded seq range into one `merged` row
(compacting at version boundaries makes each merged row exactly one version's changes, so "which version or turn"
stays answerable); thinning re-buckets merged rows and may merge adjacent ones; rows are never deleted while a retained
version needs them. Reconciled with S3's ruling (Decision Log 29, 30): times are floored to the minute at write, so
`bucketMs` is 60,000 from the first row and thinning only merges adjacent rows (the spike's minute re-bucketing at
thinning becomes a no-op).

### 4. The port provider and the acknowledgement (verified; unchanged from v13 but for imports)
`s2/v14/provider/port.ts` (`PortProvider`) has no Electron, Node or window import; it takes any `PortLike`
(`postMessage`, `addEventListener('message'|'close')`, `start`, `close`) and ran on a DOM `MessagePort` in sandboxed,
context-isolated renderers (handed over by the preload with `window.postMessage(…, [port])`) and on a Node
`MessagePort` for the agent. Frames (`s2/src/frames.ts`, Yjs-free): y-protocols `0` sync and `1` awareness, MAWS `100`
ack; exact-size `Uint8Array`s. The host counts content frames per connection and after the commit sends one ack per
connection per flush ("your first N content frames are durable; the doc is at revision R"); the provider drops acked
local updates; updates made while not live are "carried" and go out inside the step 2 answering the host's step 1
(computed from the host's state vector: exactly what the host lacks); `state = {phase: off | handshake | live, synced,
unsaved, revision}` maps onto X32's `saved | saving | unsaved | reconnecting`. Node check: 20 offline edits and 5 typed
during the handshake reached the host with 0 rejections. Replicas: two hidden windows (`show:false`,
`backgroundThrottling:false`) and one `AgentReplica` (`s2/v14/host/agent-replica.ts`: a Node `MessageChannel` plus the
same provider, actor `{kind: 'session', appSessionId}`; `whenSaved()` resolves on the ack, which a tool call waits for);
rows carry the right actor; awareness crosses and is removed on close.

### 5. Numbers, v14 against v13 (verified)

### 7. The detached binary channel (verified as far as §6 needs; v13 and v14)
Framing (`s2/src/socket/framing.ts`, `encodeDocFrame`, `splitRecords`): from socket protocol 2, after the JSON-line
hello and welcome, a JSON line (starts `{`, ends 0x0A; `JSON.stringify` escapes control characters, so a line never
holds 0x00) or a doc frame `0x00 | u32 BE length | u32 BE channel | payload` (one y-protocols frame), told apart by the
first byte; a protocol-1 peer is refused before it sees a frame. `out/socket-check*.json`: 2,000 interleaved records
including 0x00/0x0A-filled payloads and a 7 MB frame, fed in random 1 B to 64 KB slices, all back in order at exact size
(4 ms). Multiplexing (`s2/src/socket/doc-channels.ts`): main allocates the channel and sends `documents.open {docId,
channel, actor}` (frames may follow at once), `documents.close {channel}`, the event `documents.closed {channel,
reason}`; unknown channels dropped; main names the actor; `HostDocChannels` turns a channel into a `HostPort` and
`MainDocRelay` moves bytes unparsed. Backpressure: past `DOC_HIGH_WATER` (8 MB queued) the host resets the channel
(`reason: reset`) and the provider re-syncs on a new port (verified in Node: one reset after 257 frames to a stalled
reader; main's reopen after a reset not run in Electron). One socket, not two: one token, one replacement rule, E11's
draining close, ordering between `documents.open` and its frames; head-of-line blocking of JSON lines behind a large
step 2 is bounded by the reset.
X13 amendment (accepted, ledger X13): socket protocol 2 carries JSON lines exactly as protocol 1 plus doc frames
`0x00 | u32 BE length | u32 BE channel | payload` (payload ≤ 64 MB, one X24 frame); hello, welcome, refuse and exit stay
JSON lines under the stable-fields promise and an old supervisor is refused on `protocol` and replaced through refuse →
exit; `SocketPort` gains `postFrame(channel, bytes)` and `onFrame`; `splitLines` becomes a record splitter keeping
`stop`/`rest()`; `documents.open`/`documents.close` requests and `documents.closed {channel, reason: host | reset}` in
X24's namespace; main allocates channels, names the actor, relays bytes unparsed at exact size; the host resets past
`DOC_HIGH_WATER`; a `channel` is u32 and a Yjs clientId never travels in a frame header; in utility mode the ports go to
the host as transfers on C1's host `MessagePort`, no channels.

### Pitfalls
- Yjs (both versions) accepts bad updates silently: v13 parks gaps, v14 integrates them behind a skip hole; both park
  missing origins and parents and unknown deletes and re-send them in every step 2. The pre-check and the eviction net
  are required.
- The provider can create its own gap if it sends edits before answering the host's step 1.
- macOS durability needs fullfsync (the app's index uses `NORMAL`; the store must not).
- Yjs emits `update` before `updateV2` in the same cleanup: do not pair the listeners (source); log V1.
- A `Buffer.subarray` from a socket ships its whole pool over structured clone: copy to exact size; an `ArrayBuffer` from a
  renderer arrives as a non-`Uint8Array` and is rejected (both verified).
- Hidden windows need `backgroundThrottling:false` (source). Every editor open mints a new clientID (source).
- v14 clientIds are 53-bit.

### 1. The model (verified)
On v14 the model is built of `Y.Node`s (one type: a name, attributes that are values or nested nodes, children that are
text with formats and nodes in one sequence; `src/ydoc.ts`, header comment):
- `deck`: a root node whose attributes are deck.json's keys except `order`; `sections` and `faces` nested nodes
  (key → JSON) so concurrent edits to different entries merge; unknown keys kept.
- `slides`: a root node, attribute id → `<slide>` with `order`, `style:*`, `attr:*` (`attr:data-transition`,
  `attr:hidden`), `held?: {source, reasons}` as attributes, `notes` a `<notes>` text node, `elements` an `<elements>`
  node, attribute id → `<el>`.
- `<el>`: `tag`, `parent` (an element id or `''` for the section), `order` (flow children) or `z` (pinned children), one
  key per `style:*` property and `attr:*` attribute, `raw?` (svg and x-embed inner markup, opaque), `text?`: a `<doc>`
  node of `p` or `li` blocks holding text with marks as formats (`{b:{}}`, `{a:{href}}`, `{span:{color}}`) and `br`
  nodes inline — `@y/prosemirror` 2's node shape. h1 to h3, p, th, td hold one `p` block; ul and ol one `li` per item.
- v13 is the same model on Y.Map, Y.Text and Y.XmlFragment (`src/ydoc-v13.ts`); every other module (`model.ts`,
  `publish.ts`, `canvas.ts`, `order.ts`, the parser, the serializer, `repair()`) talks only to the seam's API.

Nesting: a `parent` key per element plus a key among its siblings, all in one flat map; re-parenting is one key, so it
never duplicates (the XmlFragment-style child delete-plus-insert re-order duplicated in 200 of 200 trials on both
versions: `exp/concurrency.ts`, "contrast"; v14 has no move operation either). Read rules (`resolveParents`,
`src/model.ts`): a missing or non-container parent resolves to the section; a cycle sends its smallest id to the section;
the host writes the resolutions with `repair()`.

Paint order needs two keys: the dialect paints all flow content as one layer where the first flow child sits, so flow
children carry `order` (layout order) and pinned children carry `z` compared against the fixed key `FLOW_LAYER = 'a0'`
(below: under the flow content; above: over; no element holds `'a0'`; `src/order.ts`). The canonical file writes
[pinned under] [flow] [pinned over] (`partition`, `src/serialize.ts`). A backdrop sent to the back stays under while
another replica inserts a new first flow child, 200 of 200 on both versions.

Object anchors `{slideId, elementId}` resolve by id alone (`resolveAnchor`): stable through a move, a z change, a slide
re-order, a regroup and a republish combined; orphaned after a delete; live again after a re-add with the same id.

### 2. The canonical parser and serializer (verified; independent of the Yjs version)
One loader, `loadSlide` (`src/parse.ts`), over a small `RawNode` interface with two adapters, parse5 for the host
(`src/parse5-adapter.ts`) and a `<template>` in fragment context for the renderer (`src/dom-adapter.ts`); both give
byte-identical canonical files on every corpus slide. `serializeSlide` (`src/serialize.ts`); `parseStyle` and
`serializeStyle` (`src/css.ts`) adopt Claude's table property for property.
- Fixed point: `serialize(parse(x))` after one pass on four of Claude's examples (SKILL.md's plan slide, layout.md's kpis
  slide, diagrams.md's connectors with the arc svg, the recipes' rotated label; excerpts in `s6/fixtures/
  claude-examples.ts`) and on a deliberately messy slide; IR → Y → IR → file gives identical bytes.
- Equality by meaning: six variants of each example (reversed attribute and declaration order, whitespace and case,
  bare numbers for px, `rgb()` for hex, entities) canonicalize to the same bytes.
- Ids: minted `e<n>-<hash(section id, publish seed)>`, deterministic per seed (an idempotent replay mints the same ids),
  never an id the live slide holds, always written into the file.
- Held with reasons, never trimmed: two sections, an unknown tag, text directly in a div, `aside` not last, a nested
  list, an `x-embed` inside a div, an svg with script, `colspan`, 16 nested divs, 201 elements, a bad section id, an
  unknown inline tag, a section id differing from the file name. Unknown properties and attributes are dropped with a
  warning; `class` and `data-*` get a note.
- Normalization: attributes `id` first, the rest alphabetical, `style` last, `hidden` bare; style in Claude's table
  order as `prop:value; …`, names lowercased, `!important` stripped, the cascade inside one attribute applied (a later
  duplicate wins, a shorthand resets earlier longhands); `padding-*` → `padding` and `border-*-radius` →
  `border-radius` in the shortest 1 to 4 value form, `background-color` → `background`, `font` → longhands; no-ops
  (`margin:0`, `box-sizing:border-box`, `grid-template:none`, `position:static`) dropped with a note, other margins with a
  warning; bare numbers become px only where the grammar says LEN, pt → px ×2, shortest numbers; keywords lowercased,
  `bold`/`normal` → `700`/`400`; colours lowercase 6/8-digit hex, opaque integer `rgb()` → hex, normalized `rgba()` and
  `hsl[a]()`, `currentcolor` dropped with a warning; borders `W style color` with Claude's defaults explicit; generic
  font families lowercased, quotes only where needed; HTML whitespace collapsing, minimal escaping (U+00A0 as `&#160;`),
  marks nested a > span > b > i > u, `strong`/`em` → `b`/`i`, a span with weight ≥ 600, italic or underline → `b`/`i`/`u`;
  comments dropped, `tbody`/`thead`/`tfoot` unwrapped, one element per line with 2-space indents.
- Kept verbatim: svg and x-embed inner markup (after one parse5 pass), svg root attributes, href, src, alt, notes
  (trimmed), and flex, transform, filter, background and grid values beyond token normalization.
- `var(--ds-*)` (Decision Log 12) survives the round trip, fallback included; any other `var()` is dropped with a
  warning; `serializeSlide(ir, {resolveVar})` resolves tokens to literals for the mirror and the Claude-compatible export.

### 3. Diff-apply of a published file as one transaction (verified, 19/19 both versions)
`publish`, `diffSlide`, `diffDeck` (`src/publish.ts`); topology: host H, a live human replica U, the agent's replica A
brought up to H only when the agent reads.

| Case | Result |
|---|---|
| No-op republish, or one equal by meaning | 0 writes, no update |
| One property changed | 1 write; 21 B V1 / 33 B V2 (both versions) |
| The human recolours after the agent's read; the agent republishes the element moved with its stale colour | only the 2 moved properties land; the human's colour stays |
| Contrast: the same file diffed against the live doc | writes the stale colour over the human's |
| Element removed / re-added with the same id | id gone, anchor orphaned / the same element, anchor live |
| Agent word change plus bold while the human types in the same box | character-level merge; 42 B V1 / 44 B V2 |
| Agent adds a `<br>` while the human types elsewhere in the box | v14: both survive (a `br` sits in the block's sequence); v13: the block is replaced and the human's text lost |
| Flow re-order of two siblings; pinned under → over | 1 key each (the longest in-order run keeps its keys) |
| Structurally invalid file | held with reasons, last good model kept, a read returns the held source, a valid republish clears it |
| One invalid path in a multi-file map | the whole publish refused, nothing written |
| deck.json re-order / removal | 1 slide key; unknown keys kept; a removal (`null` plus order) one update |

### 4. Concurrency on two replicas (verified, 200 trials each, random client ids; identical on both versions)
- Concurrent move (left plus top): always one replica's whole position, never mixed (v14 A 102 / B 98; v13 A 89 / B 111),
  in one transaction or two.
- Move plus restyle of one element: both land.
- Z-order: different maxima deterministic; the same maximum mints the same key, broken by id, and both replicas'
  `repair()` writes identical values.
- One slide re-ordered two ways: one wins, no duplicate. Two slides into the same gap: the same key, `s1,s3,s4,s2` by id,
  one repair write separates them.
- Delete versus edit: the delete wins silently, the anchor orphans. Move into a group versus the element's deletion:
  deleted, group intact. Move into a group versus the group's deletion: the orphan shows at the section, one repair.
  A cycle: the smallest id to the section, one repair. Agent publish versus a human move of the same element: merged.

### 5. A minimal canvas (verified in happy-dom; not in Chromium)
`SlideCanvas` (`src/canvas.ts`) renders from the model and patches the DOM from the seam's change records (v14 from
`deltaDeep`), never importing Yjs; after every step the second replica's patched DOM equals a fresh render: a 3-move drag
(`attachDrag`, one transaction per move) is 6 style writes on one node; bring to front or send to back moves 1 node (plus
`data-layer="under"`); a text edit re-renders 1 box; an agent publish adding, restyling and removing one element each is
1 create, 1 style write, 1 remove, 1 placement (keyed placement: the longest in-order run stays). Under-layer rendering
isolates the section and gives its under pinned children `z-index:-1`, because plain CSS paints positioned elements over
all flow content (CSS 2.1 Appendix E; source, not checked in a real paint — P3-C's export window needs the same rule and
a pixel check).
The Tiptap binding on v14 (`exp/binding-v14.ts`, 10/10, `@y/prosemirror` 2.0.0-15 with a slide-text schema no wider than
Claude's inline set): `ynodeToPmnode` reads the model's `<doc>` for `p` and `ul`; what `pmnodeToDelta` writes the model

`exp/collab-v14.mjs`) holds the model's document, writes no normalization update on bind, its typing reaches the other
replica with marks and `<br>`, a model patch reaches the editor, and marks are stored under plain names.

### Pitfalls
v14-specific: `Y.Node.toString()` returns markup, read plain text from the delta; `observeDeep` delivers one event per
transaction on the observed node with empty `keysChanged`, so change records come from `ev.deltaDeep`; with a renderer,
`toDeltaDeep` returns the whole document with attributions on changed leaves and deletions as content attributed

`@y/y` and trips the duplicate guard): P3's binding module lives in `src/` with one `@y/y`; two prosemirror-model copies in
one process break the binding: one prosemirror copy shared by Tiptap and the binding; inserts pass every mark key
explicitly (`null` for absent) so nothing inherits from the left.
Both versions: diff a publish against the agent's base, never the live doc; equal fractional keys are the common case
for "to front" and "after X" (`generateKeyBetween` is deterministic), handled by the id tie-break and the deterministic
repair; delete beats a concurrent edit silently, so the publish protocol names that conflict; Claude's connector example
uses `border-width` and `border-style`, missing from its table (added); the canvas drags left/top-pinned elements only
(right/bottom pins need converting); the `font` shorthand expands only the parts given; Claude's minted ids are computed
from position and shift on insertion, which is why MAWS writes every id and seeds minting per publish (re-minting a
deleted id would re-attach an orphaned comment to a new element); parse5 reports parse errors and `DOMParser` none, so
hold decisions come from tree checks only.

### 2. Leaving history and undo (verified)
The live editor enters with `configureYProsemirror({ytype: versionFragment, renderer})` and leaves with `{ytype: live,
renderer: null}` (`showVersion`, `leaveHistory`, `s3/lib/collab.mjs`); after leaving, replica and host bytes equal those

### 3. Artifact-wide restore (verified, `s3-restore.mjs`)
After V0: in the document, typing, a deleted paragraph, a heading level, a format, a task, a tone, a new thread th3 (mark
and map entry), an agent rewrite, an inserted paragraph, a cell, a code block, a block moved (delete and re-insert with
the same id), paragraph s20p2 replaced by nB; tab t2 renamed "Appendix B" and edited, a new tab t3, th2 resolved, the
human typing inside th1's marked text; in a stand-in deck (`deck` map, `slides` map id → slide with fractional order,
`style:*`, notes text, `elements` map id → `{tag, z, style:*, text}`), slide s3 deleted, s13 added, an element moved, the
deck retitled, a slide re-ordered, notes and element text edited, an element deleted, a thread resolved. The host
computes one update R from (V0's state, the live state) and applies it with origin `{actor: 'human:restore'}` while
agent 2's replica edits concurrently in content the restore keeps, in content it removes, and inside rewritten text.

| | (a) revert: `revertUpdate` | (b) structural diff, children paired by name | (b′) paired by name and `id` |
|---|---|---|---|
| Document checks | 30/30 | 28/30 | 30/30 |
| Deck checks | 13/13 | 13/13 | 13/13 |
| Concurrent edit into a replaced block | dropped (the CRDT rule) | grafted into the restored s20p2 | dropped |
| Update size (25 and 100 sections, same edits) | 1.14 KB | 1.12 KB | 1.16 KB |
| Compute, 25 / 100 sections | 7–23 / 23–72 ms | 43 / 119 ms | 32 / 135–297 ms |
| Deck compute | 0.7 ms | 3 ms | 3 ms |
| Needs | the version state and the live state only | a v14 workaround (pitfall 5) | that, plus an id on every node |

Applying R at the host takes 0.3 ms for all three. **(a) chosen**: correct on every check, fastest, kind-agnostic (one
operation for documents and decks), CRDT-exact, needs only states (so it works across compaction by construction). How:
a scratch gc-off doc gets the old state then the live state; the changes since are `excludeContentIds(ids(scratch),
ids(old))`; `Y.undoContentIds(scratch, since)` deletes what was inserted since and re-inserts what was deleted since, and
the update it emits is shipped (about 15 lines; the primitive `DiffRenderer.rejectChanges` uses; `s3/lib/restore.mjs`).
What (a) brings back: the prose fragment equal to V0 block for block apart from the concurrent edits; block ids in V0
order without duplicates, the moved block in place, th1's mark span exactly its words; code text and language, the cell,
heading level, task, tone, bold; t2's title "Appendix" and body equal to V0, t3 gone; th2 unresolved, th3 and its mark
gone, the threads map equal to V0; slide s3 back with its 5 elements, notes and text, s13 gone, the moved element back,
title, order, notes, text and the deleted element restored; concurrent edits in kept content survive (an append, an
insert inside rewritten text, an element move, a notes edit), the edit into removed content is dropped; three replicas
converge; the human's editor shows the restored doc, `check()` valid. Attribution after restore: every change credited to
`human:restore` or the concurrent agent; an untouched paragraph still shows `import` only; restored text (new ids) shows
the restorer. Never destroys: restoring the version taken just before the restore gives the pre-restore state back.
**Undo after a restore is a real hazard** (verified): with the human's undo stack kept, the first ⌘Z skips 24 no-op items
then redoes the human's earlier deletion of s2p4, which the restore already brought back — paragraph s2p4 twice. Clearing
every bound editor's UndoManager when a restore lands fixes it.

### Pitfalls (verified unless marked)
1. S1's undo and redo commands undo into the live doc while history is shown: refuse them when the binding is not on the
   live ytype or a renderer is set.
2. Commands still run on a read-only view and write into the throwaway version doc: a `filterTransaction` refusing local
   doc changes in history.
3. Commands calling `configureYProsemirror` need `tr.setMeta('preventDispatch', true)` (S1's pitfall 2 again).
4. Undo after a restore resurrects content the restore brought back: clear every bound editor's UndoManager when a
   restore lands (likewise for any revert made on another replica; source: `rejectChanges` uses the same redo).
5. v14 rough edge: `applyDelta` with a `setAttr` whose value is a delta holding nested `setAttr` deltas throws
   "Unexpected content type" (`Y.Node.from` converts one level; `probe-diff.mjs`); convert deeply (`materialize`,
   `s3/lib/restore.mjs`). Matters to any deck writer.
6. `lib0/delta.diff` pairs children by name, grafting a concurrent edit into a replaced block: pair by id, or use (a).
7. Node writers produce mark keys through `pmnodeToDelta` with the editor's schema (a hand-written `comment--th3` was
   dropped, "schema declares no mark").
8. Per-keystroke times fragment runs (102 for 17 changes): merge touching runs; quantizing times shrinks provenance
   about 4×.
9. Each restore writes as a fresh scratch clientID (the state vector grows one client per restore; provenance credits the
   actor).
10. A concurrent agent write into content the restore removes is dropped silently (the CRDT rule).
11. Restored content gets new ids, so "Show editors" credits the restorer.

### §4.2 and §4.7 amendments proposed
1. §4.2 history renderer: "History renders with v14's `DiffRenderer(prevDoc, nextDoc, {attributions})` over two
   throwaway gc-off docs loaded from version states; the editor enters with `configureYProsemirror({ytype: version
   fragment, renderer})` and leaves with `{ytype: live, renderer: null}`; the live doc is never written" (replacing
   state-pair mode and `unrenderSnapshot()`).
2. §4.2 schema marks: "the four `y-attributed-*` marks (insert, delete, format, attrs) allowed on every node type, and
   `--attributed` variants of the strict containers (blockquote, listItem, taskItem, callout), in every schema from day
   one" (replacing "the `ychange` mark and the block attribute").
3. §4.2 provenance: one encoded `Y.ContentMap` per update, never folded; bucketing merges maps (`Y.mergeContentMaps`);
   times floored to the minute at write (the display granularity; about 4× smaller).
4. §4.2 restore: "one kind-agnostic host operation that reverts the changes since the version (`Y.undoContentIds` on a
   scratch gc-off doc holding version ⊕ live), shipped as one update of the restorer; per-kind adapters handle only the
   after-effects (mirror threads to `artifact_threads`, recompute orphans, run the id repair); on landing every bound
   editor clears its UndoManager" (replacing "a host operation per kind that diff-applies": a name-paired structural
   diff is wrong under concurrency).
5. §4.2 undo: both guards (undo and redo refuse when the binding is not live; a transaction filter refuses local doc
   changes in history).
6. §4.7: "N changes" counts touching runs merged; comment marks are excluded from changes (filter `comment` keys out of
   `y-attributed-format`; not tested beyond seeing the key); attribute marks on new nodes are not shown as attribute
   changes; same-id type changes may later be drawn as "type changed".
