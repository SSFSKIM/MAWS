## S1 — Yjs v13 or v14

**Verdict: v14 (`@y/y` 14.0.0-rc.28 with `@y/prosemirror` 2.0.0-15, pinned exactly).** Every functional gate passes;
the data gate passes (no loss, no corrupt encoding, v14 reads v13 bytes); API stability does not: `@y/prosemirror`'s JS
API broke twice in September 2026 and is still moving. Judged non-blocking because the API MAWS touches sits in one
module and the persisted bytes are Yjs's binary format. Confidence: high on function, moderate on maturity.

Method: Node 22 with happy-dom, real Tiptap 3.31.3 editors, replicas wired through y-protocols sync and awareness frames
via a host hub that logs every update as `{seq, actor, at, bytes}` (the `artifact_updates` shape). No Electron run
(the DOM input path and IME are S4's).

### 1. Binding in Tiptap 3.31.3 (two editor replicas and an agent replica)
- v14 26/26 checks, v13 25/25 on the same checks (verified: `node spikes/p3-store/s1/v14/s1-binding.mjs`,
  `node spikes/p3-store/s1/v13/s1-binding.mjs`; `s1/out/v14-binding.txt`, `v13-binding.txt`): typing and splits sync;
  paste gets fresh ids and strips foreign ones; `Y.UndoManager` scoped to the binding (A's undo removes only A's edit;
  undo-all restores the original ids; redo); remote carets; the agent replica's caret from a Node-side relative position
  renders; an `editing: {blocks}` awareness field reaches the editors.
- The v14 custom extension is 54 code lines (`s1/v14/collab.mjs`, `YCollaboration`: `syncPlugin`, `yCursorPlugin`,
  `yUndoPlugin`, undo and redo commands and keys, binding in a microtask). Schema hardening is 75 more lines
  (`s1/v14/schema.mjs`, adapted from upstream's MIT `yhub-tiptap-demo/src/schema.js`): the four `y-attributed-*` marks,
  marks allowed on containers, codeBlock admitting them, the `--attributed` variants, guards on TrailingNode, Link and
  tables. No Tiptap fork.
- v14 merges one concurrent case better (verified): both replicas offline press Enter at the start of the same
  paragraph; v13 duplicates the paragraph and its id, v14 gives two empty paragraphs. A concurrent mid-paragraph split at
  different offsets duplicates the tail on both (a split is "delete tail + insert node").

### 2. UniqueID
- Ids survive split (the first half keeps the id), paste (fresh ids) and undo on both versions (verified).
- Pitfall (verified): UniqueID skips only transactions with v13's `y-sync$` meta; v14's binding marks remote changes
  `y-sync-transaction`, so stock UniqueID on v14 writes ids into remote blocks from every peer. Fix without a fork:
  `UniqueID.configure({filterTransaction: tr => !isBindingTransaction(tr)})` (`s1/v14/collab.mjs`), and name the extension
  `collaboration` so UniqueID takes its collaborative path. Tiptap core's `Delete` extension also filters only `y-sync$`
  (source: `@tiptap/core` dist line 5572): set `coreExtensionOptions.delete.filterTransaction` the same way.
- The host's id repair stays required on both versions (writers that omit ids, concurrent splits; verified on v13's
  concurrent-Enter duplicate).

### 4. Suggestion mode for an agent edit (v14)
- 18/19 checks (verified: `node spikes/p3-store/s1/v14/s1-suggest.mjs`; re-run by the executor, 18/19).
- Topology: the host keeps the base doc and a suggestion doc (`gc:false, isSuggestionDoc:true`); the agent edits its
  own replica of the suggestion doc; the human's editor shows `DiffRenderer(baseReplica, suggestionReplica,
  {attributions})` in view mode. Four hunks render attributed to the agent, deletions struck; the owner's typing goes
  to base; per-hunk accept and reject land in base and the suggestion doc converges; a second live proposal renders;
  reject-all clears it.
- The one failure: accepting a text-only range inside an inserted paragraph returns true but leaves pending structs in
  the reviewer's base replica; accepting by the node range (`from-1 … to+1`) works. Accept buttons pass block ranges.
- Accepted content keeps the agent's clientID, but the base log credits the accepting port: provenance must map a
  suggestion doc's clientIDs to the suggester.
- v13 equivalent (estimate, not built): a fork doc per proposal, a structural diff into a custom overlay, per-hunk Y
  ops onto base; a home-grown DiffRenderer of about 1.5k to 3k lines, fragile on tables and attributes.

### Verdict reasoning
Gates: binding, UniqueID, undo and cursors pass; DiffRenderer with log-built attributions passes 13/13 where v13 does
8 to 10; suggestion mode passes with one range pitfall; the Node writer passes; data passes; API stability fails
literally. v14 still, because (1) the one-way risk is about data and the data passes; (2) the API MAWS touches is small
(`syncPlugin`, `configureYProsemirror`, `DiffRenderer`, the ContentMap helpers, `pmnodeToDelta`/`ynodeToPmnode`, the
mark names) and fits one module, so a re-pin edits that module, not documents; (3) a shipped editor runs this stack on
the same Tiptap; (4) v13's gaps land on §2 item 4, the differentiator (attribute and format changes invisible, no
times, a home-built suggestion engine). What would flip it: the architect reading "an API expected to break" as
blocking; a v14-only failure in S3, S4 or S7 (IME under `y-sync-transaction`, large-document first sync); a wish for zero
dependency churn before P4.

Executor's note on the residual risk: the binary encoding is stable, but how `@y/prosemirror` maps ProseMirror into
`Y.Node`s (mark storage keys such as `name--<hash>` for overlapping marks, the attributed variants) is binding-level
and could change between prereleases; that would be a content normalization of stored documents, not an unreadable
store. P3-A should keep S1's suite as the re-pin gate and store a binding-version tag per document.

### Pitfalls (verified unless marked)
1. UniqueID on v14 needs `filterTransaction`; filter core `Delete` too (source).
2. Undo and redo commands set `tr.setMeta('preventDispatch', true)`, else "Applying a mismatched transaction".
3. Bind after the EditorView constructor returns (a microtask): Tiptap's dispatch needs `editor.view`.
4. A mark's `excludes` changes its Y storage key (`Code.extend({excludes})` stored `code--<hash>`); overlapping marks
   (the `comment` mark) are stored as `name--<contenthash>` (source: CAVEATS). Writers produce marks through
   `pmnodeToDelta` with the editor's exact schema: schema parity is also key parity.
5. The `--attributed` variants carry every canonical attribute including the id; add them to UniqueID's `types`.
6. Without a renderer, a remote node-attribute change logs a one-time `y-attributed-attrs … swallowed` warning; content
   unaffected (`s1/v14/probe-attrs-warning.mjs`).
7. Partial accept inside an inserted block leaves pending structs; accept by block range.
8. An accepted suggestion is credited in the log to the accepting port; credit the suggester by clientID.
9. `@y/prosemirror` declares `@y/y` a dependency, not a peer: dedupe to one copy (the guard is `__ $YJS14$ __`), pin
   exact, install by version (the `latest` tags are stale).
10. A v13 client must never open a P3 document (it throws).
11. Concurrent mid-paragraph splits duplicate the tail on both versions.
12. Upstream docs lag: `@y/y`'s README still documents v13 types.
13. Awareness timers keep a Node process alive; scripts exit explicitly.

### 1. The model (verified)
On v14 the model is built of `Y.Node`s (one type: a name, attributes that are values or nested nodes, children that are
text with formats and nodes in one sequence; `src/ydoc.ts`, header comment):
- `deck`: a root node whose attributes are deck.json's keys except `order`; `sections` and `faces` nested nodes
  (key → JSON) so concurrent edits to different entries merge; unknown keys kept.
- `slides`: a root node, attribute id → `<slide>` with `order`, `style:*`, `attr:*` (`attr:data-transition`,
  `attr:hidden`), `held?: {source, reasons}` as attributes, `notes` a `<notes>` text node, `elements` an `<elements>`
  node, attribute id → `<el>`.
- `<el>`: `tag`, `parent` (an element id or `''` for the section), `order` (flow children) or `z` (pinned children), one
  key per `style:*` property and `attr:*` attribute, `raw?` (svg and x-embed inner markup, opaque), `text?`: a `<doc>`
  node of `p` or `li` blocks holding text with marks as formats (`{b:{}}`, `{a:{href}}`, `{span:{color}}`) and `br`
  nodes inline — `@y/prosemirror` 2's node shape. h1 to h3, p, th, td hold one `p` block; ul and ol one `li` per item.
- v13 is the same model on Y.Map, Y.Text and Y.XmlFragment (`src/ydoc-v13.ts`); every other module (`model.ts`,
  `publish.ts`, `canvas.ts`, `order.ts`, the parser, the serializer, `repair()`) talks only to the seam's API.

Nesting: a `parent` key per element plus a key among its siblings, all in one flat map; re-parenting is one key, so it
never duplicates (the XmlFragment-style child delete-plus-insert re-order duplicated in 200 of 200 trials on both
versions: `exp/concurrency.ts`, "contrast"; v14 has no move operation either). Read rules (`resolveParents`,
`src/model.ts`): a missing or non-container parent resolves to the section; a cycle sends its smallest id to the section;
the host writes the resolutions with `repair()`.

Paint order needs two keys: the dialect paints all flow content as one layer where the first flow child sits, so flow
children carry `order` (layout order) and pinned children carry `z` compared against the fixed key `FLOW_LAYER = 'a0'`
(below: under the flow content; above: over; no element holds `'a0'`; `src/order.ts`). The canonical file writes
[pinned under] [flow] [pinned over] (`partition`, `src/serialize.ts`). A backdrop sent to the back stays under while
another replica inserts a new first flow child, 200 of 200 on both versions.

Object anchors `{slideId, elementId}` resolve by id alone (`resolveAnchor`): stable through a move, a z change, a slide
re-order, a regroup and a republish combined; orphaned after a delete; live again after a re-add with the same id.

### 2. The canonical parser and serializer (verified; independent of the Yjs version)
One loader, `loadSlide` (`src/parse.ts`), over a small `RawNode` interface with two adapters, parse5 for the host
(`src/parse5-adapter.ts`) and a `<template>` in fragment context for the renderer (`src/dom-adapter.ts`); both give
byte-identical canonical files on every corpus slide. `serializeSlide` (`src/serialize.ts`); `parseStyle` and
`serializeStyle` (`src/css.ts`) adopt Claude's table property for property.
- Fixed point: `serialize(parse(x))` after one pass on four of Claude's examples (SKILL.md's plan slide, layout.md's kpis
  slide, diagrams.md's connectors with the arc svg, the recipes' rotated label; excerpts in `s6/fixtures/
  claude-examples.ts`) and on a deliberately messy slide; IR → Y → IR → file gives identical bytes.
- Equality by meaning: six variants of each example (reversed attribute and declaration order, whitespace and case,
  bare numbers for px, `rgb()` for hex, entities) canonicalize to the same bytes.
- Ids: minted `e<n>-<hash(section id, publish seed)>`, deterministic per seed (an idempotent replay mints the same ids),
  never an id the live slide holds, always written into the file.
- Held with reasons, never trimmed: two sections, an unknown tag, text directly in a div, `aside` not last, a nested
  list, an `x-embed` inside a div, an svg with script, `colspan`, 16 nested divs, 201 elements, a bad section id, an
  unknown inline tag, a section id differing from the file name. Unknown properties and attributes are dropped with a
  warning; `class` and `data-*` get a note.
- Normalization: attributes `id` first, the rest alphabetical, `style` last, `hidden` bare; style in Claude's table
  order as `prop:value; …`, names lowercased, `!important` stripped, the cascade inside one attribute applied (a later
  duplicate wins, a shorthand resets earlier longhands); `padding-*` → `padding` and `border-*-radius` →
  `border-radius` in the shortest 1 to 4 value form, `background-color` → `background`, `font` → longhands; no-ops
  (`margin:0`, `box-sizing:border-box`, `grid-template:none`, `position:static`) dropped with a note, other margins with a
  warning; bare numbers become px only where the grammar says LEN, pt → px ×2, shortest numbers; keywords lowercased,
  `bold`/`normal` → `700`/`400`; colours lowercase 6/8-digit hex, opaque integer `rgb()` → hex, normalized `rgba()` and
  `hsl[a]()`, `currentcolor` dropped with a warning; borders `W style color` with Claude's defaults explicit; generic
  font families lowercased, quotes only where needed; HTML whitespace collapsing, minimal escaping (U+00A0 as `&#160;`),
  marks nested a > span > b > i > u, `strong`/`em` → `b`/`i`, a span with weight ≥ 600, italic or underline → `b`/`i`/`u`;
  comments dropped, `tbody`/`thead`/`tfoot` unwrapped, one element per line with 2-space indents.
- Kept verbatim: svg and x-embed inner markup (after one parse5 pass), svg root attributes, href, src, alt, notes
  (trimmed), and flex, transform, filter, background and grid values beyond token normalization.
- `var(--ds-*)` (Decision Log 12) survives the round trip, fallback included; any other `var()` is dropped with a
  warning; `serializeSlide(ir, {resolveVar})` resolves tokens to literals for the mirror and the Claude-compatible export.

### 3. Diff-apply of a published file as one transaction (verified, 19/19 both versions)
`publish`, `diffSlide`, `diffDeck` (`src/publish.ts`); topology: host H, a live human replica U, the agent's replica A
brought up to H only when the agent reads.

| Case | Result |
|---|---|
| No-op republish, or one equal by meaning | 0 writes, no update |
| One property changed | 1 write; 21 B V1 / 33 B V2 (both versions) |
| The human recolours after the agent's read; the agent republishes the element moved with its stale colour | only the 2 moved properties land; the human's colour stays |
| Contrast: the same file diffed against the live doc | writes the stale colour over the human's |
| Element removed / re-added with the same id | id gone, anchor orphaned / the same element, anchor live |
| Agent word change plus bold while the human types in the same box | character-level merge; 42 B V1 / 44 B V2 |
| Agent adds a `<br>` while the human types elsewhere in the box | v14: both survive (a `br` sits in the block's sequence); v13: the block is replaced and the human's text lost |
| Flow re-order of two siblings; pinned under → over | 1 key each (the longest in-order run keeps its keys) |

### 4. Concurrency on two replicas (verified, 200 trials each, random client ids; identical on both versions)
- Concurrent move (left plus top): always one replica's whole position, never mixed (v14 A 102 / B 98; v13 A 89 / B 111),
  in one transaction or two.
- Move plus restyle of one element: both land.
- Z-order: different maxima deterministic; the same maximum mints the same key, broken by id, and both replicas'
  `repair()` writes identical values.
- One slide re-ordered two ways: one wins, no duplicate. Two slides into the same gap: the same key, `s1,s3,s4,s2` by id,
  one repair write separates them.
- Delete versus edit: the delete wins silently, the anchor orphans. Move into a group versus the element's deletion:
  deleted, group intact. Move into a group versus the group's deletion: the orphan shows at the section, one repair.
  A cycle: the smallest id to the section, one repair. Agent publish versus a human move of the same element: merged.

### Pitfalls
v14-specific: `Y.Node.toString()` returns markup, read plain text from the delta; `observeDeep` delivers one event per
transaction on the observed node with empty `keysChanged`, so change records come from `ev.deltaDeep`; with a renderer,
`toDeltaDeep` returns the whole document with attributions on changed leaves and deletions as content attributed
`delete` (walk attributions, not op types); S1's `collab.mjs` cannot be imported across packages (it loads that package's
`@y/y` and trips the duplicate guard): P3's binding module lives in `src/` with one `@y/y`; two prosemirror-model copies in
one process break the binding: one prosemirror copy shared by Tiptap and the binding; inserts pass every mark key
explicitly (`null` for absent) so nothing inherits from the left.
Both versions: diff a publish against the agent's base, never the live doc; equal fractional keys are the common case
for "to front" and "after X" (`generateKeyBetween` is deterministic), handled by the id tie-break and the deterministic
repair; delete beats a concurrent edit silently, so the publish protocol names that conflict; Claude's connector example
uses `border-width` and `border-style`, missing from its table (added); the canvas drags left/top-pinned elements only
(right/bottom pins need converting); the `font` shorthand expands only the parts given; Claude's minted ids are computed
from position and shift on insertion, which is why MAWS writes every id and seeds minting per publish (re-minting a
deleted id would re-attach an orphaned comment to a new element); parse5 reports parse errors and `DOMParser` none, so
hold decisions come from tree checks only.

### 3. Artifact-wide restore (verified, `s3-restore.mjs`)
After V0: in the document, typing, a deleted paragraph, a heading level, a format, a task, a tone, a new thread th3 (mark
and map entry), an agent rewrite, an inserted paragraph, a cell, a code block, a block moved (delete and re-insert with

computes one update R from (V0's state, the live state) and applies it with origin `{actor: 'human:restore'}` while
agent 2's replica edits concurrently in content the restore keeps, in content it removes, and inside rewritten text.

| | (a) revert: `revertUpdate` | (b) structural diff, children paired by name | (b′) paired by name and `id` |
|---|---|---|---|
| Document checks | 30/30 | 28/30 | 30/30 |
| Deck checks | 13/13 | 13/13 | 13/13 |
| Concurrent edit into a replaced block | dropped (the CRDT rule) | grafted into the restored s20p2 | dropped |
| Update size (25 and 100 sections, same edits) | 1.14 KB | 1.12 KB | 1.16 KB |

Applying R at the host takes 0.3 ms for all three. **(a) chosen**: correct on every check, fastest, kind-agnostic (one
operation for documents and decks), CRDT-exact, needs only states (so it works across compaction by construction). How:
a scratch gc-off doc gets the old state then the live state; the changes since are `excludeContentIds(ids(scratch),
ids(old))`; `Y.undoContentIds(scratch, since)` deletes what was inserted since and re-inserts what was deleted since, and
the update it emits is shipped (about 15 lines; the primitive `DiffRenderer.rejectChanges` uses; `s3/lib/restore.mjs`).

insert inside rewritten text, an element move, a notes edit), the edit into removed content is dropped; three replicas
converge; the human's editor shows the restored doc, `check()` valid. Attribution after restore: every change credited to
`human:restore` or the concurrent agent; an untouched paragraph still shows `import` only; restored text (new ids) shows
