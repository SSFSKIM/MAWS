UX wave, board ticket 733, second probe: the user frame's own fields for text that was not typed (pasted_content,
inline_pastes, client_composed, text_not_typed): what the model receives, and what the auto mode classifier decides
(2026-11-17; on the build VM; branch ux-wave/733-paste-probe, on top of the first probe's f2ba2c3a7; scenario
scenarios/pass3/uxwave-733-fields.mjs)

Why. 733's design document rests two statements on the engine's source alone. First, a client can declare a paste on
the frame and the engine frames it. Second, those fields bear on what the model and the classifier treat as the
person's own words. The project's rule is that a wire claim is checked against a recording. These are the recordings.

The schema (cli.pretty.js 2.1.322, line 1127713, the user frame `Ln`; quoted in part):
  pasted_content  optional array; each entry "a string or an array of content blocks. The CLI appends the text of each
                  entry after the typed text, in order, and may wrap it in `<pasted_content>` tags. Blocks other than
                  text are ignored ... A list of over 1,000 entries and blocks in all is ignored."
  inline_pastes   optional array of strings: "Text the user pasted that is still in `message.content` where they put
                  it ... the CLI may wrap each entry in `<pasted_content>` tags where it still stands in the last text
                  block. It looks for the first 100 entries that are not blank."
  client_composed optional literal true: "delivers its text as written, with no `@path` file-mention expansion and no
                  slash-command dispatch. On current CLIs the turn-start attachment pass is skipped as a whole ..."
  text_not_typed  @internal; any value but false or null reads as true: "delivered as written ... The checks of whether
                  a message's words are the user's own do not read this mark yet: they too go by the origin."
  The code (source, not run): Dat (241751) is called on the stdin path (615179) and wraps only while oO(), the gate
  tengu_virtual_pancake, is on; the owner's cache has it on. An inline_pastes entry is wrapped only when its trimmed
  length is 20 or more (_Ot = 20, the terminal's own cut, LZe 1220630; Fbe there tests for "ultraplan", not for a line
  break). The id is the engine's yCe(), sha256(session id)[0:4], which is MAWS's pastedTagId.

Answer A. Yes, the engine honours both paste fields on a stdin frame and frames the paste itself, with the session's
own id. inline_pastes wraps the paste in place only at 20 trimmed characters or more; a line break does not lower the
cut. pasted_content appends the paste after the typed text and wraps it at any length. The rewritten text, not the
text sent, is what the replay, the transcript's user row and the model's request hold. No field and no shape tried
drew an error frame.

Answer B. The two paste fields end as MAWS's own form, byte for byte, and the classifier treated them the same:
allowed in 0 of 5 each, against 1 of 5 for wrapPasted and 5 of 5 typed. The two flags change nothing in what the
model receives, and nothing the classifier's counts show: allowed in 4 of 5 each, against 5 of 5 typed. Neither flag
marks a typed approval as not the person's own.

Inference (not observed directly).
  - MAWS can let the engine frame a paste, through pasted_content (appended at the end) or inline_pastes (in place, at
    20 characters or more), and the model gets the same block as from wrapPasted. The engine then owns the id and the
    20-character cut, and the replay and user row hold the engine's rewrite, not MAWS's text. A paste in the middle
    of a sentence needs inline_pastes. pasted_content moves the paste to the end of the message.
  - The wrap depends on the gate tengu_virtual_pancake. With the gate off (source), pasted_content is appended as LF LF
    + the text with no tags, and inline_pastes does nothing. MAWS's own wrapPasted does not depend on the gate.
  - For the classifier, what counts is the tagged text the model receives, not which field produced it. Neither flag
    is read as "not the person's words": client_composed and text_not_typed let a typed approval through as typed
    text does (4 of 5 each against 5 of 5; the samples cannot tell these apart).
  - The forms that mark a paste were allowed 1 of 20 in all (wrapPasted here and as the first probe's P3,
    pasted_content, inline_pastes); 1 of 25 with P4's segment plus joiner. The marking lowers the rate; it does not
    close the path.
