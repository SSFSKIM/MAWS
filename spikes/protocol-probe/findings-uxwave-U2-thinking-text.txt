UX wave U2, O-27 and Probes and checks 9: does a thought carry text, per model, with and without MAWS's request
(docs/doperpowers/specs/2026-11-12-ux-wave/U2-transcript-structure.md, item O-27 "Which thoughts get a line inside a
run", check 9; 2026-11-12)

Question. MAWS's engine host sends `set_max_thinking_tokens { max_thinking_tokens: null, thinking_display: 'summarized' }`
after initialize at every session start (src/engine-host/session.ts, near line 1186). MAWS's own journals show every
thinking block with text since then, but only for claude-opus-5-5. For each model alias the owner's sessions use, does
the thinking block carry text on the wire and in the transcript file, with the request and without it?

Verdict. Every model returns text under the request and none without it, on the wire and in the file alike: 18 of 18
launches split exactly on the request. With it, the stream's thinking block is `thinking_display: "summarized"` with
non-empty `thinking_delta`s, the final `assistant` frame's thinking block holds the same text, and the transcript row
holds it too. Without it, the display is `"updates"`: two or three `thinking_delta`s with empty text, an empty
`thinking` in the assistant frame and in the row, a signature in each. Both halves carry the duration and the display on
the wire (`thinking_duration_ms`, `thinking_display` on the assistant frame) and in the file (`thinkingDurationMs`,
`thinkingDisplay` on the row). In the spec's terms: no model returns no text under the request, so check 9's fallback
("its thoughts fall under #479's line") applies to no model; the O-27 rule as written holds for opus, fable, sonnet and
haiku alike. Confidence: high for these four models on this engine and route; the prompt always made the model think,
so a turn in which a model does not think at all was not seen.

  - The control response to set_max_thinking_tokens is `{subtype: "success"}` with no body, every time (seq 14).
  - The stream event frame itself carries `thinking_display` beside `parent_tool_use_id` and `api_message_id`; the
    block start holds `thinking: ""` and `signature`, one `signature_delta` closes it in both halves.
  - The assistant frame's keys include `thinking_duration_ms` and `thinking_display` in both halves; the transcript row's
    keys `thinkingDurationMs` and `thinkingDisplay`, equal to the wire's.
  - `system/thinking_tokens` frames (`estimated_tokens`, `estimated_tokens_delta`) arrive in both halves.
  - Every turn reported thinking tokens in the result's modelUsage (121 to 439), so each model did think in both halves.

Inference.
  - The request decides the text for every model; nothing model-specific was seen. The spec's journals (opus only) are
    therefore representative of the other three models.
  - Without the request this engine's sdk default is "updates", not "omitted": a block exists, with its duration, but no
    text. A launch that loses the request (it is not acknowledged before the first prompt; session.ts does not hold the
    prompt for it) would give text-less thoughts with durations, which #479's line already covers.
  - The duration is on every route that reads the file and on the wire, with or without the request, which is what the
    coordinator's lead (1) stated; confirmed here for all four models.

Not tried. A turn in which the model does not think; models outside the four aliases; the request sent mid-session; a
terminal (interactive) session's display, which the spec's measured 94% text-less terminal thoughts suggest differs.
