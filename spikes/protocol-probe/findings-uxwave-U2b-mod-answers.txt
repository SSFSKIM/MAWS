Method.
  Engine 2.1.322 (/opt/maws-probe/engines/2.1.322; every system/init reads 2.1.322), run only under vm-run.sh (VM.md).
  Two installations, both taken by git from the public doperpowers repository into a clone on the VM, with a worktree for
  each: "before" = c7619f359 (to-human 0.8.2); "after" = 0fed175f3134f5669aad145bae3b29f5a03ed643 (to-human 0.9.0). Every
  fixture's provenance row names its commit, version and the sha256 of to-human.tsx and folds.tsx. Branch heads seen:
  d27248be at the start, then 0fed175f. The only "after" recordings made on d27248be were of the resumed part's after
  cases; all of them were made again on 0fed175f, and only the 0fed175f recordings are committed. The branch's last
  head, a98c578e, differs from 0fed175f by five lines of a comment in to-human.tsx (no code), so nothing was run again.
  Each run copies the checkout's whole `to-human/` and `sminos/` folders, unchanged, into a scratch folder, plus a plugin
  of doperpowers' `output-styles/to-human.md` alone, and loads all three with --plugin-dir, as live-maws-check.py does
  (but the whole to-human folder, so maws-surface.json is there). The scratch HOME carries settings
  `outputStyle: doperpowers:to-human` and `prependPlugins: [to-human@inline, sminos@inline]`;
  CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1. No CLAUDE_CONFIG_DIR is set, as MAWS sets none: the config is $HOME/.claude.
  The launch is MAWS's: ENGINE_FLAGS (-p, stream-json both ways, --permission-prompt-tool stdio,
  --include-partial-messages, --forward-subagent-text, --replay-user-messages, --include-hook-events, setting sources
  user,project,local), --await-initialize, --session-id or --resume, and buildEnvironment's constants (MAWS_LANE=B among
  them). The advertisement goes where withOwnerChannel writes it, the settings env:
  `--settings {"dialogExpiry":"never","env":{"MAWS_NATIVE_TO_HUMAN":"8"|"9"}}`, or no env for none. Permission mode
  `default`, with every permission request answered allow. After initialize (appInitialize, the `maws` SDK server
  served) the probe attaches as surface `desktop`, client `maws-main`, and sends `ui_render` with the props
  src/renderer/src/transcript/surface/adapters.ts builds. Those are userInput (origin sdk), assistantInput,
  callProps/groupInput (a run of three calls as `group:<first call>`), and engineUserProps (a hand-back as peer with
  `from`, a task notice as task-notification with `task`). The new asks are as §E gives them: a thought as
  AssistantMessage {text, isFirstOfReply:false, isSummary:true}, a turn's line as TurnDuration
  {word, durationMs, isExpanded:true} under `<anchor>~turn` anchored at the turn's prompt, and a notice the host made as
  UserMessage under `<anchor>~<tag>`.
  The resumed part makes no model call (ANTHROPIC_BASE_URL is unreachable). It resumes a seeded transcript of invented
  text, uxwave-u2b-mod-common.mjs seedRows: a prompt; a thought with text; three Bash calls; an unmarked text; a
  message-tool call; a mixed text (a message and words beside it); a ListAgents call; a subagent hand-back; a task
  notification; an asynchronous sminos question with its delivered answer; a final marked text.
  The live part runs on haiku (claude-haiku-5-5) through the gateway. Its mechanical questions (E1's negatives and
  control, E3, E4, E5) also run against uxwave-u2b-mock-api.mjs, a local stand-in for the Messages API. The stand-in
  scripts the main loop from the prompt, answers every summary request with a fixed line, and logs every request it
  receives. A summary request is recognised by the mod's own system prompt (LABEL_SYSTEM). The engine, launch and mod
  are the same as in the real runs; only the endpoint differs. For E6 the real summary run goes through a local relay
  that forwards each request to the gateway unchanged (headers never logged) and logs the usage each answer reports.
  Real model requests spent: about 34 in all, about $0.02. That is 6 one-turn launches (1 main request and 1 short
  side request each, the engine's own), and the summary run twice (11 requests and 2 summaries each). The first summary
  run is discarded: the probe did not ask the message call's row, so the view never saw a mark.
  Runs: each resumed case once; each live launch once; the real summary run once (after the discarded first run); each
  stand-in case once; the in-place control once. Where timing could change a result, it says so below.
