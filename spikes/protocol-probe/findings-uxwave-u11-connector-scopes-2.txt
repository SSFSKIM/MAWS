Contradictions with the first pass or the draft.
  - The draft (first section, third bullet): an address entry needs "the engine's own expansion of variables and of the
    plugin's folder, which holds the plugin's version". For this plugin, installed with `claude plugin install` from a
    local directory marketplace, the engine ran the server from the marketplace's own folder (record line 2,
    `configs["plugin:cs-plug:cs-pserver"].args[0]` = `<scratch>/cs-market/cs-plug/srv.mjs`), not from the installed
    copy that installed_plugins.json names (`<home>/.claude/plugins/cache/cs-market/cs-plug/<version>`, line 1
    `pluginInstallShape`); an entry with the installed folder admitted nothing (line 7, allow-cmd-install). So the
    folder an entry must name depends on the plugin's source; for a source fetched into the cache (git, a URL) it was
    not run.
  - The draft (#476, "When the rule runs"): a connector switched off at launch "was started by the engine once, in
    that one launch, before the toggle reached it". cs-local (the local-scope server, which the engine starts about
    100 ms after the others) was started after its own off had been answered, in both runs (line 16, early-initialize:
    toggles answered by 616 ms, `stdioTimeline` cs-local `start` at 624 ms, `SIGINT` at 676 ms; run 2: 697 ms, 706 ms,
    748 ms). "Started once in that launch" holds; "before the toggle reached it" does not always.
  - Nothing contradicts the first pass. Its allow-user (an allowlist blocks what it does not name) and its reading of
    `/mcp disable` (writes `disabledMcpServers` under the project entry) are confirmed by runs here.

Method.
  Engine 2.1.322 under spikes/protocol-probe/vm-run.sh (VM.md) on the build VM the first pass used; the gateway through
  the loopback forward. Scenario scenarios/pass3/uxwave-u11-connector-scopes-2.mjs, run twice as
    ./vm-run.sh --prefix conn2a --out /tmp/conn2-r1 run run-pass3.mjs uxwave-u11-connector-scopes-2
  (conn2b, /tmp/conn2-r2 for the second). Scratch HOME and repository per run; nothing of a person's: no account, no
  sign-in, all servers invented stubs on loopback. The six servers are the first pass's (cs-proj in the repository's
  .mcp.json; cs-user and cs-oauth by `claude mcp add --scope user`, stdio and HTTP; cs-local by `--scope local`; the
  plugin cs-plug's plugin:cs-plug:cs-pserver and plugin:cs-plug:cs-poauth, installed at user scope), with one change:
  the plugin's stdio server is `node ${CLAUDE_PLUGIN_ROOT}/srv.mjs cs-pserver`, so a command entry can be tried with
  the variable and with each folder it could stand for. The HTTP stub admits only the token seeded in the scratch
  credential store and records each request with its time; three more paths serve add-json's servers with no
  sign-in (`/open/<name>` streamable HTTP, `/sse/<name>` the legacy SSE transport). The stdio stub logs its start,
  every JSON-RPC method, a signal and a closed stdin, with the time. Folders: the repository (<root>), a linked
  worktree beside it (<worktree>), <root>/sub. Every session is MAWS's launch (uxwave-common-arrivals.mjs mawsLaunch);
  the allow cases add `--debug-file` and the record keeps the engine's lines about settings and MCP from it. The
  terminal cases start the interactive engine (`--model haiku`) in tmux inside the scenario, type the commands, and
  read .claude.json after each. A turn ("Reply with only the word ok", haiku) is sent only in the cases that read
  init's tools and the deferred names. Spend: under $0.01 a run.
  The two runs agree field by field (times, seqs and ids aside) except one race: at early-status's first mcp_status,
  three stdio servers read `pending` in run 1 and `connected` in run 2. Run 1 is committed.
  Fixtures: the record fixtures/uxwave/u11-connector-scope2.ndjson, one case a line (line N below), and one journal
  per session, fixtures/uxwave/u11-connector-scope2-<case>[-<step>].jsonl, where seq N is the row with "seq": N.
  The journals are trimmed by the scenario: stream events dropped, control payloads over 4 kB that name no probe
  server (initialize's answer, the maws server's tool list) reduced to their size and keys, arrays over 24 items
  reduced to their count and the probe's own items. No engine transcript is committed; deferred names are in the
  record's `deferred` (the transcript's deferred_tools_delta at its line 6, as the scenario read it).

What could not be run here, and why.
  - Checks 6, 7, 8 and 10 were not in this pass's brief (6 needs an account with a connector; 7 the Mac mini's OAuth
    gate job).
  - A plugin from a marketplace that is fetched (git or URL) into the plugin cache: the folder its servers run from,
    and so whether a plugin update changes the command line an address entry must match, is not shown; only a
    local directory marketplace was run.
  - Two engines writing .claude.json at the same instant.
