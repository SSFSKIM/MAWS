shell command's block (the four frames of findings-uxwave-u1-classifier-block.txt question 1, and the file row's
toolDenialKind)? Then, with the grant using the word "call" and Design 2's subject, is the retry run, three of three

Verdict. Yes to both: 6 of 6 retries ran and the classifier allowed each (3 MCP, 3 Write). Each retry's input equals
the blocked call's input exactly. The document's default for Reported 4 holds: offer the button for a call of any
tool that can be named whole. `blockedCallOf` need not answer null for a call that is not a shell command.
The block has the same shape as a shell command's, in all 6 runs:
  1. a `system` `permission_denied` frame: tool_name ("mcp__uxw__note" or "Write"), tool_use_id,
     decision_reason_type "classifier", decision_reason (the stand-in "The server-side auto mode classifier judged
     this action dangerous (it gave no explanation)"), message; no input, no agent_id;
  2. the call's error tool result, with tool_result_meta [{id, non_execution_kind "automode-blocked",
     permission_decision {reject, config, classifier}}];
  3. the turn result's permission_denials entry {tool_name, tool_use_id, tool_input} (the MCP tool's arguments
     {text}; the Write's {file_path, content});
  4. in the transcript file, the result row's toolDenialKind "automode-blocked", with permissionDecision {reject,
     config, classifier, reasonCode "classifier:auto-mode"}.
  No can_use_tool in any run.
The grants, as sent: consentMessage('call', subject) of src/shared/engine/arrival.ts, where the subject is the
compact JSON of Design 2:

Method. Engine 2.1.322, model haiku (claude-haiku-5-5), auto mode, gateway route, feature cache seeded; MAWS's launch
as in findings-uxwave-u1c-during-turn.txt (uxwave-common-send-permission.mjs, --debug-file). The rule, in the scratch
user settings: {"autoMode": {"soft_deny": ["$defaults", "Probe Marker: any action whose input contains the string
maws-probe-marker, whether a shell command, a file write or an MCP tool call (a test marker on this machine)."]}}.
c-mcp: a stdio MCP server `uxw` written by the scenario (newline-delimited JSON-RPC, no dependencies) with one tool

uxwave-u1c-stream.mjs, cases c-mcp and c-write, one fresh session per run. Fixtures (fixtures/uxwave/):
