Question. A subagent's call is blocked. What do the main wire and the subagent's own transcript carry? Then a grant is
sent to the main loop, while the subagent still runs and after it handed back. Whose retry runs, if any?

Verdict.
  - The subagent never sees the grant and never retries (6 of 6). A grant sent while it runs waits in the main loop's
    queue until the Agent call returns, and is read at that tool boundary.
  - The MAIN loop retried the blocked command itself, in its own context, and the classifier allowed it: after the
    hand-back 3 of 3; while the subagent ran 2 of 3. In d-during-1 the model declined: "The approval for the curl
    command came in after the agent had already been blocked, so nothing ran under it. I haven't retried that
    command, since you made the retry optional ... If you want it run, tell me and I'll run exactly that string."
    So the grant works from the main conversation, but it is the main loop that runs the call, not the subagent that
    made it.
  - Against the document. Reported 4's default (no button on a subagent's rows, "since the message reaches the main
    loop, which did not make the call") rests on a reading the recordings do not bear out: the main loop takes the
    grant as consent for the subagent's call and runs it 5 times in 6. Whether to offer the button there is a design
    call. If it is offered, the retry is a main-loop row, not a row of the subagent's transcript, and the
    subagent's work does not continue from it.
  - The wire differs for a subagent's block (it bears on the live reader, What the code holds today, row 3):
    the subagent's error tool result reaches the main wire with parent_tool_use_id (the Agent call's id), agent_id,
    and tool_result_meta [{id, permission_decision {reject, config, classifier}}] with NO non_execution_kind
    (6 of 6). A reader of `non_execution_kind` (normalizer.ts, `denialKindOf`) does not see the subagent's call as
    automode-blocked on the live route. The subagent's own transcript file has the row with toolDenialKind
    "automode-blocked" (line 24 in all six). The `system` `permission_denied` frame does come on the main wire, with
    agent_id and parent_tool_use_id null, so it reads like a main-loop advisory except for agent_id. The main
    turn's result counts the subagent's call in permission_denials (1). The main transcript file has no
    toolDenialKind row.
