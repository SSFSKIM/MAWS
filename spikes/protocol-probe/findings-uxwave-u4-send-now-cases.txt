Question. For the request MAWS's host will write, `interrupt {send_now: true, message_uuid}`, what does the engine
answer and put on the wire, in what order, what does its transcript file hold afterwards, and is it the same on three
runs, when (1) the uuid names nothing the engine holds; (2) two messages wait at the next step; (3) a Stop follows the
request before its answer, or after it and before the cut turn's end; (4) what lies between the cut turn's end and the
message's turn; (5) the turn is writing text, behind a subagent, holding a permission request, or in a call that cannot
be moved; (6) the message waits after the turn; (7) the engine does not know the key.

The transcript file afterwards (the uxw_transcript rows).
- A send-now that moved a shell command (a, two, later, stop-moved): the cut turn leaves the "moved" tool result and
  nothing else: no interrupt marker, no line for the end; the message is a user line with a new promptId. Nothing in
  the file tells this end from a turn that simply went on.
- While writing (k-text): the partial reply and "[Request interrupted by user]", the same lines a Stop leaves.
- Permission (k-perm), hook (k-hook): the error tool result ("Tool permission request aborted", the rejection text),
  no marker.
- A Stop before the move (stop-*): the rejection and "[Request interrupted by user for tool use]"; with the hold, the
  message's enqueue and dequeue queue-operations and no user line for it.
- Two messages: one user line for both, under the second's uuid; MCP and n-started: the message as a queue `remove`
  with no user line of its own (read in the turn).

Where the engine differs from the document's reading of the source.
1. Two waiting messages (Reported 6(b)): naming one delivers all that wait at the next step, joined into one user
   message under the last one's uuid (two-1-*, two-2-*). Inference: `pressWaiting` (cli.pretty.js:600834-600852)
   moves for every waiting message and marks them all; the named uuid only selects the answer.
2. A Stop's effect depends on the move, which comes about 1 s after `delivering`: before it, a plain interrupt kills
   the command and the message still runs next (stop-inflight-*, stop-after-*); after it and before the cut turn's
   end, a plain interrupt is a no-op (stop-moved-*). MAWS's square, which withdraws the message first, holds it either
   way; only the command's fate differs (killed before the move, kept after).
3. Under MAWS's environment (CLAUDE_CODE_FORK_SUBAGENT=true) a foreground subagent call did not occur (k-agent-1..4),
   so "Send now behind a running subagent" is not a state MAWS's sessions reach in these runs; the first pass's (b)
   needs that variable unset.
4. An MCP tool call is moved like a shell command and the message is read in the same turn (k-mcp-*), with no
   structured flag on its result.

Bearing on other parts of the spec.
- Interfaces B, the plain-Stop-after-the-move path: the Stop empties the set, so the cut end reads "You stopped" while
  the message runs. Only a caller that interrupts without holding the waiting steers meets it (today's Esc path does,
  `holdEngineQueued` false; after U4 Esc is Send now on the first row).
- Interfaces C: a moved MCP call reads as ended while it runs; its result text is the only mark.
- Reported 4 (the transcript file holds no terminal reason) is confirmed and extends to two messages: the first's uuid
  never appears in the file, so a backfilled transcript cannot find that message by its uuid.
- The cut prompt's `cancelled` after `started` holds in every cutting case (24/24), as the first pass found.
- The cost of `later`: none for MAWS, which writes no `later`; noted because Claude Desktop's ⌘Enter does.

Not provoked. A foreground Agent call under MAWS's environment (four tries; see 5(b)). A tool that cannot be moved once
it has started (the MCP tool, the candidate, is movable; the hook case holds a call before it starts). A Stop written
between the cut turn's result and the message's start (the gap is 2 to 5 ms). The direct route (it does not
authenticate on this VM, VM.md). Model spend: about US$0.13 over the 57 runs (haiku; the largest total_cost_usd of each run).
